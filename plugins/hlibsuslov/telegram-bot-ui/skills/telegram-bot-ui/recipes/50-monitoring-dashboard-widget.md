# 50 — Monitoring dashboard widget (private chat, production)

Registry rows: `10.4-W02`, `10.4-W04`, `10.4-W07`, `10.4-W08` (`recipes/registry.json`). Checked 2026-11-15, Bot API 10.4.

1. **Request and visible result.** “Our on-call bot sends a wall of text every time something changes. I want one health card per service that stays current.” — A card in the engineer's private chat: service name, status pill (Operational / Degraded / Outage), 1h · 24h · 7d chips, four KPI tiles with deltas, a p95 sparkline, error bars with the threshold marked red, an incident line, "Updated 10:58" and Refresh. Incidents change it in place and the caption (“api-prod · Degraded · p95 640 ms · errors 4.8%”) changes with it, so the chat list and notifications tell the same story.
2. **Why the new feature.** 10.4 widgets: a chart and live state inside one bubble, in the chat theme, updated silently with `editMessageWidgetData` (no “edited” mark, no new message). Before: re-send text or a chart image, or open a Mini App.
3. **Requirements.** Bot API ≥ 10.4. **Production: private chats only** (Guide, 2026-11-15) — a team channel or group gets the Rich Message/keyboard alternative. `allow_queries: true`; `allowed_updates` includes `widget_query`. Size: 3586 compressed bytes (English), 3758 (Russian), limit 4096. State ≈ 350 of 1024 bytes.
4. **Payload.** `examples/payloads/r50-monitoring-dashboard.json` (generated); fixtures `examples/fixtures/widget_query_dashboard_period.json`, `widget_query_dashboard_foreign.json`, `widget_query_sync.json`. Key part:
   ```json
   {"chat_id": 111111111, "html": "<style>:root{--k-tx:var(--tg-theme-text-color,#000);…</script>",
    "caption": "api-prod · Operational · p95 182 ms · errors 0.31%", "allow_queries": true,
    "chat_data": "{\"svc\":\"api-prod\",\"st\":0,\"p\":\"24h\",\"at\":1794736680,\"kpi\":[[\"Uptime\",\"99.95\",\"%\",0.02,1],…],\"lat\":[171,…],\"err\":[2,…],\"thr\":10,\"inc\":\"\",\"r\":0}",
    "reply_markup": {"inline_keyboard": [[{"text": "24h report", "callback_data": "mon:rep:24h"}, {"text": "7d report", "callback_data": "mon:rep:7d"}], [{"text": "Incidents", "callback_data": "mon:inc"}]]}}
   ```
5. **Code.** Widget source `examples/widgets/src/metrics-dashboard.html` (kit tokens, `K.spark`/`K.bars` from `_kit/chart.js`, `K.start(draw, {sync: "sync"})`), built `examples/widgets/metrics-dashboard.html`, demo states `examples/widgets/demo/metrics-dashboard.json` (default, degraded, stale, empty). Bot: `examples/python/widget_gallery/h_metrics_dashboard.py` (`decide`), `core.py` (`GalleryBot.send`, `.push`, `.handle`), recipe `examples/python/recipes/r50_monitoring_dashboard.py`.
6. **Sequence and state.** sendWidget(state r0, caption, keyboard) → widget appears → background `sync` (private original only, ≤ 1 per 5 s) → answer `{ok, s, r:0}` → alert pipeline: `push()` = editMessageWidgetData(r1) + editMessageCaption → tap 7d → `widget_query{data:"p:7d"}` → owner check (`from.id`) → recompute ≤ 24 points → editMessageWidgetData(r2) → commit → answerWidgetQuery({ok, s, r:2}); redelivered update → skipped; a query from another user → `not_allowed`; flood wait on the edit → `{ok:false, err:"busy"}`, record unchanged.
7. **Result.** Mock-up (320 px): `api-prod ……… ● Degraded` · `[1h][24h][7d]` · `Uptime 99.2% ▼0.7 | p95 640 ms ▲420` · `Errors 4.8% ▲4.4 | RPS 980 ▼18` · sparkline `190–660 ms` · bars with red spikes · `Elevated 5xx on /pay since 09:42` · `Updated 10:58  [Refresh]`.
8. **Typical mistake, limits, alternative.** Loading Chart.js from a CDN (nothing is fetched — draw SVG); shipping the whole time series (1024-byte state — aggregate to ≤ 24 points); editing on every metric tick (`editMessageWidgetData` counts as a sent message — push on status change or at most every few minutes, let the open widget `sync`); forgetting the caption (the chat list keeps saying “Operational”); trusting `p:` data without the owner check. Alternative: a Rich Message table with a Refresh button (works in groups and channels).
9. **Run and verify.** `py -3 examples/python/recipes/r50_monitoring_dashboard.py` · `py -3 scripts/build_widget.py examples/widgets/src/metrics-dashboard.html --strict --lang ru` · `py -3 scripts/preview_widget.py examples/widgets/src/metrics-dashboard.html --serve 8765` (mock runtime) · `tests/test_widget_gallery.py`. Evidence: offline contract and a browser mock in light/dark/RTL/200–600 px; not rendered in Telegram clients.
10. **Adapt.** Replace `series()` with your metrics query (aggregate server-side), map your alert states to `st` 0/1/2, keep labels localized by the bot, and send the build for the user's language (`--lang`).
