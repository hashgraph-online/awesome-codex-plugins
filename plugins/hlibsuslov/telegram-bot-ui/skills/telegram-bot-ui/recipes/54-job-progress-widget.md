# 54 — Long job progress in one card (private chat, production)

Registry rows: `10.4-W02`, `10.4-W04`, `10.4-W07`, `10.4-W08` (`recipes/registry.json`). Checked 2026-11-15, Bot API 10.4.

1. **Request and visible result.** “Exports take minutes and users keep asking ‘is it working?’.” — One card: “Exporting 12,480 rows to CSV”, stages (queued, fetching, transforming, uploading, done) with the current one marked, a percentage bar, 7,440 / 12,480, elapsed time ticking, ETA, Cancel (tap twice within 3 s to confirm); when done, Open file; when failed, the reason and Retry.
2. **Why the new feature.** 10.4 widgets: silent in-place progress (no “edited” mark, no new messages) and a clock that ticks on the device. Before: editing a text message every few seconds, or a typing indicator that says nothing.
3. **Requirements.** Bot API ≥ 10.4; production: private chats only; `allow_queries: true`. Size 2991 bytes compressed (English). `editMessageWidgetData` counts as a sent message (Guide): push stage changes and progress at most every ~10 s; the open widget refreshes itself with background `sync`.
4. **Payload.** `examples/payloads/r54-job-progress.json`; fixture `examples/fixtures/widget_query_job_cancel.json`. State: `{"ti":"Exporting 12,480 rows to CSV","st":"running","sg":2,"p":7440,"n":12480,"t0":1794736666,"at":1794736800,"eta":58,"r":0}`.
5. **Code.** Widget `examples/widgets/src/job-progress.html` (elapsed = now − `t0`, one `setInterval` redraws only the clock; two-tap confirm is local), demo `examples/widgets/demo/job-progress.json` (default/running, queued, done, failed), handler `examples/python/widget_gallery/h_job_progress.py` (`sync`, `cancel`, `retry`), recipe `examples/python/recipes/r54_job_progress.py` (worker loop with a 10 s push throttle).
6. **Sequence and state.** sendWidget(queued, r0) → worker ticks every second → bot pushes only when ≥ 10 s passed and something changed (3 pushes in 30 s, r1–r3) → widget on screen sends `sync` → catch-up edit (r4) + answer → user taps Cancel twice → `cancel` → state failed “Cancelled by you” → a repeated `cancel` → `bad_request` → `retry` → queued again.
7. **Result.** Mock-up: `Exporting 12,480 rows to CSV · ● fetching ● transforming ○ uploading · ▓▓▓▓▓▓░░░░ 60% · 7,440 / 12,480 · 2:14 elapsed · ~58 s left · [Cancel]`.
8. **Typical mistake, limits, alternative.** Counting seconds in the widget (it can be destroyed and re-created any time — derive from `t0`); editing on every worker tick (flood wait); `confirm()` for Cancel (returns `false` in widgets); a progress percentage without the absolute numbers (the caption and screen readers need text); forwarding a running job as if live (a static forward is a snapshot). Alternative: `sendChatAction` + an edited text message, or Rich Message progress for groups.
9. **Run and verify.** `py -3 examples/python/recipes/r54_job_progress.py` · `py -3 scripts/preview_widget.py examples/widgets/src/job-progress.html --serve 8765` (mock; timers run in the browser, not in QuickJS). Evidence: offline contract; not rendered in Telegram clients.
10. **Adapt.** Feed `push()` from your job queue (stage, processed, ETA), keep the throttle, update the caption on completion (“Export ready · 12,480 rows”), and put the file link behind `openLink` on a tap.
