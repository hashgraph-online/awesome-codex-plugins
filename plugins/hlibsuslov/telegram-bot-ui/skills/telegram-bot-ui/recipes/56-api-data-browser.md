# 56 — API data browser: a widget as the front end of a REST backend (private chat, production)

Registry rows: `10.4-W02`, `10.4-W04`, `10.4-W07`, `10.4-W08` (`recipes/registry.json`). Checked 2026-11-15, Bot API 10.4.

1. **Request and visible result.** “Show our support tickets from the helpdesk API in Telegram: list, open one, assign it or close it.” — A card “Support tickets · 8”: Open / Mine / All chips, five rows (title, #id · requester · priority, status pill), ‹ 1 of 2 ›; a tap opens the detail (requester, priority, updated, text that can be selected) with Assign to me, Close ticket, ‹ Back and Open in app. When the helpdesk is slow, it shows “Service is slow. Cached data from 10:12”.
2. **Why the new feature.** 10.4 widgets give a live, tappable view of backend data inside the chat. The widget itself has **no network** (Guide: every network API throws `NetworkDisabledError`), so the bot is the bridge.
3. **Requirements.** Bot API ≥ 10.4; production: private chats only; `allow_queries: true`. Size 3235 bytes compressed (English), 3451 (Ukrainian). The backend call must finish well inside the 15-second answer window (timeout 6 s here).
4. **Payload.** `examples/payloads/r56-api-data-browser.json`; fixture `examples/fixtures/widget_query_api_open.json` (`"data": "o:4104"`). Request grammar: `f:<open|mine|all>`, `pg:<n>`, `o:<id>`, `b`, `x:<id>:<assign|close>`, `sync`. The fallback keyboard includes a URL button `https://t.me/example_bot?startapp=tickets`.
5. **Code.** Widget `examples/widgets/src/api-browser.html`; demo `examples/widgets/demo/api-browser.json` (default, detail, stale, empty); handler `examples/python/widget_gallery/h_api_browser.py`: `TicketsApi` protocol, `MockTicketsApi` (offline), `RestTicketsApi` (urllib, base URL and token read from the bot's environment by name: `WIDGET_API_BASE`, `WIDGET_API_TOKEN`; never used by tests), `use_api()`, a per-user page cache (30 s), `backend_user()` mapping `from.id`; recipe `examples/python/recipes/r56_api_data_browser.py`.
6. **Sequence and state.** sendWidget(first page, r0) → background `sync` → GET list → edit + answer → `f:all` → `pg:2` → `o:4104` → GET detail → view `d` with `app` link prefix → `x:4104:assign` → POST, re-checked by the backend → answer “Assigned to you: #4104”, cache invalidated → `b` → fresh page → 60 s later the upstream times out → answer the cached page with `stale: 1` and “Showing cached data” instead of a `TIMEOUT` → a backend webhook closes #4109 → the bot pushes the list (new revision).
7. **Result.** Mock-up (320 px): `Support tickets ……… 10` · `[Open][Mine][All]` · `Bulk import fails  #4109 · Olena P. · High  (open)` … · `‹  2 of 2  ›`; detail `Webhook returns 502 · Requester Marco R. · Priority Normal · Updated 15 Nov, 09:20 · [Assign to me][Close ticket] · [‹ Back][Open in app]`.
8. **Typical mistake, limits, alternative.** `fetch()` in the widget (throws); an API key or token in the HTML or state (both are readable by the user); passing whole API responses as state (1024 bytes: project to five rows); waiting on a slow upstream past 15 s (the widget shows `TIMEOUT`, the answer is refused); trusting `x:` data without the backend's own check; polling the API on a timer for every user (push on webhooks, `sync` only while on screen). Alternative: a Mini App for search, long forms and attachments — the widget's “Open in app” passes only the ticket id in `startapp`.
9. **Run and verify.** `py -3 examples/python/recipes/r56_api_data_browser.py` · `py -3 scripts/preview_widget.py examples/widgets/src/api-browser.html --serve 8765` (mock; requests go to the mock backend through the real handler) · `tests/test_widget_gallery.py`. Evidence: offline contract with a mock backend; not rendered in Telegram clients; no real endpoint called.
10. **Adapt.** Implement `TicketsApi` for your endpoint (or call `use_api(RestTicketsApi())`), map `from.id` to your accounts in `backend_user()`, keep the 5-row projection and the cache, push on your webhooks, and point `APP_LINK` at your Mini App. Related: `widget-patterns.md#11-widget-as-the-front-end-of-a-backend`, `#12-widget-vs-mini-app-hand-off`, 50.
