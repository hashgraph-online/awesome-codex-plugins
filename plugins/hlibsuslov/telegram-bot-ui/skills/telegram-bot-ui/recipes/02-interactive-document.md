# 02 — Interactive document: compact table, expandable quote, attached file, buttons, quoting

Registry rows: `10.4-Q01`, `10.4-Q02`, `10.4-X02`, `10.3-R01`, `10.3-R02`, `10.3-R03`, `10.3-R04`, `10.3-R05`, `10.3-R06`, `10.3-R07`, `10.5-G03` (`recipes/registry.json`). Verified 2026-11-12, Bot API 10.4; expandable quote re-checked 2026-11-22, Bot API 10.5.

1. **Request and visible result.** “Send the policy as a proper document: a status table, the rotation steps we tick off, the long auditor note folded, the PDF attached, an Approve button — and when someone quotes a line, answer that line.” — One rich message: heading, a sentence with the owner as a link and the checklist id as `<code>`, a view switch [Production] [Staging] right above the compact table, the rotation steps each ending in a quiet “Done” link (`RichTextButton`, `style: "link"`), collapsed note, PDF block. **Approve policy** is on the keyboard under the message. “Done” re-renders the document with that step ticked and an “Undo”; the switch re-renders the table; Approve changes only the keyboard (a disabled “Approved”). A reply quoting “signing key” gets an answer that quotes exactly that fragment. Why this split: [references/rich-message-buttons.md](../references/rich-message-buttons.md) — a document button only for a press that changes its own element.
2. **Why the new feature.** 10.3 adds buttons, `is_compact`, expandable quotations and documents *inside* rich messages (before: a separate file message and a keyboard under the whole document). 10.4 lets the bot read and send quotes from rich messages (`TextQuote.rich_texts`, `quote_rich_texts`). 10.5 makes the expandable quotation a container (`blocks` instead of `text`), so the auditor's checklist stays a real list inside the folded note.
3. **Requirements.** Bot API ≥ 10.3 (quotes ≥ 10.4; expandable quote with `blocks` ≥ 10.5 — 10.3/10.4 servers expect `text`). Production, any chat where the bot may send rich messages (media rights for the document). Ephemeral/inline limits: see validator contexts.
4. **Payload.** Full request sequence: `examples/payloads/r02-interactive-document.json` (generated from the code); incoming fixture: `examples/fixtures/message_quote_rich.json`. Key part:
   ```json
   {"type": "buttons", "align": "left", "buttons": [
     {"text": "Production", "disabled": {}}, {"text": "Staging", "callback_data": "doc:view:staging"}]},
   {"type": "list", "items": [{"blocks": [{"type": "paragraph", "text": ["Generate the new signing key · ",
     {"type": "button", "button": {"text": "Done", "callback_data": "doc:done:gen", "style": "link"}}]}]}]}
   ```
   and the keyboard: `{"inline_keyboard": [[{"text": "Approve policy", "callback_data": "doc:approve:v3", "style": "success"}]]}`.
5. **Code.** `examples/python/tgkit/rich.py` (builders, `quote_text`, `quote_from_paragraph`, `find_ton_addresses`), `examples/python/recipes/r02_interactive_document.py`, TS `examples/ts/recipes.ts::interactiveDocument`. Validate with `scripts/validate_rich.py`.
6. **Sequence and state.** sendRichMessage(blocks, reply_markup) → message_id → user replies with a quote (`quote.text` == "", `rich_texts`) → bot replies with `reply_parameters.quote_rich_texts` → “Done” callback → answerCallbackQuery → editMessageText(rich_message with the step ticked, the same reply_markup) → view switch → the same → Approve callback → answerCallbackQuery → editMessageReplyMarkup(disabled “Approved”).
7. **Result.** Mock-up: `## Key rotation policy v3 · …owner (link)… ROT-2026-v3 · [Production] [Staging] · [compact table] · ### Rotation steps · 1 of 3 · ✓ Generate… · Undo / Deploy… · Done / Revoke… · Done · ▸ Auditor note… · 📄 Full procedure (PDF)` and under it the keyboard `[Approve policy]`.
8. **Typical mistake, limits, alternative.** Putting Approve, a url or Back inside the document (`RICH_BUTTON_MAIN_ACTION`, `RICH_BUTTON_OUTSIDE`, `RICH_BUTTON_NAVIGATION`); reading only `quote.text` (empty for rich quotes); sending `expandable_blockquote` with `text` (rejected since 10.5 — wrap it in a paragraph block); `style: link` on a URL button; `pay`/`icon_custom_emoji_id` on rich buttons; > 8 buttons in a row; uploading a new file inside a draft. Alternative: regular message + document message + inline keyboard.
9. **Run and verify.** py -3 examples/python/recipes/r02_interactive_document.py · tests/test_text_and_rich.py · tests/test_keyboard_validator.py. Evidence: offline contract.
10. **Adapt.** Copy the builders; adapt the content mapping; keep callback data stable (`doc:approve:<version>`). Related: `tables.md`, `telegram-capabilities.md#rich-additions-bot-api-103-105`, 04 (personal view of the same doc).
