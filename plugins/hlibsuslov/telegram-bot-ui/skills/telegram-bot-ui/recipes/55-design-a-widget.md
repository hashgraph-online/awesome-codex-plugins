# 55 — Design a new widget from a user's description (describe → widget workflow)

Registry rows: `10.4-W02`, `10.4-W04`, `10.4-W07`, `10.4-W08` (`recipes/registry.json`). Checked 2026-11-15, Bot API 10.4.

1. **Request and visible result.** “Let me set a price alert for TON right in the chat, with a slider, in Russian.” — The agent does not copy a gallery file blindly: it decides the surface, writes a spec, models the state, assembles the widget from kit parts, builds it for the user's language, validates, previews, and ships it with a caption and a keyboard alternative. Result: the `price-alert` widget (asset, current price, above/below chips, a horizontal slider with − / + buttons, once/every chips, distance in %, Save alert).
2. **Why the new feature.** 10.4 widgets plus this skill's kit and tools make a new widget a few hundred lines of readable source, not a hand-tuned 4 KB file.
3. **Requirements.** Bot API ≥ 10.4; production: private chats only; the user's language from `from.language_code`. Budget: 3800 bytes compressed (hard limit 4096) per language build; state ≤ ~900 bytes so answers carrying it fit 1024.
4. **Payload.** `examples/payloads/r55-design-a-widget.json` (the Russian build is what is sent); fixture `examples/fixtures/widget_query_sync.json` reused with `set:` data. Request grammar: `set:<above|below>:<price>:<once|every>` (absolute: no revision needed).
5. **Code.** The steps below, executable in `examples/python/recipes/r55_design_a_widget.py` (`choose_surface`, `build_widget.build_text(..., langs=("ru",))`, `GalleryBot.send(..., html=...)`); result `examples/widgets/src/price-alert.html`, `examples/python/widget_gallery/h_price_alert.py`.
6. **Sequence and state.** The workflow an agent follows for any description:
   1. **Decide** with `widget-patterns.md#1-decision-guide-widget-keyboard-rich-message-or-mini-app`: typed text, network or > 560 px → Mini App; not a private chat → keyboard/Rich Message; text to read → Rich Message; one choice → keyboard; in-place changes or custom controls → widget.
   2. **Spec** in five lines: who sees it (private chat), what it shows (main fact = caption), actions (verbs), places it must survive (preview, no viewer), the fallback keyboard.
   3. **State model**: the smallest projection that draws the view (`{"a":"TON/USD","px":547,"st":"active","dir":"above","th":590,"mode":"once","r":3}`), money in minor units, labels localized by the bot, revision `r`; mark verbs as absolute (`set:…`) or relative (`t:3@rev` → `stale_verbs`).
   4. **Compose from the kit** (`widget-design-system.md#5-layout-primitives-kit-classes`): `.k` root, `.hd` + `.tt` header, `.rw` of `.ch` chips for choices, a slider with `touch-action: pan-y` plus − / + buttons, figure text `min(1.6em, 9vw)`, `.st` status line, plain `<button>` for the primary action; strings in `/*@lang xx*/` blocks; `K.start(draw)`; `K.ask(data, {done})` only inside click handlers.
   5. **Handler**: `decide(state, act, ctx)` validating every argument (`BadRequest`), returning `None` when nothing changes, `{"msg": …}` for sentences; register it as `SPEC` in `examples/python/widget_gallery/h_<name>.py` with a demo JSON (default + 2–3 states, queries).
   6. **Build**: `py -3 scripts/build_widget.py SRC --strict --lang ru` (and every other language) — fix every runtime gap and lint finding, stay ≤ 3800 bytes; trim strings before features.
   7. **Validate and preview**: `py -3 scripts/validate_widget.py OUT --strict`, `py -3 scripts/preview_widget.py SRC --serve 8765` in light/dark/outgoing, RTL, 200–600 px, 20 px text, no caption, forward, preview, offline bot; then a real client.
   8. **Ship**: `sendWidget` with the user's build, a caption mirroring the main fact, the keyboard alternative; edit the caption when the main fact changes.
7. **Result.** Mock-up (ru): `TON/USD · 5,47 $ · [Выше][Ниже] · ─────●──── · −  5,90 $  + · +7,9 % · [Один раз][Каждый раз] · [Сохранить]`.
8. **Typical mistake, limits, alternative.** Starting from HTML instead of the state model (the 1024-byte limit then forces a rewrite); three languages in one build (over 4 KB); vertical drags (always the chat's); a slider without buttons (no keyboard or accessibility fallback); trusting the price the widget shows; skipping the strict build. Alternative: the inline keyboard “Above 5.90 / Below 5.00” in the fallback.
9. **Run and verify.** `py -3 examples/python/recipes/r55_design_a_widget.py` · `py -3 scripts/build_widget.py examples/widgets/src/price-alert.html --strict --lang ru --demo examples/widgets/demo/price-alert.json` · tests `tests/test_widget_build.py`, `tests/test_widget_gallery.py`. Evidence: offline; the preview is a mock; not rendered in Telegram clients.
10. **Adapt.** Use this list for any described interface; start from the closest gallery widget only after step 3, and keep the generated widget, its demo and its handler together so the gallery tests cover it. Related: 50–54, 56, `widget-design-system.md`, `widget-patterns.md`.
