# 53 — Quiz with a shared leaderboard (private chats + one shared widget, production)

Registry rows: `10.4-W02`, `10.4-W03`, `10.4-W04`, `10.4-W07`, `10.4-W08`, `10.4-W09` (`recipes/registry.json`). Checked 2026-11-15, Bot API 10.4.

1. **Request and visible result.** “Run a weekly quiz in the bot with a leaderboard everyone sees.” — Each player gets a private quiz card (question 2 of 5, progress bar, four answers; after a tap the right and wrong answers are coloured and a one-line explanation appears; Next; final score and Play again). One leaderboard widget (top 5 with medals, player count, and “Which mode next week?” with live counts) is shown in every player's chat and updates for all of them.
2. **Why the new feature.** 10.4 shared widgets: one object, one public state, any number of messages (`sendSharedWidget`), refreshed while on screen (`watchPublicData`). Before: re-sending a leaderboard message to everyone.
3. **Requirements.** Bot API ≥ 10.4. Production: private chats only — the leaderboard is created once (`is_shared` + `allow_queries`) and re-sent to each player's private chat; forwards and group play are test-server only. Sizes: quiz 2779, leaderboard 2933 bytes compressed (English).
4. **Payload.** `examples/payloads/r53-shared-quiz-leaderboard.json`; fixtures `examples/fixtures/widget_query_quiz_answer.json` (`"a:2:1@1"`) and `widget_query_leaderboard_vote.json` (`"v:1"` with `widget_id`). Re-send: `{"chat_id": 111111111, "widget_id": "77700…", "caption": "Leaderboard · Mila K. leads with 9,840 · 1,284 players"}`.
5. **Code.** Sources `examples/widgets/src/quiz.html`, `leaderboard.html` (`K.start(draw, {watch: true})`, `K.ask("v:1", {f: "publicData"})`, own vote in `localStorage` inside `try`); handlers `examples/python/widget_gallery/h_quiz.py` (answers kept in the bot's question bank; `a` and `next` are stale verbs), `h_leaderboard.py` (votes in the widget's server-side memo: one per `(widget_id, from.id)`); shared path `core.GalleryBot._handle_shared` (answer at once, `SharedWidgetWriter` ≤ 1 edit/s); recipe `examples/python/recipes/r53_shared_quiz_leaderboard.py`.
6. **Sequence and state.** Quiz: sendWidget(question without the answer) → `a:1:2@0` → reveal + score (r1) → `a:1:0@0` → stale → `next@1`. Leaderboard: sendWidget(`is_shared`, `allow_queries`) to the bot owner's chat → read `widget.id` → `sendSharedWidget` to each player → votes from two players 0.3 s apart → each voter's answer carries the new state and `my` → `editSharedWidgetData` written at most once per second → other players see it at the refresh period (30 s default, `cache_time` 5–3600).
7. **Result.** Mock-up: quiz `Question 2 of 5 ▓▓░░░ · What is the capital of Australia? · [Sydney][Melbourne][Canberra ✓][Perth] · Canberra was built as a compromise between Sydney and Melbourne. [Next]`; leaderboard `🥇 Mila K. 9,840 · 🥈 Jonas 9,215 · … · Which mode next week? Blitz 213 · Marathon 148 · Duels 98 (your vote)`.
8. **Typical mistake, limits, alternative.** Putting the correct answer in `chat_data` (the code and state are readable: reveal only after the answer); counting votes per message instead of per `(widget_id, from.id)`; one edit per vote (flood wait above 1 edit/s); expecting live updates without `watchPublicData()`; promising forwards of the leaderboard in production. Alternative: native Telegram polls/quizzes for one-question cases.
9. **Run and verify.** `py -3 examples/python/recipes/r53_shared_quiz_leaderboard.py` · `py -3 scripts/preview_widget.py examples/widgets/src/leaderboard.html --serve 8765` (mock: the shared refresh is not emulated). Evidence: offline contract; not rendered in Telegram clients.
10. **Adapt.** Keep the question bank and scores server-side, write the leaderboard from your scores table through the coalescing writer, choose `cache_time` for how often it really changes, and offer the plain keyboard (`lb:v:<i>`) as the alternative.
