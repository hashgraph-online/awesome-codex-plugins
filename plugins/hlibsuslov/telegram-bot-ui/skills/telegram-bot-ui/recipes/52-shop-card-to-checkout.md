# 52 — Shop: product card → cart → receipt (private chat, production)

Registry rows: `10.4-W02`, `10.4-W04`, `10.4-W07`, `10.4-W08` (`recipes/registry.json`). Checked 2026-11-15, Bot API 10.4.

1. **Request and visible result.** “Our shop bot lists products as text. Make a real product card, a cart and a receipt.” — Three widgets: a product card (drawn bottle, colour and size chips, − 1 + stepper, “Only 3 left”, Add to cart), a cart (lines with steppers, promo line, delivery chips, subtotal/discount/delivery/total, Checkout), and after payment a receipt (items, VAT, total, PAID chip, Copy number, Download PDF, Refund request).
2. **Why the new feature.** 10.4 widgets: catalogue UI with live stock and totals inside the chat, each card updating in place. Before: photos with keyboards and recalculated text.
3. **Requirements.** Bot API ≥ 10.4; production: private chats only; `allow_queries: true`. Sizes (English): product 3287, cart 3186, receipt 2903 bytes compressed (limit 4096). **Payment itself stays outside the widget**: the bot's invoice (Telegram payments) or the wallet flow of recipe 07.
4. **Payload.** `examples/payloads/r52-shop-to-checkout.json`; fixture `examples/fixtures/widget_query_cart_add.json` (`"data": "add:0:2"`). Product state: `{"n":"Steel bottle","rt":46,"rv":128,"pr":2490,"cur":"EUR","c":["Moss","Sand","Ink"],"z":["500 ml","750 ml","1 L"],"k":[8,3,0,…],"ct":0,"r":0}` (stock per colour × size).
5. **Code.** Sources `examples/widgets/src/{product-card,cart-checkout,receipt}.html`; demos in `examples/widgets/demo/`; handlers `examples/python/widget_gallery/h_product_card.py` (`add:<variant>:<qty>` checks stock), `h_cart_checkout.py` (`q:<line>:<±1>@rev` stale verb, `dl:<i>`, `checkout`), `h_receipt.py` (`refund`; copy and PDF link are local `copyText` / `openLink` on a tap); recipe `examples/python/recipes/r52_shop_to_checkout.py`.
6. **Sequence and state.** sendWidget(product) → `add:1:2` → stock 3 → 1, `ct` 2 (edit + answer “Added to cart”) → `add:1:2` again → `{err:"stock", msg:"Only 1 left"}` → bot sends the cart widget → `q:1:+1@0` (r1) → `q:0:+1@0` → stale → `dl:2` (r2) → `checkout` → read-only “awaiting payment” (r3), answer “Pay 54.25 EUR to place the order” → the bot sends its invoice in the chat → payment confirmed → receipt widget.
7. **Result.** Mock-up: `[bottle] Steel bottle ★4.6 (128) €24.90 · [Moss][Sand][Ink] · [500 ml][750 ml][1 L] · − 2 + · Only 3 left · [Add to cart]` → `Cart: 3 lines … Total €54.25 [Checkout]` → `Receipt INV-20481 · PAID · [Copy number] [Download PDF]`.
8. **Typical mistake, limits, alternative.** Taking a price or total from the widget (always recompute on the server); one giant widget for the whole shop (separate cards keep each state ≤ 1024 bytes and each code ≤ 4 KB); product photos as `data:` images (they barely compress — draw, or send a photo above the widget); asking for a card number in a widget (impossible and prohibited: use Telegram payments). Alternative: a Mini App catalogue for large inventories.
9. **Run and verify.** `py -3 examples/python/recipes/r52_shop_to_checkout.py` · `py -3 scripts/build_widget.py --all --check` · `py -3 scripts/preview_widget.py examples/widgets/src/cart-checkout.html --serve 8765` (mock). Evidence: offline contract; not rendered in Telegram clients; no payment executed.
10. **Adapt.** Map `k` to your inventory (reserve on add, release on timeout), keep money in minor units (`K.money`), keep the cart's quantity verb stale-checked, and send the receipt only after the payment update arrives. Related: 07 (wallet), 51, `widget-patterns.md#9-wallet--ton-actions-only-what-telegram-documents`.
