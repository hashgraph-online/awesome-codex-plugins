# 인도 전 검증

> 만든 PDF는 주장입니다. 쪽 이미지, 바이트 검사, 추출 텍스트가 그 주장을 증거로 바꾸는 세 검사입니다.

## 1. 관문

만든 문서는 모두 아래 세 검사를 이 순서로 통과합니다. 하나를 건너뛰면 보고의 결함이고 지름길이 아닙니다.

| 단계 | 명령 | 증명하는 것 |
|---|---|---|
| 구조 | `check <out.pdf>` | 글꼴이 임베딩됐고 언어 태그가 있고 빈 쪽이 없으며 스캔이 표시됨 |
| 기하 | `info <out.pdf>` | 쪽 수·쪽 크기·회전·메타데이터가 의도한 값 |
| 겉모습 | `render <out.pdf> --out-dir DIR` | 쪽이 실제로 서술한 문서처럼 보임 |

텍스트가 중요한 문서에는 네 번째가 붙습니다.

| 단계 | 명령 | 증명하는 것 |
|---|---|---|
| 판독 | `text <out.pdf>` | 그린 문자열이 올바른 문자 체계로 추출됨 |

## 2. `check` 결과 읽기

| `status` | 할 일 |
|---|---|
| `ok` | 결과와 실행한 검사를 보고 |
| `caveated` | `issues[]` 코드마다 그 손실을 붙여 보고. 파일을 끝났다고 하지 않음 |
| `blocked` / `error` | 아무것도 만들어지지 않음. 코드와 필요한 것을 보고 |

`build` 경로의 `NO_STRUCTURE_TREE`는 예상된 결과입니다. 그래도 한 줄로 적을 한계입니다. 화면 낭독기가 그 파일에서 읽기 순서를 복원하지 못합니다. 숨기지도 말고 접근성 있다고 표현하지도 마세요.

## 3. 렌더가 잡는 것

바이트 검사로는 안 보이고, 모두 실제 문서에서 나간 적이 있는 결함입니다.

| 결함 | 이미지에서의 흔적 |
|---|---|
| 좌우·상하 반전 | 글자가 오른쪽에서 왼쪽으로, 또는 거꾸로 읽힘 |
| 베이스라인 오류 | 위 괘선에 겹치거나 여백에 떠 있음 |
| 머리글 반복 누락 | 표가 이어지는 둘째 쪽에 열 이름이 없음 |
| 여백 침범 | 텍스트나 표 끝이 여백을 넘음 |
| 대체 글꼴 | 문단 중간 한 단어만 눈에 띄게 다른 글꼴 |
| 한국어 줄바꿈 결함 | 줄이 `,`나 `)`로 시작 |
| 쪽 번호 누락 | 여러 쪽 문서인데 바닥글 영역이 빔 |
| 빈 마지막 쪽 | 마지막 쪽에 내용이 없음 |
| 셀 잘림 | 줄바꿈되지 않고 열 경계에서 글자가 잘림 |

## 4. 보고에 남길 증거

- 출력 경로, 쪽 수, mm 단위 쪽 크기.
- `check` 상태와 모든 이슈 코드.
- 렌더해 확인한 쪽과 본 내용.
- 정확한 명령줄. 결과를 재현할 수 있어야 함.
- 실행하지 않은 검사와 그 이유. 실행하지 않은 검사는 미실행으로 보고하고 통과로 적지 않음.

## 5. 한계 보고

사과가 아니라 산출물의 성질로 적습니다.

- "구조 트리가 없어 화면 낭독기가 읽기 순서를 복원하지 못합니다."

- "OCR 정확도는 확인하지 않았습니다. 3쪽 이미지를 직접 확인해 주세요."

## 6. 검증을 건너뛰어 달라는 요청

파일은 만들고, 건너뛴 것과 그로 인해 남는 위험을 보고합니다. 사용자의 지시는 작업을 정하지 보고의 정확성을 정하지 않습니다. 아무것도 확인하지 않았는데 "검증했다"고 적는 보고는 누가 속도를 요구했든 거짓입니다.
