# 레퍼런스 충실도

사용자가 구체적인 시각 목표를 줄 때, 즉 스크린샷, 목업 이미지, 디자인 내보내기, 재현할 라이브 페이지가 있을 때 `match` 모드에서 이 참조를 읽습니다. 레퍼런스가 계약입니다. 이 파일은 계약을 추출하는 방법, 그에 맞춰 짓는 방법, 일치를 증명하는 방법을 정합니다.

## 1. 계약 추출

코드를 쓰기 전에, 레퍼런스가 고정하는 것을 인상이 아니라 측정으로 적습니다.

| 부분 | 기록할 것 |
|---|---|
| 토큰 | 색, 글꼴 패밀리와 크기, 굵기, 줄 높이, 반경, 그림자, 간격 단계. 각각 값과 출처 요소 |
| 기하 | 레퍼런스 너비에서 컨테이너 너비, 열 수, 간격, 정렬, 주요 요소의 크기 |
| 문구 | 대소문자와 문장부호까지 보이는 텍스트 그대로 |
| 상태 | 레퍼런스가 보여 주거나 암시하는 호버, 포커스, 활성, 비활성, 비어 있음, 오류 상태 |
| 반응형 의도 | 다른 너비에서의 동작이 보이면 그대로, 아니면 명시한 가정 |

프로젝트에 토큰 파일이나 디자인 문서가 있으면 계약을 거기에 적고, 없으면 보고서에 적습니다. 모르는 부분은 조용히 채우지 말고 가정으로 표시합니다.

## 2. 라이브 페이지 레퍼런스

사용자가 지목한 공개 페이지는 다음을 따릅니다.

- 압축된 소스를 읽지 말고 브라우저에서 실행 시점의 진실(계산된 스타일, 레이아웃 사각형, 전환, 키프레임)을 읽습니다.
- 주요 컨트롤의 기본, 호버, 포커스, 활성 상태와 캡처할 너비에서의 페이지를 표본으로 잡습니다.
- 계약에 필요한 것만 가져옵니다. 다른 사이트의 로고, 브랜드 이미지, 라이선스 없는 글꼴, 마케팅 문구는 복사하지 않고 사용자의 콘텐츠나 표시된 자리 표시를 씁니다.
- 일반 fetch로 읽을 수 없는 페이지는 그것을 맞추는 일과 다른 문제입니다. 차단이나 로그인을 우회하지 말고 그 경계를 보고합니다.

## 3. 계약에 맞춰 짓기

- 스크린샷 한 장에 맞춘 일회성 코드가 아니라 추출한 토큰을 담은 재사용 가능한 기본 요소를 짓습니다. 같은 기본 요소를 쓰는 두 번째 화면은 새 매직 넘버 없이 동작해야 합니다.
- 값은 계약에서 가져옵니다. 계약 값이 프로젝트의 기존 토큰과 같으면 그 토큰을 재사용하고, 새 값일 때만 토큰을 추가합니다.
- 프로젝트의 컴포넌트, 라우팅, 데이터 규칙은 유지합니다. 레퍼런스는 모양을 정하고 구조를 정하지 않습니다.

## 4. 일치 증명

1. 레퍼런스와 같은 뷰포트, 같은 상태, 같은 콘텐츠로 결과물을 캡처합니다.
2. 나란히 놓고 측정으로 비교합니다. 토큰 값, 요소 크기, 위치를 봅니다. 눈으로만 비교하면 부족합니다.
3. 모든 편차를 이유와 함께 나열합니다. 설명 없는 편차는 실패이고, 받아들인 편차에는 사용자의 동의나 밝힌 기술적 이유가 필요합니다.
4. 계약이 다루는 상태와 다른 너비를 확인한 뒤 나머지 [rendered-verification.ko.md](../rules/rendered-verification.ko.md)를 따릅니다.

## 5. 한계

- 정적 이미지는 동작을 보여 줄 수 없으므로 보이는 상태를 넘어서는 동작은 가정이고, 가정이라고 표시합니다.
- 구할 수 없거나 라이선스가 없는 글꼴, 이미지, 아이콘은 가장 가까운 사용 가능한 선택으로 바꾸고 대체했음을 보고합니다.
- 일치는 캡처한 뷰포트, 테마, 콘텐츠에 대한 것입니다. 모든 곳에서 일치한다고 주장하지 않고 그렇게 밝힙니다.
