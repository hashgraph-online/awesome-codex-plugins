# 리서치: 차트

이 패키지의 차트 파트를 어떻게 골랐는지, 그리고 ECMA-376 스키마가 실제로 강제하는 규칙이 무엇인지 적습니다. 파워포인트가 받아 주지만 스키마가 거부하는 차트는 엄격한 읽는 쪽이 통째로 버리는 차트입니다. 그래서 여기서는 스키마가 관문입니다.

## 1. 차트 유형과 쓰는 자리

유형 열 개를 구현했습니다. 목록이 짧은 것은 의도입니다. 각 항목이 주장의 한 모양을 맡고, 열한 번째가 필요한 덱은 보통 슬라이드 두 장이 필요한 덱입니다.

| 유형 | 내세우는 주장 | 막는 실패 |
|---|---|---|
| `column` | 몇 개 범주 비교 | — |
| `bar` | 이름이 긴 범주 비교 | 세로일 때 돌아간 이름표 |
| `stacked` | 몇 기간의 구성 | — |
| `stackedBar` | 이름이 긴 범주의 구성 | — |
| `line` | 시간에 따른 변화 | 막대는 기간이 끊겼다고 말함 |
| `area` | 부피가 있는 시간 변화 | 선은 총량을 작게 보이게 함 |
| `scatter` | 두 측정값의 관계 | 선은 공유 시간축을 암시함 |
| `pie` | 한 시점의 구성, 조각 3~5개 | — |
| `doughnut` | 같은 구성, 가운데에 총계를 둘 자리 | — |
| `combo` | 한 장에 두 단위 | 부피 축에 눌린 비율 선 |

## 2. 혼합 차트 문제

혼합 차트가 존재하는 이유는 덱이 흔히 "부피는 늘고 비율은 줄었다"고 말하기 때문입니다. 단위가 다른 두 계열을 한 축에 놓는 것은 거짓입니다. 비율 선이 기준선에 붙어 0으로 읽힙니다.

OOXML은 혼합 차트를 하나의 `chartSpace` 안 두 차트 그룹으로 표현합니다. 범주 축을 공유하고 각자 값 축을 가집니다. 플롯 영역에 `barChart`와 `lineChart`가 차례로 놓이고, 축 목록에 `catAx` 하나와 `valAx` 둘이 들어갑니다.

두 번째 값 축은 눈금선을 그리지 않아야 합니다. 그리면 서로 어긋나는 가로 규칙 두 벌을 읽는 사람이 보게 됩니다. 위치는 오른쪽이고 범주 축의 최댓값에서 교차하며, 선이 쓰는 눈금을 볼 수 있도록 보이게 둡니다.

막대 절반과 선 절반 모두 축 id를 그룹의 **마지막 자식**으로 가져야 합니다. 파워포인트는 없어도 받아 주지만 ECMA 스키마는 받지 않습니다. 엄격한 읽는 쪽은 이것이 빠지면 차트 전체를 버립니다.

## 3. 실제로 걸린 스키마 규칙

| 규칙 | 무슨 일이 있었나 |
|---|---|
| `c:legendPos`는 `b`, `t`, `l`, `r`, `tr`만 받음 | `val="bottom"`은 파워포인트의 관대한 파서를 통과하고 스키마에서 실패합니다. 범례를 숨기려면 "none" 값이 아니라 요소를 빼야 합니다 |
| `c:barChart`는 `<c:axId>` 쌍으로 끝남 | 그룹 일곱 곳에서 빠져 있었고, 스키마가 차트를 무효로 보고했습니다 |
| `a:tcPr`은 테두리가 채움보다 앞인 순서 | 표 칸에서 `solidFill` 뒤의 `lnB`가 슬라이드 파트 전체를 실패시킵니다 |
| `c:ser` 자식 순서 고정 | `spPr`, `marker`, `dLbls`, `xVal`, `yVal`, `smooth` 순서 |

교훈은 "파워포인트가 열면 통과"가 관문이 아니라는 것입니다. 관문은 ECMA-376 XSD에 대한 `xmllint --schema`이고, 패키지는 납품 전에 이것으로 확인합니다.

## 4. 캐시 값과 워크북

모든 차트 계열은 서식 코드와 값을 담은 `numCache`를 함께 가집니다. 읽는 쪽이 워크북을 열지 않고 그림을 보여 주기 위해서입니다. 그러나 임베디드 시트가 없는 차트는 "데이터 편집" 대화상자가 비어 보여, 숫자를 고치려는 사람에게 덱이 고장 난 것처럼 보입니다.

이 패키지는 차트마다 최소 스프레드시트를 `ppt/embeddings/`에 넣고 차트 관계에서 연결합니다. A열에 범주, 계열마다 자기 열을 씁니다. 읽는 쪽이 데이터를 고치면 그 수정이 실제 자리에 떨어집니다.

## 5. 값 이름표와 산점도

산점도는 점마다 x 값이 필요합니다. spec은 점마다 숫자 하나와 범주 이름표를 싣고, 이름표가 모두 숫자로 읽히면 이름표를 x로, 아니면 점의 순서를 x로 씁니다. 값을 두 축에 함께 쓰면 대각선이 그려지고, 이는 작성자가 의도한 적이 없습니다. 이 결함은 스키마가 아니라 렌더를 눈으로 보고 찾았습니다.

차트 글자 8포인트는 발표 화면에서 보이지 않습니다. 축과 값 이름표는 패키지에서 12포인트, 미리보기에서 15~16 CSS 픽셀로 잡아 둘이 어긋나지 않게 했습니다.

## 6. 구현하지 않은 것

- 추세선, 오차 막대, pie-of-pie: 각자 대화상자가 필요하고 덱 하나를 이것 없이 만드는 일이 흔합니다.
- 3D 변형: 장식을 위해 가독성을 지불합니다.
- 축 끊기와 로그 눈금: 로그 축이 필요한 덱은 다른 차트가 필요한 덱입니다.
