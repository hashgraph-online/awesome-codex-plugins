# 화면 패턴

발견 사항이 랜딩 페이지, 마케팅 섹션, 대시보드, 관리 패널, 로그인 후 화면에 관한 것일 때, 또는 `design`이나 `restyle` 계획이 익숙한 섹션을 집어 들 때 읽는다. 각 항목은 기본 모양, 그것이 생성된 것처럼 읽히는 이유, 대신 할 일을 밝힌다. rule ID는 `references/anti-pattern-catalog.md`를 가리킨다.

## 목차

- 1. 랜딩과 마케팅 페이지
- 2. 앱과 대시보드 화면
- 3. 장식
- 4. 정직한 자리 표시

## 1. 랜딩과 마케팅 페이지

| 패턴(rule ID) | 생성된 것처럼 읽히는 이유 | 대신 |
|---|---|---|
| 히어로, 부제, CTA 두 개, 스크린샷, 기능 그리드, 후기, FAQ, CTA, 푸터 순서 (`structure.template-sequence`) | 순서가 제품의 이야기가 아니라 학습 데이터의 기본값이다 | 섹션을 제품의 서사 순서로 배열한다. 내용이 없는 섹션(실제 후기가 없는 경우)은 존재하지 않는다 |
| 모든 섹션이 가운데 정렬 제목, 부제, 똑같은 카드 그리드다 (`structure.uniform-rhythm`) | 섹션들이 서로 구분되지 않는다 | RHYTHM 다이얼에 맞춰 구성을 바꾼다. 텍스트 위주와 시각 위주, 대칭과 비대칭 |
| 섹션 사이의 유일한 변화가 배경색 반전이다 (`structure.alternating-background`) | 구성이 해야 할 일을 색이 대신한다 | 바탕만 바꾸지 말고 구성을 바꾼다 |
| "작동 방식"이 언제나 1, 2, 3이 붙은 둥근 아이콘 셋이다 (`structure.three-step-default`) | 실제 과정이 깔끔한 세 단계인 경우는 드물다 | 실제 단계 수를 그 흐름이 취하는 모양으로 보여 준다 |
| 히어로 아래 로고 줄 (`copy.unsupported-proof`) | 이름을 대고 확인할 수 있는 고객이 없는 신뢰 주장이다 | 실제로 쓰기 허락을 받은 로고만 둔다. 아니면 줄 자체를 두지 않는다 |
| 요금제 3열에 가운데 열 "Most popular" 배지 (`structure.pricing-default`) | 모양 자체가 기본값이라 강조가 아무 의미도 없다 | 제품에 있는 만큼 요금제를 둔다. 목표에 맞는 하나를 강조하고 이유를 쓰거나, 아무것도 강조하지 않는다 |
| 작동하는 모습을 한 번도 보여 주지 않는 제품 판매 페이지, 약관이나 개인정보 페이지도 없음 (`structure.demo-without-product`) | 뒤에 아무것도 없는 약속이다 | 실제 제품을 보여 주거나 아직 출시하지 않았다고 정직하게 밝힌다. 가입이나 결제가 있으면 실제 법적 페이지가 필요하다 |
| Product, Company, Resources, Legal 푸터 열 (`structure.ai-footer`) | 열 구성이 템플릿에서 왔다 | 사이트에 실제로 있는 링크끼리 묶는다. 반쯤 빈 네 열보다 한 열이 나을 수 있다 |
| 입력 중인 명령이 보이는 꾸민 터미널 창을 히어로로 씀 (`quality.fake-chrome`) | "개발자 도구" 분장이다 | 실제 CLI가 있으면 실제 스크린샷을 쓴다. 아니면 실제 제품 UI를 쓴다 |
| 회색 스켈레톤 막대를 "제품 화면"으로 씀 (`structure.skeleton-product-shot`) | 미완성으로 읽힌다 | 시선이 닿는 곳에 실제 문구가 있는 실제 화면을 쓴다(`references/mockup-craft.md`) |
| 템플릿 FAQ("내 데이터는 안전한가요?", "언제든 해지할 수 있나요?") (`structure.template-faq`) | 이 제품의 사용자가 묻지 않은 질문이다 | 실제 사용자 질문만 둔다. 없으면 FAQ를 두지 않는다 |
| 어두운 색이 "기술스러워" 보여서 페이지 전체를 다크로 함 (`surface.dark-default`) | 제품 결정이 아니라 유행이다 | 브랜드, 제품 유형, 대상 사용자로 테마를 고른다. 정해진 이유가 없으면 라이트와 다크를 모두 확인한 동작하는 토글을 낸다 |

## 2. 앱과 대시보드 화면

| 패턴(rule ID) | 생성된 것처럼 읽히는 이유 | 대신 |
|---|---|---|
| 제품과 무관하게 왼쪽 사이드바, 상단 바, 지표 카드 넷, 차트, 표 (`structure.dashboard-shell`) | 화면이 지원하는 일이 아니라 기억에서 고른 레이아웃이다 | 화면의 역할과 사용자가 여기서 내리는 결정 하나를 밝히고 그 둘레로 위계를 세운다(실패한 작업이 본문이고 지표 행은 각주다) |
| 지표 카드 넷(12,483 / 94.2% / $48.2K)에 초록색 "+12% this week" 증감 (`copy.unsupported-metric`) | 데이터인 척하는 장식이다. 증감은 존재하지 않는 시계열을 주장한다 | 데이터에 연결된 실제 숫자를 쓰거나 실제인 지표 하나만 둔다. 증감은 이름 붙인 실제 비교 기간이 있을 때만 붙인다 |
| "Sarah Chen님이 2시간 전에 문서를 업데이트했습니다"에 이름이 돌아가며 바뀜 (`structure.filler-feed`) | 지어낸 사람과 사건으로 빈 제품을 바쁜 것처럼 보이게 한다 | 실제 사건을 쓰거나, 먼저 무엇을 할지 말하는 정직한 빈 상태를 쓴다 |
| 공간이 허전해 보여서 "개요"라는 제목으로 넣은 차트 (`structure.chart-without-question`) | 차트는 답이다. 질문이 없으면 질감일 뿐이다 | 질문을 제목으로 쓴다("지난 24시간 시간당 실패 작업"). 문장이 더 잘 답하면 문장을 쓴다. 구간 색은 3:1 대비를 지킨다 |
| 모든 행에 점 세 개 메뉴가 붙은 Name, Status, Date, Actions 열 (`structure.generic-columns`) | 열 구성이 데이터가 아니라 표 컴포넌트에서 왔다 | 이 표에서 내리는 결정에 맞춰 열을 잡고 결정에 쓰는 필드를 앞에 둔다. 행 메뉴에는 실제로 있는 동작만 넣는다 |
| 빈 필드와 셀을 `John Doe`, `johndoe@example.com`, "Let's build something"으로 채움 (`copy.placeholder-person`) | 실제인 척하는 지어낸 내용이다 | 빈 셀은 비워 두거나 정직한 자리 표시를 쓴다. `Your name`, `email@example.com`, `[REAL DATA]` |
| "No data available"에 일러스트, 맨 스피너, 또는 데이터가 절대 채우지 않을 레이아웃의 스켈레톤 (`quality.missing-states`) | 상태는 있지만 사용자에게 아무것도 알려 주지 않는다 | 빈 상태는 이유와 그것을 채우는 동작 하나를 말한다. 로딩은 무엇을 불러오는지, 오류는 무엇이 실패했고 무엇을 할지 말한다. 첫 실행, 필터 결과 없음, 권한 거부는 서로 다른 화면이다 |

## 3. 장식

| 패턴(rule ID) | 대신 |
|---|---|
| 반짝임, 별, 마술봉, 번개, 다이아몬드, 큐브, 로봇, orb를 기능 아이콘으로 쓰고 보라색을 "AI 색"으로 씀 (`copy.ai-sparkle`) | 기능과 관련 있는 아이콘을 쓰거나 아이콘을 두지 않는다. 기능이 하는 일을 보여 준다 |
| 모든 아이콘이 같은 기본 얇은 선 라이브러리에서 옴 (`type.default-icon-set`) | 관련성, 제품의 무게와 선 굵기를 보고 세트를 고른다. 세트 선택은 결정이다 |
| 제목, 목록, 배지, 버튼의 이모지 (`copy.emoji-decoration`) | 인터페이스 텍스트에서 걷어낸다. 이유가 있는 실제 아이콘을 쓰거나 아무것도 두지 않는다 |
| 거의 모든 버튼에 붙은 화살표 (`surface.arrow-everywhere`) | 방향 단서가 필요한 동작에만 남긴다 |
| pill + 얇은 테두리 + 글로우 + 점 + 대문자 "AI Powered", "Beta", "New" (`surface.decorative-pill`) | 배지는 실제 상태에만 붙인다. 조합 전체를 쓰는 일은 없다 |
| 제목이 말하는 내용을 H1 위 pill로 반복 (`structure.repeated-eyebrow`) | 없앤다. 실제 정보는 제목이나 부제에 넣는다 |
| 아무것도 표시하지 않는 맥동하고 빛나는 점 (`surface.status-dot`, `motion.pulse-without-state`) | 점은 실제 상태에만, 글로우나 끝없는 맥동 없이 쓴다 |
| 카드나 행 왼쪽 가장자리의 얇은 색 띠 (`surface.thick-side-stripe`) | 실제 상태를 표시할 때만 남긴다 |
| Undraw, Storyset, 3D 블롭 캐릭터 (`surface.generic-illustration`) | 실제 스크린샷이나 제품에 묶인 일러스트를 쓴다 |
| 내비게이션 바, 카드, 모달, 사이드바에 한꺼번에 블러. 모든 곳의 글로우. 모든 요소의 pill 모양. 사방의 큰 그림자 (`surface.dose-exceeded`) | `rules/delivery-gate.md` §5의 사용량 상한을 따른다 |
| 사용자가 요청하지 않은 유명 제품의 겉모습을 전체적으로 베낌 (`structure.product-clone`) | 참조는 영감을 준다. 제품은 자기 정체성을 유지한다 |

## 4. 정직한 자리 표시

실제 콘텐츠가 없고 물어볼 수 없을 때는 다음과 같이 한다.

- 로고: 제품 이름을 어울리는 서체의 텍스트로 쓰거나 `[LOGO]`
- 사람: 이니셜이나 단순한 도형. 지어낸 얼굴이나 이름은 쓰지 않는다
- 숫자: 보여 주지 않거나 `[REAL DATA]`
- 미완성 기능: 제거하거나 눈에 보이는 "Coming soon" 라벨(코드 주석 포함)

지어낸 섹션보다 빈 섹션이 낫다.
