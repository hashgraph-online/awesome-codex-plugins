# 반응형 재배치

쓰기 모드가 폰부터 데스크톱까지 버텨야 하는 레이아웃을 만들거나 고칠 때, 그리고 감사 발견 사항이 중단점, 넘침, 터치 영역, 모바일 내비게이션에 관한 것일 때 읽는다. 원칙은 이렇다. 모바일 레이아웃은 데스크톱 레이아웃을 작게 줄인 것이 아니라 다른 레이아웃이다. 의도를 갖고 다시 쌓고 다시 조정하고 다시 배열한다.

## 목차

## 1. 중단점과 상태

| 징후 | 이유 | 고치기 |
|---|---|---|
| 모든 폭에 레이아웃 하나. 폰 화면은 데스크톱을 눌러 담은 것 | 카드가 부딪히고 넓은 캔버스를 전제로 쓴 텍스트가 좁은 폭에서 비좁아진다 | 내용이 버티지 못하는 지점을 진짜 모바일 상태로 정의한다. 열이 쌓이고 크기가 줄고 필요한 곳에서 순서가 바뀐다 |
| 기기 폭(375, 414, 768)을 딴 중단점 이름 | 기기는 해마다 바뀐다. 레이아웃이 내용이 아니라 스펙표를 따른다 | 뷰포트를 좁혀 가며 내용이 깨지는 지점을 보고 그곳에 중단점을 둔다 |
| 모바일 규칙을 뒤에 덧붙인 override로 붙임 | 패치는 보고된 증상만 고치고 다음 증상을 남긴다 | 좁은 폭에 자체적인 크기와 쌓기 방식을 정하고 그 폭에서 페이지 전체를 확인한다 |
| 상태가 정확히 둘: 폰용 쌓기와 넓은 그리드 | 태블릿과 작은 노트북 폭(약 600-1024px)이 늘어난 쌓기나 빽빽한 그리드를 물려받는다 | 내용이 요구하는 만큼 상태를 둔다. 보통 단일 열, 두 열, 전체 그리드 순서다 |

## 2. 크기와 치수

| 징후 | 이유 | 고치기 |
|---|---|---|
| 데스크톱 패딩, 간격, 히어로 높이, 카드 크기를 폰에도 유지 | 1440px에서 자신감 있게 읽히는 값이 375px에서는 화면을 압도한다 | 타이포, 패딩, 간격에 더 작은 모바일 단계를 쓴다. 터치 영역은 최소값을 지킨다 |
| 변하지 않는 고정 px 글자 크기 | 제목이 폰 전체를 차지하고 본문 행 길이는 넓은 화면에 맞춰져 있다 | `clamp()`로 유동 타이포를 쓰거나 중단점에서 더 작은 타이포 단계를 쓴다 |
| `100vh` 섹션 | 모바일에서 브라우저 크롬까지 포함해 보이는 영역을 넘고 내용을 접힌 아래로 밀어낸다 | 내용에 맞춰 높이를 잡거나, 전체 높이 섹션이 의도라면 `100dvh`를 쓴다 |
| 데스크톱 섹션 패딩(96-128px)을 모바일에도 유지 | 페이지가 빈 공간을 지나며 스크롤된다 | 모바일 단계에서는 절반이나 그 이하로 줄인다 |

## 3. 그리드와 쌓기

| 징후 | 이유 | 고치기 |
|---|---|---|
| 나란한 열이 폰에서도 나란히 유지 | 열마다 가느다란 조각이 되고 텍스트 줄바꿈이 엉키고 카드가 겹친다 | 중단점에서 한 열로 무너뜨린다 |
| 고정 px의 `grid-template-columns` | 트랙이 폭을 유지해 넘침을 강제한다 | `auto-fit`이나 `auto-fill`을 붙인 `minmax()`, 무너지는 그리드 영역을 쓴다 |
| 한 열짜리 내용에 12열 그리드를 강제 | span이 보이지 않는 그리드의 임의 분수가 된다 | 내용을 따라 열을 정한다. 폰에서는 한 열, 많아야 두 열 |

## 4. 넘침

| 징후 | 이유 | 고치기 |
|---|---|---|
| 표, 코드 블록, 이미지, 긴 문자열이 뷰포트보다 넓어 페이지가 옆으로 스크롤됨 | 사용자가 페이지가 어디서 끝나는지 볼 수 없다. 데스크톱 미리보기에서는 보이지도 않는다 | 넓은 요소를 찾는다. 미디어에 `max-width: 100%`, 코드 줄바꿈, 재배치하거나 스크롤로 감싼 표. 가장 좁은 폭에서 가로 스크롤이 없어야 한다 |
| 좁은 폭이나 200% 확대에서 `overflow: hidden`이 텍스트나 컨트롤을 잘라 냄 | 실패를 숨기고 내용을 없앤다 | 컨테이너가 늘어나거나 줄바꿈하거나 무너지게 둔다. 썸네일처럼 의도한 자르기에만 clip을 쓴다 |
| 고정 px `width`나 `min-width`를 가진 flex·grid 자식 | 자식이 데스크톱 크기를 유지해 밖으로 터진다 | 상대 폭, `flex-wrap`, grid·flex 자식의 `min-width: 0`을 쓴다 |

## 5. 터치 영역

| 징후 | 이유 | 고치기 |
|---|---|---|
| 터치 최소값보다 작은 컨트롤 | 엄지는 커서가 아니다 | WCAG 2.2 AA는 24×24 CSS px을 요구한다. 터치 표면에서는 44×44(Apple 기본값, WCAG AAA)나 Android의 48×48 dp를 목표로 한다. 보이는 크기가 작으면 패딩이나 더 큰 히트 박스를 쓴다 |
| 간격 없이 붙여 놓은 큰 타깃 | 맞닿은 두 컨트롤이 하나처럼 동작한다 | 하나의 누름 영역이 다음 컨트롤을 덮지 않게 간격을 둔다 |
| hover에서만 존재하는 메뉴, 펼침, 툴팁 | 터치스크린에는 hover가 없다 | 모든 hover 상호작용에 탭 대응을 두고 `:active` 피드백을 보이게 한다 |

## 6. 모바일 내비게이션

| 징후 | 이유 | 고치기 |
|---|---|---|
| 데스크톱 링크 행을 폰에서도 유지 | 링크가 빽빽해지고 줄바꿈되거나 가장자리 밖으로 넘친다 | 중단점에서 접는다. 주요 목적지 몇 개는 하단 바에, 나머지는 메뉴에 넣는다 |
| 아무 표시 없는 햄버거 아이콘이 전부를 숨김 | 사용자가 메뉴가 있는지, 무엇이 들었는지 모를 수 있다 | 라벨을 붙이거나("메뉴"), 주요 목적지는 보이게 두고 보조 목적지만 숨긴다 |
| 고정 하단 바가 마지막 항목이나 마지막 버튼을 덮음 | 내용이 바 아래로 스크롤되어 닿을 수 없게 된다 | 패딩과 `env(safe-area-inset-bottom)`으로 바 높이를 확보한다 |
| 높은 고정 머리말이 화면을 크게 차지 | 내용이 레터박스가 된다 | 고정 크롬을 작게 유지한다. 적절하면 스크롤할 때 줄이거나 숨긴다 |

## 7. 검증

샘플 폭 두 개가 아니라 전체 범위로 뷰포트를 끌어 보며 확인한다. 확인한 폭, 가장 좁은 폭의 가로 스크롤 결과, 고정 바 아래에서 닿을 수 있는 마지막 항목을 기록한다. 렌더 캡처가 없으면 이 항목은 `static_only`다.
