# 연출 화면 제작

`mockup` 모드에서 읽는다. 연출 화면(mockup)은 제품을 보여 주는 일러스트로, 프로젝트 자체 스택(HTML과 CSS, 또는 기존 컴포넌트 프레임워크)으로 만들고 정지 화면이나 애니메이션으로 둔다. 동작하는 클라이언트도, 브라우저 자동화도 아니며 실서비스를 호출하지 않는다.

## 목차

- 1. 아이디어
- 2. 다섯 가지 실패 유형
- 3. 코드보다 계획
- 4. 화면
- 5. 프레이밍
- 6. 아이콘, 표식, 색
- 7. 모션과 커서
- 8. 검증

## 1. 아이디어

연출 화면은 실제 제품처럼 읽히되 보는 사람에게 필요한 만큼 단순하고 의도를 담아 프레이밍하며 모든 모션에 원인이 있다. 문장을 단순화하고 맥락은 단순화하지 않는다. 차분한 중성색 위에 구조를 갖춘 온전한 화면을 두고 이야기의 중심이 되는 곳에만 실제 문장을 쓰고 나머지는 placeholder 줄로 채운다.

## 2. 다섯 가지 실패 유형

| 실패 | 나타나는 모습 | 해결 |
|---|---|---|
| 과다 | 모든 행에 실제 텍스트, 곳곳에 숫자 | 실제 문자열 수를 세고 나머지를 placeholder 막대로 바꾼다 |
| 와이어프레임 | 회색 블록 둘과 버튼 하나 | 화면에 온전한 구조(내비게이션, 패널, 행)를 준다 |
| 상자에 가둠 | 창 전체를 고른 여백으로 카드에 축소 | 창을 잘라 한두 모서리로 넘치게 한다 |
| 평평함 | 모든 객체가 같은 테두리 카드 안에서 같은 무게 | 중심 객체 하나를 두고 보조 객체는 더 가볍고 작게 |
| 무미건조 | 브리프와 무관한 회색 창과 커서 | 제품 고유의 모습과 브리프가 말하는 행동 하나를 보여 준다 |

## 3. 코드보다 계획

`brief.md`에 다음을 쓴다.

1. 매체와 위치: 정지 또는 애니메이션(루프, 화면에 들어올 때 한 번, hover 시); 표시될 슬롯 크기.
2. 겉모습: 제품 토큰(캔버스, 표면, 텍스트 수준, 선, 강조색, 반경, 컨트롤과 행 높이)을 매핑한다; 팔레트를 지어내지 않는다.
3. 이야기(애니메이션만): 세에서 다섯 비트와 결말; 이유 없는 커서 이동 금지; 화면에서 원인 없이 데이터가 되감기지 않는다.
4. 행동 하나와 생략한 것.

보이는 크기로 설계한다. 좁은 모바일 슬롯은 데스크톱을 축소한 것이 아니라 자체 압축 레이아웃을 갖는다.

## 4. 화면

| 규칙 | 값 |
|---|---|
| 실제 문자열 | 약 3에서 7개: 제목, 행동의 대상, 입력되는 것, 결과 |
| placeholder 막대 | 시선이 머무는 곳에서만 멀리 두고 폭은 행마다 다르게(예: 60, 45, 70, 52%) |
| UI 텍스트 | 실제 크기 기준 11-15px, 무대와 함께 확대; 읽을 수 없을 만큼 작게 쓰지 않는다 |
| 작은 텍스트의 행간 | 최소 1.3 |
| 텍스트 안쪽 여백 | 창, 카드, 패널, hover 행 가장자리에서 약 12px; 8px 미만은 결함 |
| 행 안쪽 여백 | 12px, 촘촘한 목록은 8px |
| 큰 숫자 | 숫자 하나는 크게 써도 된다; 숫자와 단위가 따로 줄바꿈되지 않는다 |
| 패밀리와 대소문자 | 패밀리 하나; 문장형 대소문자 |
| 제목 | 연출 앱의 제목은 호스트 페이지의 문서 제목(`h1`-`h6`)이 아니다 |
| 정렬 | 거의 접하는 선을 만들지 않는다: 가장자리는 정렬되거나 확실히 떨어지며 1-3px 정도 어긋나지 않는다 |

## 5. 프레이밍

- 중심 객체 하나, 위성 객체는 최대 둘이며 위성끼리 서로 다른 종류다.
- 중심 객체의 약 10-40%를 무대 밖으로 잘라 낸다; 중심 객체는 무대 폭의 최소 3분의 2를 채우고 한쪽 모서리로 넘친다.
- 거터 하나를 최종 크롭에서 잰다; 몇 픽셀 어긋난 거터는 실수로 읽힌다.
- 흰 페이지의 창 뒤에 판을 깔지 않고 죽은 모서리를 두지 않으며 중심 객체를 가리키려고 테두리를 두르지 않는다(아무도 주지 않은 포커스 상태로 읽힌다).
- 창은 기기 모양을 유지한다; 플랫폼 크롬(상태 표시줄, 홈 인디케이터, 창 컨트롤)을 기억으로 그리지 않는다: 스크린샷이나 프로젝트 자산에서 플랫폼의 실제 비율을 가져온다.

## 6. 아이콘, 표식, 색

- 아이콘은 세트 하나, 선 굵기 하나, 크기 하나(UI에서 약 14-16px)에서 온다; 손으로 그린 글리프를 쓰지 않는다; 작은 아이콘은 채우고 색은 하나만 쓴다.
- 이모지는 콘텐츠이지 아이콘이 아니다.
- AI 기능에는 반짝임, 마술봉, 별 아이콘과 보라색 "AI 색"을 쓰지 않는다; 기능이 하는 일을 보여 준다.
- 로고를 지어내지 않는다: 색 사각형 안의 글자는 제품의 표식이 아니다. 프로젝트에 있는 제품의 실제 표식이나 제품 글꼴의 평범한 워드마크를 쓴다. 제3자 상표와 앱 아이콘을 재현하지 않는다.
- 잉크 수준 몇 개와 강조색 하나; 그라디언트나 글로우는 이야기에 기여하거나 빠지며 반투명 요소가 다른 내용과 겹치지 않는다.

## 7. 모션과 커서

| 규칙 | 값 |
|---|---|
| 루프 길이 | 중심 루프는 10-16초 |
| 시차 | 읽기 순서로 관련 항목 사이 40-80 ms |
| 결말 | 약 2초 유지; 아무것도 약 3초를 넘겨 멈춰 있지 않는다 |
| 속도 | UI 피드백은 실제 제품만큼 빠르게 유지한다; 이야기 전달 모션만 느려진다 |
| 연속성 | 루프가 내비게이션을 거꾸로 재생하지 않는다; 다음 행동은 이음매에서 약 1초 안에 시작한다 |
| 변화 | 바뀐 것만 바꾼다; 단단한 객체가 서로를 지나며 페이드되지 않는다; 툭 나타나는 요소가 없다 |
| 커서 | 다음 행동으로 이동한다; 클릭하는 글자를 가리지 않는다; 요소 가장자리에서 종류가 바뀐다; 잠시 머문 뒤 흐려진다 |
| 모션 감소 | 결말 프레임을 정지 화면으로 보여 준다 |

## 8. 검증

- 정지 화면이나 포스터 프레임을 먼저 정한다; 그것만으로 이야기가 전달되어야 한다.
- 무대를 표시 폭과 좁은 폭에서 캡처한다; 모든 질문은 코드가 아니라 직접 본 프레임으로 답한다.
- §2의 실패 유형을 체크리스트로 삼아 독립 검토(`rules/independent-review.md`)를 실행한다.
- 가장 크게 보이는 실패부터 고치고 다시 캡처하며 예산 안에서 반복한다.
