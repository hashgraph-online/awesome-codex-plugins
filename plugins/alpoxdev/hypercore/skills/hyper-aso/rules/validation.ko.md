# ASO 검증

**목적**: ASO 실행 완료를 선언하기 전의 품질 점검.

## 리포트 완전성

- [ ] 범위 블록에 앱, 스토어 식별자와 URL, 스토어, 로캘, 앱 상태, 모드, 증명 표면이 있음
- [ ] 모든 발견사항에 심각도, 스토어, 카테고리, 증거, 증거 등급, 확신도, 구체적 개선안이 있음
- [ ] 발견사항이 여덟 개 점수 카테고리로 묶이고 영향 순으로 우선순위화됨
- [ ] 요약에 측정한 카테고리 기준 점수가 있거나 비교 가능한 점수가 없는 이유가 명시됨
- [ ] 새 앱 버전이 필요한 실행안은 그렇게 표시됨

## 커버리지 점검

### Simple 실행

- [ ] 요청받은 표면을 범위 내 모든 스토어와 로캘에서 읽음
- [ ] `report.md`와 `sources.md`가 `.hyper/aso/[slug]/` 아래에 저장됨

### Complex 실행

- [ ] `rules/aso-workflow.md`의 모든 단계가 완료됐거나 사유와 함께 건너뛴 것으로 기록됐고 `flow.json`이 최신임
- [ ] 메타데이터: 스토어와 로캘별 모든 텍스트 필드와 스토어 단위로 센 길이
- [ ] 크리에이티브: 아이콘, 필수 기기 클래스별 스크린샷 세트, 미리보기나 프로모션 영상, 피처 그래픽
- [ ] 전환 도구: 맞춤 페이지나 등록정보, 실험, 이벤트나 프로모션 콘텐츠를 조사함
- [ ] 평점: 스토어프런트별 평점과 수에 날짜를 붙임, 요청 구현, 응답 커버리지
- [ ] 품질: 바이탈, 크래시, 크기 데이터를 읽었거나 `unknown`으로 표시함
- [ ] 정책 위험과 웹-앱 연결을 점검함
- [ ] `results.json`이 `assets/runtime/check-results.jq`를 통과하고, 마지막 편집 뒤 `results.js`와 `dashboard.html`을 다시 생성함

### Setup 모드

- [ ] `report.md`가 `rules/aso-workflow.md` §8의 일곱 setup 단계를 따르고, 모든 항목이 `done`, 소유자가 붙은 `planned`, `not-applicable`, 빠진 접근 권한을 밝힌 `unknown` 중 하나임
- [ ] 제안한 모든 필드가 한도에 맞고 센 길이가 표시됨
- [ ] 콘솔 단계는 정확한 값으로 준비해 두고, 권한을 받지 않은 한 소유자에게 남김

## 한도와 출처 점검

- [ ] 리포트에 적은 모든 글자 수, 바이트, 크기, 개수, 기간, 임계값이 `references/policy-limits.md` 또는 이번 실행에서 다시 연 출처의 확인 날짜와 일치함
- [ ] Apple 키워드 필드 제안을 UTF-8 바이트로 세었고, 로캘이 다중 바이트 문자를 쓰면 바이트와 글자의 충돌을 밝힘
- [ ] `sources.md`가 외부 주장마다 URL, 접근 날짜, 적용 주장, 증거 등급, 한계를 기록했고 날짜가 실행 날짜보다 늦지 않은 절대 날짜임
- [ ] 벤더 추정치(인기도, 검색량, 난이도, 벤치마크)에 벤더, 척도, 날짜가 붙음

## 증거 규율

- [ ] `official`, `live`, `console`, `tool`, `synthetic`, `heuristic` 증거에 라벨이 붙고 라벨 없이 섞이지 않음
- [ ] 기록된 측정 없이 순위, 검색량, 전환율, 평점, 다운로드 수를 적지 않음
- [ ] 벤더 주장을 Apple이나 Google 규칙으로 제시하지 않음(iOS 설명 색인, 캡션 OCR, 키워드 밀도)
- [ ] 콘솔 지표는 같은 정의(Play의 2026년 클릭률 전환)와 같은 기간 안에서만 비교함
- [ ] 실험 결과는 스토어 자체가 보고한 상태로만 보고함
- [ ] 어떤 개선안도 도배, 경쟁사나 무관한 브랜드명, 순위나 가격 주장, 보상이나 조건부 평점 요청을 쓰지 않음
- [ ] 콘솔, 도구, 라이브 접근이 없는 경우 신뢰 한계로 밝힘

## Optimize Mode Checks

- [ ] `score_history[0]`이 기준선이고 어떤 변경보다 먼저 기록됨
- [ ] 모든 반복이 점수, 결정(`kept`, `discarded`, `reset`), 평가자 버전, 변경, 증거를 기록함
- [ ] 미해결 스토어 실험을 기다리는 반복은 pending으로 보고하고 `kept`가 아님
- [ ] `best_run`이 유지된 반복이나 기준선 중 점수가 가장 높은 것을 가리킴
- [ ] 각 반복이 필드 하나, 에셋 세트 하나, 실험 계획 하나만 바꿈
- [ ] 중단 사유가 목표, 예산, 정체, 가드 실패, 소유자 전용 단계, 사용자 중단 중 하나임
- [ ] 완료 시 `ship`, `iterate`, `caveated ship`, `block` 중 하나를 잔여 위험과 함께 기록함

## Severity Guide

| 심각도 | 기준 | 예시 |
|---|---|---|
| **critical** | 정책 위반, 필수 에셋 세트 누락, 한도 초과 필드, 확인된 발견 가능성 차단 | Play 제목의 순위 주장, 100바이트를 넘는 키워드 필드 |
| **warning** | 관측이나 콘솔 증거로 뒷받침되는 검색 커버리지 또는 전환의 실질 손실 | 이름, 부제, 키워드 필드에 반복되는 단어, 주 로캘에 현지화 스크린샷 없음 |
| **info** | 선택적 개선, 확신도 낮은 휴리스틱, 실험 아이디어 | 혜택을 앞세운 첫 스크린샷 테스트 |
