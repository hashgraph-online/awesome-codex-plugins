# 시안은 근거 자료

이미지를 검토하기 전과 인계를 쓰기 전에 이 규칙을 읽습니다. 생성한 시안은 의도를 그린 그림입니다. 이 규칙은 그 그림을 어디까지 믿어도 되는지, 코드에서 무엇을 교체해야 하는지, 한국어 글자를 어떻게 다루는지, 어떤 접근성 점검을 어디서 하는지를 정합니다.

## 1. 시안이 증명하는 것

| 이미지가 근거가 되는 것 | 이미지가 근거가 되지 않는 것 |
|---|---|
| 어떤 영역이 있고 순서가 어떤지 | 정확한 픽셀 크기, 간격 값, 글꼴 수치 |
| 무엇을 강조하고 주 동작이 무엇인지 | 실제 문구, 실제 데이터, 실제 브랜드 마크 |
| 어떤 컴포넌트가 나오고 어떻게 묶이는지 | 동작, 상태, 모션, 반응형 |
| 토큰 아래에서의 전체 밀도와 톤 | 대비 값이나 터치 대상 크기 |

검토 항목마다 세 라벨 중 하나를 붙이고, 표현으로 라벨을 올리지 않습니다.

- `seen`: 반환된 이미지에서 관찰한 것.
- `computed`: 그림이 아니라 토큰 값에서 계산한 것.
- `not checkable in an image`: 그림으로는 보여 줄 수 없는 것. 인계 요구사항이 됩니다.

## 2. 이미지 속 글자, 숫자, 마크

- 이미지는 완성된 콘텐츠를 보여 주고, 그중 어느 것도 콘텐츠가 아닙니다. 모든 문자열, 숫자, 날짜, 이름은 코드에서 사용자의 문구로 교체하기 전까지 샘플 데이터입니다. 올바르게 렌더링된 것도 마찬가지입니다.
- 이미지의 모든 숫자, 차트 값, 날짜, 가격, 이름, 아바타는 지어낸 것이고 샘플 데이터로 나열합니다. 지어내되 현실적이어야 하고, 지어내되 빠뜨리면 안 됩니다.
- 이미지의 모든 로고, 앱 아이콘, 일러스트, 사진은 대역입니다. 코드에서는 프로젝트 자체 에셋이나 사용자가 쓸 권리가 있는 에셋으로 교체합니다.
- 이미지의 아이콘은 아이콘이 놓일 자리와 뜻을 보여 줍니다. 구현은 프로젝트의 아이콘 세트를 씁니다.
- 인계는 이 교체 대상을 표로 나열해 이미지의 어떤 것도 콘텐츠로 옮겨 적히지 않게 합니다.

중요한 구분은 이것입니다. 시안은 밀도와 위계와 정렬을 보여 주려면 완성돼 보여야 하고, 동시에 코드에서 교체할 대상으로 취급받아야 합니다. 콘텐츠가 빠진 시안은 밀도 자체를 보여 줄 수 없으므로 교체되기 전에 이미 근거로서 실패한 것입니다.

## 3. 한국어 글자 렌더링

생성 이미지는 한글을 잘 렌더링하지만 완벽하지는 않고, 틀린 음절도 얼핏 보면 맞아 보입니다. 이 패키지의 모델에서 측정한 동작은, 완성된 한국어 화면이 전부 읽히게 돌아오고 화면당 틀린 음절이 기껏해야 한두 개라는 것입니다. 이것은 브리프가 글자 대신 막대를 쓰게 만들었던 실패보다 훨씬 나은 상태입니다.

호출 전에는 다음과 같이 합니다.

- 화면이 보여 주는 모든 문자열을 실제 길이와 철자 그대로 렌더링합니다. 화면을 몇 개 라벨로 줄이지 않습니다. 라벨이 없는 화면은 검토할 밀도가 없습니다.
- 사용자의 실제 문구가 있으면 그것을 씁니다. 없으면 평이한 작업용 문구를 쓰고 메모에 `working copy`로 표시합니다.
- 본문 줄은 문단이 아니라 실제 화면이 쓰는 길이의 완결된 문장으로 씁니다. 블록당 세 줄 제한이면 모델이 문단을 지어내지 않습니다.
- 렌더링할 문자열은 한 번씩 따옴표 안에 역할과 화면 위 자리와 함께 적고, 몇 번 나오는지 밝힙니다.
- 모든 숫자, 날짜, 금액을 브리프 안에 문자 그대로 적습니다.

호출 뒤에는 다음과 같이 합니다.

- 이미지의 모든 문자열을 브리프와 한 글자씩 대조합니다. 중요한 것만 골라 보지 않습니다. 판정은 `정확 n/m`으로 적고, `m`은 브리프가 언급한 개수가 아니라 화면이 보여 주는 모든 문자열의 수입니다.
- 빠지거나 더해지거나 모양이 깨진 음절은 그 문자열에 대한 `fail` 하나입니다. 화면의 나머지가 맞다는 이유로 통과가 되지 않습니다.
- 실패하면 틀린 문자열의 철자를 고치거나 자리를 옮겨 재생성하고, 브리프의 나머지는 그대로 둡니다. 이미지를 덧대어 고치지 않습니다.
- 상한에 닿았는데 문자열이 여전히 틀리면 이미지는 레이아웃용으로 남기고, 그 문자열을 틀린 철자와 올바른 철자를 함께 `not rendered correctly`로 기록하고, 올바른 문자열을 인계의 문구 표에 싣습니다. 글자는 처음부터 콘텐츠가 아니었으므로 시안은 여전히 쓸 수 있습니다.

## 4. 접근성 점검

그림으로는 증명할 수 없어서 여기서 계산하거나 명시하는 점검이 두 가지 있습니다.

대비는 WCAG 대비율 공식으로 토큰에서 계산합니다.

| 쌍 | 최소 |
|---|---|
| 배경 위 본문 글자 | 4.5:1 |
| 배경 위 큰 글자(18포인트 이상, 또는 굵은 14포인트 이상) | 3:1 |
| 채워진 버튼, 배지, 색이 있는 표면 위 글자 | 글자 크기에 따라 위와 같음 |

- 첫 브리프 전에 두 테마의 모든 글자와 배경 쌍을 계산하고 비율을 메모에 `computed`로 기록합니다.
- 반환된 이미지에서 색을 추출하지 않습니다. 생성 이미지는 토큰 값을 정확히 재현하지 않습니다.
- 사진이나 그라데이션 위에 놓는 글자는 뒤에 단색이나 스크림 층을 두도록 명시하고, 그 층을 기준으로 쌍을 계산합니다.

터치와 포인터 대상은 인계에 요구사항으로 적습니다.

| 대상 화면 | 요구사항 |
|---|---|
| 웹 | 모든 포인터 대상이 최소 24×24 CSS px(WCAG 2.2 AA). 주 동작은 44×44 CSS px를 목표로 함(AAA) |
| iOS와 iPadOS | 기본 컨트롤 크기 44×44 pt |
| Android | 터치 대상 최소 48×48 dp |

이미지에서 `seen`으로 확인할 것도 있습니다.

- 상태를 색만으로 전달하지 않습니다. 오류, 선택, 필수 입력란에는 글자, 아이콘, 모양도 함께 있습니다.
- 화면마다 주 동작이 하나이고 보조 동작과 눈에 띄게 구분됩니다.
- 읽는 순서가 위에서 아래로 가는 시각 순서를 따릅니다.

## 5. 인계에 담는 것

메모의 인계 섹션은 구현자가 받는 내용입니다. 다음을 담습니다.

| 부분 | 내용 |
|---|---|
| 계약 | 영역 순서, 위계, 컴포넌트 목록, 토큰 |
| 계약이 아닌 것 | 이미지에서 잰 픽셀 값, 렌더링된 글자, 숫자, 로고, 아이콘, 사진 |
| 문구 표 | 영역, 코드에 쓸 문자열, 그 상태(`user copy`, `working copy`, `needed from user`) |
| 보이지 않는 상태 | 로딩, 비어 있음, 오류, 비활성, 포커스, 긴 글자, 흐름에 필요한 그 밖의 상태 |
| 접근성 요구사항 | 계산한 대비 쌍과 플랫폼의 대상 크기 |
| 열린 질문 | 시안이 정하지 못한 결정. 예를 들어 크기 사이의 반응형 동작 |

구현자는 계약과 프로젝트 자체 컴포넌트로 만듭니다. 그림과 토큰이 어긋나면 토큰을 따릅니다.

### Evidence grade

근거 표, 세 라벨, 한국어 렌더링 절차는 `LOCAL`입니다. 한글 렌더링이 불안정하다는 서술은 측정한 비율이 아니라 이 패키지의 작업 가정이고, 런타임이 한글을 잘 렌더링해도 절차는 그대로 유효합니다. WCAG, Apple, Android 값은 `PRIMARY`이고 위 날짜에 읽었습니다.
