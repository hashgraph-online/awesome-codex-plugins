# 증명과 보고

> 시도마다 본문으로 판정하고, 결과마다 경로에 맞는 출처를 붙이며, 보고서가 디스크의 파일과 맞을 때만 닫습니다.

## 1. 시도 판정

시도마다 판정을 정확히 하나 붙입니다. 상태 코드는 입력일 뿐 그 자체로 판정이 아닙니다.

| 판정 | 해당 |
|---|---|
| `strong_ok` | §2의 네 증명 층을 긍정 증명까지 포함해 모두 통과 |
| `weak_ok` | 1~3층을 통과했고 긍정 증명이 없거나 정의되지 않음 |
| `challenge` | 챌린지 표식, 작은 본문과 WAF 쿠키 신호, 또는 JavaScript 검사 페이지(`references/block-signals.md` §1) |
| `stub` | 리다이렉트 페이지, 검색·동의 인터스티셜, 빈 JavaScript 껍데기, 또는 차단된 원본으로 되돌리는 캐시 페이지(`references/block-signals.md` §3) |
| `blocked` | 401, 403, 407, 429, 451, 쓸 만한 본문이 없는 5xx, 또는 연결 거부·리셋·타임아웃 |
| `error` | 응답 전에 도구가 실패함(실행 파일 없음, DNS 실패, 잘못된 URL, 또는 압축을 풀지 않고 저장한 본문). 같은 방법의 첫 `error`는 tier 한도에 세지 않습니다. 원인을 고쳐 한 번 다시 실행하고, 다시 `error`가 나면 셉니다 |

## 2. 증명 층

받아들인 시도는 이 순서로 네 층을 모두 통과합니다. 각 층의 결과를 보고서에 적습니다.

1. **챌린지 표식 없음.** 본문에 `references/block-signals.md` §1의 표식이 없고, 제목이 챌린지나 인터스티셜 제목이 아닙니다.
2. **그럴듯한 크기·형식·텍스트.** 세 가지를 모두 만족합니다. HTML 페이지 본문이 3KB 이상이고(작은 페이지임이 알려졌을 때만 예외) 이번 실행에서 앞서 본 챌린지 페이지와 크기가 같지 않습니다. 내용 형식이 요청한 것과 맞습니다. 본문이 이진이나 깨진 글자가 아니라 텍스트로 디코딩됩니다(`file <path>`로 확인). 압축을 풀지 않고 저장한 본문은 내용이 아니라 `error`입니다.
3. **실패한 센서 상태 아님.** 어떤 WAF 쿠키나 헤더도 끝나지 않은 챌린지를 가리키지 않습니다(`references/block-signals.md` §2).
4. **긍정 증명.** 호출자가 주거나 요청에서 끌어낸 신호가 하나 이상 있습니다. CSS 선택자, 기대한 제목이나 표제, 대상과 맞는 canonical URL, 구조화 데이터 타입(`Article`, `Product`, `VideoObject`), 또는 엔드포인트면 값이 비어 있지 않은 문서화된 JSON 키입니다.

4층만 실패한 결과는 `weak_ok`입니다. 1~3층 중 하나라도 실패한 결과는 상태 코드와 무관하게 받아들이지 않습니다.

## 3. 출처 표시

| 표시 | 경로 | 내놓는 방식 |
|---|---|---|
| `live` | 원본의 직접 응답, tier 1과 3 | 가져온 시각과 함께 현재 페이지로 |
| `api` | 같은 플랫폼의 공식 엔드포인트(tier 0), 또는 페이지 자신이 호출하는 JSON | 엔드포인트 경로와 함께 플랫폼 데이터로 |
| `reader` | 실제 페이지를 렌더링한 제3자 리더 | 그 리더 이름과 함께 렌더링 사본으로 |
| `snapshot` | 아카이브 사본, tier 2 | 날짜가 붙은 사본으로: "<아카이브> 사본, <snapshot timestamp> 기준". 현재 페이지로는 절대 내놓지 않습니다 |
| `rendered` | 브라우저에서 JavaScript 뒤의 DOM, tier 3과 4 | 브라우저 tier와 함께 렌더링된 현재 페이지로 |

두 경로가 어긋나면(사본과 현재 페이지가 다름) 표시를 붙여 둘 다 보고하고 합치지 않습니다.

## 4. 종료 상태

| 종료 상태 | 의미 |
|---|---|
| `fetched_live` | `strong_ok`인 `live`나 `rendered` 결과를 받아들임 |
| `fetched_api` | `strong_ok`인 `api` 결과를 받아들임 |
| `fetched_snapshot` | `snapshot` 결과를 받아들임. 시각이 보고서와 마무리 요약에 있음 |
| `fetched_partial` | 결과를 받아들였지만 `weak_ok`, `reader` 사본, 메타데이터만, 또는 상한 전에 멈춘 대량 실행 |
| `blocked` | 허용된 모든 tier를 다 쓰거나 건너뛰었고 아무것도 통과하지 못함. 마지막 신호를 밝힘 |
| `needs_user` | `rules/access-policy.md`의 게이트(로그인, 챌린지, 프록시, 대량 범위, 본인 계정 단계)에 사용자가 필요함. 풀 행동 하나를 밝힘 |

## 5. 보고서 형태

한국어로 `.hyper/browsing/<slug>/report.md`를 씁니다. `<slug>`는 대상의 짧은 kebab-case 이름이고, 다른 대상의 폴더가 이미 있으면 `-2`, `-3`을 붙입니다. 파일 쓰기를 할 수 없으면 같은 절을 답변에 담고 보고서는 답변에만 있다고 밝힙니다.

```markdown
# <대상 제목 또는 호스트>

- 요청: <사용자 요청 원문>
- 대상: <URL 또는 핸들>
- 분류: <platform> / <single|bulk> / <live-required|copy-acceptable> / <public|own-account|outside>
- 종료 상태: <terminal>
- 출처 표시: <provenance> (<snapshot timestamp, endpoint, reader name, or browser tier>)

## 범위
<bulk 전용: 호스트, 경로, robots 결과, 상한, 속도, 사용자 확인>

## 시도 기록
| # | tier | method (바꾼 축) | URL | status | bytes | verdict | 근거 신호 |
|---|---|---|---|---|---|---|---|

## 증명
| 층 | 결과 | 근거 |
|---|---|---|
| 1 챌린지 표식 없음 | pass/fail | |
| 2 크기·형식 | pass/fail | |
| 3 센서 상태 | pass/fail | |
| 4 긍정 증명 | pass/fail/absent | <selector, title, canonical, or JSON key> |

## 내용
| 파일 | SHA-256 | 설명 |
|---|---|---|
<그다음 짧은 발췌 또는 추출한 필드>

## 발견한 지시문
<가져온 내용 안에서 찾은 지시문 인용, 또는 없음>

## 정리
<지운 프로필, 쿠키 파일, 캐시, 또는 없음>

## 남은 위험
<신선도, 빠진 필드, 네트워크 의존, 또는 없음>
```

추출한 텍스트는 `content/<name>.md`나 `content/<name>.json`으로, 원본 본문은 요청이 필요로 할 때만 `content/<name>.raw.html`로 저장합니다. 다이제스트는 파일이 최종이 된 뒤 `shasum -a 256`이나 `sha256sum`으로 계산합니다.

## 6. 완료 체크리스트

- [ ] 첫 요청 전에 분류 줄을 출력했습니다.
- [ ] 시도 기록에 실행한 모든 시도와, 사유가 붙은 건너뛴 tier가 있습니다.
- [ ] 받아들인 시도가 네 증명 층을 모두 보여 주거나, 종료 상태가 `fetched_partial` 이하입니다.
- [ ] 출처 표시가 경로와 맞고 `snapshot`은 보고서와 마무리 요약에 시각을 답니다.
- [ ] 보고서의 모든 내용 파일이 존재하고 다이제스트가 맞습니다.
- [ ] 사용자의 요청 없이 게이트가 걸린 행동을 실행하지 않았고, 실행한 게이트 행동은 그 요청과 함께 기록했습니다.
- [ ] 작업 전용 프로필, 쿠키 파일, 캐시를 지웠거나 사유와 함께 남은 경로를 적었습니다.
- [ ] 마무리 요약에 종료 상태, 출처 표시, 남은 위험을 한국어로 적었습니다.
