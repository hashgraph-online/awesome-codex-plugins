# 브라우저 Tier

> Tier 3과 4: 실행이 직접 띄우고 버리는 브라우저, 또는 사용자 본인 계정을 위한 사용자 자신의 브라우저. 세션을 복사하는 방식은 쓰지 않습니다.

## 1. 기능 확인

tier 3 전에 런타임이 어떤 브라우저 기능을 노출하는지 찾습니다. 런타임이 이미 제공하는 브라우저 자동화 도구나 라이브러리, 또는 이미 설치된 헤드리스 브라우저 실행 파일 중 하나이며, 이번 실행을 위해 새로 설치하지 않습니다. 그 이름과 판을 보고서에 적습니다. 없으면 tier 3·4를 `skipped`로 표시하고 `blocked`나 `fetched_partial`로 끝냅니다. 추론만으로 페이지를 렌더링했다고 설명하지 않습니다.

## 2. Tier 3: 자체 브라우저

1. `.hyper/browsing/<slug>/profile/` 아래에 새 프로필 디렉터리를 만듭니다. 브라우저를 사용자 자신의 프로필로 향하게 하지 않습니다.
2. 런타임 자체의 브라우저 기능으로 헤드리스부터 띄웁니다. 별도 브라우저 빌드를 설치하거나, 스텔스 스크립트를 주입하거나, `navigator.webdriver`를 손으로 덮지 않습니다. 런타임 브라우저가 통과하지 못하는 챌린지는 tier를 끝냅니다.
3. 한 번 탐색하고 네트워크가 잦아들 때까지, 또는 최대 10초 기다린 뒤, 텍스트로 답이 되는 요청이면 스크린샷이 아니라 텍스트나 접근성 스냅숏으로 읽습니다.
4. 내용이 데이터일 때는 페이지 자신의 네트워크 요청을 잡아 JSON 호출(`/api/`, `/graphql`, `.json`)을 찾습니다. JSON URL을 tier 1로 다시 요청하고, 플랫폼 자신의 호출이면 출처 `api`로 기록합니다.
5. 새로 고침 한 번과 10초 대기 뒤에도 남는 챌린지는 tier를 끝냅니다. 사람의 행동을 요구하는 챌린지는 `rules/access-policy.md` §4로 넘깁니다.
6. 스크린샷은 요청이 필요로 할 때만 찍고 `content/` 아래에 저장합니다.
7. `finally` 단계에서 브라우저를 닫고 프로필 디렉터리를 지우며 삭제를 기록합니다.

어떤 자동화 라이브러리에도 통하는 의사 코드:

```text
profile = new dir .hyper/browsing/<slug>/profile
browser = launch(headless, user_data_dir=profile)
try:
  page = browser.open(url); page.wait(network_idle or 10s)
  text = page.text_or_snapshot(); requests = page.network_log()
  save(text, content/<name>.md)
finally:
  browser.close(); remove(profile)
```

## 3. Tier 4: 연결 브라우저

1. 런타임이 제공하는, 사용자가 이미 쓰고 로그인한 브라우저에 연결하는 기능만 씁니다. 그 프로필로 새로 띄우거나, 복사하거나, 내보내지 않습니다.
2. 어떤 호스트의 어떤 페이지가 열릴지 사용자에게 알리고, 실행이 읽기 전용임을 밝힙니다.
3. 탐색하고 텍스트나 스냅숏으로 읽으며, 로그인, 2단계 코드, 챌린지에서 멈춥니다. 사용자가 직접 끝내면 실행을 이어 갑니다.
4. 쓰기 동작(보내기, 구매, 게시, 삭제, 설정)은 사용자가 이번 실행에서 그 동작 하나를 요청하지 않는 한 클릭하지 않습니다.
5. 사용자의 브라우저나 열어 둔 탭을 닫지 않고, 데이터를 지우지도 않으며 연결만 해제합니다.

## 4. 쿠키

쿠키는 사용자 브라우저에서 실행으로 옮기지 않습니다. 사용자 실제 프로필에서 쿠키를 내보내는 것은 그 세션을 복사하는 일이라, 그런 도구가 있어도 범위 밖입니다. 자체 브라우저가 받은 쿠키는 버리는 프로필 안에만 두고 함께 삭제합니다.
