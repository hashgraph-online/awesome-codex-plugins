# 워크플로

> 요청에서 모드를 고르고, 행동 전에 먼저 읽고, 정해진 형식으로 보고한다.

## 모드 선택

| 요청에 나오는 말 | 모드 | 첫 도구 호출 |
|---|---|---|
| 무엇이 들었는지, 구조, 시트 목록, 수식 위치 | `inspect` | `inspect <file>` |
| 얼마인지, 몇 개인지, 어디가 제일 큰지 | `inspect` | `inspect <file> --rows 20` |
| 검사, 검토, 맞는지, 오류, 합계 빠짐 | `verify` | `verify <file>` |
| 바꿔, 수정, 고쳐, 값 넣어, 시트 추가 | `patch` | `inspect` 후 `patch` |
| 만들어, 생성, 보고서, 양식, 템플릿 | `build` | 원본 데이터를 먼저 `inspect` |
| CSV·텍스트를 엑셀로 | `profile` → `build` | `profile <csv>` |
| 다른 프로그램에서 값이 안 보인다 | `recalc` | `inspect` 후 `verify` |

요청 두 개가 겹칠 수 있다. 기존 파일에 "매출 요약 만들어줘"는 원본을 패치하는 것이 아니라 `inspect` → 새 시트 `build`다. 단, 사용자가 셀을 지목했으면 패치다.

## 단계 순서

1. **기준선.** `doctor`를 한 번, 그다음 입력 파일을 `inspect`한다. 기록할 것: 시트 이름, 크기, 수식 개수, 오류 셀, 캐시 유무, 매크로, 외부 링크. 이 사실은 인용하고, 요약하며 없애지 않는다.
2. **범위.** 모드와 바뀔 셀·범위·시트를 정확히 밝힌다. 사용자가 셀을 지목했으면 그 셀, 시트를 지목했으면 어느 범위를 건드리는지 말한다.
3. **작업.**
   - `inspect`/`verify`는 읽기만 하고 쓰지 않는다.
   - `patch`는 변경 하나당 `--set-value`/`--set-formula`/`--set-format`/… 을 하나씩, 한 호출에 모아서 준다. 사용자가 제자리 수정을 요청하지 않았으면 `--out`으로 새 경로에 쓴다.
   - `build`는 JSON 스펙을 먼저 써서 구조를 검토할 수 있게 한 뒤 빌드한다.
   - `recalc`는 수식을 쓴 빌드 뒤에, 계산하지 않는 리더도 값을 보게 하려고 실행한다.
4. **검증.** 수식이 있으면 `verify`를 돌린다. 패치는 도구가 이미 미변경 파트를 다이제스트로 증명하고 불일치면 거부한다. 출력을 다시 `inspect`한다.
5. **읽기 확인.** 설치된 독립 리더(`uv run --with openpyxl`)로 제3자가 파일을 여는지 확인하는 것이 우선이다. 리더가 없으면 읽기 확인이 이 도구 모음의 파서까지였다고 밝힌다.
6. **보고**는 아래 형식으로 한다.

## 보고 형식

```
## 결과
<한 문장: 무엇을 했고 어디에 있는지>

- 경로: /abs/path/파일명.xlsx
- 시트: <이름들>
- 바뀐 것: <셀/범위 목록 또는 "새로 만든 파일">
- 검증: <verify 요약 — 수식 n개 재계산, 불일치 m개, 미검증 k개>
- 보존: <건드리지 않은 파트 n개 다이제스트 일치 / 해당 없음>
- 확인한 것: <읽어서 본 값, 열어본 결과>
- 못 한 것: <없으면 이 줄을 빼고, 있으면 무엇을 왜 못 했는지>
```

검증 줄 없이 "완료했습니다"라고 쓰지 않는다. 확인을 돌릴 수 없었으면 그 줄에 그렇게 적고, 제목에 이유를 밝힌다.

## 숫자

- 파일의 캐시 셀에서 읽은 값은 **캐시 값**으로, 셀 주소와 함께 보고한다.
- 이 스킬이 계산한 값은 **재계산 값**으로, 계산에 쓴 수식과 함께 보고한다.
- 평가기가 지원하지 않는 함수에 걸린 값은 **미검증**으로, 함수 이름과 함께 보고한다. 직관으로 채우지 않는다.

## 모호할 때

대상 시트나 셀이 모호하면 `inspect` 결과의 후보를 나열하고 한 번 묻는다. 위치로 시트를 고르지 않는다. 사용자가 범위를 줬는데 데이터가 그 너머로 이어지면 지목된 범위만 하고, 추가 행은 조용히 범위를 늘리지 말고 보고에 적는다.
