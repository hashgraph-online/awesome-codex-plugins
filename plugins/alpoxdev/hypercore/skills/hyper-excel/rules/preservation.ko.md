# 보존

> 기존 워크북 수정은 다시 쓰기가 아니라 외과 수술이다.

## 계약

작업이 지목한 파트만 바뀔 수 있다. 나머지 압축 항목은 바이트 단위로 같게 유지한다. `patch_workbook.py`가 이를 강제한다. 결과를 쓴 뒤 다시 열어 모든 파트의 다이제스트를 재고, 건드리지 않은 파트가 바뀌었으면 출력을 거부한다. 이 검사를 통과하지 않으면 원본을 교체하지 않는다.

무엇을 지키는지, 사용자가 손실을 알아차리는 순서대로 적는다:

| 파트 | 잃는 경로 | 지키는 방법 |
|---|---|---|
| 차트 | 대부분 라이브러리의 재저장, 일부 차트 유형은 조용히 사라진다 | 미변경 파트 복사 |
| 이미지, 로고 | `drawings/`를 다시 만드는 라이브러리 | 미변경 파트 복사 |
| 셀 서식, 테마 색 | 다른 테마로 `styles.xml`을 재작성 | 스타일 표에 덧붙이기만 함 |
| 조건부 서식 | `dxfs` 항목 없이 `dxfId`를 쓰는 작성기 | `dxfs` 항목 등록 |
| 데이터 유효성 목록 | `dataValidations`를 건너뛰는 작성기 | 노드 삽입 |
| 피벗과 피벗 캐시 | 피벗을 이해하지 못하는 재저장 전부 | 미변경 파트 복사 |
| VBA | `vbaProject.bin`을 지우는 작성기 | 미변경 파트 복사 |
| 메모, 하이퍼링크, 정의된 이름 | 부분 지원 작성기 | 미변경 파트 복사 |
| 인쇄 영역, 머리글, 페이지 설정 | 부분 지원 작성기 | 미변경 파트 복사 |

## 규칙

1. **기본은 패치다.** 사용자가 수정, 바꿔, 고쳐라고 하거나 셀을 지목하면 패치한다. 눈에 보이는 결과가 맞아도 재빌드는 파트를 잃는다.
2. **통과 검사 없이 제자리 덮어쓰기를 하지 않는다.** 목적지가 다르면 `--out`을 쓴다. 사용자가 같은 파일을 원할 때만 `--in-place`를 쓰고, 그래도 도구가 교체 전에 검증한다.
3. **재빌드는 다른 요청이다.** 패치로 표현할 수 없는 변경(새 피벗, 시트 구조 변경)이면 재빌드가 무엇을 잃는지 말하고, 사용자가 동의할 때만 재빌드한다.
4. **매크로는 실행하지 않는다.** `.xlsm` 패치는 `vbaProject.bin`을 그대로 복사한다. 지우지 않고, 바이트를 고치지 않고, 시험했다고 말하지 않는다.
5. **서식은 덧붙이기만 하고 번호를 다시 매기지 않는다.** 새 숫자 서식은 기존 사용자 지정 범위 위의 아이디를 받고, 새 `cellXfs` 항목은 끝에 추가된다. 번호를 다시 매기면 이전 인덱스를 참조하던 모든 셀이 깨진다.
6. **공유 문자열은 건드리지 않는다.** 쓴 문자열은 `inlineStr`을 쓰므로 `sharedStrings.xml`이 바뀌지 않고, 다른 셀의 인덱스도 움직이지 않는다.
7. **패치로 쓴 수식에는 캐시가 없다.** 그렇게 밝히거나, `recalc`로 계산하지 않는 리더도 값을 보게 한다.
8. **낡은 계산 체인은 지운다.** 수정 뒤 `calcChain.xml`은 더 이상 없는 위치를 가리킬 수 있다. `--strip-calc-chain`으로 지우면 엑셀이 다시 만든다.

## 파일이 잠겨 있거나 열려 있을 때

엑셀에 열린 워크북은 macOS에서 같은 경로로 교체되지 않을 수 있다. `--out`으로 쓰고 검증한 뒤 새 경로를 알린다. 잠긴 쓰기를 반복해서 재시도하지 않는다.

## 보존 보고

파트를 이름으로 적는다. "건드리지 않은 파트 23개 다이제스트 일치"는 증거이고, "서식 유지됨"은 주장이다. 도구 출력의 `touchedParts`를 그대로 옮긴다.
