# 검증

> 파일에 대해 주장하는 것을 실제로 확인하기 전에는 워크북이 끝난 것이 아니다.

## 게이트, 순서대로

| 게이트 | 명령 | 통과 조건 | 실패하면 |
|---|---|---|---|
| 구조 | `inspect <file>` | 파싱되고 `E_*` 경고가 없다 | 실패를 보고하고 파일로 답하지 않는다 |
| 범위 | `verify <file> [--max-cells N]` | `cells_complete == pass` | 시트를 다 읽지 못했다. 모든 집계가 읽은 셀만 덮으므로 그렇게 밝힌다 |
| 무결성 | `verify <file>` | `errorLiterals` 없음, 캐시 불일치 없음, 순환 없음 | 셀을 나열하고, 고치거나 공개한다 |
| 보존 | `patch …` 출력 | `verification.status == "pass"` | 아무것도 쓰이지 않았다. 작업을 고친다 |
| 읽기 확인 | `inspect` 재실행 또는 독립 리더 | 열리고, 시트 이름과 셀 값이 같다 | 쓰기 실패로 본다 |
| 캐시 | `recalc` 후 `verify` | `cache_complete == pass` | 어떤 수식이 왜 캐시되지 않았는지 보고한다 |

## 각 게이트가 실제로 증명하는 것

- **구조**는 패키지를 읽을 수 있고 리더가 필요로 하는 파트가 있음을 증명한다. 값이 맞다는 뜻은 아니다.
- **무결성**은 재계산한 수식이 저장된 값과 일치하고, 오류 리터럴이 없고, 자기 참조가 없음을 증명한다. 평가기가 계산하지 못한 수식은 `unevaluated`이며 `pass`가 아니고, 셀 하나가 평가기를 예외로 멈춰도 나머지 셀 보고가 사라지지 않는다. `unevaluated`에 셀·수식·예외 종류가 함께 남는다.
- **보존**은 건드리지 않은 파트가 바이트 단위로 같음을 증명한다. 바뀐 파트가 사용자가 원한 것이라는 뜻은 아니다. 그건 보고가 맡는다.
- **읽기 확인**은 두 번째 파서가 파일을 받아들임을 증명한다. 독립 리더가 설치되어 있지 않으면 확인이 제한적이었다고 밝힌다.
- **캐시**는 계산하지 않는 리더가 값을 봄을 증명한다. 캐시 값이 권위 있다는 뜻은 아니다. `fullCalcOnLoad`가 엑셀에서 원본부터 다시 계산하게 한다.

## 보고의 숫자

세 표기를 일관되게 쓴다:

- `캐시 값` — 파일의 `<v>`에서 읽은 값. 셀을 밝힌다.
- `재계산 값` — 번들 평가기가 만든 값. 수식을 밝힌다.
- `미검증` — 평가기가 구현하지 않은 함수. 함수 이름을 밝힌다.

파생 숫자(증가율, 차이)는 결과만 쓰지 않고 입력과 수식을 함께 보인다.

## 주장하면 안 되는 것

- 일부 수식이 미검증인데 "수식 검증 완료"라고 하지 않는다.
- 눈으로 본 인상으로 "서식 유지"라고 하지 않는다. 다이제스트 비교를 인용한다.
- 이 기기에서 실제 스프레드시트 엔진이 열지 않았다면 "엑셀에서 열린다"고 하지 않는다.
- 수식이 오류 없이 돌았다는 것만으로 "값이 맞다"고 하지 않는다.

## 복구 루프

검증 실패는 복구 한 번, 재검증 한 번이다. 같은 원인으로 같은 검사가 두 번 실패하면 멈추고 보고한다. 무엇이 실패했는지, 무엇을 시도했는지, 사용자가 무엇을 정해야 하는지 적는다. 맹목적으로 재시도하지 않고, 검사를 통과시키려고 약화하지 않는다.
