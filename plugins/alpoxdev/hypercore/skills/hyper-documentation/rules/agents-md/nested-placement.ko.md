# 중첩 배치

**목적**: 기록한 측정을 바탕으로 디렉터리에 별도 `AGENTS.md`를 둘 가치가 있는지 판정한다. 이는 패키지 heuristic이며 저장소를 실제로 읽는 일을 대신하지 않는다.

## 1. 점수의 성격

배치 점수는 자식 파일을 정당화하는 게이트다. 모든 보고에 패키지 heuristic으로 표기해 vendor 기준이 아닌 것으로 분명히 한다. 디렉터리는 그 하위 트리가 스스로 관할할 만큼 다르다고 점수가 말할 때만 자식 `AGENTS.md`를 가진다. 그렇지 않으면 부모가 그 영역을 담당한다.

점수가 저장소 전체를 쓸어내는 일로 이어지게 하지 않는다. 전체 계층을 한 번에 다시 잡는 bulk hierarchy run은 사용자가 명시적으로 요청했을 때만 하고, 점수는 검토 대상인 자식 파일 하나만 정당화한다.

## 2. 신호와 가중치

각 신호는 저장소 근거가 있을 때만 측정한다. 측정할 수 없는 신호는 `unmeasured`이며, `unmeasured`는 절대로 0으로 취급하지 않는다.

| 신호 | 측정 대상 | 가중치 |
|---|---|---|
| 파일 수 | 하위 트리의 소스 파일 | 2 |
| 하위 디렉터리 수 | shipped code가 담긴 직속 자식 디렉터리 | 2 |
| 코드 비율 | 문서나 데이터가 아니라 코드인 비율 | 2 |
| 고유 패턴 | 하위 트리 안에 있는 서로 다른 build·test·규칙 패턴 | 5 |
| 모듈 경계 | 하위 트리가 넘는 package·workspace·소유 경계 | 3 |
| 심볼 밀도 | 파일당 exports와 entry point | 1 |
| exports | 하위 트리가 소유한 공개 진입점 | 1 |
| 참조 중심성 | 부모 규칙과 이웃 파일이 이 하위 트리를 가리키는 정도 | 2 |

측정한 신호들의 가중치를 합산한다. `unmeasured` 항목은 합계에 넣지 말고 이름 그대로 run snapshot에 적는다.

## 3. 기준치

| 점수 | 판정 |
|---|---|
| 15 초과 | 하위 트리에 자식 `AGENTS.md`가 생긴다 |
| 8 이상 15 이하 | 점수에 덧붙여 뚜렷한 영역 차이가 있어야 자식 파일이 생긴다 |
| 8 미만 | 부모가 그 영역을 담당한다. 자식 파일을 만들지 않는다 |

같은 저장소에서 같은 점수는 두 run에서 다른 계층을 만들지 않는다. 두 run을 비교할 수 있도록 run snapshot에 측정한 내용을 기록한다.

## 4. 깊이 예산

깊이 예산은 기본값 3이며 생성만 제한한다. 예산보다 깊은 자식 파일은 만들지 않는다. 예산은 예산보다 깊은 기존 파일을 지우지 않는다. 예산보다 깊은 기존 파일은 그대로 둔다. 삭제는 사용자가 명시적으로 요청했을 때만 한다.

## 5. 점수 근거 행

각 배치 판정은 점수, 신호별 값, `unmeasured` 항목, 깊이, 예산을 함께 기록한다. 그 행이 없는 배치는 정당하지 않은 것이다.
