# 메모리 생명주기

**목적**: 항목을 어떻게 읽고, 갱신하고, 병합하고, 압축하고, 만료하고, 삭제하는지 정합니다. **읽는 조건**: 예산 경고 임계가 울릴 때, 항목을 바로잡거나 낡은 것을 발견했을 때, 감사나 `consolidate` 실행이 시작될 때 읽습니다.

## 1. 읽는 쪽

- 세션 시작: 색인을 읽고, 작업과 줄이 맞는 주제 파일만 연다. `rules/memory/structure.md` §2의 조회 한도까지다 [A33, D:M9].
- 경로, 명령, 버전, 상태를 지목한 항목으로 행동하기 전에 저장소와 대조해 확인한다. 다르면 그 항목이 낡은 것이다. 저장소가 이기고, 항목은 제자리에서 바로잡는다 [A29, A54, B68, F25].
- 메모리는 안내일 뿐 현재 동작의 증거가 아니다. 메모리가 그렇게 말한다고 사실이 확인됐다고 주장하지 않는다 [D:M9, B68].

## 2. 갱신

- 델타 편집을 한다. 항목 하나를 추가하거나, 바로잡거나, 제거한다. 파일 전체를 다시 만들지 않는다. 파일 전체를 LLM으로 다시 쓰면 측정된 문맥 붕괴와 간결성 편향이 생겼다 [E40, E41].
- 교훈이 여전히 유효하면 낡은 줄을 삭제하기보다 바로잡는 쪽을 택하고 `verified`를 갱신한다 [E60].
- 옛 사실을 대체하는 사실은 `supersedes`를 정하고 옛 항목을 보관소로 옮긴다. 둘 다 활성으로 남기지 않는다 [D:N1, F21].
- 사실마다 자리를 하나만 둔다. 새 항목이 옛 항목과 겹치면 옛 항목에 병합한다 [A60].

## 3. 통합

경고 임계가 울릴 때, 예정된 검토 때, 또는 파일을 다른 에이전트에 넘기기 전에 `consolidate`를 실행한다. 이름 붙은 한 단계이며 네 가지 동작을 한다 [B74]. 한도에 가까워질 때 병합하거나 버리라는 알림은 B38이고, 통합 pass는 B67이다:

1. **병합**: 중복과 거의 중복을 항목 하나로 합친다.
2. **해소**: 모순을 해소한다. `verified` 날짜가 더 새롭고 신뢰가 더 높은 항목을 남기고 다른 쪽을 대체하며 이유를 기록한다. 상충하는 지시는 모델이 임의로 해소하므로 하나도 남기지 않는다 [A20].
3. **삭제 또는 만료**: 편입 검사를 통과하지 못하거나 만료된 항목을 삭제하거나 만료시킨다.
4. **재맞춤**: 색인을 경고 임계 아래로 다시 맞춘다.

대량 편집 전에 스냅숏을 남겨, 오염이나 잘못된 병합이 생겨도 돌아갈 알려진 정상 상태를 둔다 [F15]. 병합할 재사용 가능한 것이 남지 않았으면 아무것도 쓰지 않는다. 채우기용 항목보다 아무것도 하지 않는 편이 낫다 [D:C9].

## 4. 만료와 잊기

잊기는 바람이 아니라 한도가 정해진 필수 동작이다. 아래 값은 맞춰 쓸 기본값이다. 앞의 두 개는 실제 운영 시스템에 근거하고, 나머지는 이 package의 선택이다.

| 항목 | 기본값 | 근거 |
|---|---|---|
| 변동성 사실(경로, 버전, 가격, 조직 상태) | 30일 뒤 다시 확인한다(이 package의 기본값). 다시 확인할 수 없으면 삭제 | D:C5(30일 미사용 시계), A53 |
| 확인되지 않았거나 격리된 항목 | 가장 빨리 만료되고 다음 통합에서 버림 | F2, F20 |
| 안정적인 선호나 규칙 | 유지하고, 모순이 생기면 다시 확인 | A53 |
| 90일 동안 쓰이지 않은 모든 항목 | 보관소로 옮김 | A53(강화 기반 만료). 유휴 시계 자체는 이 package의 선택 |
| 보관소 | 정한 보관 기간 뒤 삭제 | D:C12 |

강화가 시계를 되돌리고, 단순 조회는 되돌리지 않는다 [A53]. 소거 실험 없이 감쇠 규칙이 품질을 높인다고 주장하지 않는다. 공개된 잊기 규칙에는 소거 실험이 없다 [E34, E35].

## 5. 삭제

- 세 가지 단위를 제공한다. 항목 하나, 주제 파일 하나, 저장소 전체다. 저장소 전체 초기화는 되돌릴 수 없다고 밝힌다 [F35].
- 삭제는 모든 사본을 제거한다. 색인 줄, 주제 파일, 모든 요약, 같은 출처에서 만든 모든 파생 항목이다 [F36, F43].
- 삭제 뒤에도 남는 사본(백업, 로그, 검토 대기열)이 있으면 전파 창을 인계에 적는다. 즉시 지워진다고 약속하지 않는다 [F37, F40].
- "이 이야기는 다시 꺼내지 마"는 표면적 사용만 억제한다. 파일과 인계에서 삭제와 구분해 둔다 [F36].
- 쓰기와 삭제의 추가 전용 변경 로그를 남긴다. 타임스탬프, 행위자, 출처, class, 결정, 내용 해시다 [F47]. 런타임이 허용하면 답을 만들 때 어떤 항목을 읽었는지도 기록한다 [F37].

## 6. 압축 이후

압축 뒤에는 색인과 지시 파일을 다시 읽는다. 요약이 모든 규칙을 지켰다고 믿지 않는다. 압축은 문맥에만 있던 규칙을 버리고, 몇백 토큰 미만의 요약은 더 많이 버린다 [E43, E44, E45].
