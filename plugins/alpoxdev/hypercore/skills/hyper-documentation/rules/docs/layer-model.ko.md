# 계층 모델

**목적**: 문서 묶음에 필요한 만큼만 계층을 나눕니다. **읽는 조건**: 규칙, 예시, provider 세부 내용을 어디에 둘지 정할 때.

## 계층

| 계층 | 소유 | 소유하지 않음 |
|---|---|---|
| Canonical core | 오래 유지되는 provider-neutral 규칙과 상위 workflow | 날짜가 붙은 vendor 사실, 긴 예시 |
| Rules | 재사용할 정책과 판단 기준 | 일회성 프로젝트 메모 |
| References | provider·runtime 세부, schema, 깊은 예시, source snapshot | 핵심 trigger나 stop 로직 |
| Source ledger | 최신·논쟁·보안·benchmark·비교 주장의 claim-to-source provenance | 출처 없는 결론 |
| Local overlay | 프로젝트 경로, 관례, scope 한계, runtime profile | 보편 정책 |
| Validation artifact | scenario, oracle, trace assertion, 결정적 검사, 확인한 evidence | 모호한 self-review |

## 배치 규칙

규칙마다 정본 위치를 하나만 두고, 지원 자료는 그것이 필요한 파일에서 직접 링크합니다. 결정적 실행, 재사용, 검증을 실제로 개선할 때만 script, asset, ledger, 추가 guide를 둡니다.
