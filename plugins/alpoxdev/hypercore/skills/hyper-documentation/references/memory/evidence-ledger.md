# Memory Evidence Ledger

> Every source the `memory` mode cites, with its exact URL, date, type and trust level, normalized from six raw research ledgers.

**Purpose**: Resolve every id cited in `rules/memory/*.md` to a primary source and show how far that source actually supports the rule. **Read when**: writing, auditing, or challenging a `memory` rule, and before adding a numeric budget or a never-record class.

## How to read trust

- **high** — official documentation, a specification or regulator text, or source code read at a pinned commit.
- **medium** — vendor engineering post, peer-reviewed paper, or a benchmark paper whose method is disclosed.
- **low** — preprint of uncertain venue, vendor blog, vendor-authored benchmark claim, or a project README with no method.

The raw ledgers used per-lane scales (`official-doc`, `source-code`, `paper`, `blog`, `spec`); this ledger normalizes those labels to the three levels above. A row keeps the ledger's own doubt: where the ledger wrote "medium (no ablation)" or "vendor benchmark", the normalized level is capped accordingly and the reason is repeated in **Not confirmed**.

Each group table maps one lane of the research run. Lane C ids are written `C:F<n>` because that file restarts numbering at F1 and would otherwise collide with lane F. Ids cited by the rules but absent from a table do not exist; see **Citation audit**.

## Not confirmed

Items from the raw ledgers that limit what these rules can claim.

- **Anthropic server-side memory caps.** The documentation only advises implementers to cap file growth and `view` output; no default byte ceiling is published (B07). The 200-line / 25 KB figure is a Claude Code load cutoff, not a platform cap.
- **Claude Code combined instruction limit.** The page says a warning appears past a combined limit but prints no number; only per-file figures exist (A5, A6).
- **Cursor, Windsurf, Cline, Copilot, Kiro limits.** Cursor's 500 lines is guidance with no enforcement (A37); no source or doc states a hard truncation. Windsurf's only stated cap is 12,000 chars per rule file (A42); its memory retention is undocumented. Cline Memory Bank has no size cap, only prompt text. Copilot's only length norm is a soft "2 pages". Kiro's memory count, size and file format are not published.
- **Codex memory schema and doc dates.** The docs give locations and phases but no field-level format for `memories_v2/`, and the Codex and OpenAI cookbook pages carry no publication date.
- **omp binary versus HEAD.** Local install is 18.18.2, the cited repo commit reports 18.18.3; the mechanism matches but effective per-setting values were not read out of the binary. All M-row numbers are repo-source values.
- **OpenClaw and goose caps.** OpenClaw's dreaming gate defaults were not read (tests use 0.25 for the loss fraction). goose has no size or count cap in its memory module, inferred from a module read rather than proven repo-wide.
- **opencode absence of memory.** Based on grepping core; a plugin-provided store was not audited.
- **Letta V1 limit enforcement.** The 100,000-char block limit is advertised in the prompt and shipped in constants, but `update_block_value` assigns without a length check; the 100k figure is documented-but-soft in V1. Only MemFS (C:F9) enforces a hard budget.
- **Mem0 v3 contradiction outcome.** The write path is ADD-only and the delete-on-contradiction prompt is unreachable; the end-to-end user-visible result is documented, not asserted by a test. Mem0's `history.db` has no retention policy found, so unbounded growth is plausible but unverified.
- **Graphiti and Zep retention.** No TTL or episode-deletion schedule was found in `graphiti_core`; edges are invalidated, not expired by time. Zep Cloud pruning was not checked.
- **LangMem TTL wiring.** The LangGraph store supports TTL, but no LangMem-specific default or sweep interval was verified.
- **Cognee TTL key.** The docs name `SESSION_TTL_SECONDS`; the code field is `session_ttl_seconds`. The env-var override path was not traced.
- **MemOS lifecycle.** The Dream maintenance module is an explicit stub, and its 7-day TTL is an example in a comment, not a shipped default.
- **MemGPT venue.** No accepted venue was found (OpenReview shows only CoRR 2023), so it is treated as a preprint.
- **Vendor-authored benchmark numbers.** Mem0's 26% relative gain and 91% latency cut (E22), Zep's 75.14% corrected LoCoMo score and its rebuttal of Mem0's measurement (E27), and OWASP Agent Memory Guard's F1 0.961 claim were not independently reproduced. E24's "Zep >600k tokens" is a competitor measurement that Zep disputes.
- **AGENTS.md effect size.** The negative result (E53) and the two efficiency studies (E55, E56) disagree and are preprints under review. The honest rule is "evaluate before deploying", not "context files help" or "hurt".
- **Third-party replication of ACE and ACON gains.** Both are peer-reviewed and self-reported, with no independent replication in these lanes.
- **Poisoning magnitudes.** MINJA, AgentPoison, MPBench and PMPA numbers are preprint or vendor-setup results; attack success varies by setup (34.25% to 66.67% ASR across two agents), so they must be cited with their setup and never as a general rate. No defence read in these lanes is claimed to work.
- **OWASP ASI06 numbering and GDPR text.** ASI06 is confirmed in the December 2025 PDF (v12.6) only; earlier drafts may have used another number. GDPR quotes come from the `gdpr-info.eu` mirror, not the Official Journal, because EUR-Lex returned an empty body. The ICO page is flagged "under review" after the Data (Use and Access) Act.
- **Secret gates in shipped agents.** GitHub push protection and gitleaks exist as gates, but no evidence shows Claude Code, Cursor or Codex validating agent-authored memory files for secrets at write time.
