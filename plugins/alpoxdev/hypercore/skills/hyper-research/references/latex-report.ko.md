# LaTeX 리포트

사용자가 LaTeX나 조판된 PDF를 요청할 때만 이 참고 파일을 씁니다. 마크다운 리포트가 납품의 기준이며 `.tex` 파일은 완성된 리포트에서 만든 산출물입니다. 반대 방향은 없습니다.

## Contents

- 납품 산출물
- 인용과 원장
- 컴파일 순서
- 로그 우선 수리
- 한국어 조판
- 페이지 검토
- 도구 부재

## Build Output

저장된 리포트 옆 `.hyper/research/`에 `[NN].slug.tex`를 만들고, TeX 도구가 있으면 컴파일한 `[NN].slug.pdf`를 함께 냅니다. `.tex` 소스는 완성된 마크다운 리포트를 옮긴 렌더링입니다. 같은 주장, 같은 인용, 같은 숫자를 씁니다. LaTeX에 맞추려 문장을 다듬을 때 `\cite`를 이동시키지 않고 불확실한 주장을 단정적으로 바꾸지 않습니다. 리포트에서 조심스럽게 쓴 주장은 `.tex`에서도 조심스럽게 쓰고, 미해결 부록에 든 주장은 페이지를 채우려고 본문으로 올리지 않습니다.

## Citation And Ledger

`.tex` 파일의 모든 `\cite{Sn}`은 실행의 출처 원장(`sources.md`)에 있는 `[Sn]` 행에 대응해야 합니다. 컴파일 전에 `.tex`의 인용 키를 전부 모아 원장 행과 대조합니다.

- 원장 행이 있는 인용 키는 컴파일할 수 있습니다.
- 원장 행이 없는 인용 키는 납품을 막습니다. 연 출처에서 누락된 행을 추가하거나 인용과 그 주장을 함께 지우고 다시 확인합니다. 실행에서 열지 않은 출처를 인용하는 리포트를 컴파일하지 않습니다.
- 인용 형태는 리포트 자체를 따릅니다. `\cite{S1}`은 행 하나를, `\cite{S1,S4}`는 행 두 개를 인용합니다. 숫자와 다른 수치는 리포트에서 붙인 `MEASURED`, `ASSUMED`, `DERIVED` 표기를 그대로 유지합니다.

`.tex` 파일은 그 인용 키가 가리킬 참고문헌도 함께 담습니다. 인용한 원장 행마다 한 항목이며, 라벨이 `S<n>`인 `thebibliography` 항목이거나 키가 `S<n>`인 `.bib` 항목입니다. 항목은 원장 행의 제목, 발행처, URL이나 경로, 발행일로 채우고 원장에 없는 필드는 지어내지 말고 비웁니다. 원장 행은 있지만 참고문헌 항목이 없는 인용 키도 PDF에서는 `?`로 나오므로, 인용을 추가하는 같은 작업에서 항목도 넣습니다.

## Compile Order

먼저 `latexmk -xelatex`로 컴파일합니다. `.bib`를 쓰는 파일이면 참고문헌 도구까지, 교차 참조를 위해서는 추가 엔진 실행까지 알아서 돌립니다.

```sh
latexmk -xelatex [NN].slug.tex
```

`latexmk`가 없으면 엔진과 참고문헌 도구, 엔진 두 번을 직접 실행합니다.

```sh
xelatex [NN].slug.tex
biber [NN].slug
xelatex [NN].slug.tex
xelatex [NN].slug.tex
```

참고문헌이 BibTeX 형태이면 `biber` 대신 `bibtex`를 씁니다. 파일이 `thebibliography` 목록을 쓰면 참고문헌 도구는 건너뜁니다. 처리할 `.bib`가 없고, 그 상태로 `biber`를 돌리면 `Cannot find 'control' file`로 실패합니다. 인용 번호와 교차 참조가 자리 잡으려면 엔진 실행 두 번이 필요합니다. 참고문헌 도구를 쓰면 그 뒤에, `thebibliography`를 쓰면 첫 실행 뒤에 옵니다. 한 번만 돌리면 PDF에 `?` 표시가 남습니다.

## Log-First Repair

소스를 고치기 전에 컴파일 로그(`.log`)부터 읽고, 첫 번째 `!` 오류부터 고칩니다. TeX는 오류 복구가 빠진 부분을 채우면 보고를 멈추므로 뒤의 오류는 앞 오류의 증상인 경우가 많습니다. 기본 순서는 이렇습니다.

1. 위 컴파일 순서를 실행합니다.
2. 로그에서 `!`로 시작하는 첫 줄을 찾습니다. 그 줄과 주변 줄이 실패를 이름 짓습니다.
3. 첫 오류의 원인만 고치고 다시 컴파일합니다.
4. `!` 줄이 없을 때까지 반복합니다.

로그를 더 조용히 만들려고 문서를 통째로 다시 쓰지 않습니다. 오류 하나, 수정 하나, 컴파일 한 번입니다. 인용 키 누락은 로그 오류가 아니므로 위 인용과 원장 절에서 별도로 확인합니다.

## Korean Typesetting

한국어 문자가 제대로 나오도록 XeTeX 엔진을 씁니다. `latexmk -xelatex`와 `xelatex`가 이미 그렇습니다. `.tex` 파일은 엔진이 찾을 수 있는 한국어 글꼴을 설정하고(`fontspec`과 기기에 있는 한국어 글꼴로) CJK를 지원하는 클래스나 패키지를 씁니다. 납품 전에 세 가지 규칙을 지킵니다.

- 한국어 글꼴이 컴파일하는 기기에 실제로 설치되어 있어야 합니다. 설치된 경우에만 이름을 적고, 한국어 글꼴이 없으면 빈 글리프를 삼키지 말고 리포트에 그 사실을 적습니다.
- 한 번 컴파일하고 로그를 확인합니다. 글리프 누락 경고(`Missing character`)는 글꼴이나 클래스가 틀렸다는 뜻입니다. 본문이 아니라 글꼴 선택을 고칩니다.
- 영어 제목, 명령어, URL은 원래 글꼴을 유지하고 한국어 산문만 한국어 글꼴을 씁니다.

## Page Review

컴파일 종료 코드뿐 아니라 렌더링 페이지도 봅니다. `pdftoppm`이 있으면 PDF를 페이지 이미지로 바꾸고 깨지기 쉬운 부분을 읽습니다.

```sh
pdftoppm -png -r 100 [NN].slug.pdf page
```

첫 페이지, 비교표가 있는 페이지 하나, 한국어 산문이 긴 페이지 하나는 최소로 검토합니다. 표가 본문 너비에 맞는지, 글리프가 비어 있지 않은지, 인용 번호가 `?`가 아니라 숫자로 나오는지 확인합니다. `pdftoppm`이 없으면 `.tex` 소스를 마크다운 리포트와 줄 단위로 대조하고, 페이지 이미지는 검토하지 않았다고 리포트에 적습니다.

## Missing Toolchain

TeX 도구가 하나도 없으면(`latexmk`와 `xelatex`가 모두 없음) `.tex` 소스를 납품하고 PDF는 만들지 않았다고 분명히 적습니다. 리포트에 누락된 도구와 PDF를 만들 명령을 함께 적습니다. 컴파일을 돌리지 않았는데 PDF가 있다고 주장하지 않고, 파일이 없는 PDF 경로를 붙이지 않습니다.
