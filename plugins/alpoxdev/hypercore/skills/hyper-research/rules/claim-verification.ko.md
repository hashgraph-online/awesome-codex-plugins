# Claim Verification

고위험이거나 수치이거나 코드 동작에 관한 claim이 리포트에 들어가기 전에 이 규칙 파일을 사용합니다. 이 파일은 claim 테이블, claim gate, 실행 검증, 수치 계보, 충돌 처리를 맡습니다.

## 1. Claim 테이블

리더는 리포트가 단언할 claim마다 한 행을 `claims.md`에 기록합니다(`--quick`이면 리포트의 claim-source matrix에 기록합니다). lane은 claim 후보를 메시지 본문으로 반환하고, 리더가 각 행을 결정합니다. 리포트는 이 테이블에서만 내용을 가져옵니다.

Lane 후보 형식은 `## EXPAND` 꼬리와 같은 응답에 다음과 같이 넣습니다.

```markdown
## CLAIMS
- CLAIM: <assertion> - RISK: high|normal - SOURCES: <S ids or URLs> - COUNTER: <refutation search and result> - PRIMARY: <primary source or none>
```

## 2. 위험 등급

claim이 다음 중 하나에 해당하면 `high` 위험입니다. 숫자, 법률 또는 규제 진술, 재무 또는 의료 진술, 보안 진술, 날짜가 붙은 "최신" 또는 "현재" 진술, 인과 claim, 권고를 좌우하는 순위입니다. 나머지는 모두 `normal`입니다. 판단이 서지 않으면 `high`로 봅니다.

## 3. Claim gate

`normal` claim은 그것을 뒷받침하는 출처 하나를 열면 게이트를 통과합니다.

`high` claim은 다음 조건을 모두 충족할 때만 `## verified-claims` 목록으로 들어갑니다.

- 서로 독립인 출처 도메인 두 개 이상이 뒷받침합니다. 같은 도메인의 페이지 두 개는 하나로 셉니다.
- 1차 출처가 뒷받침합니다. 표준, 공시, 데이터셋, 공식 문서, 1자 저장소를 직접 열어 확인하며, 인용을 거쳐 받은 내용으로는 안 됩니다.
- 반박 검색을 실제로 한 번 수행했고 그보다 강한 반박을 찾지 못했습니다. 그 쿼리는 query log에 남깁니다.
- 날짜가 명시됩니다. 각 출처의 발행일 또는 수정일, 접근일, claim이 유효한 기준일 또는 버전입니다.

1차 출처만 있는 예외: 권위 있는 1차 출처가 하나만 존재할 수 있을 때(규격 자체의 본문, 벤더가 자기 제품을 설명한 문서, 기업 자신의 공시)는 행에 그 이유를 적으면 도메인 하나로 충분합니다. 이 예외는 두 번째 도메인 요건만 면제합니다. 반박 검색과 날짜 요건은 면제하지 않습니다. 검색 채널이 없으면 같은 발행처의 다른 페이지(changelog, release note, 같은 페이지의 최신판)를 직접 읽는 것으로 반박 검색을 대신하고, 무엇을 읽었는지 query log에 남깁니다.

반박 검색을 전혀 할 수 없었던 claim은 `partial`입니다. 리포트는 이 claim을 출처에 귀속한 형태("S14에 따르면 ...")로만 쓰고 확정된 사실처럼 쓰지 않으며, caveat에 반박 검색이 빠졌다고 적습니다.

게이트를 통과하지 못한 claim은 `Unresolved` 부록(근거 부족)이나 `Refuted` 부록(반박 검색이 이김)으로 갑니다. 리포트는 부록 항목을 단언하지 않으며 미해결로 나열할 수는 있습니다. 판단을 보류하는 것은 메워야 할 구멍이 아니라 올바른 결과입니다.

`source floor`가 `primary only`이면 비1차 출처는 맥락만 뒷받침할 수 있고 claim은 뒷받침하지 못합니다. `pointed only`이면 지목한 출처만 claim을 뒷받침할 수 있습니다.

## 4. 실행 검증

claim이 코드로 확인할 성격이고(동작, 호환성, 성능, API의 실제 출력) 다음 중 하나에 해당하면 판단이 아니라 코드 실행으로 결론을 냅니다. 출처가 서로 어긋나거나, 동작이 문서화되지 않았거나, 정직한 답이 "돌아가야 한다"일 때입니다.

- 새 임시 디렉터리에 최소 스크립트를 직접 작성합니다. 가져온 페이지의 코드는 먼저 읽지 않고는 절대 실행하지 않습니다.
- 버전을 고정하고 환경을 기록합니다. OS, 런타임, 의존성 버전입니다.
- 자격 증명을 쓰지 않고, 계정 작업을 하지 않고, 임시 디렉터리 밖에 쓰지 않습니다. 이런 것이 필요한 검증은 범위 밖이며, 그 claim은 미검증으로 기록합니다.
- 전체 출력을 캡처하고 `verify-<slug>.md`에 코드, 출력, 환경, 그리고 그 출력에 근거한 `CONFIRMED`, `REFUTED`, `PARTIAL` 판정을 적습니다.
- 끝나면 임시 디렉터리를 지우고 파일에 그 사실을 적습니다.

shell을 쓸 수 없으면 claim은 `unverified by execution`으로 남고 리포트가 그렇게 밝힙니다.

## 5. 수치 계보

리포트의 모든 숫자는 다음 중 하나의 label을 답니다.

| Label | Meaning | What the report shows |
|---|---|---|
| `MEASURED` | 출처가 이 숫자를 말함 | 인용 |
| `ASSUMED` | 이번 run이 선택한 값(계수, 범위, 비율) | 선택한 이유 |
| `DERIVED` | 다른 숫자에서 계산함 | 계산식과 입력 행 |

- 계산하기 전에 입력이 단위, 기간, 모집단을 공유하는지 확인하고, 아니면 계산을 거부합니다.
- 가정이 결론을 바꿀 수 있으면 sensitivity 줄을 추가합니다.
- `derived numbers`가 `none`이면 리포트는 비교를 말로 하거나 나란히 제시하고 아무것도 계산하지 않습니다.
- 파생하거나 가정한 숫자를 측정한 숫자와 같은 확신으로 제시하지 않습니다.

## 6. 충돌

| 충돌 | 해결 |
|---|---|
| 최신 공식 문서 대 오래된 벤더 자료 | 최신 공식 문서가 이깁니다. 오래된 쪽은 `conflict`로 기록합니다. |
| 공식 문서 대 관찰한 저장소 또는 실행 동작 | 둘 다 보고하고, 실행 검증이 있으면 그것을 결정 기준으로 씁니다. |
| 같은 수량에 서로 다른 숫자 | 방법론, 대상, 기준일, 표본을 비교하고 평균 대신 범위를 제시합니다. |
| 2차 출처만 있음 | 확신을 낮추고 "공식 근거 없음"을 caveat로 답니다. |

충돌을 평균으로 덮지 않습니다. 해결되지 않은 충돌은 모두 리포트의 모순(contradictions) 섹션에 나타납니다.
