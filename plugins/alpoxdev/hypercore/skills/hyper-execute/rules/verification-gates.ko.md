# Verification Gates

이 규칙 파일은 워커를 배정하기 전과 행을 닫기 전에 읽습니다. 다섯 게이트, 실제 표면 QA 형태, 적대 트리거 표, 완료 주장과 검증자 형태, 판정 규칙, 시도와 정지 규칙, `- [~]` 의미, 마지막 검증 웨이브, 근거 위생을 소유합니다. 선택과 배정은 `execution-loop.ko.md`에 있고, 워크트리와 전달은 `worktree-and-delivery.ko.md`에 있습니다.

## 1. 다섯 게이트

모든 행은 체크박스를 뒤집기 전에 웨이브 워크트리 안에서 다섯 게이트를 모두 통과합니다.

| 게이트 | 통과 조건 | 아티팩트 |
|---|---|---|
| 계획 재확인 | 행의 `Acceptance`, `QA happy`, `QA failure`, `Write scope`, `Depends on`을 기억이 아니라 계획 파일에서 다시 읽었습니다 | 인용한 인수 줄 |
| 자동 검사 | 계획이 지정하고 저장소가 제공하는 모든 명령(테스트, 타입 검사, 린트, 빌드)이 최종 상태에서 통과했습니다 | 명령 출력 원문 |
| 실제 표면 QA | `QA happy` 호출이 돌았고 관찰값이 성립했으며, `QA failure` 호출도 돌았고 관찰값이 성립했습니다 | 2절의 형태별 캡처 아티팩트 |
| 적대 QA | 트리거 사실이 성립하는 모든 클래스를 관찰값과 함께 탐침했고, 나머지 클래스에는 해당 없음 사유를 한 줄씩 적었습니다 | 클래스별 결과 줄 |
| 정리 | 등록한 QA 자원을 모두 철거했고, 프로세스, 포트, 컨테이너, 임시 디렉터리, 브라우저 세션이 남지 않았습니다 | 자원별 영수증 하나 |

돌릴 수 없는 게이트는 `not-run`이며 통과가 아닙니다. 사유를 남기고 행을 막습니다.

## 2. 실제 표면 QA 형태

아티팩트는 사용자가 만나게 될 표면에서 나와야 합니다.

| 표면 | 호출 | 아티팩트 |
|---|---|---|
| HTTP 엔드포인트 | 실행 중인 서버에 `curl -i` | 상태 줄, 헤더, 본문 |
| CLI 또는 TUI | pty에서 실제 바이너리 실행 | stdout, stderr, 종료 코드 |
| 브라우저 또는 GUI | 런타임의 브라우저나 데스크톱 자동화로 페이지·앱 조작 | 주장을 증명하는 스크린샷 또는 DOM 상태 |
| 데이터 형태 작업 | 변경 전후 데이터베이스 질의나 설정 덤프 | 그 차이 |
| 실패 경로 | `QA failure` 호출 | 오류 메시지와 종료 코드 |

- `--dry-run`, 단독 단위 테스트, 워커가 쓴 로그 줄은 실제 표면 근거가 아닙니다.
- 로그 줄은 표면에 대한 주장이지 표면 자체가 아닙니다.
- `QA failure` 줄은 필수입니다. 성공 경로만 확인한 행은 `needs-fix`로 남습니다.

## 3. 적대 클래스 트리거 표

클래스는 그 트리거 사실이 이 행에서 성립할 때만 적용됩니다. 적용되면 탐침하고 관찰값을 캡처하며, 성립하지 않으면 사유를 한 줄로 남깁니다.

| 클래스 | 트리거 사실 | 탐침 | 관찰값 |
|---|---|---|---|
| 잘못된 입력 | 새 입력이나 신뢰할 수 없는 입력을 해석함 | 빈 값, 과대 값, 타입 불일치, 잘못된 인코딩 입력 | 이름 붙은 오류, 0이 아닌 종료 코드, 크래시 없음 |
| 프롬프트 주입 | 페이지, 이슈, 문서, 모델 출력 같은 외부 텍스트를 읽음 | 지시문을 담은 픽스처 | 지시는 무시되고 사실만 추출됨 |
| 취소와 재개 | 재개 가능하거나 오래 도는 흐름 | 중간에 중단한 뒤 상태에서 재개 | 상태가 일치하고 중복 효과 없음 |
| 낡은 상태 | 아티팩트를 생성·캐시·재사용함 | 같은 상태로 두 번 실행 | 두 번째 실행이 일관되고 낡은 값을 읽지 않음 |
| 더러운 워크트리 | 사용자가 수정했을 수 있는 경로를 건드림 | 메인이 아니라 웨이브 워크트리의 파일을 더럽힘 | 사용자 파일이 그대로이고 조용한 덮어쓰기 없음 |
| 멈추거나 긴 명령 | 네트워크, 표준 입력, 잠금 때문에 멈출 수 있음 | 타임아웃을 걸고 실행 | 종료되고 보고하며 고아 프로세스를 남기지 않음 |
| 흔들리는 테스트 | 새 테스트이거나 타이밍에 민감함 | 반복 실행하고 순서를 바꿔 실행 | 안정적으로 통과하고 순서 의존이 없음 |
| 오해를 부르는 성공 출력 | 로그나 래퍼의 종료 코드로 성공을 주장함 | 아티팩트와 실제 상태를 확인 | 상태가 주장과 일치함 |
| 반복 중단 | 쓰기 중간에 중단될 수 있음 | 두 번 중단한 뒤 재개 | 멱등이고 부분 쓰기가 없음 |

`stale_state`, `dirty_worktree`, `misleading_success_output`은 어떤 행이든 `confirmed`가 되기 전에 탐침합니다.

## 4. 완료 주장과 검증자 형태

워커의 완료 주장은 최종이 아닙니다. 워커는 이 주장을 반환하고, 별도 검증자가 판정을 반환합니다.

```json
{
  "DoneClaim": {
    "task": "<행 번호와 제목>",
    "changed_files": ["path"],
    "tests": ["정확한 명령 + 결과"],
    "manual_qa": ["아티팩트 경로"],
    "cleanup": ["영수증"],
    "risks": ["알려진 위험 또는 none"]
  },
  "AdversarialVerify": {
    "verdict": "confirmed | false-positive | needs-fix | needs-human-review",
    "failure_class": "none | product | harness",
    "evidence": ["파일 경로, 명령 출력, 아티팩트, 또는 명시적 not inspected"],
    "repro": "가능하면 정확한 명령이나 수동 단계",
    "confidence": 0.0
  }
}
```

규칙:

- 행을 닫는 판정은 `confirmed` 하나뿐입니다. `false-positive`, `needs-fix`, `needs-human-review`는 모두 막습니다.
- `needs-human-review`는 열린 질문과 함께 완료 블록에 보고합니다. 기본값으로 통과하지 않습니다.
- 검증자는 독립적이어야 합니다. 그 행을 구현하거나 크게 고치지 않은 새 워커나 게이트 리뷰어입니다.
- 검증자에게는 계획 행, 인수 줄, 아티팩트 자체를 줍니다. 워커의 요약만 주지 않습니다.
- 실행하지 않은 테스트를 실행했다고 주장하면 diff가 맞아 보여도 `needs-fix`이고 `failure_class`는 `product`입니다.
- 결과를 재현하지 못한 검증자는 `confirmed`가 아니라 근거 목록을 붙인 `needs-human-review`를 반환합니다.
- `confidence`는 검증자 자신의 숫자이며 아티팩트를 대신하지 않습니다.

## 5. 시도, 서명, 정지 규칙

- 시도는 행마다 세고, 그 행의 모든 하위 작업과 재분할을 합산하며, 첫 배정에 설정한 `checkpoint_opened_at`부터 시간을 잽니다.
- 실패 서명은 실패한 검사와 그 첫 오류 줄이며, 임시 경로, 타임스탬프, 프로세스 id, 실행 id, 소요 시간 같은 변동값을 제거합니다.
- 다음 중 하나가 성립하면 행을 멈춥니다. 같은 서명이 연속 시도에서 반복됨, 세 번째 시도 실패, 첫 배정으로부터 4시간 경과, 또는 판정 없이 레인이 끝나거나 세션이 재개되었는데 4시간 경계가 이미 지남.
- harness 실패(제품 동작을 실행하기 전에 러너, 픽스처, CI 잡, 환경이 실패)는 체크포인트 안에서 수리 배정을 한 번 받고, 그 배정은 시도로 세지 않습니다. 수리 뒤에도 반복되면 위 규칙으로 멈추고 harness 공백을 밝히며, 아래에 적은 harness 수리 후속 행을 하나 덧붙입니다.
- 멈출 때는 그 행의 미검증 변경을 웨이브 워크트리에서 되돌리고, 행을 `- [~]`로 뒤집고, `Unmet: <공백, 마지막 서명, 시도 횟수>`를 덧붙이고, 그 레인을 취소한 뒤 남은 행으로 계속 진행합니다.
- `- [~]`는 실행 완료에는 닫힌 것으로 세지만 충족된 의존성으로는 절대 세지 않습니다. 어떤 행이 `[~]`로 닫히는 순간, 그 행에 직간접으로 의존하는 열린 행은 모두 즉시 `Unmet: dependency <n> blocked`로 함께 `[~]`가 됩니다. `<n>`은 가장 가까운 차단 조상입니다. 영향을 받은 행마다 `row.blocked` 원장 이벤트를 하나씩 남기고, 그 행들에는 시도를 세지 않고, 레인을 취소한 뒤 독립 행으로 계속 진행합니다.
- 마지막 검증 행은 `[~]` 행의 의존 대상이 아닙니다. 반영된 작업을 검증하고 각 `[~]` 행을 알려진 공백으로 보고하며, 그 공백만으로 마지막 행이 실패하지는 않습니다.
- `[~]` 행은 이 실행에서 새 행으로 다시 큐에 넣지 않습니다. 아래 harness 수리 후속 행만 예외입니다.

### Harness-Repair Follow-up

수리 배정 한 번 뒤에도 harness 실패가 반복되면 위대로 행을 `- [~]`로 닫고, `rules/execution-loop.md` 3.4절의 덧붙이기 경로로 후속 행을 정확히 하나 추가합니다. `[~]` 행이 새 행을 만드는 경우는 이것뿐입니다.

- **행 문구.** 체크박스 줄은 `Repair harness: <실패한 검사> - <첫 오류 줄>`로 쓰고, 위의 변동값을 제거한 실패 서명을 씁니다. 원래 행의 `Acceptance` 줄이 후속 행의 인수 기준이며, 후속 행은 그것을 완화하거나 넓히지 않습니다.
- **중첩 줄 아홉 개.** 후속 행은 `Wave`, `Depends on`, `Write scope`, `References`, `Acceptance`, `QA happy`, `QA failure`, `Commit`, `Tier`를 모두 갖춥니다. 원래 행의 `[~]` 상태가 막는 대상에는 의존하지 않고, `Write scope`는 실패한 harness 표면만 덮습니다.
- **상한.** 후속 행도 3.4절의 후속 행 상한 열 개에 포함됩니다. 상한에 이미 닿았으면 덧붙이지 않고 harness 공백을 보고합니다.
- **원장.** 원래 행, 새 행 번호, 실패 서명, `kind: harness-repair`를 담은 `row.followup` 원장 이벤트를 하나 남깁니다. todo 목록에도 다른 행과 똑같이 등록합니다.
- **두 번째 덧붙임 없음.** 후속 행 자체가 `- [~]`로 닫히면 서명과 함께 완료 블록에 보고하고, 그 harness 서명에 대해 후속 행을 더 덧붙이지 않습니다. 한 서명이 다시 반복되어도 수리 행이 연쇄되지 않습니다.
- **원래 행은 닫힌 채로 둡니다.** 원래 행은 `[~]`, `Unmet:` 줄을 그대로 유지하고 다시 큐에 넣지 않습니다. 후속 행은 자기 번호와 자기 시도 예산을 가진 새 행입니다.

## 6. 마지막 검증 웨이브

`## Todos`의 모든 행이 `[x]` 또는 `[~]`이고 모든 웨이브가 반영되었을 때:

1. `F1` 계획 준수 감사를 배정합니다. 각 행의 쓰기 범위와 인수를 마지막 웨이브 브랜치의 커밋과 대조합니다.
2. `F2` 코드 품질 리뷰를 배정합니다. 통합 기준에서 마지막 웨이브 브랜치까지의 전체 diff에 새 리뷰어를 붙입니다.
3. `F3` 실제 표면 QA를 배정합니다. 계획의 종단 시나리오를 병합되지 않은 통합 기준이 아니라 마지막 웨이브 브랜치에서 다시 돌립니다.
4. `F4` 이상 상태 충실성을 배정합니다. `IS-<n>` 행과 `## Success criteria` 표의 모든 행을 1:1로 확인합니다.
5. 계획이 선언한 마지막 검증 명령을 직접 실행하고 출력을 그대로 캡처합니다.

`--make-pr`에서는 쌓기 때문에 마지막 웨이브 브랜치에 앞선 웨이브가 모두 들어 있어 F1부터 F3까지가 그 브랜치를 읽습니다. `--ship`에서는 마지막 웨이브가 병합된 통합 기준입니다. F 행은 검토 대상 행을 구현하지 않은 워커에게 갑니다. 여기서 발견한 부족분은 새 번호의 `- [ ] <N>.` 행이 되고 다른 행과 똑같이 실행합니다. 메모로 남기지 않습니다. F 행은 `[~]` 공백만으로 닫지 않습니다.

## 7. 근거 위생

- 아티팩트는 웨이브 워크트리가 존재하는 동안 그 안에 있고, 정리 전에 `<main_root>/.hyper/execute/<slug>/evidence/`로 복사합니다.
- 아티팩트 이름은 `<행>-<게이트>-<내용>.<확장자>`로 붙여 완료 블록이 가리킬 수 있게 합니다.
- 명령 출력은 원문으로 캡처합니다. 요약으로 바꾸지 않습니다.
- 정리 영수증은 철거 명령과 그 출력, 또는 경로가 사라졌다는 명시적 확인입니다.
- 자격 증명, 토큰, 개인정보를 아티팩트나 원장에 쓰지 않습니다.
