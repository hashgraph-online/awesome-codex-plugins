## 이 스킬이 사용하는 주장

1. **정적 프런트엔드 패키징.** Tauri는 별도로 build한 frontend를 통합하고 구성된 distribution을 bundle합니다. 따라서 Vite SPA는 구성된 distribution directory에 정적 asset을 생성해야 하며 development URL만이 아니라 실제 production handoff를 테스트해야 합니다. 출처: [프런트엔드 통합](https://v2.tauri.app/start/frontend/), [Vite guide](https://v2.tauri.app/start/frontend/vite/), [Configuration](https://v2.tauri.app/reference/config/).
2. **Native RPC 경계.** Tauri command는 frontend에서 `invoke`로 호출하는 등록된 Rust function이며 async 및 value/error 반환을 지원합니다. Raw invocation을 좁은 typed desktop API 뒤에 두고 privileged command마다 Rust에서 validate/authorize합니다. 출처: [Rust 호출](https://v2.tauri.app/develop/calling-rust/), [보안 개요](https://v2.tauri.app/security/).
3. **Native/application state는 Rust 측이 소유합니다.** Managed state를 command에서 사용할 수 있지만 synchronization, persistence, access policy는 application 책임입니다. 출처: [Rust state](https://v2.tauri.app/develop/state-management/).
4. **최소 권한은 config와 enforcement의 결합입니다.** Capability와 permission은 command/plugin access를 제한하고 선택된 window/webview, platform 또는 remote URL에 적용할 수 있습니다. Scope와 CSP는 노출을 줄이지만 client code를 authorization boundary로 만들지 않습니다. 출처: [Capability](https://v2.tauri.app/security/capabilities/), [Permission](https://v2.tauri.app/security/permissions/), [CSP](https://v2.tauri.app/security/csp/).
5. **Semantic에 따라 IPC를 선택합니다.** Request/response는 command, 작은 one-way notification은 event, ordered/high-throughput stream은 channel을 사용합니다. React listener는 SPA navigation 뒤에도 살아 있으므로 effect cleanup에서 제거해야 하며, Tauri 2.12는 webview 파괴 시 listener를 추가로 회수하지만 이 정리 의무를 없애지는 않습니다. 출처: [IPC model](https://v2.tauri.app/concept/inter-process-communication/), [Frontend 호출](https://v2.tauri.app/develop/calling-frontend/).
6. **Custom command에는 ACL 경로가 필요합니다.** Command 등록 자체는 least-privilege를 만들지 않습니다. `invoke_handler` command는 `AppManifest::commands`가 선언하기 전까지 모든 window/webview에서 허용됩니다. Application command를 선언하고 permission/capability에 매핑하며 Rust에서 scope와 domain authorization을 강제합니다. 출처: [Application manifest](https://v2.tauri.app/security/capabilities/), [Runtime authority](https://v2.tauri.app/security/runtime-authority/), [Command scope](https://v2.tauri.app/security/scope/).
7. **Native 및 packaging 동작에는 native 근거가 필요합니다.** Tauri는 여러 layer의 test를 문서화하며 unit/mock frontend test만으로 packaged webview, OS integration, privileged operation denial을 증명할 수 없습니다. 출처: [Testing](https://v2.tauri.app/develop/tests/), [Mocking](https://v2.tauri.app/develop/tests/mocking/), [WebDriver](https://v2.tauri.app/develop/tests/webdriver/).
8. **Channel과 대용량 응답 IPC에는 version floor가 있습니다.** `2.11.6` 이전에는 대용량 channel 응답이 순차 식별자로 앱 전역 queue에 쌓였고 내부 `plugin:__TAURI_CHANNEL__|fetch` command가 renderer가 보낸 header만으로 정상 ACL 거부 없이 이를 반환해, 다른 webview가 읽거나 비울 수 있었습니다. `2.11.6`은 entry를 소유 webview에 결속하고 식별자를 무작위로 만들며 소유 webview가 닫히면 entry를 정리합니다. `2.12.0`은 닫힌 webview로 보내던 대용량 channel payload를 queue에 남기지 않습니다. 출처: [GHSA-w28w-mhc8-qvjv](https://github.com/tauri-apps/tauri/security/advisories/GHSA-w28w-mhc8-qvjv), [tauri v2.12.0](https://github.com/tauri-apps/tauri/releases/tag/tauri-v2.12.0).
9. **Application permission은 prefix 없는 식별자입니다.** `AppManifest::commands`는 application manifest에 `allow-$command`와 `deny-$command` permission을 자동 생성하고, prefix 없는 capability 항목은 이 manifest에서 해석됩니다. `prefix:base` 식별자는 prefix가 가리키는 plugin manifest를 선택하므로 application permission을 `settings:allow-read`로 쓰면 plugin permission으로 해석되어 ACL build가 실패합니다. 출처: [Permission](https://v2.tauri.app/security/permissions/), [tauri-build ACL source](https://raw.githubusercontent.com/tauri-apps/tauri/dev/crates/tauri-build/src/acl.rs).
10. **WebView permission 요청은 ACL과 별개 layer입니다.** `on_permission_request`는 `PermissionKind`를 받아 `PermissionResponse::{Allow, Deny, Default}`를 반환하며 geolocation, notification, camera/microphone, MIDI, sensor, local font, pointer lock, 자동 다운로드, file system access, autoplay 같은 webview 수준 권한을 다룹니다. 이는 capability가 아니라 webview가 강제하므로 ACL이 이를 대신할 수 없습니다. 출처: [Announcing Tauri 2.12](https://tauri.app/blog/tauri-2.12/), [tauri v2.12.0](https://github.com/tauri-apps/tauri/releases/tag/tauri-v2.12.0).
11. **Capability deny는 2.12.0부터 실행 컨텍스트로 한정됩니다.** 그 이전에는 remote URL에 대해 command를 deny한 capability가 local app에서도 함께 deny했습니다. 따라서 upgrade하면 이전에 막혔던 local 호출이 다시 허용될 수 있으므로 allow/deny 쌍을 다시 테스트해야 합니다. 출처: [tauri v2.12.0](https://github.com/tauri-apps/tauri/releases/tag/tauri-v2.12.0).

## 적용 주의사항

- Registry 확인값은 snapshot이며 version pin 또는 compatibility 보증이 아닙니다. 구현 결정에는 대상 lockfile과 설치 package metadata를 사용합니다.
- 공식 page가 product mechanism을 설명해도 file, credential, signing key, production service access 또는 app publish/release 권한을 부여하지 않습니다. 그런 작업에는 명시적 사용자 권한이 필요합니다.
- 주장을 인용할 때 source URL과 `last_verified_at`을 보존합니다. 오래된 vendor behavior를 새 behavior와 섞지 말고 stale claim을 교체합니다.
- Tauri 3은 pre-release(3.0 alpha)이며 이 스킬의 upgrade 대상이 아닙니다. 예고된 ACL 저장 구조 변경은 2.x 프로젝트의 지침이 아닙니다.
