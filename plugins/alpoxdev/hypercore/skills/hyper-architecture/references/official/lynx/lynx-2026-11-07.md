# Lynx Official Evidence Snapshot

Read when an installed version, a config key, a template file, or an engine compatibility rule decides the change. This snapshot records the official claims this package relies on and the date each was verified.

- last_verified_at: 2026-11-07
- `status`: reviewed from the Lynx documentation site, the `@lynx-js/create-lynx@0.2.1` template tarball, the engine release feed, and npm registry metadata
- `baseline`: engine 4.2.0 (released 2026-10-27, PrimJS 4.2.1); `@lynx-js/react` 0.129.2; `@lynx-js/rspeedy` 0.18.5; `@lynx-js/types` 4.4.2; `@lynx-js/react-rsbuild-plugin` 0.22.2
- `refresh_when`: the installed engine, `@lynx-js/react`, or `@lynx-js/rspeedy` differs materially, or compatibility, threading, or bundle guidance changes
- `authority`: evidence only; user and project instructions and the installed project's own behavior remain authoritative

## Scaffolder

`@lynx-js/create-lynx` supersedes `create-rspeedy`. The changelog for 0.2.0 states that it "supersedes `create-rspeedy`, which now carries a deprecation notice and no longer receives updates."

```bash
# current command
npm create @lynx-js/lynx@latest

# legacy alias still printed in the quick-start page; works today
npm create rspeedy@latest
```

New projects use the first. An existing repository already scaffolded with the second does not need a migration for its own sake.

## Tooling reality

- No official Lynx ESLint plugin exists. `@lynx-js/eslint-plugin-react-lynx` and `@lynx-js/eslint-config` both return 404 on npm as of 2026-11-07.
- The `rslint` template variant ships `@rslint/core` `^0.9.0` with a `rslint.config.ts` that combines `js.configs.recommended`, `ts.configs.recommended`, and `reactHooksPlugin.configs.recommended`, run through `rslint`. The latest `@rslint/core` observed was 0.10.0, so read the installed version rather than hardcoding it.
- The ReactLynx template itself ships no linter and no Prettier config. Prettier appears nowhere in the documentation bundle.
- Oxlint has no Lynx plugin. Its `react/no-unknown-property` rule is DOM-oriented and needs `ignore` entries for Lynx attributes such as `bindtap`, `catchtap`, `main-thread:bindtap`, `item-key`, `list-type`, `span-count`, `scroll-orientation`, and `auto-size`. Config discovery uses `.oxlintrc.json` or `oxlint.config.ts`.
- Any Lynx oxlint configuration is a project choice, not an official Lynx setup.

## Node and platform floors

- Node.js: `^20.19.0 || >=22.12.0`, declared by `@lynx-js/rspeedy` and every scaffolded `package.json`. The quick-start page states "Node.js 20.19 or later. Node.js 22.12 or later is also supported."
- Rspeedy CLI documents Node's native TypeScript stripping at `>=23.6`, `>=22.6` with `--experimental-strip-types`, and `>=22.7` with `--experimental-transform-types`. That is a CLI convenience, not the supported floor.
- Target platforms: iOS 10 and Android 5.0 (API 21) or newer.
- Development OS: macOS recommended; Windows and Linux are "not yet verified or guaranteed" by the engine project.
- Supported runtime platforms today: Android, iOS, Web, OpenHarmony. Desktop through the Clay renderer exists for macOS and Windows; Lynxtron is "Coming soon".
- License: Apache-2.0 for the engine and the frontend stack.

## Verbatim template configs

`lynx.config.ts` from the official ReactLynx TypeScript template, plus the size and verification switches this package recommends:

```ts
import { pluginQRCode } from '@lynx-js/qrcode-rsbuild-plugin';
import { pluginReactLynx } from '@lynx-js/react-rsbuild-plugin';
import { defineConfig } from '@lynx-js/rspeedy';
import { pluginTypeCheck } from '@rsbuild/plugin-type-check';

export default defineConfig({
  source: {
    entry: './src/index.tsx',
  },
  plugins: [
    pluginQRCode({
      schema(url) {
        // `?fullscreen=true` opens the page full screen in Lynx Explorer.
        return `${url}?fullscreen=true`;
      },
    }),
    pluginReactLynx({
      engineVersion: '3.9', // raise only to the lowest host engine you actually ship on
      optimizeBundleSize: { mainThread: true, background: true },
      extractStr: true,
    }),
    pluginTypeCheck(),
  ],
  // Web target is opt-in; without this Rspeedy builds `{ lynx: {} }`.
  // environments: { lynx: {}, web: {} },
});
```

## Compatibility rules

| Rule | Detail |
|---|---|
| `engineVersion` semantics | A bundle declaring N runs on an engine of N or newer; on an older engine it fails fatally with error 10204 |
| `engineVersion` default | `'3.2'` — a floor, not a target |
| `targetSdkVersion` | Legacy alias of `engineVersion`; do not introduce it in new config |
| Lazy bundle floor | A Consumer earlier than 0.115.0 cannot load a lazy bundle built with 0.115.0 or later |
| `FetchBundle` loader | Requires `engineVersion` 3.9 or later |
| `!important` in CSS | Requires `engineVersion` 3.9 or later |
| `flex` shorthand | From 3.9, an omitted `flex-basis` parses as `0%` instead of `0` |
| `position: sticky`, `grid-row`/`grid-column` shorthands, HarmonyOS motion path | Added in 3.9 |
| Trace | Supported from engine 3.4 on Android, iOS, and HarmonyOS |
| WebAssembly | From 3.8, Android only, background thread only |
| Main-thread syntax ceiling | ES2019 |
| Background-thread syntax ceiling | ES2015 |
| Polyfills | Injected on iOS only |
| `useLayoutEffect` | Alias of `useEffect` per the API index; called unsupported by the lifecycle page |
| React API level | ReactLynx exposes the React v17 API surface; `@lynx-js/react/compat` adds React 18 APIs such as `startTransition` |

## Unverified items

These were not confirmed by a documentation page or changelog entry at the time of writing. State them as unverified or omit them; never assert them as rules.

- The exact `@lynx-js/react` minor to engine minor mapping. No matrix exists.
- Whether React hooks other than `useMainThreadRef` may be called inside a `'main thread'` function.
- Whether `'background only'` (space) and `background-only` (hyphen) compile identically. Both spellings appear across docs.
- `Suspense` and transition semantics: whether they follow React 17 or React 18 behavior.
- `@lynx-js/lynx-ui` compatibility with a given engine or ReactLynx version.
- Lynx for Web production readiness; `@lynx-js/web-core` is at 0.26.7 against an engine of 4.2 with no readiness statement.
- Node 24 and npm 11 specifically; only `^20.19.0 || >=22.12.0` is asserted.
- The Oxlint `react/no-unknown-property` ignore list for Lynx attributes; the attribute names are documented but the rule configuration is this package's own.
- Desktop host architecture for macOS and Windows; Lynxtron is "Coming soon".
