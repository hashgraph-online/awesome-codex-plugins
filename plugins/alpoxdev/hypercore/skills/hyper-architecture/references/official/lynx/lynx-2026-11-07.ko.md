# Lynx 공식 증거 Snapshot

설치된 version, config key, template file, engine 호환 규칙이 변경을 좌우할 때 읽습니다. 이 snapshot은 이 패키지가 의존하는 공식 주장과 각각의 확인 날짜를 기록합니다.

- last_verified_at: 2026-11-07
- `status`: Lynx 문서 site, `@lynx-js/create-lynx@0.2.1` template tarball, engine release feed, npm registry metadata에서 검토
- `baseline`: engine 4.2.0 (2026-10-27 release, PrimJS 4.2.1); `@lynx-js/react` 0.129.2; `@lynx-js/rspeedy` 0.18.5; `@lynx-js/types` 4.4.2; `@lynx-js/react-rsbuild-plugin` 0.22.2
- `refresh_when`: 설치 engine, `@lynx-js/react`, `@lynx-js/rspeedy`가 크게 다르거나 compatibility, threading, bundle 지침이 바뀔 때
- `authority`: 증거 전용. 사용자와 project 지시, 설치 project의 실제 동작이 계속 우선합니다

## Scaffolder

`@lynx-js/create-lynx`가 `create-rspeedy`를 대체합니다. 0.2.0 changelog는 그것이 "`create-rspeedy`를 대체하며, 그 package는 이제 deprecation 안내를 달고 더 이상 update를 받지 않는다"고 적습니다.

```bash
# 현재 command
npm create @lynx-js/lynx@latest

# Quick-start page가 아직 안내하는 legacy alias. 오늘은 동작
npm create rspeedy@latest
```

새 project는 첫 번째를 씁니다. 두 번째로 이미 scaffold된 기존 repository는 그것만을 이유로 migration할 필요가 없습니다.

## Tooling 현실

- 공식 Lynx ESLint plugin은 없습니다. 2026-11-07 기준 `@lynx-js/eslint-plugin-react-lynx`와 `@lynx-js/eslint-config`가 npm에서 404입니다.
- `rslint` template variant는 `@rslint/core` `^0.9.0`과 `rslint.config.ts`를 제공합니다. `js.configs.recommended`, `ts.configs.recommended`, `reactHooksPlugin.configs.recommended`를 조합하고 `rslint`로 실행합니다. 관측된 최신 `@rslint/core`는 0.10.0이므로 hardcode하지 말고 설치 version을 읽습니다.
- ReactLynx template 자체는 linter도 Prettier config도 제공하지 않습니다. 문서 bundle 어디에도 Prettier가 나오지 않습니다.
- Oxlint에는 Lynx plugin이 없습니다. `react/no-unknown-property` rule은 DOM 지향이므로 `bindtap`, `catchtap`, `main-thread:bindtap`, `item-key`, `list-type`, `span-count`, `scroll-orientation`, `auto-size` 같은 Lynx attribute를 `ignore` 항목으로 넣어야 합니다. Config 탐색은 `.oxlintrc.json` 또는 `oxlint.config.ts`를 씁니다.
- Lynx용 oxlint 설정은 공식 Lynx 구성이 아니라 project 선택입니다.

## Node와 platform 하한

- Node.js: `^20.19.0 || >=22.12.0`. `@lynx-js/rspeedy`와 모든 scaffold된 `package.json`이 선언합니다. Quick-start page는 "Node.js 20.19 이상. Node.js 22.12 이상도 지원"이라고 적습니다.
- Rspeedy CLI는 `>=23.6`, `>=22.6`에 `--experimental-strip-types`, `>=22.7`에 `--experimental-transform-types`를 붙인 Node native TypeScript stripping을 문서화합니다. CLI 편의이지 지원 하한이 아닙니다.
- Target platform: iOS 10과 Android 5.0(API 21) 이상.
- 개발 OS: macOS 권장. Windows와 Linux는 engine project가 "아직 검증하거나 보장하지 않음"으로 적습니다.
- 현재 지원 runtime platform: Android, iOS, Web, OpenHarmony. macOS와 Windows용 Clay renderer 기반 desktop이 존재하고 Lynxtron은 "Coming soon"입니다.
- License: engine과 frontend stack 모두 Apache-2.0.

`rspeedy inspect`는 resolve된 Rsbuild와 Rspack config를 출력하며 config 주장을 확인하는 공인된 방법입니다.

## Verbatim template config

공식 ReactLynx TypeScript template의 `lynx.config.ts`에 이 패키지가 권장하는 크기 및 검증 switch를 더한 것입니다.

```ts
import { pluginQRCode } from '@lynx-js/qrcode-rsbuild-plugin';
import { pluginReactLynx } from '@lynx-js/react-rsbuild-plugin';
import { defineConfig } from '@lynx-js/rspeedy';
import { pluginTypeCheck } from '@rsbuild/plugin-type-check';

export default defineConfig({
  source: {
    entry: './src/index.tsx',
  },
  plugins: [
    pluginQRCode({
      schema(url) {
        // `?fullscreen=true` opens the page full screen in Lynx Explorer.
        return `${url}?fullscreen=true`;
      },
    }),
    pluginReactLynx({
      engineVersion: '3.9', // raise only to the lowest host engine you actually ship on
      optimizeBundleSize: { mainThread: true, background: true },
      extractStr: true,
    }),
    pluginTypeCheck(),
  ],
  // Web target is opt-in; without this Rspeedy builds `{ lynx: {} }`.
  // environments: { lynx: {}, web: {} },
});
```

`tsconfig.json`. Template이 제공하는 그대로입니다.

```json
{
  "compilerOptions": {
    "strict": true,
    "isolatedModules": true,
    "verbatimModuleSyntax": true,
    "esModuleInterop": true,
    "skipLibCheck": true
  },
  "references": [{ "path": "./tsconfig.node.json" }, { "path": "./src" }],
  "files": []
}
```

`tsconfig.node.json`:

```json
{
  "extends": "./tsconfig.json",
```

## Compatibility 규칙

| 규칙 | 세부 |
|---|---|
| `engineVersion` 의미 | N을 선언한 bundle은 N 이상 engine에서 실행. 구형 engine에서는 fatal error 10204로 실패 |
| `engineVersion` default | `'3.2'`. 하한이지 target이 아님 |
| `targetSdkVersion` | `engineVersion`의 legacy alias. 새 config에서 도입하지 않음 |
| Lazy bundle 하한 | 0.115.0 이전 Consumer는 0.115.0 이후로 build한 lazy bundle을 load할 수 없음 |
| `FetchBundle` loader | `engineVersion` 3.9 이상 필요 |
| CSS `!important` | `engineVersion` 3.9 이상 필요 |
| `flex` shorthand | 3.9부터 `flex-basis` 생략 시 `0`이 아니라 `0%`로 parse |
| `position: sticky`, `grid-row`/`grid-column` shorthand, HarmonyOS motion path | 3.9에서 추가 |
| Trace | engine 3.4부터 Android, iOS, HarmonyOS에서 지원 |
| WebAssembly | 3.8부터 Android 전용, background thread 전용 |
| Main-thread 문법 상한 | ES2019 |
| Background-thread 문법 상한 | ES2015 |
| Polyfill | iOS에만 주입 |
| `useLayoutEffect` | API index는 `useEffect` alias, lifecycle page는 미지원으로 서술 |
| React API 수준 | ReactLynx는 React v17 API surface를 노출. `@lynx-js/react/compat`가 `startTransition` 같은 React 18 API를 추가 |

## 미확인 항목

글을 쓰는 시점에 문서 page나 changelog 항목으로 확인하지 못한 것들입니다. 미확인으로 표시하거나 생략하며, 규칙으로 단정하지 않습니다.

- `@lynx-js/react` minor와 engine minor의 정확한 대응. Matrix가 없습니다.
- `useMainThreadRef` 외의 React hook을 `'main thread'` function 안에서 호출할 수 있는지.
- `'background only'`(공백)와 `background-only`(hyphen)가 동일하게 compile되는지. 문서 전체에 두 표기가 나타납니다.
- `Suspense`와 transition 의미가 React 17 동작인지 React 18 동작인지.
- `@lynx-js/lynx-ui`가 특정 engine이나 ReactLynx version과 호환되는지.
- Lynx for Web의 production 준비 상태. `@lynx-js/web-core`는 engine 4.2에 대해 0.26.7이고 준비 서술이 없습니다.
- Node 24와 npm 11의 구체 동작. `^20.19.0 || >=22.12.0`만 단정됩니다.
- Lynx attribute에 대한 Oxlint `react/no-unknown-property` ignore 목록. Attribute 이름은 문서화됐지만 rule 설정은 이 패키지의 것입니다.
- macOS와 Windows desktop host 구조. Lynxtron은 "Coming soon"입니다.
