설치된 Astro 버전, 설정 키, 호환성 파괴 변경, 런타임 하한이 변경을 좌우할 때 읽습니다. 이 스냅숏은 이 패키지가 의존하는 공식 주장과 각 항목을 확인한 날짜를 기록합니다.

- `baseline`: `astro` 7.4.7(2026-11-05 배포), Node `>=22.23.4`, Vite `^8.3.5`, `@astrojs/node` 11.1.11, `@astrojs/vercel` 11.0.20, `@astrojs/cloudflare` 14.4.6, `@astrojs/netlify` 8.2.12, `@astrojs/react` 7.1.4, `@astrojs/mdx` 8.1.3, `@astrojs/check` 0.9.12, `prettier-plugin-astro` 1.1.2

- `authority`: 근거일 뿐입니다. 사용자와 프로젝트 지시, 설치된 프로젝트 자체의 동작이 여전히 권위를 갖습니다.

## Node and toolchain floors

- Node `>=22.23.4`. 설치 페이지는 v23 같은 홀수 버전을 지원하지 않는다고 덧붙입니다(L-04).
- Node 18과 20 지원은 6.0에서 제거됐고, 당시 최소값은 22.12.0이었습니다(L-02).
- Rolldown 번들러를 쓰는 Vite 8이 7.0에서 Vite 7을 대체했습니다(L-01, L-41, L-49).
- TypeScript는 Astro가 직접 고정하지 않지만, `astro check`는 `@astrojs/check`와 TypeScript `^5 || ^6`을 요구하고 7.0을 거부합니다(L-51, L-52).

## Breaking changes v5 → v6 → v7

### 5.0

- `output: 'hybrid'`가 제거되고 `'static'`이 hybrid 동작을 흡수해, 정적 사이트도 개별 라우트를 서버 렌더링으로 선택할 수 있게 됐습니다(L-03).

### 6.0

- Node 22 최소, Vite 7, Shiki 4, Vite Environment API 재편(L-02).
- Zod 4: `z.string().email()`이 `z.email()`이 되고, `{ message }`가 `{ error }`가 되며, 기본값이 출력 타입과 맞아야 하고, `.prefault()`가 파싱된 기본값을 제공합니다(L-02).
- 레거시 콘텐츠 컬렉션이 제거되어 콘텐츠 계층이 필수가 됐습니다. `src/content/config.ts`는 더 이상 유효한 위치가 아닙니다.
- `<ViewTransitions />`, `Astro.glob()`, `astro:schema`, `astro:content`의 `z` 재export가 제거됐습니다.
- `getStaticPaths()` 안의 `Astro`가 폐기됐습니다. `Astro.site` 대신 `import.meta.env.SITE`를 씁니다.

### 7.0

- Rust `.astro` 컴파일러가 기본이자 유일한 컴파일러입니다. 닫히지 않은 태그는 오류가 되고 잘못된 HTML 중첩은 더 이상 자동 교정되지 않습니다(L-01, L-41).
- 기본 `compressHTML`이 `true`에서 `'jsx'`로 바뀌어 인라인 요소 사이 공백이 JSX 방식으로 제거됩니다. `compressHTML: true`나 명시적 `{" "}`로 되돌립니다.
- Sätteri(네이티브)가 기본 Markdown 처리기이고 `@astrojs/markdown-remark`는 더 이상 기본 설치되지 않습니다. remark와 rehype 플러그인을 유지하려면 `markdown.processor: unified()`를 설정하고 `@astrojs/markdown-remark`를 설치합니다.
- 실험 플래그 `logger`, `queuedRendering`, `rustCompiler`, `advancedRouting`, `cache`/`routeRules`가 안정화되어 최상위로 이동했습니다. `experimental` 안에 남겨 두면 유효하지 않습니다.
- `src/fetch.ts`가 고급 라우팅용 예약 파일 이름이 됐습니다. `fetchFile`이 이름을 바꾸거나 비활성화합니다(L-01, L-06, L-17).
- `@astrojs/db`가 제거됐습니다. `node:sqlite`, Drizzle, 플랫폼 데이터베이스를 씁니다.
- `astro:transitions` 내부가 제거됐습니다. `TRANSITION_*` 상수, `isTransitionBefore*Event`, `createAnimationScope`입니다.
- `getContainerRenderer()`가 통합 패키지 루트에서 `@astrojs/react/container-renderer`로 이동했습니다(preact, solid-js, svelte, vue, mdx도 같습니다).

## Rendering and routing facts

- `output`은 `'static'` 또는 `'server'`뿐이고, `'server'`는 "does not bring any additional functionality. It only switches the default rendering behavior."입니다(L-17, L-09).
- 라우트별 `export const prerender = false`(정적 모드) 또는 `= true`(서버 모드)는 정적으로 분석 가능해야 합니다.
- 온디맨드 라우트에는 어댑터가 필요하고, `server:defer` 서버 아일랜드와 라이브 컬렉션도 마찬가지입니다.
- 온디맨드 라우트의 HTML은 기본적으로 스트리밍되며 응답 헤더는 페이지 수준에서만 수정할 수 있습니다.
- 파일 기반 라우팅은 `.astro`, `.md`, `.mdx` 페이지와 `.js`/`.ts` 엔드포인트를 포함합니다. `[param]`은 한 세그먼트, `[...rest]`는 나머지 경로를 매칭합니다(L-06, L-05).
- 라우트 우선순위: 예약 라우트, 세그먼트가 많은 쪽, 정적 우선 동적, 명명 파라미터 우선 rest, 프리렌더 동적 우선 온디맨드 동적, 엔드포인트 우선 페이지, 파일 라우트 우선 리다이렉트.
- 예약 라우트 접두사: `_astro/`, `_server_islands/`, `_actions/`.
- `src/pages/404.astro`는 `404.html`을 만들고, `src/pages/500.astro`는 온디맨드 전용이며 `error` prop을 받습니다(L-37).
- `Astro.rewrite()`는 브라우저 URL을 유지하고 미들웨어를 포함한 전체 렌더 단계를 다시 돕니다.
- 기본 `src/fetch.ts` 파이프라인 순서는 트레일링 슬래시 정규화, 리다이렉트, 세션, 액션, 사용자 미들웨어, 페이지 렌더링, i18n, 캐싱입니다.

## Content, Actions, and environment facts

- `src/content.config.ts`가 `collections`를 export하고, 각 항목은 필수 `loader`(`glob()` 또는 `file()`)와 선택적 Zod `schema`를 가집니다. `z`는 `astro/zod`에서 옵니다(L-10).
- `deferRender: true`(7.1)는 빌드 메모리를 줄이려고 Markdown 렌더링을 미룹니다.
- `getCollection()` 순서는 비결정적이므로 명시적으로 정렬합니다.
- 라이브 컬렉션은 `src/live.config.ts`, `defineLiveCollection()`, 커스텀 로더, 어댑터를 씁니다.
- Actions는 `src/actions/index.ts`에 있고 `/_actions/<name>`으로 공개되며 서버 출력을 요구합니다(L-11, L-12, L-57).
- 미들웨어는 명명된 `onRequest`를 export하고 `sequence()`로 조합하며 타입이 붙은 `context.locals`로 상태를 공유합니다(L-13).
- 세션(5.7+)에는 드라이버가 필요합니다. Node, Cloudflare, Netlify 어댑터는 기본 드라이버를 제공하고 Vercel은 제공하지 않습니다. `session: false`(7.2+)는 세션을 제거합니다(L-14, L-50).
- `env.schema`는 `envField.string|number|boolean|enum`을 쓰고, 클라이언트 문맥의 비밀 값은 설계상 불가능합니다(L-15).
- `security.checkOrigin`은 기본값이 `true`이고 안전하지 않은 메서드에 대해 `Sec-Fetch-Site`를 `Origin` 대체와 함께 확인합니다(L-17).

## Tooling facts

- `astro dev`와 `astro build`는 타입 검사를 하지 않고 `astro check`가 하며 오류 시 종료 코드 1을 냅니다(L-26, L-28).
- `astro check`는 `@astrojs/check`와 `typescript`가 필요하고 TypeScript 7.0을 폐기 예고와 함께 거부합니다(L-51).
- `astro sync`는 `astro:content`, `astro:env`, `astro:actions`용 `.astro/types.d.ts`를 생성합니다.
- Prettier는 `prettier-plugin-astro`와 `*.astro` parser override로 `.astro`를 포맷합니다(L-40).
- Oxlint는 `.astro` 파일의 `<script>` 블록만 lint하고 템플릿 lint가 없습니다(L-43, L-44).
- Oxfmt는 Prettier 기반 경로로 `.astro`에 도달하며 `@astrojs/compiler-rs`와 `astro` 옵션이 필요합니다(L-45, L-46).
- Vitest 통합은 `astro/config`의 `getViteConfig()`를 쓰고, 컴포넌트 테스트는 `experimental_AstroContainer`를 씁니다(L-25, L-27).

## Unverified items

작성 시점에 공식 페이지나 패키지 타입으로 확인되지 않은 항목입니다. 미확인으로 표시하거나 빼야 하며, 규칙으로 단정하지 않습니다.

- 라이브 로더 캐시 힌트에 쓰는 `Astro.cache.set(entry)`의 정확한 타입 형태. 7.0 포스트는 그 형태를 보여 주지만 캐싱 가이드는 명시적 옵션 객체만 문서화합니다.
- `security.csp`가 어떤 어댑터에서든 실제 HTTP 헤더를 낼 수 있는지. 문서화된 것은 `<meta>` 방식뿐입니다.
- 라이브 로더 API의 전체 시그니처(`loadCollection`/`loadEntry` 반환 타입과 오류 봉투). 산문만 있습니다.
- `compressHTML: 'jsx'`가 `.mdx` 출력의 공백을 `.astro`와 다르게 바꾸는지.
- `@astrojs/ts-content-mapper`의 성숙도. 0.2.0 실험이고 `astro check` 폐기는 버전 없이 예고됐습니다.
- `image.layout`이 `public/` 파일에 적용되는지. 문서는 그 이미지가 절대 최적화되지 않는다고 하지만 설정 상호작용은 밝히지 않습니다.
- `astro check`가 폐기 예고 뒤에도 타입 게이트로 남는다는 주장.
