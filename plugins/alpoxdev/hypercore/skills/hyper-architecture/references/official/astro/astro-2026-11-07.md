## Node and toolchain floors

- Node `>=22.23.4`. The install page adds that odd-numbered versions such as v23 are not supported (L-04).
- Node 18 and 20 support was dropped in 6.0, which required 22.12.0 at the time (L-02).
- Vite 8 with the Rolldown bundler replaced Vite 7 in 7.0 (L-01, L-41, L-49).
- TypeScript is not pinned by Astro itself, but `astro check` requires `@astrojs/check` plus TypeScript `^5 || ^6` and rejects 7.0 (L-51, L-52).

## Breaking changes v5 → v6 → v7

### 5.0

- `output: 'hybrid'` was removed; `'static'` absorbed hybrid behavior, so a static site can opt individual routes into server rendering (L-03).

### 6.0

- Node 22 minimum, Vite 7, Shiki 4, and the Vite Environment API refactor (L-02).
- Zod 4: `z.string().email()` becomes `z.email()`, `{ message }` becomes `{ error }`, defaults must match the output type, and `.prefault()` supplies parsed defaults (L-02).
- Legacy content collections were removed; the Content Layer is mandatory. `src/content/config.ts` is no longer a valid location.
- `<ViewTransitions />`, `Astro.glob()`, `astro:schema`, and the `z` re-export from `astro:content` were removed.
- `Astro` inside `getStaticPaths()` was deprecated; use `import.meta.env.SITE` instead of `Astro.site`.

### 7.0

- The Rust `.astro` compiler is the default and only compiler. Unclosed tags now error and invalid HTML nesting is no longer auto-corrected (L-01, L-41).
- Default `compressHTML` changed from `true` to `'jsx'`, so whitespace between inline elements is stripped JSX-style. Restore with `compressHTML: true` or an explicit `{" "}`.
- Sätteri (native) is the default Markdown processor; `@astrojs/markdown-remark` is no longer installed by default. To keep remark and rehype plugins, set `markdown.processor: unified()` and install `@astrojs/markdown-remark`.
- Experimental flags `logger`, `queuedRendering`, `rustCompiler`, `advancedRouting`, and `cache`/`routeRules` became stable and moved to top level. Leaving them inside `experimental` is invalid.
- `src/fetch.ts` became a reserved file name for advanced routing; `fetchFile` renames or disables it (L-01, L-06, L-17).
- `@astrojs/db` was removed; use `node:sqlite`, Drizzle, or a platform database.
- `astro:transitions` internals were removed: `TRANSITION_*` constants, `isTransitionBefore*Event`, and `createAnimationScope`.
- `getContainerRenderer()` moved from the integration package root to `@astrojs/react/container-renderer` (same for preact, solid-js, svelte, vue, mdx).

## Rendering and routing facts

- `output` is only `'static'` or `'server'`; `'server'` "does not bring any additional functionality. It only switches the default rendering behavior." (L-17, L-09)
- Per-route `export const prerender = false` (static mode) or `= true` (server mode) must be statically analyzable.
- Any on-demand route needs an adapter, as do `server:defer` server islands and live collections.
- HTML streams by default on on-demand routes, and response headers can only be modified at page level.
- File-based routing covers `.astro`, `.md`, and `.mdx` pages plus `.js`/`.ts` endpoints. `[param]` matches one segment, `[...rest]` matches the rest (L-06, L-05).
- Route priority: reserved routes, more segments, static over dynamic, named params over rest, prerendered dynamic over on-demand dynamic, endpoints over pages, file routes over redirects.
- Reserved route prefixes: `_astro/`, `_server_islands/`, `_actions/`.
- `src/pages/404.astro` builds `404.html`; `src/pages/500.astro` is on-demand only and receives an `error` prop (L-37).
- `Astro.rewrite()` keeps the browser URL and re-runs the full render phase including middleware.
- The default `src/fetch.ts` pipeline order is trailing-slash normalization, redirects, sessions, actions, user middleware, page rendering, i18n, caching.

## Content, Actions, and environment facts

- `src/content.config.ts` exports `collections` with a required `loader` (`glob()` or `file()`) and an optional Zod `schema`. `z` comes from `astro/zod` (L-10).
- `deferRender: true` (7.1) defers Markdown rendering to cut build memory.
- `getCollection()` order is non-deterministic; sort explicitly.
- Live collections use `src/live.config.ts`, `defineLiveCollection()`, a custom loader, and an adapter.
- Actions live in `src/actions/index.ts`, are public at `/_actions/<name>`, and require server output (L-11, L-12, L-57).
- Middleware exports a named `onRequest`, composes with `sequence()`, and shares state through typed `context.locals` (L-13).
- Sessions (5.7+) need a driver; Node, Cloudflare, and Netlify adapters default one, Vercel does not. `session: false` (7.2+) removes it (L-14, L-50).
- `env.schema` uses `envField.string|number|boolean|enum`, and a client-context secret is impossible by design (L-15).
- `security.checkOrigin` defaults to `true` and checks `Sec-Fetch-Site` with an `Origin` fallback for unsafe methods (L-17).

## Tooling facts

- `astro dev` and `astro build` do not type-check; `astro check` does and exits 1 (L-26, L-28).
- `astro check` needs `@astrojs/check` and `typescript`, and refuses TypeScript 7.0 with a deprecation notice (L-51).
- `astro sync` generates `.astro/types.d.ts` for `astro:content`, `astro:env`, and `astro:actions`.
- Prettier formats `.astro` through `prettier-plugin-astro` with a `*.astro` parser override (L-40).
- Oxlint lints only `<script>` blocks in `.astro` files and has no template linting (L-43, L-44).
- Oxfmt reaches `.astro` through the Prettier-backed path and needs `@astrojs/compiler-rs` plus the `astro` option (L-45, L-46).
- Vitest integration uses `getViteConfig()` from `astro/config`; component tests use `experimental_AstroContainer` (L-25, L-27).

## Unverified items

These were not confirmed by an official page or package type at the time of writing. State them as unverified or omit them; never assert them as rules.

- The exact typed shape of `Astro.cache.set(entry)` for live loader cache hints. The 7.0 post shows the form; the caching guide documents only the explicit options object.
- Whether `security.csp` can emit a real HTTP header on any adapter. Only the `<meta>` mechanism is documented.
- The full live loader API signature (`loadCollection`/`loadEntry` return types and the error envelope); only prose exists.
- Whether `compressHTML: 'jsx'` changes `.mdx` spacing in a way that differs from `.astro`.
- `@astrojs/ts-content-mapper` maturity: 0.2.0, experimental, and the `astro check` deprecation is announced without a version.
- Whether `image.layout` applies to files in `public/`; docs say those images are never optimized, but the config interaction is not spelled out.
- Any claim that `astro check` remains the type gate after its announced deprecation.
