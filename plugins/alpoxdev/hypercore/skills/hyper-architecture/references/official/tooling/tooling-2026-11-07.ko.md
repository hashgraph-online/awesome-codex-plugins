|---|---|

| `tabWidth` | 2 |
| `semi` | true |
| `singleQuote` | false |
| `trailingComma` | "all" |

- config file 이름은 `.prettierrc`, `.prettierrc.json`, `.prettierrc.yml`, `prettier.config.{js,mjs,cjs,ts,mts,cts}`, `.prettierrc.toml`, `package.json`의 `"prettier"` key입니다. 탐색은 format 대상 file에서 위로 올라갑니다.
- `printWidth`는 hard maximum이 아니라고 명시돼 있습니다.
- `.editorconfig`의 `max_line_length`, `indent_size`, `end_of_line`은 덮지 않으면 Prettier에 반영됩니다.
- CLI는 `--check`(format이 남으면 non-zero), `--write`, `--list-different`, `--log-level`입니다.
- `.prettierignore`는 gitignore 문법을 쓰고, Prettier는 같은 directory의 `.gitignore`도 따릅니다.
- `prettier-plugin-tailwindcss`는 마지막 plugin이어야 하고 Tailwind v4에서는 `tailwindStylesheet`를 설정합니다.
- `prettier-plugin-astro`는 `plugins: ["prettier-plugin-astro"]`와 override `{files: "*.astro", options: {parser: "astro"}}`가 필요합니다.
- `@ianvs/prettier-plugin-sort-imports`는 oxlint `import/*` rule이 있으면 필요 없고, 마지막이어야 하는 Tailwind plugin과 위치가 충돌합니다.
- `eslint-config-prettier`는 hybrid ESLint repository에서만 의미가 있고 마지막에 둡니다.

## Framework 차이

Next.js 16:

- `next lint` 제거, `next build`가 더는 lint하지 않고 Next config의 `eslint` option도 제거됐습니다.
- 이전 codemod는 `npx @next/codemod@canary next-lint-to-eslint-cli`입니다.
- 지원 경로는 `eslint` + `eslint-config-next`와 `defineConfig([...nextVitals, globalIgnores([...])])`입니다.
- 넘겨야 하는 기본 ignore는 `.next/**`, `out/**`, `build/**`, `next-env.d.ts`입니다.
- `eslint-config-next`는 ESLint 9와 10을 지원합니다.
- Oxlint는 `nextjs` plugin으로 Next rule을 덮을 수 있습니다.

Expo:

- `npx expo lint`는 ESLint를 설치하고 `eslint-config-expo`를 extend하는 flat `eslint.config.js`를 만들며, 명령 자체는 `lint` script만 실행합니다.
- `eslint-config-expo`는 oxlint로 대체할 수 없습니다. Expo rule과 RN global이 그 ESLint config에 있습니다.
- 실제 설정은 `oxlint && npx expo lint`이고 `eslint-plugin-oxlint`가 중복을 끕니다.
- `expo/tsconfig.base`는 `module: "preserve"`, `moduleDetection: "force"`, `moduleResolution: "bundler"`, `customConditions: ["react-native"]`, `jsx: "react-jsx"`, `noEmit`, `skipLibCheck`, ESNext target과 lib을 설정합니다.

Astro:

- `astro check`는 `@astrojs/check`와 `typescript`를 요구하고 TypeScript 7.0을 명시적 message와 함께 거부하며, 그 명령이 향후 Astro release에서 deprecate된다고 적습니다.
- `@astrojs/check` 0.9.12의 peer는 `typescript ^5 || ^6`이고 최신 6.x는 6.0.3입니다.
- TypeScript 7.1+ 지원 경로는 `@astrojs/ts-content-mapper` 0.2.0과 `tsc --noEmit --runExternalCode`입니다.
- `tsconfig.json`은 `astro/tsconfigs/base|strict|strictest`를 extend하고 strictest는 `noUnusedLocals`, `noUnusedParameters`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitReturns`, `noImplicitOverride`, `noFallthroughCasesInSwitch`를 더합니다.
- Oxlint는 `.astro`의 `<script>` block만 lint하고 호환성 표는 "No template linting yet"입니다.
- Prettier는 `prettier-plugin-astro`와 `*.astro` parser override가 필요합니다.

Lynx:

- 자사 ESLint plugin이 없고 ReactLynx template에는 linter도 Prettier config도 없습니다.
- scaffold linter template은 Rslint(`@rslint/core` `^0.9.0`, 최신 0.10.0)입니다.
- Oxlint는 `.ts`/`.tsx`를 일반 TSX로 lint하고 Lynx plugin은 없습니다.
- `react/no-unknown-property`는 DOM 기준이라 Lynx attribute에서 false positive를 냅니다.
- 생성된 `src/tsconfig.json`은 `jsx: "react-jsx"`, `jsxImportSource: "@lynx-js/react"`, `types: ["@lynx-js/rspeedy/client"]`, `module: "ESNext"`, `moduleResolution: "Bundler"`, `noEmit: true`이고 template의 `engines.node`는 `"^20.19.0 || >=22.12.0"`입니다.

## Repo glue

- EditorConfig 표준 property는 `end_of_line`, `insert_final_newline`, `trim_trailing_whitespace`, `indent_style`, `indent_size`, `charset`이고, `root = true`인 root file 하나를 둡니다.
- gitattributes의 `* text=auto`는 줄바꿈을 정규화하고 확장자별 `eol`이 이를 덮습니다.
- lefthook은 1.10.0부터 `jobs:`, 1.10.10부터 `glob` list, `pre-commit`에서만 `stage_fixed`, `pre-commit`/`pre-push`에서 `root` 경로 filtering을 지원합니다.
- Corepack은 Node 14.19.0부터 25.0.0 미만까지 Node에 포함됩니다. `packageManager`는 `name@x.y.z`이고 `name`은 `yarn`/`npm`/`pnpm`입니다. hash는 선택이며 권장되고 `devEngines.packageManager`는 Corepack이 검증합니다.
- Node 고정은 `engines.node`와 `.node-version`/`.nvmrc`로 하며 어느 것도 Node가 강제하지 않습니다.

## 미확인 항목

- Prettier VS Code extension의 marketplace id는 이 snapshot에서 자체 listing으로 확인하지 않았습니다. 기억으로 인용하지 않습니다.
- 공식 Biome → oxlint migrator를 찾지 못했습니다. `rules/setup/typescript.md`의 표는 이 패키지의 변환 mapping입니다.
- Oxlint `react-perf`의 개별 rule 이름은 확인하지 않았습니다. plugin을 켠 뒤 설치본의 rule 목록을 읽고 이름을 씁니다.
- Astro가 `astro check`를 deprecate하는 시점은 "in a future Astro release"로만 적혀 있고 version이 정해지지 않았습니다.
- Lynx의 `react/no-unknown-property` `ignore` 목록은 공개된 Lynx lint config가 아니라 문서에서 본 attribute 이름에서 가져왔습니다.
- oxfmt 1.0 시점과 native Astro formatter는 열린 항목입니다(Oxc issue #28267). 그 전까지 Prettier가 권장입니다.
