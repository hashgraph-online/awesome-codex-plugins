- `eslint-config-prettier` matters only in a hybrid ESLint repository and must be last.

## Framework deltas

Next.js 16:

- `next lint` removed, `next build` no longer lints, the `eslint` option in the Next config removed.
- Migration codemod: `npx @next/codemod@canary next-lint-to-eslint-cli`.
- Supported path: `eslint` + `eslint-config-next` with `defineConfig([...nextVitals, globalIgnores([...])])`.
- Default ignores to carry over: `.next/**`, `out/**`, `build/**`, `next-env.d.ts`.
- `eslint-config-next` supports ESLint 9 and 10.
- Oxlint can cover the Next rules through its `nextjs` plugin.

Expo:

- `npx expo lint` installs and configures ESLint and creates a flat `eslint.config.js` extending `eslint-config-expo`; the command only runs the `lint` script.
- `eslint-config-expo` cannot be replaced by oxlint: Expo rules and RN globals live in that ESLint config.
- Practical setup: `oxlint && npx expo lint` with `eslint-plugin-oxlint` disabling overlap.
- `expo/tsconfig.base` sets `module: "preserve"`, `moduleDetection: "force"`, `moduleResolution: "bundler"`, `customConditions: ["react-native"]`, `jsx: "react-jsx"`, `noEmit`, `skipLibCheck`, ESNext target and lib.

Astro:

- `astro check` requires `@astrojs/check` and `typescript`; it refuses TypeScript 7.0 with an explicit message and says the command will be deprecated in a future release.
- `@astrojs/check` 0.9.12 peers on `typescript ^5 || ^6`; latest 6.x is 6.0.3.
- TypeScript 7.1+ support route: `@astrojs/ts-content-mapper` 0.2.0 and `tsc --noEmit --runExternalCode`.
- `tsconfig.json` extends `astro/tsconfigs/base|strict|strictest`; strictest adds `noUnusedLocals`, `noUnusedParameters`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitReturns`, `noImplicitOverride`, `noFallthroughCasesInSwitch`.
- Oxlint lints only `<script>` blocks in `.astro`; the compatibility matrix says "No template linting yet".
- Prettier needs `prettier-plugin-astro` plus the `*.astro` parser override.

Lynx:

- No first-party ESLint plugin; the ReactLynx template ships no linter and no Prettier config.
- Scaffold linter template is Rslint (`@rslint/core` `^0.9.0`, latest 0.10.0).
- Oxlint lints `.ts`/`.tsx` as ordinary TSX; it has no Lynx plugin.
- `react/no-unknown-property` is DOM-oriented and false-positives on Lynx attributes.
- The generated `src/tsconfig.json` sets `jsx: "react-jsx"`, `jsxImportSource: "@lynx-js/react"`, `types: ["@lynx-js/rspeedy/client"]`, `module: "ESNext"`, `moduleResolution: "Bundler"`, `noEmit: true`; the template sets `engines.node: "^20.19.0 || >=22.12.0"`.

| Fact | Detail |
|---|---|
| Stable rustc/cargo | 1.99.1 |
| rustfmt stable keys | `edition`, `style_edition`, `max_width`, `hard_tabs`, `tab_spaces`, `newline_style`, `reorder_imports`, `use_field_init_shorthand`, `use_small_heuristics` |
| rustfmt nightly-only keys | `imports_granularity` (#4991), `group_imports` (#5083), `trailing_comma` (#3379), `struct_field_align_threshold` (#3371), `format_code_in_doc_comments` (#3348), `unstable_features` (#3387) |
| rustfmt defaults | `max_width` 100, `hard_tabs` false, `tab_spaces` 4, `reorder_imports` true |
| `cargo fmt --all --check` | `--all` includes local path dependencies; `--check` exits 1 when changes would be made |
| Direct `rustfmt` edition | Defaults to 2015, so set `edition` in `rustfmt.toml` |
| Clippy groups | `correctness` deny-default; `suspicious`, `complexity`, `perf`, `style` warn-default; `pedantic`, `restriction` allow-default; `restriction` not recommended as a whole |
| `[lints]` priority | `priority` is signed; negative numbers have lower priority, so a group at `-1` loses to lints at `0` |
| Workspace inheritance | `[workspace.lints.*]` plus `[lints] workspace = true`; MSRV respected since 1.74 |
| `clippy.toml` MSRV | `msrv = "1.30.0"` form; patch may be omitted |
| Fail on warnings | `CARGO_BUILD_WARNINGS=deny` or `[build] warnings = "deny"` in `.cargo/config.toml` (Cargo ≥1.97); `-- -D warnings` invalidates caches |
| `clippy --fix` | Implies `--all-targets` |
| Profiles | `[profile.*]` recognized only in the root manifest |

## Repo glue

- EditorConfig standard properties: `end_of_line`, `insert_final_newline`, `trim_trailing_whitespace`, `indent_style`, `indent_size`, `charset`; one root file with `root = true`.
- gitattributes: `* text=auto` normalizes endings; explicit `eol` per extension overrides.
- lefthook: `jobs:` since 1.10.0; `glob` accepts a list since 1.10.10; `stage_fixed` works only in `pre-commit`; `root` filters paths for `pre-commit`/`pre-push`.
- Corepack: shipped inside Node from 14.19.0 up to but not including 25.0.0; `packageManager` is `name@x.y.z` with `name` in `yarn`/`npm`/`pnpm`; the hash is optional and recommended; `devEngines.packageManager` is validated by Corepack.
- Node pinning: `engines.node` plus `.node-version`/`.nvmrc`; neither is enforced by Node itself.

## Removed and changed features

| Item | Change | Consequence |
|---|---|---|
| `next lint` | Removed in Next.js 16 | Wire `eslint .` or `oxlint` directly |
| Next `eslint` config key | Removed in Next.js 16 | Configure the linter outside `next.config` |
| `next build` linting | Removed in Next.js 16 | A separate lint step is mandatory |
| TS `baseUrl` | Hard error in TS 7 | Use `paths` without `baseUrl` |
| TS `moduleResolution: node`/`node10` | Hard error in TS 7 | `bundler` or `nodenext` |
| TS `target: es5` | Hard error in TS 7 | Raise the target |
| rustfmt `imports_granularity`, `group_imports` | Nightly-only | Not usable on a stable pin |
| Clippy `-- -D warnings` | Discouraged since Cargo 1.97 | Use `CARGO_BUILD_WARNINGS=deny` |
| Oxlint top-level `ignore` | Never existed | Use `ignorePatterns` |
| Oxlint `import/order` | Never existed | Order imports by another mechanism or not at all |
| Oxlint layout rules | Never existed | Nothing to disable for Prettier |
| `@typescript/native-preview` | Legacy nightly channel | Use `typescript@next` |

## Unverified items

- The Prettier VS Code extension's marketplace id was not read from its own listing in this snapshot; do not cite one from memory.
- No official Biome → oxlint migrator was found; the table in `rules/setup/typescript.md` is this package's translation mapping.
- Oxlint `react-perf` rule names beyond the plugin's presence were not verified individually; enable the plugin, then read the shipped rule list before naming a rule.
- Astro's timeline for deprecating `astro check` is stated only as "in a future Astro release"; no version is committed.
- Lynx's `ignore` list for `react/no-unknown-property` is taken from attribute names seen in the docs, not from a published Lynx lint config.
- oxfmt's 1.0 date and native Astro formatter are open items (Oxc issue #28267); Prettier remains the recommendation until that lands.
