## Official Facts Used By This Skill

### File routes, `createFileRoute`, and the `Route` export

- File-based routes는 **커리 형태** `createFileRoute(path)(options)`로 configure합니다.
- `createFileRoute`는 `string` 인자 하나(file route의 path)를 받고, `RouteOptions` 인자 하나를 받는 함수를 return합니다. 이 path는 `tsr generate` / `tsr watch`가 자동으로 삽입하고 갱신합니다.
- File route instance는 `tsr generate`와 `tsr watch`가 올바르게 동작하도록 `Route` identifier로 export해야 합니다.
- Sources:
  - <https://tanstack.com/router/latest/docs/api/router/createFileRouteFunction>
  - <https://tanstack.com/router/latest/docs/routing/routing-concepts>

### Flat, directory, and mixed route structures

- Router는 directory routes, flat routes(`.`이 nesting level을 나타냄), mixed flat/directory structures를 공식 지원합니다.
- Hypercore가 app pages에 route directories를 선호할 수는 있지만, 이는 team convention이지 official Router requirement가 아닙니다.
- Source: <https://tanstack.com/router/latest/docs/routing/file-based-routing>

### `routeTree.gen.ts` is generated, should be committed, and is not hand-edited

- `routeTree.gen.ts`는 Router bundler plugin 또는 CLI가 생성합니다. API reference의 `generatedRouteTree` 기본값은 `./src/routeTree.gen.ts`입니다.
- FAQ는 이 파일을 **커밋해야 한다**고 말합니다. "Although the route tree file (i.e., `routeTree.gen.ts`) is generated by TanStack Router, it is essentially part of your application's runtime, not a build artifact." 그리고 "You should commit this file into git so that other developers can use it to build your application."
- Route generation에서 제외된 파일과 폴더는 `routeTree.gen.ts`에 추가되지 않습니다.
- API reference는 생성된 route tree path를 linter와 formatter에서 무시하도록 권고합니다.
- 생성된 파일을 손으로 고치지 않습니다(Hypercore convention).
- Sources:
  - <https://tanstack.com/router/latest/docs/faq>
  - <https://tanstack.com/router/latest/docs/api/file-based-routing>
  - <https://tanstack.com/router/latest/docs/routing/routing-concepts>

### Ignore prefix and route/index tokens

- `routeFileIgnorePrefix` 기본값은 `-`입니다. "By default, this value is set to `-`." 이 기본값이 `-hooks/`, `-components/`, `-functions/` co-location 관례를 떠받치는 근거입니다. 문서의 예시도 `index.tsx`와 `route.tsx` 옆에 무시되는 `-components` 디렉터리를 보여줍니다.
- `routeToken` 기본값은 `route`, `indexToken` 기본값은 `index`입니다.
- 두 token 모두 이제 **regex**를 받습니다. `tsr.config.json`에서는 `{ "regex": "...", "flags": "..." }`, inline config에서는 native `RegExp`를 씁니다. 또한 `[x]` **escaping**으로 segment를 literal로 유지할 수 있습니다(예: `[home-page].tsx`).
- `routeFileIgnorePattern` 기본값은 `undefined`입니다.
- 주의: `routeFilePrefix`, `routeFileIgnorePrefix`, `routeFileIgnorePattern`을 File Naming Conventions guide의 token과 겹치게 설정하지 않습니다.
- Sources:
  - <https://tanstack.com/router/latest/docs/api/file-based-routing>
  - <https://tanstack.com/router/latest/docs/routing/routing-concepts>

### `autoCodeSplitting` is a bundler-plugin option

- `autoCodeSplitting`은 TanStack Router Bundler Plugin을 쓸 때만 사용할 수 있습니다. 기본값은 `false`이고, 다음 major release(v2)에서는 `true`가 될 예정입니다.
- `tanstackStart()`로는 전달할 수 **없습니다**. Start plugin이 자신이 받는 router config에서 `autoCodeSplitting`과 `target`을 omit하기 때문입니다.
- Source: <https://tanstack.com/router/latest/docs/api/file-based-routing>

### Search param transformation

- 현재 search 변환 API는 `search.middlewares`입니다. Route 또는 그 descendants의 새 link를 만들 때 search params를 변환하는 함수이며, navigation 시 search validation 뒤에도 실행됩니다.
- 흔한 용례를 위해 Router가 generic helper `retainSearchParams`와 `stripSearchParams`를 제공합니다.
- Legacy `preSearchFilters` / `postSearchFilters`는 API reference에서 deprecated로 표시되며("⚠️ deprecated, use `search.middlewares` instead"), search-params guide에는 더 이상 등장하지 않습니다.
- Sources:
  - <https://tanstack.com/router/latest/docs/guide/search-params>
  - <https://tanstack.com/router/latest/docs/api/router/RouteOptionsType>

### Search parameter validation

- `validateSearch`는 planning callback입니다. "It must be deterministic and side-effect-free for the same input; do not navigate or mutate application/router state from it."
- Zod v4: Zod schema를 `validateSearch`에 직접 전달합니다. "With Zod v4, you should directly use the schema in `validateSearch`"이며 adapter가 필요 없습니다. `@tanstack/zod-adapter`의 `peerDependencies`가 `zod: ^3.23.8`을 고정하므로 Zod 4와는 아예 함께 설치할 수 없습니다.
- Zod v3: `@tanstack/zod-adapter`(`zodValidator`, `fallback`)를 사용합니다.
- 문서 자체에 불일치가 하나 있습니다. middleware guide의 예시 하나가 아직 `zodValidator`를 import합니다. Zod 버전 분기는 `how-to/validate-search-params`와 `guide/search-params`를 기준으로 판단합니다.
- Sources:
  - <https://tanstack.com/router/latest/docs/how-to/validate-search-params>
  - <https://tanstack.com/router/latest/docs/api/router/RouteOptionsType>
  - <https://tanstack.com/router/latest/docs/guide/search-params>
  - <https://registry.npmjs.org/@tanstack/zod-adapter/latest>

### Route lifecycle, `beforeLoad`, and `loader`

- `beforeLoad`는 route가 load되기 전에 실행됩니다. 실패하면 이 route의 loader와 그 descendants가 실행되지 않습니다. Context object를 return하면 route context에 merge되어 `loader`와 child routes에서 쓸 수 있습니다.
- `loader`는 route가 match될 때 실행됩니다. 둘 다 async이고 promise를 return할 수 있으며, 그 경우 `pendingMs` threshold에 도달하면 `pendingComponent`를 보여주면서 route가 pending state에 들어갑니다.
- `loaderDeps`는 planning/cache-key 함수입니다. 같은 validated search input에 대해 deterministic하고 side-effect-free여야 합니다.
- Object-form `loader`의 `staleReloadMode`는 `'background'`(stale-while-revalidate) 또는 `'blocking'`을 고릅니다.
- Source: <https://tanstack.com/router/latest/docs/api/router/RouteOptionsType>

### Router context

- Root route context는 `createRootRouteWithContext<MyRouterContext>()`로 만듭니다. `beforeLoad`는 loaders와 child routes를 위해 context를 확장할 수 있습니다.
- Source: <https://tanstack.com/router/latest/docs/routing/routing-concepts>

### Where the "loaders are isomorphic" statement lives

- Route loaders가 isomorphic이라는 권위 있는 진술은 **Start** 문서에 있고 Router 문서에는 없습니다. Start의 execution-model guide는 "Route `loader`s are isomorphic - they run on both server and client, not just the server."라고 말합니다.
- 이 snapshot을 위해 가져온 Router 문서 페이지 중 어느 것도 loaders가 isomorphic이라고 말하지 않으므로, 이 주장을 Router에 귀속시키지 않습니다.
- Source: <https://tanstack.com/start/latest/docs/framework/react/guide/execution-model>

## Refresh Triggers

다음 경우 이 snapshot을 refresh합니다:

- Router file naming conventions, route generation requirements, 또는 `routeToken` / `indexToken` / `routeFileIgnorePrefix` 기본값이 변경됨.
- Zod/adapter usage에 대한 search validation guidance가 변경되거나 search 변환 API(`search.middlewares`)가 변경됨.
- Loader / `beforeLoad` lifecycle, pending behavior, 또는 `staleReloadMode` semantics가 변경됨.
- **공식 문서 페이지가 변경됨**, 그리고 pinned version에 대한 advisory check를 돌립니다. "Local package versions move materially"에 trigger를 걸지 **않습니다**. Router와 Start는 `1.x`에 머물면서 patch 릴리스에서도 breaking change를 싣고, 반대로 여러 patch 릴리스가 동작 변화 없이 지나가기도 합니다. 1.170.41부터 1.170.46까지는 내부 composition과 link hydration 작업, 패키지 자체 agent skill 배포뿐이었습니다. 따라서 version bump는 어느 방향으로도 신뢰할 수 있는 drift 신호가 아닙니다.
