## Electron Versions and Support

- 새 major는 8주마다 나오며, 짝수 Chromium major를 따르고 alpha 4주와 beta 4주를 거칩니다. 45 → 46 간격은 약 11주입니다.
- 지원 대상은 최근 stable major 세 개이고 각 major의 최신 minor만 지원하며, 가장 오래된 major는 보안 fix만 받습니다. Breaking change는 보통 두 major 이상 동작을 유지한 뒤 제거됩니다.

| Line | Stable | End of life |
|---|---|---|
| 43 | 2026-06-30 | 2027-01-05 |
| 44 | 2026-08-24 | 2027-03-02 |
| 45 | 2026-10-21 | 2027-04-27 |
| 46 (planned) | 2027-01-05 | 2027-06-22 |

오래 유지된 default는 이렇습니다. `nodeIntegration`은 5부터 false, `contextIsolation`은 12부터 true, renderer sandbox는 20부터 켜져 있고, `remote`는 14에서 제거됐고, `contextBridge`로 넘긴 `ipcRenderer`는 29부터 `{}`로 도착하며, `File.path`는 32에서 제거됐고(`webUtils.getPathForFile`), `BrowserView`는 30에서 폐기됐습니다(`WebContentsView`).

## Breaking Changes That Shape Architecture

- 44: macOS 13 이상, 32-bit build 없음, renderer에서 `clipboard` 제거(`navigator.clipboard` 또는 preload wrapper를 씁니다).
- 45: sandbox preload에서 `events`, `timers`, `url`, `Buffer`, `setImmediate`를 잃고, `require`는 `electron`만 불러옵니다. screen capture는 `media`가 아니라 `display-capture`로 요청합니다. sandbox가 아닌 opener의 `window.open` 자식 창은 자체 sandbox process를 갖습니다. ASAR file descriptor는 `fs`를 거쳐야만 동작합니다. 동기 `safeStorage` API는 폐기됐습니다.
- 46(미출시): 동기 `safeStorage`가 제거되고, `utilityProcess`의 `child.kill()`은 더 이상 강제 종료하지 않습니다.

## Process Model and IPC

- Main은 Node이며 Electron main API 전체를 쓰고 UI thread를 소유합니다. Renderer는 Chromium이고 Node가 없으며 sandbox에서 돕니다. Preload는 `require('electron')`만 쓸 수 있는 sandbox context입니다(`contextBridge`, `ipcRenderer`, `webFrame`, `webUtils`, `nativeImage`, `crashReporter`). Utility process는 Node이며 `ready` 뒤에 fork되고 app `session`을 쓸 수 있습니다.
- `RunAsNode` fuse가 꺼져 있으면 `child_process.fork`가 실패합니다. 문서가 지정한 대체 수단은 `utilityProcess.fork`입니다.
- IPC pattern은 `invoke`/`handle`(권장), `send`/`on`, renderer로 보내는 `webContents.send`, renderer나 process 사이의 `MessagePort`입니다. `sendSync`는 권장하지 않습니다.
- Payload는 structured clone을 씁니다. DOM object, `process.env`, stream, Electron object, class prototype은 넘어가지 않고, `Error`는 custom property를 잃습니다.
- `contextBridge`는 값을 복사해 freeze하고 function을 proxy하며 `Symbol`을 버립니다. listener wrapper는 `IpcRendererEvent`를 page로 넘기면 안 됩니다.
- ESM(28부터): main은 `.mjs` 또는 `"type": "module"`을 쓰고 `ready` 전에 명시적으로 await합니다. sandbox preload는 ESM을 쓸 수 없어 CommonJS여야 하고, sandbox가 아닌 ESM preload는 `.mjs`가 필요합니다.
- Lifecycle: `requestSingleInstanceLock`과 `second-instance`를 함께 씁니다. `window-all-closed`는 macOS를 빼고 종료합니다. `activate`는 macOS에서 창을 다시 만듭니다. `open-url`과 `open-file`은 `ready` 전에 등록해야 합니다. macOS URL scheme은 build 시점에 `Info.plist`에 선언해야 합니다.

## Security Checklist and Fuses

보안 tutorial은 20개 항목을 나열합니다. 안전한 content, remote content에 Node를 주지 않음, context isolation, sandbox, permission request handler(Electron은 기본으로 모두 허용합니다), `webSecurity` 유지, CSP, `allowRunningInsecureContent` 금지, experimental feature 금지, `enableBlinkFeatures` 금지, `allowpopups` 없이 option을 검증한 `<webview>`, 파싱한 origin으로 navigation 제한, 새 창 제한, `shell.openExternal`에 untrusted input 금지, 최신 Electron 사용, 모든 IPC sender 검증, `file://` 대신 custom protocol 사용, fuse 검토, untrusted content에 Electron API를 노출하지 않음입니다.

- `protocol.registerSchemesAsPrivileged`는 `ready` 전에 한 번 실행합니다. `protocol.handle`은 `ready` 뒤에 응답하며 경로 이탈을 거부해야 합니다. `register*Protocol`/`intercept*Protocol` 계열은 폐기됐습니다.
- Fuse(default): `RunAsNode` on, `EnableCookieEncryption` off, `EnableNodeOptionsEnvironmentVariable` on, `EnableNodeCliInspectArguments` on, `EnableEmbeddedAsarIntegrityValidation` off, `OnlyLoadAppFromAsar` off, `LoadBrowserProcessSpecificV8Snapshot` off, `GrantFileProtocolExtraPrivileges` on, `WasmTrapHandlers` on입니다. Fuse는 signing 전 packaging 시점에 뒤집습니다.
- ASAR integrity: macOS는 16부터, Windows는 30부터 지원하며 불일치하면 앱이 종료됩니다.
- `safeStorage`: main 전용이고 45부터 async API를 씁니다. Keychain, DPAPI, Secret Service 또는 KWallet을 쓰며, Linux의 `basic_text`는 보호가 아닙니다. macOS는 안정적인 signature가 필요합니다.

## Build Tools

- electron-vite: `electron.vite.config.*`에 `main`, `preload`, `renderer` block을 둡니다. 기본 entry는 `src/main/index.ts`, `src/preload/index.ts`, `src/renderer/index.html`이고 production에서 renderer는 `base: './'`입니다. dev URL은 `ELECTRON_RENDERER_URL`에 있고 env prefix는 `MAIN_VITE_`, `PRELOAD_VITE_`, `RENDERER_VITE_`, `VITE_`입니다. `.env` file은 기본으로 config에 load되지 않습니다(`loadEnv`). Version 6은 Rolldown을 통합하고 `rollupOptions`와 `rolldownOptions`를 받습니다. `build.externalizeDeps`(main과 preload에 기본 on)와 `build.bytecode`가 5에서 폐기된 plugin을 대체합니다. Isolated build(`build.isolatedEntries`에 `externalizeDeps: false`)는 sandbox와 호환되는 single-bundle preload를 만듭니다. `electron-vite dev -w`는 main을 rebuild해 restart하고 preload 변경 시 reload합니다. 일부 문서 page는 아직 version 5를 설명합니다.
- Electron Forge 8: Vite plugin이 stable이고 Vite 8을 대상으로 하며 isolated build와 opt-in `hotRestart`를 씁니다. `publish`는 `release`로 이름이 바뀌었습니다. `MAIN_WINDOW_VITE_DEV_SERVER_URL`과 `MAIN_WINDOW_VITE_NAME`을 주입합니다. template `vite`(TypeScript)는 `vite.*.config.mts` 세 개와 fuse 여섯 개를 뒤집는 `FusesPlugin`을 포함합니다.
- 공식 electron-vite `react-ts` template: `sandbox: false`이고 `@electron-toolkit/preload`의 `electronAPI`를 노출하며 production은 `loadFile`로 load합니다. `tsconfig.node.json`과 `tsconfig.web.json`을 넣어 주고 router, Tailwind, test는 없습니다.

## Packaging and Updates

- electron-builder 26: `electron-builder.yml`, `asarUnpack`, `electronFuses`, `npmRebuild`를 씁니다. `mac.notarize`는 hardened runtime과 `allow-jit` entitlement를 씁니다. 기본 docs URL은 v27을 보여 주고 stable docs는 `/v26/` 아래에 있습니다. 암묵적 CI publishing은 폐기됐습니다.
- `electron-updater`: app dependency이고 `publish` config를 쓰며 `setFeedURL`은 쓰지 않습니다. macOS는 `zip` target이 필요하고 Squirrel.Windows는 지원하지 않습니다.
- 내장 `autoUpdater`: macOS(Squirrel.Mac, signed app 필요)와 Windows(MSIX 또는 Squirrel.Windows)를 지원하고 Linux는 없습니다. `update.electronjs.org`는 공개 GitHub 저장소가 필요하며 `update-electron-app`으로 10분마다 확인합니다.

## Renderer Stack

- TanStack Router: browser history가 기본이고, hash history는 server가 없는 환경에 맞으며 memory history는 location을 memory에 둡니다. Vite plugin은 `@vitejs/plugin-react`보다 먼저 실행됩니다. `routesDirectory`와 `generatedRouteTree`는 작업 directory 기준으로 해석되므로 electron-vite renderer는 절대 경로를 넘깁니다. `routeTree.gen.ts`는 lint와 format에서 제외합니다.
- TanStack Query: 기본으로 stale이고 mount, focus(`visibilitychange` 경유), reconnect에서 refetch합니다. `focusManager.setEventListener`와 `onlineManager.setEventListener`가 web listener를 대체하고, `networkMode: 'always'`는 network가 필요 없는 `queryFn`에 맞습니다.
- Tailwind CSS v4: `@tailwindcss/vite`와 `@import "tailwindcss"`를 씁니다. CSS 우선 방식의 `@theme`, `@source`, `@plugin`, `@custom-variant`가 있고, scan은 `.gitignore`된 경로, `node_modules`, binary, CSS, lockfile을 건너뜁니다. 기준 browser는 Safari 16.4, Chrome 111, Firefox 128이고, `npx @tailwindcss/upgrade`로 v3에서 옮깁니다. `prettier-plugin-tailwindcss`는 마지막에 두고 v4에서는 `tailwindStylesheet`가 필요합니다.

## Testing

- Electron은 runner를 제공하지 않습니다. 문서가 제시한 선택지는 WebdriverIO, Selenium, Playwright(실험적, CDP 경유, Electron 21 이상)입니다.
- Playwright `_electron.launch`는 inspect fuse가 꺼져 있으면 time out합니다. native dialog는 `evaluate`로 stub해야 합니다.
- Vitest environment는 `node`, `jsdom`, `happy-dom`, `edge-runtime`이고 Browser Mode는 별도 프로젝트입니다.

## Unverified Topics

- `@tanstack/router-plugin`의 file watching이 electron-vite main process restart와 어떻게 상호작용하는지. 1차 출처가 없습니다.
- "server가 없는 환경"이라는 설명을 넘어선, Electron에 특정된 공식 TanStack 지침.
- `sandbox: true`에서 `electron-trpc` 1.0의 동작.
- `protocol.handle`과 `utilityProcess`를 도입한 Electron version. 문서는 밝히지 않습니다.
- `.desktop` file을 통한 Linux deep-link 등록. `app` API page가 다루지 않습니다.
- `autoCodeSplitting`이 electron-vite chunking과 어떻게 상호작용하는지.
