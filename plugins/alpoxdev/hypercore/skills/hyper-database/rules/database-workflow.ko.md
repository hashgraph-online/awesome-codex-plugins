# 데이터베이스 워크플로

엔진 라우팅이 끝난 뒤 이 규칙을 사용합니다. 모드를 고르고, 모드별 단계를 고정하고, 부작용을 제한하며, 보고서 경로를 정합니다.

## 1. 모드 선택

| Request shape | Mode | Edits files |
|---|---|---|
| "설계해줘", "design the schema", 새 서비스, 새 컬렉션 또는 키 공간 | design | 저장소가 있고 사용자가 보고서만 원한다고 하지 않았으면 합니다 |
| "점검", "리뷰", "audit", "is this safe", 상위에서 온 "audit only; do not edit" | review | 대상 파일은 고치지 않습니다. `.hyper/database/` 아래 보고서만 씁니다 |
| 무언가를 바꿔 달라는 요청 없이 "계획 봐줘", "explain this plan", "why is this query slow" | review, tune의 실행 계획 읽기만 포함(인덱스·쿼리 수정 없음) | 대상 파일은 고치지 않습니다. 보고서만 씁니다 |
| "마이그레이션 써줘", "add a column", "rename", "backfill", "fix this migration" | change | 합니다 |
| "느려", "slow", "timeout", "lock wait", "deadlock", "hot key", "throttled", "index 잡아줘" | tune | 인덱스와 쿼리 파일에 한해 합니다 |
| "백업", "복구", "리플리카", "failover", "pooling", "upgrade", "보안", "모니터링", "capacity" | operate | 설정과 런북 파일에만 합니다 |
| "뭐 쓸까", "which database", "Redis vs Valkey", "single-table or not" | choose | 하지 않습니다 |

- 요청이 두 가지 형태를 함께 가지면("설계하고 마이그레이션까지") choose, design, change, tune, operate 순서로 실행합니다. review는 한 실행에서 편집 모드와 결합하지 않습니다.
- "점검만", "report only", "do not edit", 상위 감사 요청은 항상 우선합니다. 모드는 review가 됩니다.

## 2. 설계 입력

설계, 인덱스, 엔진 결정 전에 다음을 수집합니다. 파일에서 먼저 읽고(API 라우트, 쿼리 코드, 기존 스키마, 이슈 텍스트, 부하 수치), 나머지는 질문 하나로 묶어 묻습니다.

| Input | Why it decides |
|---|---|
| 접근 패턴: 각 읽기와 쓰기, 그 필터, 정렬, 빈도 | 키, 인덱스, NoSQL 배치가 여기서 나옵니다 |
| 규모와 증가: 현재 행 또는 항목 수, 일일 증가량, 보존 기간 | 파티셔닝, TTL, 인덱스 비용 |
| 불변 조건: 절대 깨지면 안 되는 규칙(이메일 유일, 잔액 >= 0, 활성 플랜 하나) | 제약과 트랜잭션 경계 |
| 일관성 요구: read-your-writes, 강한 일관성, 최종 일관성 허용 여부 | 엔진, 복제본 읽기, 캐시 설계 |
| 지연 시간과 가용성 목표, RPO와 RTO | 토폴로지, 백업 방식, 장애 조치 |
| 테넌시와 데이터 민감도(PII, 결제, 규제 지역) | 격리 모델, 암호화, 보존, 삭제 |
| 플랫폼 제약: 매니지드 서비스, 기존 엔진, 팀 역량, 예산 | 선택 범위 |

사용자가 답을 주지 않았는데 답이 필요하면 보고서의 `가정` 목록에 밝힌 가정으로 진행하고, 조용히 추측하지 않습니다.

## 3. 모드별 단계

| Mode | Phases |
|---|---|
| design | 입력 -> 엔티티와 접근 패턴 표 -> 엔진 적합성 확인 -> 논리 모델 -> 물리 모델(타입, 키, 제약, 인덱스, 파티셔닝 또는 키 배치) -> DDL 또는 스키마 파일 -> 운영 절 -> 검증 -> 보고서 |
| review | 파일에서 입력 수집 -> 규칙 ID별 점검(엔진 중립, 그다음 엔진 가이드) -> 심각도 순위 -> 수정안을 담은 보고서, 편집 없음 |
| change | 현재 스키마와 데이터 규모 -> `rules/schema-changes.md` §2에 따른 변경 분류 -> expand/contract 단계 -> 마이그레이션 파일 -> 린트 또는 드라이 런 -> 롤백 계획 -> 보고서 |
| tune | 느린 문장과 그 실행 계획 또는 지표 -> 규칙 ID별 원인 -> 한 번에 변경 하나(인덱스, 쿼리 재작성, 설정) -> 재측정 -> 유지 또는 되돌림 -> 보고서 |
| operate | 현재 토폴로지와 설정 -> `rules/operations.md` 대비 격차 -> 설정 또는 런북 변경 -> 검증 단계 -> 보고서 |
| choose | 입력 -> 하드 제약을 만족하는 후보 엔진 -> 접근 적합성, 일관성, 운영 비용, 생태계, 라이선스 비교 표 -> 무엇이 결론을 바꾸는지 밝힌 권고 -> 보고서 |

## 4. 부작용 게이트

| Action | Rule |
|---|---|
| 스키마 파일, 마이그레이션, 쿼리, 설정 읽기 | 허용합니다 |
| 감지기, 린터, 타입 검사, ORM의 오프라인 diff 실행 | 허용합니다 |
| DDL, 실행 계획, 복구를 시험할 일회용 로컬 데이터베이스(컨테이너, 인메모리, 임시 파일) 기동 | 허용합니다. 실행 후 정리하고 보고서에 밝힙니다 |
| 일회용이 아닌 데이터베이스에 실행 없이 `EXPLAIN` | 사용자가 이번 실행을 위해 그 연결을 제공했을 때만 합니다. 읽기 전용 역할을 권장합니다 |
| 공유, 스테이징, 운영 대상에 `EXPLAIN ANALYZE`, DML, DDL, `VACUUM FULL`, 인덱스 빌드, `FLUSHALL`, `KEYS`, `DEBUG`, 복구, 장애 조치, 설정 변경 | 이번 실행에서 사용자가 명시적으로 요청하고 대상 이름을 확인했을 때만 합니다. 아니면 사용자가 실행할 명령과 검증을 작성합니다 |
| 일회용이 아닌 대상의 읽기 전용 점검(`SHOW`, `pg_stat_*` 뷰, `INFO`, `CONFIG GET`, `SLOWLOG GET`, 실행 없는 `explain()`, `rs.status()`) | 사용자가 이번 실행을 위해 그 연결을 제공했거나 그 대상 점검을 요청했을 때만 합니다. 읽기 전용 역할을 권장합니다. 이런 명령이 막힌 매니지드 서비스에서는 제공자의 파라미터 그룹이나 콘솔 설정을 대신 읽습니다 |
| 매니지드 리소스 생성, 요금 등급 변경, 백업 삭제, 데이터 삭제 | 항상 먼저 묻습니다 |

자격 증명, 연결 문자열 값, 고객 행을 출력하지 않습니다. 명령과 출력 발췌에서는 `<redacted>`로 가립니다. 사용자가 이번 실행에서 요청하지 않았다면 연결을 얻으려고 실제 `.env`나 비밀 파일을 열지 않고, 사용자에게 연결을 제공하거나 직접 실행해 달라고 요청합니다.

실행 확인 전에 대상의 정체를 확인합니다. 사용자는 "운영"이라 부르는데 파일은 로컬이나 테스트 DB를 가리키면(또는 그 반대면) 멈추고 두 근거를 인용해 한 번 묻습니다.

## 5. 심각도

| Severity | Meaning | Example |
|---|---|---|
| critical | 데이터 손실, 손상, 보안 노출, 배포 시 장애 | 읽는 쪽이 살아 있는데 `DROP COLUMN`; 인증 없이 노출된 Redis; 원본 저장소에 시험하지 않은 복구 |
| high | 정상 성장에서 일어날 만한 장애 또는 정합성 버그 | 큰 테이블에 `ACCESS EXCLUSIVE`를 잡는 테이블 재작성; 불변 조건 뒤에 없는 유일 제약; 핫 파티션 키 |
| medium | 측정 가능한 낭비 또는 다음 단계를 막는 설계 | 쓰지 않거나 중복인 인덱스; N+1 쿼리; 캐시 키 계열에 없는 TTL |
| low | 관례 또는 유지보수성 | 이름 규칙 표류, 분명하지 않은 컬럼의 설명 누락 |

## 6. 보고서 경로

`.hyper/database/<slug>/report.md`에 씁니다. `<slug>`는 작업을 나타내는 짧은 kebab-case 이름입니다. 폴더가 다른 작업에 이미 있으면 `-2`, `-3`을 붙입니다. 보조 산출물(변경 전후 실행 계획, 린터 출력, 감지기 JSON)은 파일로 옆에 두고 보고서에서 링크합니다. [../references/report-template.md](../references/report-template.md)를 따릅니다.
