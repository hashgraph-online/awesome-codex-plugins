# 검증

실행을 완료로 선언하기 전에 이 규칙을 사용합니다. 각 주장 유형에 필요한 증거, 모드별 완료 점검, 실행하지 못한 런타임 점검을 보고하는 방식을 정합니다.

## 1. 주장별 증거 게이트

| Claim | Evidence that proves it | Not enough |
|---|---|---|
| "이 엔진을 씁니다" | 감지기 행 또는 읽은 파일과 그 신호 | 요청의 문구만 |
| "이 인덱스를 씁니다" / "이 쿼리가 더 빠릅니다" | 변경 전후 실행 계획(`EXPLAIN`, `explain("executionStats")`, `TRACING ON`, DynamoDB `ConsumedCapacity`), 또는 대표 데이터에서 돌린 벤치마크 | "인덱스가 쿼리를 빠르게 합니다" |
| "이 마이그레이션은 무중단으로 안전합니다" | 그 정확한 문장에 관해 엔진이 문서화한 잠금 수준이나 알고리즘, 재작성하는 행 수, 시간 상한, 사본에서의 예행이나 린터 통과 | "작은 변경입니다" |
| "이 제약이 유지됩니다" | 스키마의 제약과, `NOT VALID`로 추가했거나 백필한 컬럼일 때 기존 데이터를 검사하는 검증 쿼리 | 애플리케이션 쪽 검사 |
| "백업이 동작합니다" | 별도 대상으로 실행한 복구와 복구한 행 수나 체크섬, 걸린 시간 | 성공을 보고하는 백업 작업 |
| "장애 조치가 동작합니다" | 관측한 다운타임과 데이터 손실을 담은 장애 조치 훈련 결과 | 존재하는 복제본 |
| "캐시나 키 설계가 메모리에 맞습니다" | `MEMORY USAGE` 표본 또는 항목 크기 추정 곱하기 키 수를 `maxmemory`와 비교 | "값이 작습니다"라는 추측 |
| "파티션 또는 샤드 키가 고르게 분포합니다" | 데이터나 표본에서 키의 카디널리티와 상위 N 비중, 또는 엔진의 핫 키 지표 | "사용자 ID는 무작위입니다" |
| 버전, 한도, 기본값, 라이선스 사실 | 날짜가 붙은 엔진 가이드 행, 가이드가 자주 바뀌는 값으로 표시하면 실제 공식 페이지 | 모델 기억 |

## 2. 런타임 점검

- 일회용 데이터베이스를 권장합니다. 스키마와 대표 행 수를 채운 컨테이너, 인메모리 엔진, 임시 파일입니다. 이미지 태그나 버전, 채운 크기, 정리를 기록합니다.
- 실행하지 못한 점검은 이유와 함께 `not run`입니다(클라이언트 없음, Docker 없음, 데이터 없음, 권한 없음). 그 점검에 `passed`를 쓰지 않고, `not run` 점검을 검증된 것처럼 발견 사항으로 옮기지 않습니다.
- 거의 빈 테이블의 실행 계획은 큰 테이블의 근거가 아닙니다. 옵티마이저는 작은 테이블에서 순차 스캔을 고릅니다. 행을 충분히 채우거나, 계획이 대표성 없는 크기에서 나왔다고 밝힙니다.

## 3. 마이그레이션 안전 체크리스트

모든 change 모드 실행과 모든 마이그레이션 리뷰는 각 줄에 답합니다.

- [ ] `rules/schema-changes.md` §2에 따른 문장 분류와, 이 엔진 버전에서 잡는 잠금 또는 알고리즘.
- [ ] 재작성하거나 스캔하는 행 수와 현재 규모에서 예상 소요 시간.
- [ ] 트래픽 뒤에 줄 서는 대신 빨리 실패하도록 설정한 `lock_timeout` / `statement_timeout`(또는 엔진의 동등 설정).
- [ ] 변경 중 옛 애플리케이션 버전과 새 버전이 모두 동작함(축소 전 확장).
- [ ] 배치 크기와 스로틀을 밝힌, 배치 단위이고 멱등이며 재개 가능한 백필.
- [ ] 작성된 롤백과 각 단계에서의 가능 여부, 또는 데이터 손실 결과와 함께 일방향으로 표시한 단계.
- [ ] 마이그레이션 도구가 계획이 가정한 대로 적용함(트랜잭션 DDL 여부, 엔진이 요구하면 마이그레이션당 문장 하나).
- [ ] 린터나 사본에서의 예행을 실행했거나 `not run`으로 표시함.

## 4. 모드별 완료

| Mode | Done when |
|---|---|
| design | 접근 패턴 표가 완전함. 모든 패턴을 키나 인덱스가 처리함. 모든 불변 조건을 제약이나 밝힌 트랜잭션이 강제함. DDL 또는 스키마 파일이 일회용 데이터베이스에서 파싱되거나 적용됨. 운영 절을 작성함 |
| review | 적용되는 엔진 중립 규칙과 엔진 규칙을 모두 점검함. 각 발견 사항에 ID, 심각도, 근거, 수정이 있음. 바꾼 대상 파일 없음(`.hyper/database/` 아래 보고서만 씀) |
| change | §3의 체크리스트가 완료됨. 마이그레이션이 일회용 데이터베이스에서 정방향으로 적용되거나 도구의 오프라인 점검이 통과함. 롤백을 밝힘 |
| tune | 유지한 변경마다 변경 전후 근거가 있음. 측정값을 개선하지 못한 변경은 되돌림. 새 인덱스의 쓰기 비용을 밝힘 |
| operate | `rules/operations.md`의 각 격차를 고쳤거나, 소유자와 함께 일정을 잡았거나, 보고서에 위험으로 수용함. 검증 단계를 작성함 |
| choose | 비교 표가 모든 하드 제약을 다룸. 권고가 어떤 근거로 결론이 바뀌는지 밝힘 |

## 5. 보고서 게이트

- [ ] `.hyper/database/<slug>/report.md`가 있고 `references/report-template.md`를 따릅니다.
- [ ] 보고서가 바뀌었다고 말하는 모든 파일이 디스크에서 바뀌었고, 다른 파일은 바뀌지 않았습니다.
- [ ] 모든 발견 사항이 실제로 읽은 파일에 있는 규칙 ID를 인용합니다.
- [ ] 모든 숫자가 계보를 가집니다. 측정(명령 포함), 추정(공식 포함), 사용자 제공입니다.
- [ ] 보고서와 첨부에 비밀, 연결 문자열 값, 고객 행이 없습니다.
