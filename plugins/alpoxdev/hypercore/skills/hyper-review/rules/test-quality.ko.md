# 테스트 품질

실패할 수 없는 테스트는 아무것도 증명하지 않는다. 변경이 더하거나 고친 모든 테스트에, 그리고 바뀐 경로를 덮는다고 주장하는 기존 테스트에 이 게이트를 적용한다. 언어 중립이다. 실행기가 무엇이든 원리는 같다.

## 1. The authoring gate

테스트마다 네 질문에 답한다. 처음 세 개에 "아니오"가 나오면 발견 사항이다.

| 질문 | 중요한 이유 | 실패한 모습 |
|---|---|---|
| 변경이 깨뜨릴 수 있는 것을 단언하는가 | 변경이 건드리지 않는 단언은 이 변경을 위해 쓰인 테스트가 아니다 | 상수, 목의 설정, 프로덕션 코드가 만들지 않는 값을 단언한다 |
| 변경이 틀렸다면 실패하는가 | 테스트에 힘이 있다는 유일한 증거는 빨갛게 될 수 있다는 것이다 | 구현을 지우거나, 기본값으로 스텁하거나, 조건을 뒤집어도 통과한다 |
| 내부가 아니라 공개 결과를 관찰하는가 | 내부에 결합한 테스트는 동작이 깨져도 통과하고, 아무것도 깨지 않는 리팩터에서 실패한다 | 계약이 반환값인데 비공개 메서드 호출, 호출 순서, 로그 줄을 단언한다 |
| 이것을 덮는 가장 작은 테스트인가 | 중복 테스트는 시간을 쓰고 어느 것이 기준인지 가린다 | 같은 준비와 같은 단언의 테스트 셋, 또는 서로 무관한 스무 개를 단언하는 테스트 하나 |

## 2. Junk classes

분류마다 발견 사항이다. 분류와 테스트 이름을 붙인다.

| 분류 | 무엇인가 | 어떻게 찾는가 |
|---|---|---|
| 동어 반복 | 단언이 입력이나 구현 상수를 그대로 되풀이한다 | `sum`을 `a+b`로 목킹했는데 `expect(sum(1,2)).toBe(3)`, 테스트가 직접 만든 값을 단언 |
| 거울 | 기대값을 테스트가 만든 프로덕션 로직 사본으로 계산한다 | 기대값이 검증 대상 함수의 복사본으로 계산됨 |
| 단언 없음 | 코드를 돌리고 아무것도 확인하지 않거나, 예외가 안 났다는 것만 본다 | 본문에 단언 호출이 없음, 내용을 보지 않은 스냅숏 하나 |
| 목 지배 | 모든 협력자를 목킹해 목을 검사한다 | 실제 경로에 들어가지 않고, 단언이 가짜의 호출 횟수에 대한 것 |
| 스냅숏만 | 생성된 스냅숏이 유일한 단언이고 변경과 함께 다시 생성됐다 | 검토한 기대 없이 스냅숏 파일만 diff에 있음 |
| 순서 결합 | 다른 테스트가 먼저 돌거나 특정 순서일 때만 통과한다 | 다른 테스트가 만든 상태를 읽거나 모듈 수준 누적에 의존 |
| 환경 의존 | 네트워크, 시계, 시간대, 머신이 필요하고 통제하지 않는다 | 현재 날짜, 원격 호스트, 남은 메모리에 단언이 의존 |
| 대기 기반 | 조건을 관찰하지 않고 고정 시간을 기다린다 | 동기화 수단으로 `sleep`이나 타임아웃 |
| 무시됨 | 변경의 일부로 건너뛰거나, `only`가 붙거나, 주석 처리됐다 | 이유 없이 바뀐 파일에 스킵 표시 |
| 넓은 catch | 오류를 삼키고 통과한다 | 단언을 감싼 포괄 try-catch, 또는 절대 실행되지 않는 catch 안의 단언 |
| 중복 | 새 사례 없이 이름만 다르게 다른 테스트를 반복한다 | 같은 준비, 같은 입력 부류, 같은 단언 |
| 픽스처 비대 | 이 테스트만을 위해 존재하고 자기 자신에 견줘 단언되는 픽스처 | 기대 응답이 프로덕션 코드가 읽는 픽스처의 사본 |

diff에 있는 무시되거나 `only`가 붙은 테스트는 블로커다. 스위트가 주장하는 것을 돌리지 않고 있다.

## 3. Mutation by hand

변이 도구를 설치하지 않는다. 한 가지를 손으로 변이하고 테스트가 빨개지는지 본다. 테스트에 힘이 있다는 가장 싼 증명이다.

적용하고 되돌리기 가장 싼 변이를 고른다.

- 비교 연산자를 바꾼다. `<`를 `<=`, `==`를 `!=`로.
- 논리곱을 바꾼다. `and`를 `or`로.
- 일찍 기본값을 반환한다. `return null`, `return []`, `return 0`, `return true`.
- 같은 타입의 식별자 둘을 바꾼다.
- 가드 절 하나를 지운다.
- 조건의 분기를 뒤집는다.

그다음:

1. 변이 하나를 적용한다.
2. 바뀐 단위의 테스트만 돌린다.
3. 실패한 테스트가 있는지, 있다면 이름과 메시지를 기록한다.
4. 변이를 되돌리고 스위트가 다시 초록인지 확인한다.

아무 테스트도 잡지 못한 변이는 변이가 아니라 테스트 스위트에 대한 발견 사항이다. 리뷰 전용 모드에서 변이는 작업 트리에서 일어나고 되돌리며, 보고서에 변이, 실행, 되돌리기를 기록한다. 트리를 바꿀 권한이 없으면 리뷰 후 수정 모드가 활성일 때만 변이를 돌리고, 아니면 게이트 결과를 단언의 정적 읽기로 적고 그렇게 밝힌다.

## 4. Coverage claims

- 커버리지 숫자는 테스트 힘의 증거가 아니다. 프로젝트가 산출할 때만 적고, 백분율을 통과로 취급하지 않는다.
- 바뀐 파일의 줄 커버리지는 그 줄이 돌았다는 뜻이지, 단언이 틀린 결과를 알아챈다는 뜻이 아니다.
- 커버리지를 낮추거나, 테스트를 지우거나, 스위트를 건너뛰는 변경은 발견 사항이다.
- 목표 경로에서 닿을 수 있는 새 분기에 diff에 테스트가 없으면 발견 사항이다.
- "다른 곳의 통합 테스트가 덮는다"는 그 테스트를 이름 붙이고 읽었을 때만 받아들인다.

## 5. What to report

테스트 발견 사항마다 적는다.

```text
Test: <path>:<line> <test name>
Class: <junk class or gate question>
Evidence: <the assertion, or the mutation that survived>
Severity: blocker | should fix | note
Fix: <the smallest change that gives the test power>
```

스위트 전체 줄도 하나 적는다.

```text
Tests: 신규 <n>, 수정 <n>, 쓰레기 <n>, 삭제 <n>, 게이트 <pass|fail>, 변이 <n>/<n> 잡힘
```

### Evidence grade

작성 게이트와 쓰레기 테스트 개념은 `MECHANISM`이다. 분류 표, 수동 변이 절차, 보고 형태는 `LOCAL`이다. 게이트는 판단 보조이지 측정된 분류기가 아니며, 이름 붙인 발견 사항이 항상 표보다 우선한다.
