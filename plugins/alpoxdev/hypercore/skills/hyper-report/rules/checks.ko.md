# 전달 전 점검

마지막 렌더 뒤에 이 순서로 실행한다. 첫 절은 전달을 막고, 둘째 절은 작성자가 판단해 기록하는 항목이다.

## 1. 막는 점검

보고서를 완료라고 부르기 전에 아래 모두가 통과해야 한다. 각 항목에는 느낌이 아니라 관찰 가능한 시험이 있다.

| 점검 | 시험 | 실패의 뜻 |
|---|---|---|
| 소스가 있고 파싱된다 | 렌더 보고서가 `status`가 설정된 유효한 JSON이다 | 레이아웃 전에 소스나 파이프라인이 깨졌다 |
| 페이지가 렌더됐다 | `layout.pages >= 1` | 아무것도 페이지에 닿지 않았다. 보통 빈 본문이나 깨진 템플릿이다 |
| 넘침이 없다 | `layout.overflow`가 비어 있다 | 내용이 페이지 아래로 잘렸다 |
| 열보다 넓은 블록이 없다 | `layout.wide`가 비어 있다 | 표나 이미지가 텍스트 열보다 넓다 |
| 이미지가 로드됐다 | `layout.images`의 모든 항목에 `ok: true`가 있다 | 이미지 경로가 틀렸거나 파일이 없다 |
| PDF 페이지 수가 맞는다 | `pdfPages == pages` | 인쇄 엔진이 페이지가 나뉜 DOM을 다시 흘렸다 |
| 요청한 형식이 있다 | `outputs`의 null이 아닌 모든 항목이 디스크의 파일이다 | 렌더 단계가 조용히 실패했다 |
| 인용이 풀린다 | 모든 `[Sn]` 표시에 출처 목록 행이 있고, 그 반대도 성립한다 | 주장에 추적 가능한 출처가 없다 |
| 결론이 있다 | 첫 장에 권고가 들어 있다 | 보고서가 배경으로 시작한다 |

렌더 보고서가 모든 레이아웃 점검을 `errors[]` 항목으로 담으므로, 그것을 읽는 것이 점검이다.

## 2. 판단 점검

기계적 시험이 없다. 작성자가 전달 메모에서 각 항목에 답한다.

- **첫 장이 브리프의 결정에 답하는가?** 1쪽만 읽는다. 답이 거기 없으면 구조가 틀렸다.
- **모든 절이 자기 주장으로 시작하는가?** 각 절의 첫 문장을 훑는다. 준비 문장으로 시작하는 절은 다시 쓸 절이다.
- **모든 표가 무언가를 비교하는가?** 행이 의미 있는 열을 공유하지 않는 표는 상자에 담은 산문이다.
- **모든 그림에 해석하는 캡션이 있는가?** 축의 이름을 붙인 캡션은 라벨이지 캡션이 아니다.
- **페이지 수가 브리프가 허용한 만큼인가?** 예산 초과는 내용을 줄일 일이지 글자를 줄일 일이 아니다.
- **요약이 잘라내지 않고 압축하는가?** 결론을 그대로 복사한 요약은 아무것도 더하지 않는다.

## 3. 다시 읽기

전달한 산출물을 열고 독자처럼 읽는다. PDF면 PDF를 연다. 이미지면 페이지마다 본다. HTML이면 인쇄 폭으로 브라우저에서 연다.

산출물 대신 소스를 읽는 것은 세지 않는다. 독자가 받는 것은 산출물이며, 레이아웃 깨짐은 소스에서 보이지 않는다.

다시 읽으며 확인한다.

- 바닥글 페이지 수가 `n / total`로 읽히고 마지막 페이지가 `total / total`이라고 말한다.
- 목차 페이지 번호가 절이 실제로 있는 곳과 맞는다.
- 제목이 페이지 아래에 홀로 남고 본문이 다음 페이지로 넘어가는 일이 없다.
- 한국어 텍스트에 깨진 글자가 없고, 한국어 문장 안의 라틴 식별자에 하이픈이 붙지 않는다.
- 표 열 정렬이 살아 있다. 수치는 오른쪽, 텍스트는 왼쪽.

## 4. 전달 메모

다음을 짧게 보고한다.

- 만든 모든 파일의 절대 경로.
- 페이지 수와 형식 목록.
- 통과한 점검, 그리고 남겨 둔 권고 발견.
- 브리프가 가정했고 사용자가 확인해야 할 것.
- 만들지 못한 형식과 그 이유.

경로 없이 "완료"라고만 하는 전달 메모는 전달이 아니다.
