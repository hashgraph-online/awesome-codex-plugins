# Markdown 방언

파이프라인은 Markdown의 고정된 부분집합만 읽는다. 그 밖의 구성은 버려지지 않고 평문으로 렌더링되므로, 지원하지 않는 문법이 출력에 문자 그대로 나타나 쉽게 눈에 띈다.

## 1. 지원하는 블록

| 구성 | 문법 | 렌더링 결과 |
|---|---|---|
| 제목 | `#`, `##`, `###`, `####` | `h1`–`h4`; `h1`과 `h2`는 목차에도 들어간다 |
| 문단 | 빈 줄로 나뉜 텍스트 덩어리 | `p` |
| 글머리 목록 | `- item`, 두 칸 들여쓰기로 중첩 | 중첩된 `ul`을 가진 `ul` |
| 번호 목록 | `1. item` | `ol` |
| 인용 | `> text` | `blockquote` |
| 펜스 코드 | 언어를 선택적으로 붙인 삼중 백틱 | `pre > code` |
| 표 | `---|---` 구분 행이 있는 GFM 파이프 표 | `thead`와 `tbody`를 가진 `table` |
| 주제 구분선 | 한 줄에 단독으로 놓인 `---` | `hr` |
| 이미지 | 자기 줄에 단독으로 놓인 `!` + `[caption]` + `(path.png)` | `figcaption`을 가진 `figure` |
| 인라인 이미지 | 문장 안의 `!` + `[alt]` + `(path.png)` | `img` |
| 목차 | 자기 줄에 단독으로 놓인 `[TOC]` | 페이지 나눔 뒤에 채워지는 `nav` |
| 원시 HTML | `<`로 시작하는 줄 | 그대로 통과 |

## 2. 디렉티브

콜론 디렉티브 세 개가 Markdown으로 표현할 수 없는 것을 담당한다.

```
:::kpi
매출 성장 | +32%
이탈률 | 4.1%
:::
```

핵심 수치를 큰 글자로 한 줄 렌더링한다. 파이프 왼쪽이 라벨, 오른쪽이 값이다. 세 개나 네 개가 쓸모 있는 최대치이며, 네 개를 넘으면 한눈에 읽히지 않는다.

```
:::callout 결정
A안을 8주 안에 착수한다.
:::
```

라벨을 제목으로 단 테두리 상자를 렌더링한다. 결정, 위험, 조건에 쓰고, 평범한 강조에는 쓰지 않는다.

```
:::pagebreak
:::
```

다음 블록을 새 페이지로 강제한다. 부록 앞에 쓰고, 흐르는 본문 안에는 절대 쓰지 않는다.

## 3. 인라인 서식

| 문법 | 렌더링 결과 | 비고 |
|---|---|---|
| `**bold**` | `strong` | 여는 `**` 바로 뒤에 공백이 아니어야 한다 |
| `*italic*` | `em` | 별표 하나만 |
| `` `code` `` | `code` | 백틱 내용은 다른 모든 규칙에서 보호된다 |
| `[text]` + `(url)` | `a` | 적힌 URL로 열린다 |
| `!` + `[alt]` + `(path)` | `img` | 경로는 출력 디렉터리 기준이다 |
| `[S1]` | 인용 표시 | 위첨자 스팬으로 렌더링된다 |

**밑줄 강조는 의도적으로 지원하지 않는다.** `snake_case_name`과 `__init__`은 적힌 그대로 렌더링된다. 기술 보고서에서는 밑줄 이탤릭보다 식별자가 훨씬 흔하고, 식별자의 절반을 조용히 이탤릭으로 바꾸는 것은 독자가 볼 수 없는 버그이기 때문이다.

## 4. 원본 파일

파일은 frontmatter 블록으로 시작한다. 모든 키는 선택이며, 제목이 없는 보고서는 파일 이름으로 대체된다.

```markdown
---
title: "시장 진입 분석 보고서"
subtitle: "2026년 4분기 후보 3안 비교"
author: "양민열"
date: "2026-11-13"
theme: "editorial"
footer: "시장 진입 분석 — 내부 검토용"
---

# 결론

A안을 8주 범위로 승인하는 것을 권한다. …
```

| 키 | 쓰이는 곳 |
|---|---|
| `title` | 표지 제목, 문서 제목, 기본 바닥글 |
| `subtitle` | 표지 둘째 줄 |
| `author` | 표지 메타데이터 |
| `date` | 표지 메타데이터 |
| `theme` | 기본 테마. 명령으로 덮어쓸 수 있다 |
| `footer` | 모든 페이지 바닥글의 왼쪽 |

표지는 자동이 아니다. 완전한 표지 형태를 원하면 본문 맨 위에 HTML 블록을 쓴다. 짧은 문서라면 첫 제목을 평범한 `# title`로 두는 것이 충분히 좋은 보고서 시작이다.

## 5. 작성자를 조용히 놀라게 하는 것

- 목록 항목 사이의 빈 줄은 새 목록을 시작한다. 목록 항목은 붙여 둔다.
- 표에는 구분 행이 필요하다. 파이프가 많은 문단은 표가 아니다.
- 자기 줄에 놓인 이미지 뒤에 텍스트가 오면 그림이 아니다. 캡션은 대체 텍스트이며, 그 대체 텍스트가 반드시 있어야 한다.
- 두 칸 들여쓰기는 목록을 중첩한다. 네 칸은 코드 블록을 만들지 않는다.
- 제목은 페이지의 마지막 블록이 되지 않는다. 페이지 나눔기가 제목을 앞으로 끌어당긴다. 제목이 페이지를 끝내야 한다면, 함께 속한 내용 뒤에 명시적 `:::pagebreak`를 둔다.
- 원시 HTML 블록은 0열에서 시작해 빈 줄까지 이어져야 한다.

## 6. 완전한 예

```markdown
---
title: "온보딩 이탈 분석"
audience: "프로덕트 리드"
---

# 결론

온보딩 3단계를 줄이면 4주 안에 이탈률을 4.1%에서 3% 아래로 낮출 수 있다 [S1]. 비용은 디자인 2주다.

:::kpi
현재 이탈률 | 4.1%
목표 | 3.0% 미만
예상 기간 | 4주
:::

## 근거

3단계에서의 이탈이 전체의 절반을 차지한다 [S2].

| 구간 | 진입 | 이탈 | 이탈률 |
|---|---:|---:|---:|
| 1단계 | 12,400 | 1,110 | 9.0% |
| 2단계 | 11,290 | 1,020 | 9.0% |
| 3단계 | 10,270 | 2,050 | 20.0% |

[TOC]

## 다음 단계

3단계를 2단계로 합치는 시안을 2주 안에 만든다 [S3].
```
