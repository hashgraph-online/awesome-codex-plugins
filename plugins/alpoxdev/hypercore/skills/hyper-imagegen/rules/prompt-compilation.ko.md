# 프롬프트 컴파일 규칙

브리프를 컴파일하기 전, 그리고 렌더링 문구·시리즈·편집 경계 규칙의 정확한 문장이 필요할 때 읽습니다.

생성 또는 프롬프트 파일 전달을 선택하기 전에 요청을 이식 가능한 시각 브리프로 컴파일합니다. 브리프는 요청된 결과를 설명하며, 제공자, 모델, 명령 문법, 숨은 제어값, 추정한 기능을 담지 않습니다.

## 요청 해소

정확성이 중요한 곳, 특히 이미지 안에 렌더링할 문구에서는 사용자가 제공한 표현을 정확히 보존합니다. 되돌릴 수 있는 표현 세부 사항만 추론합니다. 누락된 원본, 권한, 렌더링 문구, 신원 보존 편집 경계, 보존/변경 경계 때문에 충실한 브리프를 만들 수 없을 때만 좁게 묻습니다. 완성된 브리프에 자리표시자를 남기지 않습니다.

편집에서는 제공된 원본의 역할, 바뀌지 않아야 할 부분, 요청된 변경을 명시합니다. 참고 자료가 있다고 해서 변경 권한이 있다고 보지 않습니다.

컴파일 전에 제공한 이미지마다 번호와 역할을 붙입니다. `Image 1: edit target`, `Image 2: style reference`, `Image 3: insert`처럼 씁니다. 스타일, 구도, 분위기, 주제 참고용으로만 제공한 이미지는 요청을 참고 자료가 있는 생성으로 만들고, 편집 대상이 있을 때만 편집입니다. 합성에서는 어느 이미지의 어떤 요소를 어느 이미지로 옮기는지, 빛·원근·크기를 바탕 이미지에 맞춘다는 점을 씁니다.

구체성 정책을 적용합니다. 자세한 요청은 새로운 창작 요구를 더하지 않고 깔끔한 브리프로 정리만 합니다. 일반적인 요청에는 결과를 실제로 좋게 만드는 세부만 보탭니다. 구도나 프레이밍 단서, 용도나 완성도 수준, 문구를 둘 여백 같은 실용적 배치 공간, 요청이 함축하는 장면의 구체성이 여기에 해당합니다. 요청이 함축하지 않은 인물, 소품, 브랜드, 슬로건, 팔레트, 이야기 흐름은 더하지 않고, 주변 레이아웃이 뒷받침하지 않는 좌우 배치를 고르지 않습니다.

## 이미지마다 하나의 완전한 브리프

요청한 이미지마다 완전한 브리프를 하나씩 만듭니다. 키워드 나열이 아니라 완전한 문장으로 장면을 묘사하고 배경이나 무대, 주된 대상, 핵심 세부, 제약, 용도 순서로 앞에 둡니다. 단순한 브리프는 보통 30~80단어에 들어가고, 밀도가 높은 레이아웃은 라벨 줄로 더 길어질 수 있습니다. 붐비는 장면은 단계 순서("먼저 …, 그다음 …, 마지막으로 …")로 쌓습니다. 자연스럽고 요청 중심의 문장으로 다음을 명시합니다.

- 용도와 구별되는 속성을 포함한 주된 대상
- 동작 또는 상태와 환경
- 프레이밍, 시점, 크기, 공간 순서, 의도적으로 비워 둔 공간
- 보이는 조명 방향, 대비, 그림자, 팔레트, 재질, 매체
- 요청한 경우 정확한 이미지 내 문구, 역할, 위치, 위계, 대비, 선명하고 철자가 정확하며 읽기 쉬운 텍스트 요구
- 제공된 참고 자료의 역할과 편집 보존/변경 제약
- 요청 수량과 요청한 캔버스 형태 또는 출력 특성

브리프의 렌더링 문구는 렌더링할 정확한 텍스트여야 합니다. 임의로 번역, 정규화, 중복, 축약하거나 단어를 추가하지 않습니다. 필요한 각 문자열은 한 번만 넣고, 몇 번 나오는지(보통 정확히 한 번) 명시하며, 읽는 순서를 분명히 합니다. 정확성이 중요하면 흔하지 않은 단어나 이름은 따옴표 문자열 뒤에 한 글자씩 철자를 적습니다.

## 관찰 가능한 제약 사용

막연한 칭찬 대신 보이는 지시를 사용합니다. 원하는 배치, 표면, 빛, 색, 질감, 분리를 직접 설명합니다. 인위적인 완벽함을 피하고 관련된 경우 자연스러운 재질 또는 피부 질감을 설명합니다.

제외 표현은 3계층 정책을 따릅니다. Tier 0(기본): 장면 제외는 단독 대상 하나, 상표 없는 표면, 복잡하지 않은 배경처럼 전부 긍정적이고 구체적인 상태로 표현합니다. 장면 네거티브는 제거되지 않고 렌더될 수 있으므로 부정 표현을 쓰지 않습니다. Tier 1(텍스트 렌더 가드): 브리프에 렌더 텍스트가 있을 때만 아래 화이트리스트 문구가 `no ...` 형태를 쓸 수 있습니다.

| Tier 1 화이트리스트 |
| --- |
| `no invented glyphs` |
| `no watermark` |

이 화이트리스트의 canonical은 검증기 상수 `TIER1_NEGATIVE_WHITELIST`입니다. 상류 킷의 "정확히 7개" 수치는 미검증이므로 실증된 2개로 시작하고, eval 행 증거가 있을 때만 늘립니다. Tier 2: 그 외 네거티브는 요청자가 명시적으로 옵트인할 때만 허용합니다. 프로바이더 스타일 네거티브 꼬리(`--no ...`)는 여전히 금지입니다.

설명 가능한 시각 속성으로 충분할 때 살아 있는 예술가, 실존 인물, 상표의 이름을 시각적 지름길로 빌리지 않습니다. 편집을 위해 제공된 권한 있는 신원 또는 브랜드 자료는 명시한 경계 안에서 보존할 수 있습니다.

## 시리즈와 변형

시리즈에서는 반복되는 시각 언어, 팔레트 계열, 텍스트가 있을 때의 활자 처리, 조명/재질 특성, 반복 모티프를 모든 브리프에 공통 불변 조건으로 씁니다. 요청된 이미지별 대상, 배치, 또는 개념 축만 바꿉니다. 탐색에서는 한 번에 주된 축 하나만 바꿉니다. 관련 없는 변형은 별도 이미지이며 하나의 캔버스에서 경쟁하는 지시가 아닙니다.

편집에서는 변경을 `change only <X>; keep <Y> unchanged`로 쓰고 보존 목록을 명시합니다. 신원(얼굴, 몸, 자세, 표정), 형태와 프레이밍, 레이아웃, 조명과 그림자, 라벨과 이미지 내 텍스트, 채도와 대비, 카메라 각도 중 해당하는 항목만 남깁니다. 적지 않은 불변 조건은 흐트러지므로 이후 수정 브리프마다 보존 목록 전체를 다시 적습니다. 여러 번 수정하면서 이미 흐트러졌다면 흐트러진 결과를 고치지 않고 원본과 원래 요청에서 새 완전한 브리프를 컴파일합니다.

## 컴파일 경계

컴파일한 텍스트는 그대로 사용할 수 있도록 정확하게 유지합니다. 전달 보고, 기능 관찰, 경로, 오류 설명, 런타임 매개변수는 프롬프트 파일 밖에 둡니다. 숨은 제공자 플래그, 이전 약식 표기, 프로필 라벨, 고정 등급, 화면비 꼬리표, 정적 크기 가정을 추가하지 않습니다. 활성 런타임이 지원하는 경우에만 지원되는 구조화 필드를 별도로 전달하며, 그 부재가 렌더링 브리프를 바꾸지 않습니다.

전달 전에 각 브리프가 완전하고 이미지 하나에 대응하며, 정확한 요청 문구를 보존하고, 참고 자료와 편집 경계를 식별하며, 구체적인 시각 제약을 담고, 보고 문구나 미해결 선택지를 포함하지 않는지 확인합니다.
