# 질의 근거

보고서를 쓰기 전과 종료 상태를 고르기 전에 이 규칙을 씁니다. 보고서 형태, 답만 내는 원칙, 답이 받아야 하는 검증, `Result:` 줄 형식의 네 가지 종료 상태를 담습니다.

## 1. 답만 냅니다

- 물어본 질문에 답합니다. 지표 하나, 집계 단위 하나, 모집단 하나, 필터 집합 하나, 기간 하나.
- extra 차트도, extra 분해도, 질문에 필요하지 않은 탐색 반복도 붙이지 않습니다. 두 번째 그룹, 추이, 차트는 질문이 이름 붙였을 때만 나옵니다.
- 데이터로 답할 수 없는 질문은 그렇다고 보고합니다. 물어본 숫자 대신 비슷한 숫자를 넣지 않고, 편한 컬럼이 지표 정의를 조용히 바꾸게 두지 않습니다. 지표 정의가 모호하고 답이 달라지면 조용히 고르지 않고 한 번 묻습니다.
- 데이터로 보일 수 없는 원인("매출이 왜 줄었나")은 계산된 변화부터 꺼내고, 가능한 원인은 명시적으로 미검증 가설로 뒤에 적습니다.

## 2. 보고서 형태

`.hyper/data/<slug>/report.md`에 저장합니다. 답이 먼저이고 근거가 뒤에 오며 종료 상태가 마지막입니다.

````markdown
# <질문 제목>

## Answer

<질문에 답하는 숫자나 표를 첫부분에 둡니다>

## Question

<측정 가능한 양 하나: 지표, 집계 단위, 모집단, 필터, 기간>

## Engine and placement

<프로브 출력 요약: 인터프리터, 엔진과 버전, `rules/placement.md`의 계산 위치 결정>

## Query

```sql
<실제로 실행한 질의 텍스트>
```

<행 수: 읽은 입력 행과 결과가 가진 행>

## Handling

<답이 의존하는 모든 컬럼의 null 처리와 중복 처리>

## Timing and digest

Input: `<파일>` (<바이트> bytes, <행> rows)
Digest: `<sha256>`
Wall-clock: <밀리초> ms on <기계>

## Cross-check

<다른 경로로 구한 핵심 숫자, 일치 여부 또는 차이 수량>

Result: answered
````

- 질문 줄은 집계 단위를 말로 적습니다. 일별, 리전별, 고객별, 주문별. 집계 단위가 없는 합계는 무엇과도 비교할 수 없습니다.
- 질의는 실행한 텍스트를 그대로 복사한 것이며 기억으로 다시 쓰지 않습니다. 재지 않은 행 수와 소요 시간은 재지 않았다고 적습니다.
- 입력 다이제스트는 읽은 대로의 입력 파일 SHA-256입니다. 입력이 데이터베이스 테이블이면 질의 텍스트와 반환 행 수를 다이제스트 대신 쓰고 어느 쪽인지 적습니다.

## 3. 검증

- 무거운 질의는 행 수와 소요 시간을 보고합니다. "끝났다"는 근거가 아니며 개수와 밀리초가 근거입니다.
- 핵심 숫자 하나를 다른 경로로 교차 검증합니다. 다른 테이블, 원시 개수, 두 번째 엔진, 같은 질의를 다른 식으로 쓴 값 중 하나입니다. 두 번째 출처를 핵심 숫자 옆에 이름 붙이고 일치 여부를 적습니다. 차이가 있으면 수량으로 적습니다.
- 두 번째 출처가 없으면 그 사실을 밝히고 교차 검증을 미검증으로 둡니다. 일치한다고 지어내지 않습니다.
- 질의가 오류를 내거나 읽을 수 없는 값을 내면 같은 질문 안에서 최대 두 번 다시 씁니다. 세 번째 실패는 실패한 질의와 오류를 담아 `blocked`로 끝냅니다.

## 4. 종료 상태

보고서는 네 가지 종료 상태 중 하나를 이름 붙이는 `Result:` 줄 하나로 끝납니다.

| Terminal | When |
|---|---|
| `answered` | 답을 계산했고, 행 수와 소요 시간과 입력 다이제스트가 보고서에 있습니다 |
| `prerequisite_missing` | 쓸 수 있는 엔진이 없습니다. 없는 엔진과 설치 명령을 보고하고, 아무것도 설치하지 않습니다 |
| `awaiting_input` | 숫자가 달라지는 질문 하나가 남았습니다. 지표 정의, 하루 경계의 시간대, 서로 모순되는 두 파일 중 정본이 여기에 해당합니다 |
| `blocked` | 데이터를 읽을 수 없거나, 어떤 안전한 계산 위치도 넘게 커서 막혔거나, 접근이 거부됐습니다 |

- `prerequisite_missing`은 없는 엔진과 설치 명령을 이름 붙이지만 실행하지 않습니다. 없는 엔진은 전제 조건이며 질문의 실패가 아닙니다.
- `awaiting_input`은 질문 하나를 한 번에 묻고 각 답이 무엇을 바꾸는지 적습니다. 빠진 정의가 숫자를 바꾸고 데이터로 확정할 수 없을 때만 씁니다.
- `blocked`는 막힌 지점을 정확히 이름 붙입니다. 읽을 수 없는 파일, 모든 계산 위치를 넘는 크기, 거부된 접근입니다. 다른 계산 위치로 피할 수 있는 막힘은 `blocked`가 아닙니다.
- 이 스킬은 커밋하거나 푸시하지 않습니다. 보고서가 실행의 끝입니다.
