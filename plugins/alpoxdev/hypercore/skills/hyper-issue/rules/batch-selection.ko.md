# Batch Selection

선택 조건, 이슈 번호, 배치가 나오면 이 규칙을 사용한다. 고정 목록, 질의 또는 번호 전개, 중복 제거, 레인 묶기, 명세 쓰기, `hyper`로 넘기기를 소유한다.

## 1. 목록 고정

1. 사용자의 말을 완전한 질의 하나로 바꾼다. 사용자가 준 모든 조건을 유지하고, 저장소 범위와 열린 상태 필터만 더한다.
2. 결과를 완전히 모은다. 모든 페이지, 풀 리퀘스트 제외, 반환 행 수와 총계 대조.
3. 상한에 걸렸거나 일부만 왔거나 실패했으면 멈춘다. 한계를 보고하고, 질의를 조용히 좁히거나 첫 페이지만 취하지 않는다.
4. 저장소와 이슈 번호로 중복을 제거하고, 첫 등장 순서를 정규 순서로 유지한다.
5. 이 시점에 목록이 고정된다. 나중 발견은 다음 배치의 새 후보로 보고하고 여기에 추가하지 않는다.

완전한 결과가 비어 있으면 레인 없이 끝나고, 한 줄 메모 외에는 명세를 만들지 않는다.

## 1b. 번호로 목록 고정

사용자가 질의 대신 이슈 번호를 적으면 그 번호가 목록이다.

1. 모든 형태를 양 끝을 포함한 명시 번호로 전개한다. `#1~3`, `#1-3`, `#1..3`, `1~3번`은 `1, 2, 3`이 되고, `#1, #4, #7`과 `#1 #4`는 적힌 그대로다. 섞인 형태는 합친다(`#1~3, #7`은 `1, 2, 3, 7`).
2. 끝이 시작보다 작은 범위나 50개 넘게 전개되는 범위는 차단 요인으로 보고하고 목록을 고정하지 않는다.
3. 번호마다 트래커에서 한 번 읽는다(번호, 제목, 상태, 본문, 라벨, 풀 리퀘스트 여부).
4. 열린 이슈인 번호만 남긴다. 뺀 번호마다 사유를 기록한다. `pull request`, `closed`, `not found`, `read failed` 중 하나다. 읽기 실패는 트래커 읽기로 장애를 확인한 뒤 한 번만 다시 시도하며, "not found"로 취급하지 않는다.
5. 전개한 뒤의 사용자 순서를 중복 없이 정규 순서로 유지한다. 모든 번호가 남김 또는 뺌 결과를 가지면 목록이 고정된다.
6. 남긴 이슈 중 본문에 `hyper:` 블록이나 필수 절이 없는 이슈는 `rules/issue-contract.md`에 따라 그 이슈를 갱신해 영어로 채운다. 쓰기 한 번, 다시 읽기 한 번이다. `--no-write`이거나 갱신이 실패하면 `## Scope`에서 쓰기 집합을 다시 도출하고 그 행에 `block: missing`을 표시한다.

남긴 이슈가 하나도 없으면 뺀 번호와 사유를 모두 적은 한 줄 메모로 배치를 끝낸다.

## 2. 그래프 재도출

`hyper:` 블록이 입력이고 간선은 계산하지, 그대로 믿지 않는다.

1. 이슈마다 `hyper:` 블록을 읽는다. 블록이 없는 이슈는 공백이다. `## Scope`에서 쓰기 집합을 다시 도출하고 명세 행에 `block: missing`을 표시한다.
2. `touches` 겹침 간선을 만든다. 두 이슈의 `touches`가 같은 경로를 공유하거나 한 글롭이 다른 쪽 경로를 덮을 때다.
3. 선언된 `depends_on`과 `conflicts_with` 간선과 합친다.
4. 이슈 사이의 순환은 차단 요인이다. 이슈 번호와 함께 보고하고 그 성분만 멈춘다. 순서를 만들어 내지 않는다.

## 3. 레인 묶기

레인은 정해진 순서로 처리하는 쓰기 집합 하나다. 레인은 병렬로 돌고, 레인 안의 이슈는 순서대로 돈다.

1. 겹침 그래프의 연결 성분이 레인이 된다. 간선이 없는 이슈는 자기 레인이다.
2. 레인마다 위상 정렬한다. 사이에 경로가 없는 두 이슈는 선언 순서, 낮은 이슈 번호 우선으로 둔다.
3. 레인 수는 로컬 동시 실행 한도, 기본값 4에서 자른다. 초과 레인은 대기하고 그 이슈는 레인 순서를 유지한다.
4. `lane_hint`가 유일하면 레인 이름으로 쓰고, 아니면 `<가장 낮은 이슈 번호>-<짧은 슬러그>`를 쓴다.

레인 수를 줄이려고 두 레인을 합치지 않는다. 같은 경로를 쓰는 두 이슈를 서로 다른 레인에 두지 않는다.

## 4. 명세

`references/batch-manifest.md` 형식으로 `.hyper/issues/<slug>/batch.md`를 쓴다. 담는 내용은 다음과 같다.

- 정확한 질의와 수집 완전성 증거, 또는 적힌 그대로의 번호와 그 전개
- 번호, 제목, 분류, 레인, 크기, 검증 명령이 붙은 정규 고정 목록
- 레인별 순서와 쓰는 경로의 합집합을 담은 레인 표
- 차단 요인: 뺀 번호, `hyper:` 블록 누락, 순환, 분할이 필요한 이슈
- 다음 단계가 읽는 핸드오프 줄과 다음에 `hyper`를 불러오는지 여부

## 5. 배치가 하지 않는 일

- 구현, 브랜치 생성, 커밋, 푸시를 하지 않는다. 넘긴 뒤에는 그 일이 `hyper`가 돌리는 단계의 몫이다.
- 닫힌 이슈를 다시 열거나 기존 브랜치를 자기 것으로 가져오지 않는다.
- 구현이 쉬워졌다는 이유로 고정 목록에 이슈를 추가하지 않는다.
- 막혀 보인다는 이유로 이슈를 빼지 않는다. 차단 요인을 기록한다.

## 6. `hyper`로 넘기기

넘기기는 `SKILL.md`의 트리거 표가 정할 때 적용한다. 이슈 번호면 기본으로, 기록이나 선택 조건이면 작업 단어가 있을 때다. `--from-hyper`, `--no-run`, `--draft-only`이거나 남긴 이슈가 없으면 적용하지 않는다.

1. 명세가 디스크에 있고 실행 가능한 레인이 하나 이상인지 확인한다. 모든 레인이 막힌 배치는 차단 요인을 보고하고 명세에서 끝난다.
2. 같은 세션에서 설치된 `hyper` 스킬을 이름으로 불러온다. 아래 요청을 채워 영어로 넘긴다.

   ```text
   Implement the issue batch fixed in .hyper/issues/<slug>/batch.md.
   - Issue stage: done by hyper-issue; the manifest is the fixed input and its list must not change.
   - Lanes: run each lane in the manifest's Lane table as one parallel lane, and its issues in the listed order.
   - Gates: each issue's verify command is its acceptance check; a blocked lane does not stop the other lanes.
   - Delivery: <the user's delivery words unchanged, or "local">.
   - Pull requests, when opened, carry `Closes #<n>` for every issue they finish.
   ```

3. 명세의 `## 핸드오프` 절에 `다음 단계: hyper (넘김)`과 시각을 기록한다.
4. 이 스킬의 실행은 넘기기에서 끝난다. `hyper` 실행을 기다리거나, 다시 확인하거나, 다시 들어가지 않는다. 마무리 보고는 `hyper`의 몫이다.
5. `hyper` 스킬이 설치되지 않았거나 불러올 수 없으면 명세에서 멈추고 `npx skills add alpoxdev/hypercore --skill hyper`를 보고한다.
