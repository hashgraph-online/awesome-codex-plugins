# 분류

한 줄을 슬롭이라고 부르기 전에 이 파일을 읽습니다. 아홉 가지 분류, 그보다 우선하는 KEEP 예외, 그리고 제거를 쓰기 전에 각 분류가 요구하는 증명을 맡습니다.

## 1. 아홉 가지 분류

후보는 분류 하나, KEEP 점검 하나, 증명 하나로 이뤄집니다. KEEP 점검에 걸리면 그 줄은 범위를 벗어나고, 증명이 없으면 그 줄은 그대로 남습니다.

| # | 분류 | 묶음 | 수정 전 증명 |
|---|---|---|---|
| 1 | 주석 메아리 | 문체 | 주석이 바로 아래 줄을 되풀이하며, 그 줄이 왜를 담은 하중 줄이 아니다 |
| 2 | 과잉 방어 | 문체 | 가드의 대상이 없을 수 없거나, 같은 경계 안의 남은 가드가 같은 입력을 덮는다 |
| 3 | 과잉 복잡도 | 문체 | 펴 놓은 형태가 같은 독자에게 같은 동작으로 읽힌다 |
| 4 | 불필요한 추상화 | 구조 | 호출자 하나, 구현체 하나, 이음매 없음. 감싸개를 없애도 모든 호출부가 평범하게 읽힌다 |
| 5 | 경계 위반 | 구조 | 잘못 놓인 책임에 이름 붙인 소유 계층이 있고, 옮겨도 순환 import가 생기지 않는다 |
| 6 | 죽은 코드 | 구조 | 아무것도 닿지 않는다. 호출자도, 반사나 문자열 조회도, 아직 뒤집히는 플래그도 없다 |
| 7 | 중복 | 숨은 비용 | 사본들이 한 의도를 따르며 갈라지지 않고, 합친 형태가 모든 호출자의 입력을 보존한다 |
| 8 | 동작 동등 비용 | 숨은 비용 | 동등함이 논증이 아니라 자명하다. 소유자가 받는 모든 입력에서 출력 집합이 같다 |
| 9 | 테스트 쓰레기 | 테스트 | [test-junk.md](test-junk.md)의 분류별 증명, 또는 그 테스트가 받는 표시 |

4, 5, 7번은 잘못 판단하면 피해가 나는 자리입니다. 이음매, 계층, 나중에 갈라질 예정이던 우연한 중복이 여기에 해당합니다. 의도가 코드에 보이지 않으면 후보는 남습니다.

## 2. 문체

### 1. 주석 메아리

줄을 되풀이하는 주석, 자명한 docstring, 구분선, 주석 처리한 코드, 소유자 없는 모호한 `TODO`나 `NOTE`입니다.

KEEP:

- 왜를 말하는 주석: 업무 규칙, 경계 사례, 플랫폼 우회, 순서 제약
- 티켓이나 이슈 링크, 정규식이나 알고리즘 설명, 단위와 부호 관례
- 시나리오를 이름으로 대는 행동 우선 표시(`# given`, `# when`, `# then`)

지우면 다음 독자가 제약을 다시 유도해야 하는 주석은 코드 모양을 되풀이해도 메아리가 아닙니다.

### 2. 과잉 방어

타입이나 호출자가 보장하는 값에 붙인 null·undefined 검사, 예외가 날 수 없는 코드를 감싼 `try`/`catch`, 필수 인자의 기본값, 더 이상 없는 호출자를 위한 호환 shim, 세 계층에 반복된 같은 검증, 모든 실패를 삼키는 넓은 catch입니다.

KEEP: 시스템 경계의 검증(사용자 입력, 외부 API 응답, 파일·네트워크 읽기), 입출력 오류 처리, null 허용 저장 필드, 로그를 남기고 다시 던지는 최상위 경계 catch 하나.

가드는 중복이 증명되기 전까지 하중을 받습니다. 증명은 안쪽 가드를 지웠을 때 바깥 계층이 거부하는 적대적이거나 잘못된 입력, 그리고 바깥 계층을 지웠을 때 그 입력이 소유자에게 닿는 관찰입니다. 증명이 없으면 제거도 없습니다. 증명되지 않은 가드는 잡음이 아니라 경계입니다.

넓은 catch를 좁히는 것은 그 표면이 무엇을 삼키는지 문서화한 경우 동작 변경입니다. 문서화된 예외 집합이 같을 때만 좁힙니다.

### 3. 과잉 복잡도

세 단을 넘는 중첩, 이어 붙인 삼항 연산, 서로 독립적인 조건 넷 이상을 묶은 불리언 식, 이름 붙인 구조체 없이 다섯을 넘는 인자 목록, 서로 무관한 일을 여러 개 하는 함수, 아끼는 줄보다 읽는 비용이 큰 한 줄짜리입니다.

KEEP: 이 코드베이스의 자리 잡은 관용구, 복잡한 형태가 빠른 이유로 측정된 뜨거운 경로, 쓴 그대로 평범하게 읽히는 불리언 `if`/`else`나 범위 검사.

가드가 같은 순서와 같은 효과의 조기 반환으로 바뀌고, 어떤 분기도 이전에 읽지 않던 상태에 의존하기 시작하지 않을 때 평탄화가 안전합니다.

## 3. 구조

### 4. 불필요한 추상화

그대로 넘기는 감싸개, 한 번만 쓰는 도우미, 테스트 이음매를 만들지 않는 구현체 하나짜리 인터페이스, 생성자만 부르는 팩토리, 오지 않은 미래를 위해 남긴 간접층입니다.

KEEP: 실제 경계에서 테스트가 대체하는 이음매, 살아 있는 구현체가 둘 이상인 형태, 프레임워크가 요구하는 타입이나 생명주기.

감싸개를 없애도 모든 호출부가 같은 작업을 이름으로 부릅니다. 본문을 인라인했더니 호출부가 더 나빠지면 그것은 정리가 아닙니다.

### 5. 경계 위반

계층을 넘나드는 코드입니다. UI가 드라이버를 import하고, 핸들러가 서비스 소유의 업무 규칙을 들고 있고, 한 모듈이 다른 모듈의 사설 상태를 읽고, 순수라는 이름의 함수가 부수 효과를 냅니다.

KEEP: 코드베이스가 이미 쓰는 지름길, 제자리에 문서화된 의도된 결합.

대상 계층이 승인된 파일 집합 밖이면 이 분류는 조용히 옮기지 않고 보고합니다. 모듈 경계를 넘기는 일은 자체 계획이 있는 별도 변경입니다.

### 6. 죽은 코드

쓰지 않는 import, 닿지 않는 분기, 호출자 없는 사설 함수, 낡은 기능 플래그, 트리에 남은 디버그 출력, 제거됐지만 아직 참조되는 심벌입니다.

KEEP: 반사, 동적 디스패치, 문자열 조회, 템플릿, 런타임 설정 키로 닿는 것, 되돌림 경로가 아직 살아 있는 플래그.

증명은 현재 파일이 아니라 저장소 전체 참조 검색입니다. 정의 지점, 호출 지점, 이름의 문자열 형태, 빌드 시스템의 진입점을 모두 봅니다. 검색을 돌릴 수 없었으면 코드를 그대로 두고 이유를 보고서에 적습니다.

### 7. 중복

리터럴만 다른 복사 붙여넣기 분기, 같은 일을 하는 도우미 둘, 여러 곳에 반복된 같은 마법 상수열입니다.

KEEP: 의도가 다르고 정당하게 갈라질 수 있는 비슷한 본문 둘, 각 자리에서 다른 개념을 가리키는 반복 리터럴.

두 본문을 하나의 매개변수화한 도우미로 합치는 일은 두 호출부 모두를 바꾸는 변경입니다. 두 호출부가 파일 집합 안에 있을 때만 승인됩니다.

## 4. 숨은 비용

### 8. 동작 동등 비용

집합 조회로 바뀌는 이차 스캔, 반복문 밖으로 나가는 재계산, 한 번만 순회하면 되는 즉시 중간 컬렉션, `join`으로 바뀌는 반복 문자열 연결, 묶음 처리로 바뀌는 반복 호출, 필요 없는 깊은 복사입니다.

단단한 규칙: 소유자가 받는 모든 입력에서 동등함이 자명할 때만 적용합니다. 경계 사례를 다 읽지 않은 알고리즘 변경은 범위 밖이고, 측정 없는 미세 최적화는 이 분류가 아닙니다.

## 5. 테스트

### 9. 테스트 쓰레기

실패할 수 없거나, 구현을 되풀이하거나, 산문을 고정하거나, 복사한 목록을 비추거나, 소스 텍스트를 grep하는 선언입니다. 분류, 표시, 분류마다 필요한 증명은 [test-junk.md](test-junk.md)가 맡습니다.

KEEP: 공개 API, 프로토콜, 설정 스키마나 기본값, 마이그레이션, 저장 형식, 보안 경계, 플랫폼 동작, 실제 산출물 사이의 배포 사본 동등성, 이슈 회귀, 기계가 소비하는 토큰을 독립적으로 지키는 테스트. 원장 행에 어느 항목인지 적습니다.

바뀌지 않은 기준에서 빨간 테스트는 제품 버그입니다. 보고하고 모든 증명에서 제외하며, 지우지도 기대값을 고쳐 통과시키지도 않습니다.

## 6. KEEP이 분류보다 우선한다

KEEP 목록은 권고가 아닙니다. 공개 시그니처, 예외 동작, 부수 효과, 보안 가드, 접근성 편의, 지원 환경은 코드가 중복처럼 보여도 계약입니다.

두 분류가 어긋나면 더 엄격한 증명이 이깁니다. KEEP 목록과 분류가 동시에 해당하면 그 줄은 남고, 보고서가 보존한 코드에 기록합니다.
