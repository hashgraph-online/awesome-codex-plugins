# 동작 잠금

첫 수정 전에 이 파일을 읽습니다. 기준 기록, 절대 지우지 않는 기존 실패, 정리가 동작을 바꾸지 않았음을 증명하는 근거를 맡습니다.

## 1. 잠금은 약속이 아니라 기록이다

동작 보존 정리는 두 가지로 증명됩니다. 같은 명령이 전과 후에 통과하는 것, 그리고 제거한 hunk를 모두 이름으로 대는 보고서입니다. 둘 다 의도에 대한 주장이 아니라 검토자가 다시 돌릴 수 있는 산출물입니다.

수정 전에 잠금을 씁니다.

```markdown
## Behavior lock (<ISO timestamp>)
- Base: <branch or commit> — <HEAD sha>
- Working tree: <clean | N modified, M untracked, listed below>
- Command: <exact test or check command>
- Result before: <pass | fail with the failing case names>
- Owner tests read: <paths>
```

기준은 작업이 시작된 상태이고, `main`도 `HEAD~1`도 아닙니다. 더러운 트리는 정상입니다. 이미 수정돼 있던 파일을 적어 두면 마지막 diff에서 이번 실행의 수정과 구분할 수 있습니다.

## 2. 먼저 기준, 진짜 명령으로

기준 명령은 손댈 영역에 프로젝트가 이미 돌리는 것입니다. 테스트 러너, 타입 검사, 린트입니다. 검사를 새로 만들지 않고, 손댈 파일로 범위를 좁히지도 않습니다.

- **통과한다.** 그 통과가 잠금입니다. 같은 명령이 마지막에도 통과해야 합니다.
- **실패한다.** 실패한 case를 이름과 출력과 함께 기준 빨강 목록에 적습니다. 그 case는 이번 실행의 모든 증명에서 제외됩니다.
- **돌릴 수 없다.** 러너, 서비스, 도구 체인이 없거나 깨진 것은 통과가 아니라 발견 사항입니다. 잠금에 정확한 오류를 적고, 프로젝트가 문서화한 동등한 명령을 찾거나 그 공백을 보고합니다.

기준에서 빨간 case는 제품 버그입니다. 지우지도, skip으로 표시하지도, 통과하는 기대값으로 고치지도 않습니다. 정리는 방금 약화시킨 스위트로 평가받을 수 없습니다.

## 3. 실패할 수 있는 경계를 고른다

잠금은 바뀔 동작을 실제로 지날 때만 의미가 있습니다.

| 바뀌는 것 | 증명하는 것 |
|---|---|
| 한 모듈 안의 함수 본문 | 사설 도우미 테스트가 아니라 공개 진입점을 부르는 소유 테스트 |
| 가드나 검증 경로 | 가드 양쪽에서 거부 입력을 넣는 case |
| 호출자가 여럿인 공유 도우미 | 호출자 경계마다 그 호출자의 스위트, 또는 그것을 모두 덮는 가장 넓은 기존 스위트 |
| 운영 코드 변경이 없는 테스트 파일 | [test-junk.md](test-junk.md) §4의 변이 증명 |
| 주석, 이름 변경, 서식만 | 같은 명령, 그리고 실행 줄이 움직이지 않았다는 서술 |

어떤 테스트도 그 표면에 닿지 않으면 잠금은 실행 재현입니다. 입력과 관찰 출력이 붙은 정확한 명령을 수정 전에 기록하고 수정 뒤에 다시 돌립니다.

## 4. 잠금 하나, 마지막에 다시

수정마다 스위트를 돌리지 않습니다. 기준을 잡을 때 한 번, 수정이 끝났을 때 한 번 돌리고, 이후 교정은 그 교정이 영향을 줄 수 있는 검사만 다시 돌립니다.

두 실행의 결과가 다르면 잡음이 아닙니다. 수정이 동작을 바꿨거나 실행이 재현되지 않는 것이고, 둘 다 보고합니다. 두 번째는 수정하지 않은 기준에서 같은 명령을 다시 돌려 증명합니다.

## 5. 동작이란 무엇인가

동작은 호출자나 사용자가 관찰할 수 있는 것이고, 코드 내부 모양이 아닙니다.

- 반환값, 실패가 던지는 오류 타입과 메시지
- 호출이 내는 부수 효과와 그 순서
- 공개 시그니처, export 이름, 직렬화 출력의 형태
- 소비자가 파싱하는 로그 줄, 스크립트가 보는 종료 코드, 빌드가 쓰는 파일
- 접근성 편의와 지원 환경 동작

스택 트레이스를 바꾸는 인라인 감싸개, 예외 클래스를 바꾸는 좁힌 catch, 부수 효과 둘의 순서를 바꾸는 평탄화는 모두 동작 변경입니다. 정리 요청이 그것을 승인하지 않습니다.

## 6. 승인된 범위

잠금은 요청이 이름을 댄 파일, 이름이 없으면 현재 diff를 덮습니다. 저장소 전체를 덮지 않습니다.

- 호출자, 이웃 패턴, 테스트를 읽는 것은 맥락이고 수정 권한이 아닙니다.
- 수정이 깨뜨릴 의존성은 두 번째 범위가 아니라 보고서의 발견 사항입니다.
- lockfile은 요청이 의존성 제거를 명시할 때만 바뀝니다.
