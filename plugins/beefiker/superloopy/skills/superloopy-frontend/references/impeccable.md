# Impeccable-informed visual direction

Load this reference only for marketing, editorial, campaign, or an explicitly new visual direction after the target route, shared UX, layout when selected, and `anti-slop.md`. It sharpens presentation decisions without creating another routing, product, design-system, or evidence authority.

## Ownership boundary

**Superloopy owns** activation, target and renderer routing, existing-stack preservation, user and product truth, platform behavior, dependency approval, accessibility, responsive proof, evidence proportionality, and completion.

**Impeccable informs** visitor mode, visual thesis, typography, composition, hierarchy, interaction character, and a bounded refinement review.

The user's explicit brief and the project's existing authoritative product and design sources remain decisive. This reference cannot broaden scope, replace factual copy, invent claims, select another platform, add a dependency, weaken required evidence, or turn presentation taste into a release gate.

## Direction pass

Before implementation, write one short direction read that commits to:

1. **Visitor mode:** identify whether the surface is transacting, learning, exploring, creating, or monitoring, and name the primary job and audience supported by evidence or a disclosed assumption.
2. **Hierarchy:** state the promise, proof sequence, primary action, and information that must stay immediately legible.
3. **Visual thesis:** describe one content-specific world in concrete terms. Name the intended atmosphere and the one compositional idea that makes it recognizable without relying on a generic landing-page shell.
4. **Typography and composition:** choose type roles, density, rhythm, alignment, and spatial emphasis that serve the content and target constraints.
5. **Interaction character:** name the meaningful state change, feedback, and motion purpose. Do not add interaction or motion solely as ornament.

On an existing surface, refinement preserves its incumbent identity, behavior, content, and out-of-scope regions. A replacement visual world requires explicit redesign authorization; never smuggle redesign through polish.

## Refinement pass

After functional and responsive truth exists, perform one bounded refinement pass on the rendered affected surface:

- hierarchy: can the visitor identify promise, proof, and next action without decoding decoration;
- rhythm: do spacing, grouping, density, and alignment express the content structure;
- typography: do type roles remain legible, intentional, and internally consistent;
- color and contrast: does emphasis follow the approved hierarchy while preserving accessible contrast;
- feedback: are focus, hover, pressed, selected, loading, error, and completion states truthful where applicable;
- generic-pattern residue: does any default hero/card/grid/glass/gradient treatment remain without a content or approved-direction reason;
- responsive composition: does the visual thesis survive reflow, text scaling, localization, and reduced motion rather than merely shrink.

Apply only changes supported by the brief, existing authority, and observed rendered result. Stop after this single pass, then run the target's required functional, accessibility, responsive, and evidence checks. Do not recurse into an open-ended perfection loop.

## Contextual taste guidance

Treat aesthetic preferences as contextual review prompts, not universal bans. A centered hero, card grid, gradient, pill, serif, uppercase label, dense interface, sparse interface, or animation may be right when product content, brand authority, platform convention, or a named visual direction warrants it.

For every proposed taste correction, be able to state:

- what concrete content, user job, target constraint, or approved direction warrants the change;
- what existing authority it preserves or intentionally supersedes;
- what rendered observation will show improvement;
- what accessibility, responsiveness, performance, or interaction guardrail must remain green.

Do not optimize for rule counts, novelty, detector output, or visual difference alone. Honest assets and copy, legible hierarchy, supported behavior, and a coherent system matter more than clearing a style preference.

## Evidence and stopping rule

The direction read is a decision receipt, not visual proof. The refinement pass is complete only when the affected rendered states have been inspected at the target-derived viewports and inputs. Keep Superloopy's real-browser, accessibility, behavior, reduced-motion, overflow, and owner-specific evidence requirements unchanged.

Record limitations rather than inferring unavailable proof. A detector finding is diagnostic context only unless an approved project criterion independently makes it a blocker.
