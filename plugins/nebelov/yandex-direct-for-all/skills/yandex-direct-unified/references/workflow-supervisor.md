# Надзорная проверка

Заполнить перед чтением действующего кабинета, перед планом записи, перед записью и перед итогом.

| Проверка | Требуемое доказательство |
|---|---|
| Объём | Понятное имя клиента и перечень только его кампаний |
| Доступ | Свежий успешный запрос к нужной службе |
| Приложение | Токен принадлежит ожидаемому общему или явно настроенному приложению |
| Исходное состояние | Снимок затрагиваемых объектов и контрольные суммы |
| Семантика | Каждая исходная строка получила решение либо явный блокер |
| Разрешение | Явное разрешение на точный пакет записи |
| Ворота | Проверены срок, объём, блокировка, стоимость и возможность отката |
| Чтение после записи | Фактические поля совпали с утверждённым пакетом |
| Итог | Нет скрытого невыполненного объёма |

Если хотя бы одна обязательная строка не доказана, следующий этап не начинается.

# Подробности

## Чек-лист вместо отдельного надзорного агента

`workflow-supervisor-check.tsv` — единый живой чек-лист задачи (схема `stage status evidence_path blocker next_action reviewer`; статусы `PASS`, `FIX_REQUIRED`, `BLOCKED`, `NOT_APPLICABLE` с указанием причины неприменимости). Основной исполнитель сам обновляет строки после фактического чтения, dry-run и readback. Перед любой записью черновика или боевой записью обязательны строки `PASS` либо обоснованное `NOT_APPLICABLE` по применимым этапам: `intake`, `access`, `snapshot`, `payment_truth` (если запись или стратегия опирается на цели, лиды, продажи, выручку, окупаемость), `site`, `sqr_or_semantics`, `build_dossier`, `dry_run`, `pre_write`, `full_build_acceptance_pre_write` (новый клиент, мультисайтовая сборка, комбинаторные объявления, новые черновики). Устная самопроверка не заменяет таблицу. Для высокого риска допускается не более одной независимой проверки плана до записи и одной проверки готового результата; OAuth, Метрика, снимок, семантика, тексты, изображения, dry-run и readback отдельными поводами для проверяющих не являются. Чек-лист или покрытие со статусом PASS, созданные тем же скриптом, который готовил ключи, не засчитываются (`self_generated_supervisor_pass`).

## Область клиента и снимок

Перед снимком общего или агентского аккаунта получить минимальный список кампаний (название, состояние, статус, посадочная/домен) и составить `client-scope.tsv`: человекопонятное название кампании, почему она относится к клиенту, источник признака. Полный снимок по всем кампаниям аккаунта с чужими кампаниями запрещён; кампанию, которую нельзя уверенно отнести к клиенту, не читать (группы, объявления, запросы, площадки, статистику). Нет ни одной уверенно клиентской кампании — остановиться с блокером области клиента. Допустима ограниченная read-only проверка только по Директу до сбора слоя «правда об оплате», если явно: доступ и область клиента свежо доказаны, перечислены точные названия кампаний, нет живых записей и нет выводов о лидах, продажах, эффективности, оптимизации, сборке или записи; её нельзя выдавать за полный снимок. При инциденте в рекламной аналитике до выводов построить текущую межповерхностную матрицу атрибуции: названия показывающихся кампаний, привязки счётчика и целей в шаблоне отслеживания, инициализация счётчика на живом сайте в браузере, визиты/звонки Roistat, состояние очереди лидов, система получения лидов (amoCRM или эквивалент) за то же окно трафика; старые названия, устаревшие допущения о счётчике и проверки только по отчётам недостаточны.

## Полный анализ действующего кабинета

Для полного анализа и выводов об эффективности собраны применимые слои: структура Директа, отчёты, SQR, площадки РСЯ (если есть), состояние объявлений, цели и UTM Метрики, таблица соответствия, если UTM не совпадает с названием кампании, слой «правда об оплате» (для выводов о лидах, продажах, выручке, окупаемости), `human-review` для противоречий, `stop-word-coverage-report.md`, чанки смыслового разбора (если строк >500), результаты конкурентного преимущества (если этап в scope). Отсутствие кабинета или аналитики блокирует только зависимые выводы и настройки.

## Чтение после записи: полный перечень

После записи черновика или боевой записи журналу записи не доверять: обязательное чтение через API по пунктам — состояние/статус кампании; стратегия и цель; номера счётчиков; минус-фразы и общие наборы; настройки (интересы, альтернативные тексты, мониторинг сайта); типы площадок; сетевая стратегия; группы и ретаргетинг по офферу; число объявлений и состояние компонентов; быстрые ссылки и уточнения; пути отображаемых ссылок (русские, ≤20, без обрезки, связаны с ключом группы); уникальность изображений РСЯ и поля модерации/готовности; кнопки РСЯ или документированный блокер; ручные ключи, группы без ручных ключей и `---autotargeting`; дубли; выбранная цель оптимизации по номеру и названию; число минусов и любая разница нормализации Директа между подготовленным и прочитанным списком; `TimeTargeting` против плана; `SitelinkSetId` у каждого TextAd и совпадение набора; категории и опции бренда автотаргетинга по карте и `group_uid`; точные id Директа строками; восстановление после неоднозначной записи; возобновление на уровне объявления, версия API `ResponsiveAd`, часы праздников; намерение канала против обеих стратегий; полный автотаргетинг по всем группам области; утверждённый слой минусов по каждой кампании/группе без конфликтов защищённых терминов; 7/3 у каждого комбинаторного `ResponsiveAd` без нормализованных дублей внутри объявления; точный набор регионов; сравнимый снимок до/после по защищённым кампаниям; полнота структуры сетевой стратегии; однородность пачек и однозначное соответствие результатов; контракт символов; эквивалентное покрытие минусов; построчная связь «запрос → минус»; значения цели/стратегии/бюджета каждое в своём поле; построчное решение операторов ключей; раздельность слоя общих защитных минусов и реальных; смысловой гейт 7/3; значимость наборов ссылок и уточнений; назначение изображений РСЯ; график; матрица площадок; сохранение компонентов; последовательность слоёв. Если Директ сам добавил `---autotargeting` или изменилась структура групп — проверить полный набор из пяти категорий и трёх опций бренда по всем группам области. Закрытие создания черновика по числу кампаний/групп/объявлений/ключей без обязательных слоёв readback — BLOCKED с соответствующим кодом: `campaign_channel_strategy_mismatch`, `geo_scope_mismatch`, `search_negatives_missing`, `responsive_ad_components_incomplete`, `missing_time_targeting_readback`, `missing_sitelink_apply_readback`, `autotargeting_full_state_missing`, `protected_campaigns_unchanged_unproven`.

## Закрытие задачи

Итоговый ответ допустим, только если: объём реально выполнен или есть непроходимый блокер; нет незакрытого хвоста черновика или боевой записи; если запись была разрешена и выполнена — readback записан; пользователь видит человекопонятные названия; частичные ошибки не скрыты; при запуске или одобрении поставлен мониторинг; для нового клиента, мультисайтовой сборки, комбинаторных объявлений и новых черновиков, если запись была разрешена и выполнена, есть `full_build_acceptance_post_write=PASS` по тому же полному набору `entity_key`, что и перед записью (при разрешении `read_only` или `local_draft` достаточно `pre_write`); для объёма с поисковыми ключами построчное решение по операторам имеет PASS, а цепочка «итоговый пакет → кабинет» — если запись была разрешена и выполнена (для локального черновика — цепочка до итогового пакета).
