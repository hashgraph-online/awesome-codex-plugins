# BI Конструктор Битрикс24: вход, права и API Superset

Справочник к [навыку](../SKILL.md). Все вызовы выполняются из вкладки браузера, где пользователь уже вошёл в портал: внешнего API с токеном у BI нет. Объекты BI — стандартный Apache Superset на отдельном хосте вида `b<номер портала>.bi.bitrix24.ru`; SQL уходит в Trino, схема `bitrix24`.

## Вход в Superset

1. Штатный вызов из вкладки портала: `BX.ajax.runAction('biconnector.dashboard.getSupersetEntityLoginUrl', {data: {entityUrl: '/sqllab/'}})` — в ответе адрес входа; перейти по нему той же вкладкой. Удобно для входа сразу в SQL Lab.
2. Если кнопка «BI Конструктор» открывает новое окно, которое ваш браузерный инструмент не пропускает: во вкладке портала перехватить адрес (временно подменить `window.open`), вызвать `BX.BIConnector.SupersetDashboardGridManager.Instance.openConstructorWorkspace()` и перейти по перехваченному адресу в той же вкладке.
3. Адрес входа содержит одноразовый токен: не печатайте его в чат, журналы и отчёты.

## Права и владельцы

- Роли текущего пользователя BI: `GET /api/v1/me/roles/`. Роли вида `bx_read`, `bx_sql`, `bx_write` — не администратор BI.
- Администратор портала Битрикс24 не равен администратору BI: права BI задаются отдельно, в «Настройки BI-аналитики».
- Superset даёт править объект только владельцу: `GET /api/v1/dataset/<id>` → поле `owners`. Ответ 403 на запись набора обычно значит «владелец — другой (или отключённый) пользователь», а не «нет прав администратора портала».
- Вывод «нет прав» делайте только после проверки: под каким пользователем открыт портал, какая у него роль в BI, кто владелец объекта.

## Подтверждённые вызовы API

CSRF-токен для записи берите из элемента `#csrf_token` на странице `/sqllab/` и передавайте заголовком `X-CSRFToken`. Токен из `GET /api/v1/security/csrf_token/` на запись может не подойти (400).

- SQL: `POST /api/v1/sqllab/execute/` с телом `{database_id, sql, runAsync: false, schema: "bitrix24", queryLimit}`; номер подключения сверяйте в SQL Lab. Проверочный запрос оборачивайте: `SELECT count(*) FROM (<запрос>) t`.
- Набор: `POST /api/v1/dataset/` `{database, schema, table_name, sql}` без поля `catalog` (с ним встречался 500); `PUT /api/v1/dataset/<id>`; `PUT /api/v1/dataset/<id>/refresh`.
- График: `PUT /api/v1/chart/<id>` `{params, dashboards: [<id дашборда>]}`.
- Дашборд: `PUT /api/v1/dashboard/<id>` `{position_json, json_metadata, css}`.
- Формат чисел в графике — `column_config` с `d3NumberFormat` `,.0f`; период по умолчанию в нативном фильтре — `defaultDataMask` с `time_range`.
- Ответы 500/502 с текстом о нагрузке Trino — повторите чтение позже; запись без перечитывания не повторяйте.

Лимит Trino — 150 стадий на запрос: читайте лиды и сделки один раз и разворачивайте через `UNNEST`, не делайте много самосоединений.

## Правка SQL набора

1. Прочитать `GET /api/v1/dataset/<id>` → `result.sql`, сверить хеш с локальной копией.
2. Проверить новый SQL в SQL Lab в том же виде, что у графика (те же `GROUP BY`).
3. Записать `PUT /api/v1/dataset/<id>` с `sql` и явными `always_filter_main_dttm` и `normalize_columns` (значения как были): без них запись сбрасывает эти поля.
4. Снять слепок всех полей до и после; изменилось что-то кроме `sql` — остановиться и откатить из слепка «до».
5. Замену текста в браузерном JS делайте `split(old).join(new)` с проверкой, что вхождение одно; `String.replace` со строкой-заменой подставляет лишние фрагменты через спецпоследовательности и ломает живой набор.

## Копия отчёта на своих наборах

Когда наборы рабочего отчёта принадлежат другому владельцу:

1. В списке отчётов Битрикс24 нажать «Сделать копию». Копия ссылается на те же графики и наборы.
2. Создать свои наборы и свои графики на них.
3. `PUT` дашборда копии: `json_metadata.positions` с новыми id графиков (иначе остаются старые), фильтры с `datasetId` новых наборов, `chart_configuration`, CSS `dashboard-chart-id-N` под новые id.
4. Сверить копию со старым отчётом построчно; старый отчёт не менять.

## Новый отчёт в списке «Отчёты в CRM»

Во вкладке портала: `BX.SidePanel.Instance.open('/bitrix/components/bitrix/biconnector.apachesuperset.dashboard.edit/slider.php')`, затем перенести раскладку (графики, фильтры, CSS) через `PUT` дашборда. Может всплыть лицензионное соглашение: принимает его администратор портала, не вы.

## Расходы рекламы

- Штатный путь — «Сквозная аналитика» Битрикс24, таблица `tracking_source_expenses`: данные подтягиваются сами. Не вшивайте расходы в SQL набора блоками `VALUES` (кроме согласованного временного резерва).
- Любой сломанный источник сквозной аналитики (без привязанного кабинета) роняет все запросы к таблице расходов. Перевод неиспользуемого источника «В архив» обратим, но это изменение постоянной настройки — только с разрешения владельца портала.
- Привязку кабинета Директа (OAuth Яндекса во всплывающем окне) начинайте и заканчивайте в одном браузере: OAuth, начатый в одном браузере и подтверждённый в другом, даёт «Wrong request».
- Проверка расходов — встроенный отчёт `/report/analytics/?analyticBoardKey=crm-ad-payback` на портале.

## Проверка дашборда после записи

- Откройте каждую вкладку дашборда настоящим кликом (программный `click` по вкладке графики не рисует).
- Все запросы `chart/data` — ответ 200; пустой ответ или ошибка у графика — не готово.
- Цифры сверьте с прежним отчётом или прямым запросом к CRM навыком [bitrix24-crm-api](../../bitrix24-crm-api/SKILL.md).
