# Design an original character that can be reused

Use this when a recurring character or mascot has no accepted design yet. Reuse an existing approved reference when one exists. A reference sheet is useful only if its individual views agree; do not generate an elaborate turnaround for a job that needs one view.

## Make the premise visible

Infer a direction from the brief when creative choices are delegated. Describe an original character through a small set of visible decisions:

| Decision | What to record |
| --- | --- |
| Role and personality | What the character does and one trait the pose or expression can show |
| Silhouette and scale | Body proportions and something in the scene that establishes relevant size |
| Face or focal feature | A few distinguishing shapes, counts or markings that survive the intended display size |
| Signature | One readable accessory, material, color or repeated feature |
| Wardrobe and props | Specific garment/material choices; distinguish fixed pieces from permitted episode changes |
| Rendering style | The accepted visual treatment, separate from the character's identity |

For example, a fictional clay snail courier might have a square canvas mailbag, two antennae and one blue shell stripe. Those details can be checked in later scenes. This is a design example, not a character to insert into unrelated briefs. A broad adjective such as “memorable” does not establish an observable trait.

Create the minimum useful anchor with the available Magic Hour image route and current budget. Make relevant details visible and check them at the intended delivery size. Do not infer nationality, personality or identity from a real person's photograph. A synthetic character is not a customer testimonial or an endorsement.

## Keep the anchor and reference roles distinct

Save only individually accepted views. Add a side, back or expression view when a requested shot needs it, and compare it with the original before calling it authoritative. Newly invented hidden details are a proposed design, not proof that the source contained them.

- **Identity view:** establishes the face/focal features, silhouette, markings and any fixed clothing.
- **Detail crop:** makes a small required feature legible. It supplements the accepted whole character rather than replacing its proportions.
- **Pose or performance reference:** supplies action, not a new face or costume.
- **Style reference:** supplies treatment or materials, not the donor's identity.

State these roles in the prompt only where the live model accepts the corresponding inputs. A multi-panel sheet is not automatically a valid animation first frame. For animation, compose and accept the intended single scene first.

If cropping a sheet, inspect the actual panel bounds. Do not assume a three-column layout or use fixed crop coordinates copied from another character. Keep the entire original and save crops as derivatives. Exclude labels, neighboring characters and unrelated panels that could enter the generated scene.

## Retain a short design record

Keep this with the accepted image files and project IDs, not only in chat:

```text
Character: original clay snail courier
Fixed: two antennae; one blue shell stripe; square canvas mailbag
Variable: expression, pose, location and lighting
Accepted views: front three-quarter; right profile
Unverified: underside and back of bag
References: whole-character anchor; shell-stripe detail crop
```

Use the real project's decisions and actual saved file locations. Retain visible counts and accepted reference roles; do not turn the note into a long compulsory prompt. On the next scene, describe the requested change and the few protected traits it puts at risk. A new name, longer prompt or repeated seed does not replace the anchor.

Compare each result with the original at both full size and delivery size. Reject only the failed view or scene, preserve accepted work, and update the record only for deliberate approved design changes. For a larger cast or series, continue with [series continuity](series.md). Model-specific reference controls and finished animation quality still need actual output review.
