# Instruction sources

Use one of these paths for the caller's selected question. These are bounded
source investigations, not permission to mine history or maintain instructions
automatically. Memory's access, staging and admission rules still apply.

## Trace a corrected claim

When tracing a fact the user corrected, start with the sources used for that
statement: loaded instructions, cited pages or known source files. Search for
the specific claim within those sources and their named source owners. Check
known generated or copied versions only where the same claim may have spread;
report the searched scope and stop rather than expanding into full session
history or unrelated stores.

Cite the conflicting passage and propose the correction at its owner. For a
generated output, identify the input that owns the claim; do not patch the
projection alone. If the statement was an inference, name its basis. If its
origin cannot be established, say unknown; an unsuccessful search does not
prove that the claim was invented.

A factual correction does not authorize persistent edits to instruction files,
project pages or a runtime's memory store, including Codex memory. Propose those
edits unless the caller already explicitly authorized that destination and
change; any authorized admission still follows its review and file-authority
rules. Report the source, the proposed or authorized correction, and unresolved
copies. Correcting the answer itself need not wait for a durable edit.

## Audit the loaded instruction set

Only when the caller requests an instruction audit, list the known global and
project instructions and any named includes or memory index within the selected
scope. Mark each item as observed loaded in this session, configured to load,
linked/read-on-demand, or unverified, citing the evidence for that status.
Configured loading is not proof of actual loading; one session is not proof of
what every session receives. Codex does not automatically import an `@file`
just because another host does. Read an explicitly requested or otherwise
authorized include as a file, and record that read separately from host loading.

Read the authorized set together for conflicting rules, duplicated instructions,
stale references, and workflow detail that could move to an on-demand owner.
Compare the exact passages and apply the host's and files' authority order;
duplicate wording alone is not grounds to remove a protective constraint.
Use known sources and named links only. Do not scan home directories, secrets
or unrelated configuration to infer an exhaustive loading stack. Missing or
unavailable inputs remain gaps.

Return findings with source owners, loading-status limits and proposed edits
inline. If reporting size, state whether it is bytes, characters or tokens and
how it was measured. The audit is report-only unless edits are explicitly
authorized; moving content or changing an instruction follows the same authority
and admission rules as any other edit. No new inventory or report file is owed.
