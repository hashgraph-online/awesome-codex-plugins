# Project profiles

Choose a profile during registration only when it improves defaults. Profiles never restrict which durable note types may be created later.

| Profile | Useful defaults |
|---|---|
| `software` | architecture, security, testing, deployment, operations |
| `research` | questions, methods, evidence, findings, limitations |
| `client-engagement` | objectives, stakeholders, deliverables, risks, approvals |
| `grant-work-package` | tasks, deliverables, milestones, dependencies, evidence |
| `product-development` | discovery, requirements, design, delivery, metrics |
| `personal-learning` | goals, concepts, exercises, references, next steps |

Record the selected value as `profile` in `Project.md` frontmatter. Use its useful defaults as initial `coverage_areas`, removing irrelevant entries and preserving user-defined areas. Do not generate empty folder trees from a profile. If no profile fits, omit it and ask for the important workstreams directly.
