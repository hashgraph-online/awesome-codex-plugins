# Schematic Brief

Complete this brief before drawing or generating imagery. Ask only for missing information that changes the physics, the required labels, or the intended use.

## Required Fields

- **Figure job:** one sentence stating the question or relationship the visual must explain.
- **Figure class:** facility, mechanism, workflow, system architecture, graphical abstract, or comparison.
- **Audience and venue:** manuscript, proposal, conference talk, poster, teaching, or internal report; include target width or slide size when known.
- **Evidence boundary:** measured, simulated, derived, proposed, conceptual, or illustrative. State which elements are not to scale.
- **System definition:** fluid/material, geometry, operating regime, coordinate frame, boundaries, and components.
- **Required objects:** components, interfaces, sensors, sample, data products, model stages, or outputs.
- **Connections:** flow directions, heat paths, electrical/signal paths, causal relationships, and data flow. State which arrows mean physical transport versus information flow.
- **Exact text:** labels, units, symbols, acronyms, and legend entries exactly as they must appear.
- **Visual hierarchy:** the one primary takeaway, secondary supporting elements, and items that belong in the caption instead.
- **Style constraints:** palette, font, line style, level of realism, background, journal style, existing figures to match, and accessibility needs.
- **Exclusions:** prohibited claims, objects, text, logos, colors, or visual effects.

## Brief Quality Check

The brief is ready when another researcher could identify what every object and arrow means without guessing. If an element has no scientific job, omit it. If a mechanism is uncertain, label it as a hypothesis or conceptual pathway rather than presenting it as an observation.
