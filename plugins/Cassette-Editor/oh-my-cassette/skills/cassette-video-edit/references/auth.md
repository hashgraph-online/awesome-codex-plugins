# Signing in to Cassette

Cassette passwords are always generated by the server and emailed to the account holder. The user
never chooses one, so **never invent, guess, or derive a password** — ask the user for the one in
their Cassette email, and never proceed with a placeholder.

## First sign-in

`auth_required` means this machine holds no credentials. Its `error.details.recovery` is an ordered
list of `{when, action, consequence}` — pick the entry whose `when` matches what the user actually
has and relay that one, not the whole list.

When the user has their emailed password, call `cassette_login` with `email` and `password`. It
verifies against Cassette before storing anything, so a wrong paste changes nothing. It stores the
password privately at file mode `0600`; do not repeat the password back in your reply.

Some users would rather keep a password out of the transcript entirely. `auth_required` and the
stale-auth errors carry `setup_command` / `reset_password_command` for exactly that — offer them as
private terminal commands when the user prefers it, and don't push.

## When the user no longer has that password

Before requesting a replacement, tell the user that a new password is emailed and that the current
one stops working **on every machine**, and get their explicit agreement. Then call `cassette_login`
with `request_new_password=true` and `confirm_replace=true`.

Never send this on a vague complaint like "I'm having password trouble" — ask first. It is
rate-limited to a few attempts an hour, so never retry it just to see whether it worked. If it
reports a delivery failure, the previous password should still work — have the user try that before
spending another attempt.

`auth_password_emailed` means the reset went out. The reset alone does not sign this machine in, so
ask the user to paste the new password from their email and call `cassette_login` with it.

## Reading auth errors

`credential_source` on the envelope tells you which situation you are in before you guess.

| code | what it actually means | what to do |
|---|---|---|
| `auth_required` | no credentials on this machine | relay the matching `recovery` entry |
| `auth_invalid_password` | the **stored** password is stale | not a typo — the user never typed it; replace it per above |
| `auth_failed` / `cassette_auth_failed` | a stored password stopped working; appears in `error.details` or inside `data.job.errors[]` on a failed job | relay the error's `recovery` string |
| `auth_not_authorized` | the address has no Cassette access | not about the password at all — relay that Cassette access has to be granted for the address first |
| `auth_env_precedence` | credentials come from environment variables | `cassette_login` refuses, because a stored file would stay shadowed; tell the user to update those variables instead |
