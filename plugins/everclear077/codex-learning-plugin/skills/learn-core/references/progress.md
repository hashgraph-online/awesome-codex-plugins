# 进度、证据与恢复

短问答用当前对话即可。持续学习或用户要求记录时，使用其指定目录，或当前可写工作区的 `learning/<topic-id>/`。先查看同名课程是否属于同一目标，避免覆盖。短名拒绝路径分隔符、`..`、Windows保留名和尾部点/空格。只查明确路径或当前工作区，不扫描整个个人目录。

起步只需 `progress.md`；确有需要再建 `notes.md`、`cards.json`、`artifacts/`。内容少时不要创建空文件。无写入能力就给可复制续学卡，不能声称保存成功。进度不可写入插件缓存、共享技能源或全局配置。

## progress.md 模板

```markdown
# 学习：主题
- 一句话目标：
- 验收标准（2–4条）：
- 基础：自述 / 已测证据分别写
- 主动学习预算：计划；用户确认已用；剩余未知就写未知
- 最小作品：首版里程碑、最终截止及当前真实状态
- 当前模式：五选一
- 待答题：原题、已给提示级别；尚未提交就标待答
- 家教契约：默认或用户明确修改过的规则
- 刻意暂缓：内容及理由

| 核心块与依赖 | 验收行动 | 状态 | 实际证据/日期 | 提示情况 | 当前缺口 |
|---|---|---|---|---|---|

## 最近尝试
- 日期/会话：
- 题目ID及条件：
- 用户首次回答摘要：
- 判定与理由：
- 用户信心（未提供就空缺）：
- 提示与后续重试：
- 错误类型及下一步：

## 作品验收
路径或可见表现、真实运行/演示结果、用户独立解释与变化任务、未验证部分。

## 复习
调度来源：Anki-FSRS / 手工建议 / 未安排
真实到期项及来源时间（能读取时）；下节优先检查；历史失败与后续修正分别保留。

## 来源
标题、作者/机构、日期/版本、URL或本地路径、已读范围与未核实点。

## 下一次
先考的一个旧概念，随后需要修复的卡点，不预先透露测试答案。
```

在有实质作答、模式切换、暂停或目标变化后更新相关部分，不每条消息重写整个档案。保存实际证据而非完整聊天隐私；不删除失败以制造好成绩。笔记保存验证过的机制、例子、反例和纠正；当前待答题答案不要自动写进正在展示的笔记。

## 续学

实际读到进度才可说已恢复。先用两句说明目标与卡点，然后按间隔模式考一个旧知识点。若有原题待答，保留并说明回忆测验后返回它；用户要求直接续答时直接续答。多个目标无法判断时只问主题/路径。

来源过时需核查，历史成绩保留。若工具未读取Anki，不能虚构其队列；可让用户提供导出信息，或进行标为手工抽取的旧知识测验。日历建议不等于后台提醒；只有用户请求且可用调度工具成功时才能声称已设置提醒。
