# 间隔回忆、Anki与FSRS

## 制卡与测验

卡片只收值得长期保留且已核对的关键提取点、常见误区、条件辨别和小型应用，不把整段笔记拆成数百张。起步每块1–3张，根据实际错误增加。正面可单独理解，背面短而准确，附条件和来源；一道卡只检验一个主要目标。复杂项目能力仍要实作，卡片无法替代。

先问、等首次作答，再显示背面。忘记、答错、看过答案或用提示才完成，不能记作独立回忆；更正和重试另记。信心由用户提供或留空，AI不可编造。

## 调度路线

1. 已使用Anki：沿用用户牌组和设置；导出本插件卡片供导入，实际复习在Anki完成。能取得真实复习记录才据此续学。
2. 希望长期使用：说明Anki牌组选项里的FSRS，并提供下述导入文件。是否启用/修改现有设置遵循用户请求，不擅自更改全局参数。
3. 暂时不用Anki：下节课先考旧知识，可建议次日和数日后再次闭卷测试，再根据表现调整。必须写「手工建议」，不冒充FSRS算出的日期，也不保证某个固定间隔最佳。

FSRS是根据复习历史估计记忆状态并排程的算法，Anki是实际承载卡片与排程的软件。期望保留率0.90是官方默认起点之一，不是个人实际保证；提高保留率会增加复习负担。参数优化应使用真实历史。不要自造算法权重，不自动强制重排所有旧卡。

按Anki含义选择评分：Again=未能回忆；Hard=回忆成功但困难；Good=正常成功；Easy=轻松成功。忘了不能选Hard。AI可根据内容指出答错，但回忆难度由学习者报告；提示完成不应伪记成功。官方参考：[FSRS选项](https://docs.ankiweb.net/deck-options.html#fsrs)。

## 随附的本地导出工具

脚本[export_anki.py](../scripts/export_anki.py)仅依赖Python标准库，将核对后的JSON卡片导出为UTF-8 TSV，不连接Anki、不设置提醒、不计算FSRS、不上传数据。可由代理直接写同格式文件，无需为了普通学习强装Python。

`cards.json`格式：

```json
{
  "cards": [
    {
      "id": "attention-mask-01",
      "front": "自回归训练中，为什么当前位置不能读取未来token？",
      "back": "否则模型可以利用目标之后的信息，破坏训练与逐步生成的条件一致性。",
      "source": "已核验来源的URL或简短出处",
      "tags": ["attention", "core"]
    }
  ]
}
```

在可写学习目录运行，替换脚本为实际安装路径：

```text
python <skill-path>/scripts/export_anki.py cards.json cards.tsv
```

已有输出默认拒绝覆盖；明确要更新文件时加 `--overwrite`。脚本验证所有卡片后才写文件，拒绝重复ID、重复正面、空问答及非法标签，保留中文，HTML转义处理多行与符号。

导入Anki时选择有Front/Back字段的基础笔记类型，映射Front→正面、Back→背面、Tags→标签，允许HTML（文件已声明）。背面包含出处；ID写在标签中供追踪，不作为Anki内部GUID。重复检查使用正面：同一正面修改背面可选更新旧笔记；改变正面会被视为新笔记，需要人工清理旧卡。该导出不迁移复习历史，也不能把JSON中的ID当作稳定更新键。

第一次导入先用少量卡核对预览、字段映射与显示。依据：[Anki文本导入与重复处理](https://docs.ankiweb.net/importing/text-files.html)。

## 使用边界

本插件实现制卡、导出和家教行为；真实到期日由Anki计算。仅生成TSV不等于已导入，不等于已启用FSRS，也不等于已经复习。未来若接真实FSRS运行库，应采用[官方py-fsrs](https://github.com/open-spaced-repetition/py-fsrs)与实际复习日志，不把手工规则命名为FSRS。这里未内置该依赖。
