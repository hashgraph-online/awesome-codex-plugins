# Authoring review and repair

Use this reference for proposal review and correction in both Skill conversion and brief generation. [The semantic contract](authoring-contract.md) defines preserved behavior; [qualification](authoring-qualification.md) owns tool/runtime evidence. Ordinary usage follows [execution](execution.md). Keep the exact source revision, proposal hash and attempt identity throughout correction.

Collect every finding returned by the current review into one correction set. Resolve all findings that can be addressed under the existing authorization before submitting the next review; check interacting routes, resources, interfaces and dependencies together. Track each finding as fixed with evidence or explicitly unresolved. Do not submit a knowingly incomplete patch merely to rediscover the remaining findings. A failed check is not passed by silence or by a smaller checklist.

Before another independent review, deterministically compile and validate the exact revised proposal and its complete resource closure. Confirm schema bounds, identities, bindings, dependency applicability and all required contract checks. Fix shared compiler or runtime causes at their owning layer. If a mechanical error remains, report it and stop that submission while continuing independent authorized work. Do not reset the repair budget with a replacement Run or import.

## Review the preserved behavior

Use the existing pinned checklist IDs and schema. Check both directions across
all source callable commands, request modes and conditions: every required behavior
is represented, and each converted operation, output, dependency or check has
source/user support. Preserve exact arguments, conditional precedence, effects,
artifact formats, diagnostic meaning and repair budgets. Necessary Host mechanics
do not create product requirements or model relay work.

Confirm configured existing writable Provider subagents for ordinary independent
production and review, and actual initiating Main orchestration for its context
and decisions. Main worker and persistent task/thread are explicit user-edited
options. Required temporal behavior remains in one live worker or a qualified
loop; an unsupported relation needs a source semantic finding. Review the Host
routing evidence without choosing Providers, copying identities or adding Roles.

Check that each applicable source phase has one mechanical observation owner.
Joins reuse completed observations and final mechanical acceptance checks bounded
freshness; source-required checks and semantic content acceptance remain intact.
A changed artifact or distinct phase retains its applicable original checks.
Require only the semantic inputs, resolved settings, reusable assets and references
needed for the assigned responsibility. Parallel work must have real independence
and the original callable interfaces; repeated context does not establish caching.

## Bounded correction and stable keys

Authoring
uses one initial plan plus at most three automatic `workflow-semantic-repair/v1`
stable-key patches for genuine semantic omissions, contradictions, distortions or
misassignments. Each patch builds on the exact current plan and never regenerates the
whole plan. If findings remain after the third patch, the Host retains the plan and
findings and waits for explicit user guidance before another targeted patch.
Mechanical output/schema errors and reviewer protocol errors stop visibly and never
spend the semantic repair budget. Coverage failures carry the exact requirement ID,
semantic keys, editable fields, source spans and current mapping so a repair never has
to guess which stable keys to change.

## Exact-artifact review and preflight

Automatic semantic correction is evidence-driven and bounded to three stable-key
repairs. Final review uses the pinned review packet plus the hashed dynamic
`__authoring__/review-proposal.json` resource; the full canonical proposal is never
inlined into the prompt or duplicated through stale repair feedback. When host projection or compiler rules change after a
planner proposal has completed, recheck that exact persisted artifact by verifying its
source Run, attempt, artifact hash and source revision; rerun deterministic compilation
and independent review without spending another planner call.
Every automatic semantic repair must name current stable semantic keys and editable
field families. Edge-only findings map to both endpoints. Unmappable feedback stops at
the Host as `semantic_diagnostic_error` instead of asking the planner to guess.
After changing conversion, projection, validation or review code, validate in this
order before any real Provider call: focused contract tests, affected cross-module
tests, offline validation of stored Workflow definitions, then deterministic preflight
of the exact persisted proposal. A Provider Run is acceptance evidence, never a way to
discover holes that these host checks could have found first.
Static relocation proves pinned resource access only, not functional portability.

Use [execution qualification](authoring-qualification.md) for source tool inheritance,
Host/model resource separation and handoff regressions. These checks apply to both
Skill2Workflow and Build Workflow; keep their mechanical evidence out of generated
task prompts and do not add source-absent model verification stages.

Audit added output fields as well as added activities. A required research,
safety or delivery report needs source support or a concrete downstream semantic
dependency that the actual artifact and existing result cannot satisfy. Empty
values do not make a required report optional. Report unsupported extra work under
the applicable semantic method/coverage check with its smallest removal; retain
source-required checks and meaningful newly established findings.

Apply this check to prompt and reference text as well. An added general
verification instruction can create a research task without adding a node or
output field. Repair a concrete inaccurate claim within the requested scope;
do not turn that repair into a global capability audit or citation requirement.
Preserve requested sources and ordinary required verification. A static review
does not prove optional searches disappeared; check the actual execution path.

## Acceptance and cleanup

A successful structure validator alone does not establish semantic quality. Require the complete pinned independent review with no unresolved findings, including every source-defined route and its output, verification and evidence handoff. The Host applies the Run-pinned completion policy described in [authoring](authoring.md). Automatic completion must finish [authoring cleanup](authoring-cleanup.md) and verify the enabled Ready revision is `launch_ready`. Manual or historical pending acceptance preserves the exact reviewed candidate and its recovery evidence. Never claim a Draft is the completed automatic result.
