# Authoring semantic contract

Use this contract for Skill conversion and brief-based generation. [Authoring](authoring.md) owns source selection and generation; [review and repair](authoring-review.md) owns proposal acceptance and correction. Ordinary task usage follows [execution](execution.md). [Qualification](authoring-qualification.md) establishes tool inheritance and engineering claims outside the generated business graph.

## Host execution defaults

Host validation authority comes from the source or the requested task. Each check
must identify the product, format or execution boundary it verifies. A broad read
grant does not authorize an unchanged-directory completion condition. Do not add
whole-workspace freshness, stable runtime bookkeeping, repeated source/resource
audits or stricter quality requirements to make Host acceptance appear safer.
Preserve original checks and repair limits, reuse their result, and observe the
actual selected products at their declared consumer. An imposed Host condition is
a generation blocker and a Host defect, not an instruction for a worker to obey
or a reason to add another planner/verification round.

Choose responsibility first, then actual difficulty. **Default exclusion applies
to Main worker, never Main O.** The initiating Main owns user intent, route
decisions, live clarification, conversation coordination and final semantic
acceptance. Bind research directly to consumers; Main does not relay it or fill
mechanical formats. Independent scanning, production and audit use workers when
explicit inputs suffice.

| Semantic profile | Default model suitability |
| --- | --- |
| `worker_read`, `worker_write` | Routine bounded inspection, documentation, production and audit: Luna / max. Reading alone is not planning. |
| `worker_complex_read`, `worker_complex_write` | Concrete cross-module analysis or complex implementation: Sol / high. |
| `review` | Source-required independent critique: Sol / high. Local self-checks remain with their producer. |
| `worker_reasoning` | Difficult planning, novel causal diagnosis or unresolved design tradeoffs: Astra / medium; state the concrete difficulty in the instructions. |
| `decision`, `orchestration_read`, `orchestration_write` | Actual initiating Main, using its current model. |

These are editable configured routes, not model names inferred from task labels.
The actual planner and reviewer packets carry the selected Providers' model,
effort and suitability descriptions beside the profile map. The Host binds the
chosen semantic profile to those pinned routes. A Workbench Role is a separate
reusable template; it is not a generated node responsibility or a model tier.

Ordinary independent production and review use configured existing enabled writable
Provider subagents in both fixed and automatic generation. Missing or ineligible
configuration fails visibly. Orchestration that needs the initiating conversation
and its decisions use actual Main orchestration. Explicit inputs can keep ordinary
integration in a worker. Main worker and persistent task/thread remain available
through explicit user edits after generation; they are not planner defaults.
Historical pinned Runs retain their own executor policy.

Current-Main context is scoped separately from source-section coverage. A cited
chapter does not automatically bind all of its Markdown guides to a conversation
decision. New generation retains guides explicitly needed by Main's instructions
or assigned typed requirements, selected interface contracts and executable resources. Workers retain their
source references; typed required resource coverage is still checked. Historical
pinned material remains unchanged.

Source-required questions that need the live conversation belong to current Main
orchestration. It can receive the user's clarification within the same Run and
bind its new semantic decisions to later workers. Provider workers do not hold
that conversation. Future-Run feedback is a separate source-defined behavior;
do not require a new Run merely to answer an ambiguity discovered while scanning.
Conditional dialogue needs a conditional graph route: bypass Main when no answer
is needed. Main emits newly resolved decisions only. Bind the original scan
evidence directly to both clarified and unambiguous consumers; do not make Main
rewrite or relay that evidence. A declared enum literal such as a no-change
decision is semantic content, not unchanged upstream transport.

Source-required quotations and exact command examples are part of authored
content and semantic evidence. They do not authorize copying unchanged protocol
records between nodes or making an Agent fill Host-owned coordinates.

Ordinary generated tool nodes do not add per-node approvals. Source-required
confirmation belongs to an explicit human gate and its protected graph paths;
preserve that gate and subject. Provider and Run approval policies still apply.
Do not add confirmation solely because an activity invokes a registered tool.

The Host deterministically assigns every generated Agent `bounded_write` and
`path_scope: {binding:'run.allowed_paths'}`, including inspection, review,
decision and finalization nodes. Semantic profiles classify work and route its
executor; they never select access. The Run still bounds effective permissions.
Runtime Providers must support writes. Explicit user read-only settings and
registered Host Tool contracts keep their declared authority.

Main worker preparation is Host-owned. Before starting the ephemeral session,
the Host materializes and hashes all declared resources, prepares exact bound
inputs and records the context contract. Small references and values use bounded
inline delivery; scripts and large values have exact local addresses. Do not add
Agent stages or startup instructions to recreate those materials.
Workflow call budgets also belong to the plugin's fixed executable invocation
adapter. Selecting a Main worker does not add a planner-authored wait field or
waiting instructions to the node; startup and continuation use the Host adapter.
The shared Host preserves inherited native tool mode and forwards existing scoped
brokers through its native MCP transport when code mode is active. Generation does
not create an adapter Agent or force direct routing. Mechanical completion-only
bindings use `completion_contract.host_check.input_bindings`; semantic node inputs
retain actual artifacts and findings. The Host preflights and pins original checker
inputs, including source-location freshness. The initial route's stateless startup
adapter accepts only newly authored semantic output and fixes launch identities.

Ordinary nodes have no `role` responsibility input. Their instructions,
inputs/outputs and executor binding define the work. Workbench Roles are separate
reusable instruction templates. Final acceptance follows `finalization.node_id`.

Fan-out workers share the writable default. Without Host-owned per-item paths,
the Host exposes `max_concurrency:1` in the compiled contract. Concurrent writers
require exact disjoint item scopes; profile names cannot bypass that rule.

## Portable dependencies and source pins

Before splitting activities, the shared Host builds `workflow-callable-inventory/v1`:
exact direct-call locations, original arguments and stdin/file transport, tool names,
source triggers, reachable local programs/imports and package observations. Each
actionable call receives its own `callable_` requirement ID. Assign every ID to a
responsible activity; section coverage cannot replace individual command variants.
Host projection supplies its pinned program handle and necessary local runtime
closure. Deployment remaps those handles, including executable arguments, while
private alias declarations, source entrypoints and benchmark answers stay outside
worker context. Original interfaces remain intact in private authoring evidence.

Literal tool arguments and distinct command variants remain separate Host facts.
Shell pipelines and exit-status guards retain their member relationships; bind
the complete original composite to one responsible activity, or an exact
registered composite-tool contract. Do not distribute process stdin or shell
exit-status dependencies between workers without a qualified transport. The
Host relocates each member's executable and arguments, and delivers transport
topology rather than executable source-relative composite text. Full proposal
rechecks rederive interfaces from the pinned source; deleting their echoed IDs
cannot remove the conversion floor. These projections reuse one inventory
observation in the compiler transaction.

Recognition is finite static evidence, not proof of arbitrary program behavior.
Dynamic calls, composite commands and unindexed program bodies retain explicit
unresolved facts for source review and focused interface qualification. Resolve
them from original code and conditions; do not execute the source task during
conversion or make every internal optional dependency a startup gate. New Runs
pin the inventory and generation-executor policy; historical Runs retain their
original compilation policy. The completion report records available executor
edits without adding those options to worker instructions.

Both Skill conversion and brief building identify environment dependencies in the
shared semantic plan. Required execution dependencies become portable
`requirements.executables`: program names or
`{name,version?,python_modules?}`. Keep workspace paths and installed executable
locations out of reusable definitions. Host step 0 validates registered local
locations, searches other installations, and reports missing dependencies before
execution. The Execution page's local dependency fields verify and persist those
locations outside Workflow exports. Invalidated locations use the same discovery
path before subsequent effects; installation always requires user consent.
Keep conditional dependencies at their source-defined phase and distinguish tools
the Workflow executes from dependencies used only by its output artifact. Preserve
project initialization that changes task files. Do not add a model node solely for
tool discovery or registration, or make optional artifact dependencies mandatory.
`workflow_source_status` reports changed SKILL.md hashes without changing any pins.
SkillRef requires exact path/name/hash and explicit nested pins. Inline creates a
new reviewable Draft; a new source version never silently updates an old Run.

## Semantic ownership and bounded interfaces

Before designing activities, account for the complete pinned source inventory:
entrypoint rules, supporting instructions, commands, executable resources,
examples, tests, manifests and adapters. Distinguish required behavior from
illustrations and archive material using source evidence. Map every required
section and callable capability to its responsible route, activity or runtime guard,
including helper commands and conditional configuration/maintenance modes. Check
both directions: every source requirement is preserved, and every converted
operation, required output or check has source/user support. Necessary Host
execution mechanics do not create product work.

For each source-defined route, identify its trigger, inputs, applicable dependency
phase, approvals, produced artifact, verification and final evidence handoff.
Keep mutually exclusive routes conditional and preserve their convergence.
Inspect cross-route effects such as configuration, browser capture, export and
cleanup; shared resources and output contracts must agree across those routes.
Split responsibilities where a stable typed result or verified artifact gives a
successor enough context, while retaining the source's quality requirements.
Preserve exact callable signatures, stdin/file formats, arguments, conditional
defaults and precedence, diagnostics, output formats, effects and repair budgets.
When a route accepts completed assets, bind those original assets and resolved
settings to the original processing/export tool; reuse them without regeneration.

Look for independent work before adding more stages. Multiple independent
artifacts can each keep their complete research, production and original checks
in one worker, then join at final acceptance. Share only actual common facts or
style decisions. A single small artifact does not justify splitting every
section into a separate session. Account for cold setup, duplicated context and
join cost when assessing a proposed split; context isolation alone does not prove
wall-time or token savings. Repeated context and stable resources do not guarantee
caching; qualify actual reuse and measure it outside the business graph.

Generated runtime-cardinality work uses Provider workers with auto/fixed fan-out semantics. Historical main_read/main_write planner profiles normalize to ordinary worker profiles without another model repair. Orchestration profiles cannot configure worker quantity. Bind original structured lists through the Host instead of making a model copy them; have Host preparation produce independent home/output/receipt paths, and project only each assigned item into its worker. Bound active sessions, join all required results in original order, retain accepted siblings and retry only failed items. Keep a single-page route compact. Video may overlap TTS and duration-independent visuals inside the existing repair-owning renderer context; expose separate graph stages only when the actual interface and repair ownership support them.

For each proposed concurrent unit, identify the values and effects it needs,
its exclusive output scope, and the downstream dependency that requires joining.
For timed media, real audio durations precede final timeline assembly; source
tools may already overlap synthesis or encoder work internally. Do not invent
segment or frame-range interfaces that the pinned tool does not expose. Read
[parallel execution](parallel.md) for the two supported mechanisms and their
executor limits. Keep required serial edges when independence or capability
cannot be established. Preserve explicit user-edited executor choices; generation
defaults do not rewrite an edited Main worker or persistent task.

Keep normal execution resources minimal and sufficient for the assigned work:
complete relevant format/behavior rules, resolved choices, current artifacts,
pinned callable program addresses and compact established evidence. Reuse inputs
and assets through declared bindings; keep receipts and complete checker records
Host-side. Archive coverage does not mean attaching the complete source
repository to each Agent. Source Skills, examples and benchmark answers belong to
conversion evidence rather than deployed worker context. Preserve their required
behavior in Workflow-owned instructions and neutral syntax references. A final
consumer usually needs the producer's conclusion and observed evidence rather
than another copy of the entire manuscript.

When downstream acceptance needs an established factual basis, use the existing
concise result for the decisive finding and its actual source reference. Preserve
uncertainties and the artifact evidence; a generic product summary alone may
force repeated research. This does not justify a mandatory research field or an
extra reporting stage, and a consumer still investigates a concrete missing fact
or inconsistency. Never claim research the producer did not perform.

Deterministic subprocess invocation, original-record joins, receipt generation and
artifact hash checks belong to registered Host tools. Existing definitions may
attach a pinned `completion_contract.host_check` to writable Main orchestration;
the Host invokes it automatically with exact `{inputs,output}` after semantic
acceptance. Semantic planning selects registered tools through its supported
contract; models must not invent compiler fields or reproduce checkers as prompts.
Completion-program entrypoints and explicit resource arguments form a Host-verified
closure independent of model reading references. Preserve actual source tools and
their stdin/file interfaces, flags and diagnostic/revision behavior; qualify wrappers
with neutral real-tool evidence before model experiments.
Delivery prose and final content acceptance can share the initiating Main stage
when no independent source review boundary requires a separate Agent.
Preserve the source's semantic work budget. Do not invent separate model stages
for safety narration, delivery preparation, repeated artifact hashing, routine
tool discovery or default visual inspection absent from the requested/source
quality contract. Let registered Host operations perform mechanical checks.
Give each applicable source phase one mechanical observation owner. Producer
completion settles its original checks, diagnostics and repair state; a downstream
join reuses that observation. Final mechanical acceptance checks bounded freshness
of the observed artifacts while source-required content acceptance remains intact.
A revised artifact or distinct source phase retains its applicable original checks;
do not remove source checks to avoid duplication or add broader audits.
Keep content authoring, its ordinary renderer calls and source-defined local
diagnostic repairs in one working context when the checks are tightly interleaved.
Host ownership of execution authority and receipts does not move this loop into
the initiating Main. When the source producer calls a CLI and repairs its actual
diagnostics, give that producer the Host-prepared callable address and resolved
choices. Let it finish the same local production loop, then hand off the artifact
and newly established findings. A mechanical completion check observes the exact
finished execution and current artifact; it does not repeat a successful render
or make every ordinary writing warning cross the Main/subagent boundary.
A lint warning alone is not an independent responsibility boundary. Do not make
each correction create a fresh worker and retransmit the whole manuscript.
Retain the original executable checks, repair budgets, observed artifacts and
final acceptance; context isolation belongs between meaningful responsibilities.
Keep a routing decision that needs live reminders or plan state in current Main;
ordinary startup returns its real first handoff and Host binds revision and identities.
Do not encode invocation settings or copied hashes in its prompt.

The planner output is the closed, compact `workflow-semantic-blueprint/v6` contract.
It fills only semantic activities, approvals, named sequence/parallel/choice groups,
data relationships, exact Host SourceContract selections, logical approval subjects,
bounded source-defined retry conditions, source dispositions, runtime dependency
decisions and requirement assignments. Bundled authoring v21 and later requests require
an explicit dependency array, including `[]`; older pinned v6 plans can omit it.
The planner and reviewer assess useful responsibility boundaries: a durable
artifact path and identity or compact typed evidence can hand analysis to
implementation or verification in a fresh context. Related work stays together
when it has no stable handoff. Node count and source headings are not split rules;
review checks the explicit producer output and successor input.

Carry concise newly established findings and relevant supporting source locations
across a research or analysis boundary alongside the produced artifact. The next
responsibility reuses that evidence, checks the actual artifact and investigates
concrete inconsistencies or gaps. Do not add research solely to populate a handoff
or make isolation discard the information needed to avoid repeating prior work.

An artifact-writing activity does not automatically require a separate research,
safety or delivery report. Add a semantic output only when the source requires it
or a genuine downstream responsibility needs a newly established finding that the
actual artifact and existing result do not convey. Allowing an empty string still
makes a required output additional work. Preserve source research and verification;
do not create a report field merely to justify context isolation.

Agent outputs contain only values the Agent creates through semantic work.
When downstream work needs unchanged fields from an earlier record, bind that
record separately and keep the Agent result ordered against it, or select an
exact registered Host tool for deterministic copying, transformation or join.
This ownership rule is field-name independent: titles, labels, names, source
text and metadata cannot be routed through an Agent merely because they are not
IDs or paths. The compiler rejects positive copy-through instructions and
Host-owned identity or location fields in Agent output contracts.
Activity instructions have a separate 10,000-character schema bound; short
descriptions retain their 2,000-character bound. After Host interface and retry
appendices, the generated node prompt must fit the 12,000-character proposal
limit. Oversize plans and repairs fail validation rather than losing their ends.
Each dependency names its portable executable, applicability, responsible activities
and exact pinned source evidence. Host validation derives spans and startup
requirements; the planner does not supply local executable addresses. An explicit
`host_preparation_observation_ids` list can assign source instructions for missing
tool discovery or installation consent to this Host lifecycle. The compiler checks
the exact clause and preserves its evidence; task-specific approvals remain
semantic gates, including when the source mixes both kinds on one line. It does not
choose a root. The Host owns all
nodes, edges, IDs, schemas, pointers, bindings, executor/provider fields, permissions,
retry fields, evidence spans and packaging. Static SourceContracts preserve exact
script argv and artifact constraints without executing source code. Nodes keep exact
disjoint evidence spans, and approval gates bind the current logical activity output.
Requirement assignments may name only
exact observed requirement IDs supplied by the Host. WorkflowForge
normalizes the semantic reference graph as a DAG: repeated choice bodies converge,
nested mutually exclusive exits remain exclusive, approval mappings retain only the
unique source-grounded gate and post-gate operations. Worker and review profiles
compile to the configured existing Provider subagents. Required temporal work
stays in one live worker activity or a qualified semantic repair loop; a relation
that this default cannot represent receives a source semantic finding. Main worker
and persistent task/thread can be selected explicitly on an edited node. The
selected Provider determines the actual model and remains editable there;
Workbench Role instructions are not injected.
Brief-built task Workflows
default to Cooperative with implicit Skill access denied. An imported source policy
is private conversion input, not a runtime entitlement; every accepted conversion is
deployed with implicit Skill access denied. Named
data types describe nested object/list interfaces while the Host generates JSON Schema
and rejects duplicate, cyclic or contradictory definitions. An activity that explicitly
cites a pinned executable resource must type each structured output through a named
type, and the Host binds that cited resource to the activity. Persisted v2/v3
blueprints are upgraded mechanically without consuming a planner repair.

Converted and built Workflows must not make any Agent hand-copy unchanged
input or resource values. This applies to arbitrary records, labels, names,
source text, metadata, IDs, paths and hashes. Bind originals beside new semantic
results or use registered Host tools to copy, transform or join them. The compiler
rejects copy-through instructions and Host-owned output fields.
For fan-out writers with per-item path scopes, the complete task packet must
bind directly from a Workflow input or an exact registered Host tool. The
compiler rejects an Agent-produced packet before the Workflow can become Ready,
including when a Host tool wraps or joins an upstream Agent output.

## Host preparation and source evidence

Separate semantic node inputs from checker-only original records. When an existing
current-Main completion checker needs a full mechanical record, the Host compiles
it into `completion_contract.host_check.input_bindings`; the node receives the
actual source, artifacts, quality diagnostics and necessary semantic findings.
Apply the same distinction to a worker's inputs. Keep the original task and every
resolved option or behavior that changes its work, including precedence and
conditional defaults. A writer can need a verified program address and resolved
render settings without needing the complete preparation manifest, receipts,
hashes, dependency recipes or export destinations. Bind supported semantic
projections directly; preserve the complete original record for the registered
Host operations and completion checks that need it. A path alone is insufficient
when the original record also carries resolved settings or conditional behavior.
Do not invent unsupported blueprint selectors or ask an Agent to copy fields:
an unavailable required projection is a Host interface defect to fix explicitly.
Before publication, verify each conditional setting and precedence/conflict case,
missing-binding failures, other routes and unchanged checker inputs. Measure the
whole invoking Main and worker, including corrections; isolation by itself does
not prove lower cost, and one successful sample does not establish repeatability.
Preserve exact checker inputs and their identity, scope, resource closure and
replay freshness. Mechanical binding failures must surface before semantic work.
Preserve native callable-tool routing and qualify aggregation and actual parallel
execution separately; do not force direct routing to conceal a native interface
failure. Eligible initial route decisions use the stateless Host-pinned semantic
startup adapter, with no model-written hash or extra preparation lifecycle.

Both authoring routes should use Host preparation for mechanical source extraction
and consistency checks. Hand consumers their assigned verified facts, complete
relevant rules and explicit decisions, retaining full packet references for deeper
reads. Do not require model-written hash literals or repeated raw-packet extraction.

For code analysis whose consumers need exact source locations, both authoring
routes may mark a compact output with
`host_validation: workspace_source_locations`. The Host compiles its shared
record schema and checks paths relative to the Run workspace or absolute paths
inside it, exact file hashes, existing inclusive line ranges and optional literal
symbol anchors. Empty `symbol` is valid when a line range and hash suffice;
descriptive labels belong in `usage`. Verified absolute paths are handed off as
relative paths. The hash identifies the file when analysis produced the
location. The Host rejects stale locations before a new consumer dispatch;
once dispatched, a writer may legitimately change that file without turning
the old analysis record into a current-file invariant. Keep the historical
record readable. A later activity that needs current locations after edits
uses updated locations produced by the writer. This does not add a model stage
or carry whole source files between nodes. Unmarked outputs remain compatible.

The host owns deterministic source anchors, typed requirement fields, graph-envelope
formatting and validation. A planner maps those stable IDs and supplies only semantic
decisions; echoed host fields are discarded and replaced by the canonical projection.
The shared planning/review packet includes the imported Draft's host-owned baseline
requirements and static import observations. Every selected supporting resource must
be reconciled against those facts before submission; neither planner nor reviewer
should rediscover or ask the proposal to echo them.

Scanner observations are evidence, not semantic requirements by themselves.
Use their anchored context to distinguish active dependencies, reference examples
and extraction mistakes. A missing required file or needed credential remains a
blocker. The Host records any mechanical reconciliation, checks all deployed
resource bytes for private-source leaks and excludes the original entrypoint and
private authoring metadata from the final package. Do not solve an import warning
by deleting source-defined behavior or weakening verification.

Launch readiness must use the real Host capability context. Workflow-local
tool names resolve through their exact declared contracts and registered broker
identities, including pinned child Workflows. A structurally valid graph alone
does not prove those implementations are available. The Host owns this check;
do not remove required tools or ask a model to invent availability evidence.

## Explicit Main worker qualification

Main worker is an optional user-edited executor. Its writable runtime fan-out
requires `fanout.workspace_field`: every item has a Host-owned independent
directory used as its actual session and command sandbox cwd. Item writes remain
inside that directory; original project and sibling directories stay outside
writable roots. The Host qualifies the owned command sandbox before execution,
rejects unenforceable roots, drains and closes each item before accepting its
effects, and keeps durable per-item retries and prior usage. Partition slots use
fresh ephemeral item sessions under the same concurrency cap. A downstream Host
owner may copy validated completed bytes to original user destinations. Per-item
path labels and post-run filtering alone do not establish command isolation.
