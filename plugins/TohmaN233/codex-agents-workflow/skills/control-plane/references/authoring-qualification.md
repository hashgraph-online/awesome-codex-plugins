# Execution qualification during authoring

Use this reference to qualify a changed authoring/runtime interface or a requested
parity, quality or performance claim. [Execution](execution.md) owns ordinary task
usage, [the semantic contract](authoring-contract.md) owns conversion meaning, and
[review and repair](authoring-review.md) owns proposal acceptance. Skill2Workflow and
Build Workflow share the same compiler, review and Host checks. Select neutral
checks for the actual changed boundary before a business trial; qualification is
external engineering evidence, not additional generated Agent work. A graph or
resource relocation pass alone does not establish functional or cost equivalence.

## Eight checks before a changed candidate enters an experiment

These checks apply to Skill2Workflow and Build Workflow. Keep their evidence in
the external engineering record, pinned to the tested source and package. They
do not add nodes, reports or startup gates to ordinary business Workflows.

1. Account for every original callable and applicable dependency; preserve its
   arguments, output, diagnostics and conditional trigger.
2. Check semantic ownership and writable executor selection. New ordinary workers
   use existing Providers; retain explicit user choices of SDK Main workers or
   persistent tasks, and keep orchestration in the initiating Main.
3. Check dependencies, independent effects and supported parallel interfaces.
   Share only common input; do not infer cache or speed savings from graph shape.
4. Give each source phase one complete mechanical observation owner. Reuse its
   established evidence rather than repeating full resource or product audits.
   Reject Host-added completion conditions without a source/user requirement:
   whole-workspace immutability, unchanged runtime state, repeated directory
   snapshots and stricter replacement quality gates are not justified by a read
   grant or by the presence of a checker. SDK automatic checks retain their exact
   verdict and closed execution; downstream observation checks selected products.
   Report an imposed Host scope as a Host projection defect, block acceptance and
   repair that boundary instead of asking the planner to add compensating nodes.
5. Check source coverage in both directions, including instructions, required
   output fields and the experimental caller. Remove source-absent research,
   delivery records and verification work before measuring the business task.
6. Qualify Host-owned bindings, formats, receipts and terminal completion facts.
   The real Drive and SDK Host Main return completion and recovery flags from
   committed state without making Main discover tools or fetch the full Run.
7. Pass focused regressions, affected interface checks and neutral real-tool
   qualification for the exact final resource closure before a model trial.
8. Check portable packaging, applicable installation dependencies, launch-ready
   identity and cleanup. Keep original Skill instructions and benchmark answers
   outside deployed worker resources.

Any unresolved check blocks the next engineering trial. An SDK command executing
successfully is evidence for that command boundary only. Static qualification is
not a timed quality or cost win. Record and meter experimental artifacts outside
the business session using existing Host receipts; do not ask the task Main to
write, discover or revalidate a duplicate benchmark delivery record. Retain the
actual costs of prior trials that did perform that extra work.

Qualify the configured existing writable Provider subagent route for ordinary
independent production and review. Actual initiating Main orchestration retains
its context and decisions. Main worker and persistent task/thread are optional
user-edited executors; qualify those only when selected. Preserve source-required
temporal work in a live worker or qualified loop, and report unsupported relations
instead of changing their meaning.

Keep source-derived operational instructions in production stages. Give final Main the
acceptance criteria, original request, current artifact/source needed for content
acceptance and directly usable established product facts through the smallest
sufficient declared projection; full mechanical records remain Host inputs. Qualify the actual Main materializer with realistic
source size: a compact reference alone does not prove an inline handoff. A declared
Host final recorder does not make the preceding final semantic Main an intermediate
stage. Do not add a source prereview followed by the same final review unless the
source or a concrete task dependency needs both. Mechanical defects that would
force an expensive re-export should be detected by the existing producer completion
interface and repaired in its current context. Respect patch authority and original
repair budgets. Actual final media acceptance remains required. Preserve source
speech semantics as well as diagram syntax; a focused label may be a spoken word,
not silent annotation. Measure complete business results separately from these
neutral interface checks.

Term coverage is not explanation coverage. If the original task asks why or how,
the producer must explain the cause and result, and the existing final Main must
check that explanation in the current source. Do not replace this with an extra
review node or expanded teaching requirements. Record provider usage separately:
lower model API cost does not establish lower total cost when voice or other paid
tool requests increase during repairs.

Compare actual Host execution permissions separately from logical node write scopes.
Context/resource/task-directory separation does not itself require another OS sandbox.
For normal writable Main workers, inherit only an explicitly observed policy from
the authenticated initiating Main through Host metadata; do not ask a model to choose
mechanical permission arguments or add a benchmark-specific override. Preserve
read-only capture boundaries, Strict isolation, disjoint item scopes and write audits.
Record the actual policy and basis. A successful execution under a different declared
policy does not prove that a previously failing platform sandbox has been repaired.
Before a fresh timed experiment, qualify its actual tool condition without a model;
keep failed interface trials and their costs separate from successful sample metrics.

Preserve the source's callable tools and exact entrypoint behavior: stdin/file
contracts, arguments, output types, diagnostic meaning, conditional dependencies
and revision budgets. A wrapper must pass neutral real-tool checks before a model
experiment. Do not replace the original renderer with an approximation or disable
source behavior to make a comparison faster.

When a producer result changes, update every consuming Host input contract,
including nested array item schemas, in the same candidate. Exercise the actual
HostToolRunner entry with the producer result and declared resource closure;
calling its implementation function directly misses input admission. Reproduce
the obsolete contract's rejection before broker effects, then verify the corrected
entry and downstream semantic handoff. A claimed deterministic tool failure must
settle that exact tool attempt visibly; it must not strand the claim or be written
back as a failure of an already completed worker.

Preserve original runtime configuration at the Host effect boundary, including
conditional voice services, browser overrides and platform runtime settings.
Sealed portable executable/home addresses may override inherited values; a short
environment snapshot must not replace the original CLI's live environment.
Keep credentials in the Host process, outside model inputs, manifests and receipts.
Use synthetic sentinels to qualify both the wrapper and its real child process
without calling paid services or exposing actual credentials. Count complete
mechanical observations by applicable source phase to catch repetition across
producer completion and join. Retain each phase's original checks and repair
diagnostics; final mechanical acceptance checks bounded freshness of observed
artifacts while preserving required semantic acceptance.

Qualify the exact final resource closure after combining adapter repairs. A later
admission fix must preserve previously verified source argument forms and diagnostic
contracts. Use neutral fixtures against the real bundled entrypoint to exercise the
combined behavior, including conflicting repeated options and rejected stdin before
draft mutation. Bind qualification to exported resource hashes and compare those
bytes with the published package; an intermediate candidate or local source tree
does not qualify a different final resource. Keep these mechanical checks and
evidence in the Host/authoring plane, without extra task-model handoff nodes.

For a source-producing adapter, admission and the exclusive effect reservation
must precede any change to the committed draft. Send candidate bytes through that
boundary; do not write them in an outer entry before the capture rejects a sealed
generation or an existing intent. Qualify rejected complete/busy calls and live
contention with exact before/after draft, receipt and product bytes. Inject an
uncertain commit failure: retain its intent and reject an unconfirmed retry.
Preserve the source's allowed component/STE repairs and original revision budget.
These are mechanical adapter checks, not extra model nodes or prompt reminders.

Qualify the source tool interface as well as the executable bytes. A direct tool
catalog does not establish equivalence to a caller's JavaScript aggregation,
parallel nested calls or explicit response-length controls. Record an unavailable
execution capability as an unresolved interface boundary; do not claim complete
inheritance from an unchanged CLI or a successful thread/start. Check the actual
execution client's effective configuration after reopening it. Preserve inherited
tool output limits; lossless capture must not silently increase model-visible
context. Bound each complete serialized response and retain unread output for
explicit continuation. Missing or unsupported budgets fail before submission.

Preserve the authenticated model's native tool mode. Qualify real JavaScript
aggregation through the bundled native host and actual App Server dynamic-tool
callbacks; a catalog field or successful thread creation is insufficient. Check
parallelism separately by overlapping actual callbacks. Native delegation can
remain serial even with `parallel_tool_calls:true`; disclose that observed limit
and retain the original tool's single-call batch capability. Never add speculative
parameters or auto-parse tool text into guessed objects.

For inherited native code mode the shared Host owns native MCP transport of the
existing scoped brokers. It retains their schemas, grants, validation and command
sandbox RPC. Qualify actual overlap, real scoped writes and Unicode with the native
App Server, then the full normal session's inherited output budget and last chunk.
Transport/owner loss must fence broker admission synchronously before receipt I/O;
known bootstrap failure must consume zero model turns. Exact Host revocation ends
the shim through its held owner channel without polling. Test cancellation, complete
broker quiescence and actual shutdown; do not turn a pipe-held error into success.

Keep waiting layers distinct. The shared outer invocation owns its one-hour
budget. Ordinary foreground commands use the Host command wait policy, whereas
explicit background work and stdin/control interaction have their own contracts.
A short foreground yield must fail at the tool boundary before creating a process;
do not ask a generated task model to repair that policy in its prompt.

Qualify failure return through the actual Host worker join as well as success.
A settled worker failure must return bounded attention to its initiating Main;
do not recursively advance when shutdown uncertainty leaves durable execution
running. Preserve the original and cleanup errors, exact current attempt and
cleanup ownership. Public wait must expose that failure without treating an old
detached heartbeat as the current execution. Test that no new dispatch occurs,
successful execution still advances, and stale failures cannot shadow a successor.
Include confirmed shutdown followed by a failed journal commit: diagnostic identity
must survive resource compaction without retaining heavy context or raw capabilities.
Re-read current state for every local failure and distinguish an audit/recording
error from actual shutdown uncertainty in both the state and bounded diagnostics.
These are shared Host checks, not generated safety nodes or model repair prompts.

Keep model references and Host completion resources separate. Registered completion
programs derive their own pinned entry and explicit resource arguments; Ready
closure and Run byte checks remain required. A semantic reviewer consumes the actual
artifact and necessary semantic references. It need not receive Host checker scripts,
tool implementations, hashes or protocol instructions to enable mechanical checks.

Qualify the actual public handoff in both inline and file delivery. Internal
context-preparation paths and diagnostic manifests belong to the Host receipt,
not the semantic task projection; an exposed pointer can induce another read and
model response even when the prompt asks to avoid it. Preserve the canonical
dispatch bytes, preparation identity and fresh verification. A public file
projection must be separately hash-bound, retain every declared semantic input
and usable resource address, and reject tampering. Include reopening existing
receipts and the inline-size boundary in qualification; do not move business
work outside the timed interval or claim a performance benefit from tests alone.

Compile mechanical originals into `completion_contract.host_check.input_bindings`
when they are needed only by the checker. Node inputs retain actual source,
artifacts, quality diagnostics and new semantic findings. Resolve and validate
Host-only inputs before model handoff, and pin their exact identity for completion
and recovery. Omitting the separate map preserves the existing input contract;
never trim records that a checker needs or weaken its acceptance rules.

Keep tightly interleaved authoring, renderer calls and local diagnostic repair in one
working context when no useful stable handoff exists. For a distinct downstream
responsibility, bind the artifact and concise new findings with supporting locations.
Qualify the producer's real call path, not just a declared CLI resource. Exercise a
source-defined warning and component failure inside the assigned producer, retain
the original repair budget, and verify that ordinary repair does not require a Main
relay. After local success, completion must verify the exact current execution,
source and artifacts without rerendering. Missing, stale or incomplete evidence
must reject visibly. A compact final result avoids forwarding a manuscript solely
for a mechanical renderer; actual final semantic acceptance still reads the product.
An inline value is delivered once. A file reference requires reading when needed.
Reuse established research; required independent review and investigation of concrete
gaps remain intact. Do not add separate delivery, safety narration or repeated research
activities without a source or user requirement.

When producer addresses depend on an item directory, include its Host-resolved
working directory in the typed public task and bind the entry to that same sealed
directory. Qualify the actual public inline or file projection: derive the call
only from that task, execute the real entry and verify the result. Private manifests
and baseline records must not supply a missing working directory during the test.
Use discovered runtime paths and the source tool's selected environment; never
inherit arbitrary worker variables or embed the author's local machine paths in
the generated Workflow definition.

Ordinary startup and completion use the existing authenticated initiating conversation.
Host owns revision, identities, receipts, hashes, resource bytes and deterministic
continuation. Fixed waiting policy comes from the shared invocation configuration.
Do not invent a latest-preparation pointer, ask models to transcribe metadata, or claim
a rewritten client call adopted the Host's invocation preset.

For an eligible initial current-Main route decision, the Host retains an exact
sealed immutable preparation outside the business workspace. The startup adapter
embeds only its opaque reference and exposes the new semantic result slot;
revision, original-input digest and launch arguments are resolved by the Host.
It executes the original initial node once through its ordinary lifecycle and
checker. Missing or changed preparations and stale inputs/revisions fail before
Run creation. Reuse the same reference for an exact retry; changed semantic
replays conflict. No latest-preparation pointer or model-transcribed pin is permitted.
Qualify this through the authenticated public entrypoint, including original
checker rejection, one-Run rejoin, terminal continuation and full recovered
startup-schema validation. Preparation alone creates no Run or model turn.

When that complete pinned contract is already available, submit the semantic slot
through it directly. Do not require another model preparation round solely to
rebuild the mechanical envelope. Typed preparation remains available for callers
that need it; it is not a mandatory extra graph stage. Count all initiating Main
responses as well as isolated workers when assessing the resulting conversion.

Qualification also covers Host scheduling during current-Main handoffs, not only
while an RPC is open. Verify the actual authorized prepare/complete, rejection,
repair, cancellation, recovery and shutdown boundaries with neutral fixtures.
Scheduling priority grants no execution authority. Fix a lifecycle defect in the
shared Host, preserving existing bounded maintenance behavior; do not compensate
with node prompts, additional safety activities or model polling.

Mechanically exercise Unicode text, long input, legal shell prologues, nonzero exits,
changed/missing resources, stale inputs and rejected checkers. Known failures must be
visible and retain evidence. Fix every returned mechanical finding before another
model submission; uncertain execution is reconciled against its exact identity.

For a requested comparison, use equivalent route-selection starts, tools, source
versions and source-default behavior. Preserve all failures, tokens, cached tokens,
cost methodology and full elapsed time. Structural passes never substitute for actual
artifact quality. Keep benchmark answers, experiment instrumentation and local-machine
paths out of generated runtime resources. Expand only after the agreed first-case gate.

Compare caller constraints as well as domain facts. A restriction supplied only
to the initiating Main is absent from an isolated worker unless the declared
input projection carries it. Use the existing shared task-context interface for
common source, operation and content constraints; qualify its exact delivery
through routing and every fan-out item without copying parent history. Require
explicit current experiment inputs instead of silently reusing an older cohort.
Missing scope is a parity defect, not proof of why a worker searched. Preserve
the caller's actual boundary; do not strengthen it into a network ban or inject
benchmark answers. These are authoring/input checks, not extra runtime audits.

Declare the comparison's requested isolation boundary before launch. Explicitly
selected fresh Main workers with independent contexts, task packets, workspaces and selected method
resources support a Skill-versus-Workflow comparison without installing the Skill
or configuring an additional system sandbox. Give the Skill worker its explicit
source path and prohibit Workflow calls; give the Workflow worker only its pinned
Workflow contract. Supply no other-arm answers, parent history or benchmark
guidance. Verify effective method instructions/tool exposure and audit actual reads.
Do not turn context/resource isolation into a requirement for OS-enforced denial.

Only an explicit requirement for enforced cross-environment read denial needs
neutral canary qualification in both directions through actual session/command
permissions, plus scoped MCP resource and conversation-history access. A named
profile or private configuration directory does not prove that stronger boundary.
Qualify it separately and report unsupported enforcement visibly; never relabel
historical samples. Do not silently rerun immutable baselines or mix changed
execution interfaces into an architecture-only comparison.

For artifact quality, inspect actual interactions required to read the content.
A clipped initial diagram may become fully readable after horizontal scrolling;
measure reachability and native-size readability before claiming content loss.
Preserve initial reviews and separate evidence-based addenda. Do not replace a
frozen baseline score with a later auxiliary rating or infer touch/keyboard
support from programmatic scrolling alone.

An inherited code-mode catalog is not evidence that native execution activated its
code-mode host. Qualify the actual owned client launch with the inherited native
feature enabled, a real aggregated callback, its original scoped brokers and
confirmed shutdown. A declaration-only receipt or direct-call success is insufficient.
Use a neutral synthetic provider for mechanical adapter checks; these checks must
never consume task answers or real model calls. Diagnose latency with Host phase
timings before another business submission. Keep history validation and every
admitted read settled before releasing locks; do not add task-model narration,
polling or safety stages to compensate for mechanical Host failures.

Use the owning Run's durable `workflow/toolInterface` event when investigating
an ephemeral normal or managed session. It records the qualified inherited
interface and budget before submission; it does not prove which native web
actions shared a model response. Correlate actual usage updates and item IDs,
and retain unknown attribution rather than calling it polling or tool discovery.
An eager tool declaration is not a parallelism proof. Qualify actual callback
overlap with the original scoped schemas before replacing a native transport;
reduced discovery that serializes formerly concurrent callbacks is a regression.
Attribute complete-task overhead separately to the initiating conversation and
isolated workers. A worker alone matching the Skill does not establish Workflow
parity. Keep required actual-content acceptance and remove only proven duplicate
Host work within one operation, preserving fresh effects and commit checks.
Normal Host history maintenance runs after exact Run publication and coalesces
full audits under durable ownership. Keep this shared policy in the Host, without
adding cleanup nodes or asking task models to manage global history.

Finish with source-independent publication, launch readiness and exact task-owned
temporary-artifact cleanup through the existing Host completion policy. Runtime
packages must not contain the original Skill entrypoint, authoring archives or examples.

Qualify adapter defects mechanically before another business trial. Preserve all
findings from one review as a batch and repair the whole batch before resubmission.
If tool latency is unexplained, retain bounded existing command lifecycle and
settlement evidence before successful cleanup; audit duration alone does not
identify shell execution, server response or observer delay. Keep this diagnosis
in the Host and external engineering collector, without extra task-model stages,
polling, output/hash transcription or speculative wait-policy changes. Distinguish
actual platform integration from platform-gated test skips. Register new tests in
the complete manifest and check its exact file set before final regression. An
isolated successful case proves only its declared delivery, cost, time and quality
gates; it does not establish the cause of a historical intermittent delay.

Restore task-owned temporary platform changes with exact ownership receipts, then
qualify the ordinary intended environment again. Preserve a post-restoration
failure as its own platform precondition; passed tests or an earlier recovered
business case do not make it disappear. A platform helper defect must not create
machine-specific Workflow resources, permanent permission workarounds, invented
runtime identities or a weaker execution sandbox. Track the upstream owner and
actual supported installation proof separately from the converted graph.

Qualify a changed foreground entrypoint using its actual default runtime shapes,
including native environment objects, optional capability fields and unused broker
entries. Plain fixture substitutes do not establish compatibility with registered
Host defaults. Runtime capability metadata is not Workflow JSON: deterministic
initialization may fingerprint supported runtime state but must preserve original
effective-context normalization and selected-contract validation. A healthy command
broker alone does not qualify the public Workflow startup path. Keep pre-Run
failures and their consumed requests visible outside valid comparison cohorts;
repair every finding in the batch before another business startup.

For a converted renderer, qualify inherited presentation behavior as well as its
process exit and writing receipt. External neutral desktop/mobile fixtures should
exercise long headings beside metadata, wide comparison tables and diagram label
legibility. Keep this qualification outside the business graph; an additional
model safety/handoff node is not a substitute for correcting the template.
Judge content against the original question and preserve the source's meaningful
selection criteria, without demanding optional additions absent from that question.

Pin the original source version and complete callable runtime closure before
conversion or comparison. A passing later release does not establish inheritance
from a frozen earlier release. An authorized optimization needs the exact source
diff, derived build provenance and neutral parity checks against that original
version. Keep implementation and executable bundle consistent; do not repair a
bundle independently of its source. Verify live provider configuration through
the actual Host environment allowlist, resource broker and child process. A
direct wrapper sentinel check does not prove that the Host admits those values.
Keep credential values out of model inputs and receipts.

Freeze a complete candidate before a comparison cohort. Preserve every timed run,
fixed baseline and first baseline-quality qualification. A passing first specimen
permits expansion; it does not prove that the later complete cohort passed. Account
for initiating Main and all workers externally. Stable resources, shared context
and lower total input do not guarantee cache reuse or lower cache-priced cost:
record actual fresh/cached/output exposure and keep any all-fresh sensitivity
separate from the agreed gates. Structural valid/Ready and
successful delivery do not establish quality or performance equivalence.

For fanout conversion, use [parallel conversion and cost evidence](authoring-parallel-cost.md)
to qualify real overlap, Host replay and binding behavior, actual cache capability,
and the cost lower bound before another paid cohort.

Inventory the source's complete callable interfaces, including helper commands,
lint variants, configuration queries/changes and installation-specific maintenance.
Trace writing and scene constraints to the frozen source itself before removing
them as converter-added requirements. Check every source callable interface and
condition against the converted route, then every converted operation, output and
check against source/user support. Preserve exact source behavior and remove only
additions whose origin is established. Check existing timed outputs against
restored constraints without inventing a new production requirement or claiming
that an unmeasured semantic revision has a newly measured cost.
Keep typed producer/consumer schemas synchronized. Qualify the actual source's
error formats, including strict failures and intentionally truncated diagnostics,
through the real Host program broker before a business trial. Preserve its repair
budget; do not silently discard missing lines or invent success after a failed tool.

When the request supplies completed assets, provide a reuse route to the original
exporter/tool and pass the existing text/audio unchanged. Do not generate those
assets again merely to export them. Protect all product and internal runtime/receipt
writes before effects, including derived names and aliases of supplied inputs.
Host delivers complete readable production and preservation facts; mechanical
identities remain Host-owned. Main checks the requested meaning, expanding its
investigation only for a concrete defect. Finalization checks selected artifacts
for changes, rather than repeating producer checks or whole-package audits.
Do not make source-absent previews, full decodes or extra exports default work.

When a plain-text answer requires the initiating conversation's context, Main
orchestration can compose and accept it. Independent plain-text production uses
the configured Provider default; a separate handoff or review still requires a
real source or task dependency. Keep the requested text-only boundary and inherited writing tools.
If paid resource use is disallowed, compare identical supplied assets first and
text-only quality separately. Meter every actual initiating/worker call externally;
current-Main ledger placeholders are accounted from that authenticated initiating
rollout, not counted twice or treated as missing worker usage. Asset preservation
does not establish quality of a newly rewritten text or qualify fresh paid synthesis.
