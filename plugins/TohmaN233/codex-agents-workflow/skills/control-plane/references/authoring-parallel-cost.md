# Parallel conversion and cost evidence

Read when converting independent page, scene or other item production into
fanout, or when claiming that the conversion saves time or API-equivalent cost.
These are authoring and external qualification rules. Do not add accounting,
cache warmup, safety-review or benchmark nodes to the user's business graph.

## Preserve the source path

Trace one successful source execution before changing its decomposition. Preserve
its route selection, exact renderer and executor-compatible callable tool arguments, resource-reading
scope, semantic checks and repair limits. A fresh child receives its own item
and the common information it needs. Re-reading an entire tool catalog or adding
unrequested research is a behavior change to diagnose, not an isolation benefit.
Preserve the callable tool interface as well as the renderer. A tool with the same
purpose but different arguments, execution route or result shape is an interface
change. Check the actual selected executable and caller tools; current upstream
documentation alone cannot establish their parity. Record unresolved differences
before a comparison, rather than removing a tool to obtain a cheaper result.
Ordinary native command tools and owned Workflow resource/program tools are
separate interfaces. The runtime inherits the authenticated native shell;
adding a resource broker must not replace that shell. Keep this in runtime
selection, rather than compensating with worker instructions. The qualified
correction and its limits are recorded in the dated source report below.
Keep the initiating Main's task to real orchestration and semantic acceptance.
The Host owns hashes, dispatch identity, journal receipts, lifecycle waits and
joining accepted products.

Keep each production rule in one authoritative declared reference. A node prompt
should add its assignment and execution-specific contract rather than repeat the
reference. If the manuscript already contains the required conclusion, pass that
manuscript to semantic acceptance; add a separate summary only for a real
downstream need. Preserve rules and repair limits when removing duplication.
Use the runtime's typed result transport rather than JSON encoded inside a JSON
string. Common preparation and item output retain the same API schema and exact
phase cardinality; these mechanics belong in Host, not extra model instructions.

Project the producer's already established mechanical facts with the usable
artifact and manuscript. Main reviews the manuscript against the request and
expands investigation when it finds a concrete problem; it need not reproduce
the producer's checks. Establish the requested delivery location before
production. The accepted reply and final links must refer to those delivered
bytes, without a later model copy or a second mechanical acceptance stage.

Separate independent item work from shared writes. Select the supported fanout
executor, result mode and disjoint item workspaces. Preserve original serial or
incremental behavior when items depend on each other. Declare actual shared
semantic information once upstream; projection gives each child its required
view without the other branches' task history. Do not select full-history
inheritance solely to claim cheaper context. It repeats inherited history in each
request and does not establish a selective common-context fork.

## State the actual cache capability

Context isolation, concurrency and prompt caching are separate mechanisms.
An identical visible prompt is not proof of an identical serialized request,
cache routing or hit. Cached prefix tokens remain input tokens for each request;
cache pricing does not mean that a common prefix is billed only once.

The inspected native interface provides fresh or full-history inheritance. It
does not expose a qualified common-prefix preparation receipt, shared cache key
or Host bulk spawn. Ordered calls in one released window permit native execution;
they do not prove that the model dispatches them in one response. Do not promise
stable native cache hits or invent a configuration field to supply that promise.

The qualified Main shared-prefix runtime uses one private common-only source,
same-client ephemeral prediction forks, core-owned MCP routing and restored-before-submit
usage witnesses. Its Host schedules the batch without Main relay calls. Preserve the
actual Main command/program interface when projecting CLI help; use that runtime's
actual tool names and arguments rather than another executor's interface. Keep original CLI bytes, arguments, grammar,
semantic checks and repair limits. Qualification proves observed cache reuse and overlap,
not a guaranteed future hit or business acceptance.

Where an explicitly selected runtime exposes supported prefix preparation, use
one canonical common prefix and stable tool serialization, complete its billed
preparation, then start independent branches with their own suffixes. Include
preparation cost and time in the comparison, record actual hit receipts, and
qualify concurrency separately. A routing key is not a hit guarantee. Changing
from native Codex execution to such a runtime changes the comparison conditions;
it is not an unreported fix to a native benchmark.

Inspect actual preparation processes and configuration reads before adding
another discovery session. Merge redundant discovery through a known typed
configuration overlay and compare it with the actual effective configuration;
do not infer arbitrary defaults from that actual result to make a check pass.
Retain authentication, caller policy, model/tool verification and owned cleanup.
An input audit must describe the actual native or broker command interface so
Host does not reconstruct obsolete declarations at the handoff boundary.

## Qualify the mechanism before the business cohort

Use existing qualified evidence for unchanged boundaries. Test only the changed
interface with a narrow external fixture before a paid cohort; do not repeat the
whole regression suite for each edit. When changing scheduler concurrency, use
a zero-model barrier with two real processes that both reach their effects
before either is released. Qualify cancellation, retries or sibling acceptance
when those boundaries change. A parallel setting alone is not runtime evidence.

Repeated acknowledgement must reuse the exact published task under fresh Host
authority. It must neither regenerate the packet nor append another publication
or identical usage receipt. Dependency verification should follow its actual
lease, permissions, scope and environment binding; unrelated sibling progress
must not fail implicit verification. An explicit sequence precondition retains
its exact compare-and-swap contract. These are deterministic Host mechanisms,
not reminders for workers or extra workflow nodes.

For performance, attribute Main, each worker, startup, collection, acceptance and
delivery separately. Count all model responses, failures, repairs and billed
preparation. Keep the fixed source baseline and pricing external and immutable.
Show actual fresh/cached/output cost as well as total input; isolation does not
establish cheaper billed cost. Preserve original failures and distinguish
inclusive overlapping spans from additive wall time.
Inspect the existing complete journal and response counters before introducing
new instrumentation. An aggregate turn total does not imply that individual
response usage is absent. Restored parent counters are not new branch charges;
actual preparation, tool continuations and reasoning output remain billed.

If an original CLI rejects particular manuscript lines, declare its Host text
amendment contract for the item worker. Host derives the allowed physical-line
scope from actual diagnostics, retains the exact rejected result, merges the
worker's edits and reruns the original checker. Do not force a complete result
to be regenerated for a single-word correction. Preserve the original component
and STE repair budgets, content limits and downstream semantic result schema.
Common preparation, result and amendment phases must share one fixed typed API
schema; validate phase cardinality and exclude simultaneous full result and
amendment output. Keep all cost measurement outside the generated Workflow.

Do not infer the reason for browsing from tool availability. Compare the actual
source instructions, assigned task, supplied information and executed call path.
Equal base instructions and common cache hits do not establish complete input
parity. Do not replace omitted source information with a new research stage.
Normalized web items
and parameter hashes establish that a call occurred; they do not establish its
raw returned context or the instruction that triggered it. Record unavailable
fork raw-event support explicitly instead of attributing an unexplained cost
difference to unavoidable context isolation. Preserve the original tool surface.

Use existing response-level usage before adding diagnostics. Normalized
`thread/tokenUsage/updated` can contain both the last response and thread totals.
Filter by exact owned thread and turn, exclude inherited fork snapshots, and
reconcile last-response sums with the authoritative paid-turn ledger. Inspect
first-response hits and fresh context added after tools; an aggregate cache
ratio alone cannot distinguish a prefix miss from new research material.

Qualify a budget setting against the actual tool path before installing it.
Hosted search context settings do not establish control of a client-executed
Responses Lite web extension. Preserve ordinary tools and required verification;
never substitute ignored configuration, silent truncation or a search ban for
evidence. Repeated prompt-only changes with moving searches require interface
diagnosis before another paid comparison.

For long Host exports, consider the qualified `host_tool_overlap` policy only
when a fixed manuscript can be reviewed independently of the completed output.
Declare one Host tool and one read-only current Main orchestration branch, direct
to their all-required join, with explicit `read_inputs` source objects. Host
owns source projection, process lifetime, cancellation and the join. Preserve
source production checks before the fork and output-dependent visual acceptance
after the join. Reuse the accepted manuscript decision only when Host verifies
the completed product preserves that exact source. This does not authorize
parallelizing original renderer internals or repeating Main in a hidden session.

When source or user acceptance allows revision, preserve that return path rather
than treating every semantic rejection as terminal failure. Use a qualified
`review_context:'current_main'` loop with one read-only initiating Main exit,
explicit acceptance gating and compact correction feedback. Keep the mechanical
finalizer outside the loop; refresh producer, export and observation only after
a concrete rejected review. An explicit null round cap means until accepted;
keep source-defined writing limits and finite local retries unchanged. A deferred
overlap review must belong to that loop; its negative verdict still prevents
acceptance. Keep final acceptance and delivery in one Main-authored result, which
Host relays exactly, instead of adding another delivery-writing activity.

Check source tool inheritance across every producer route, including literal
argv/stdin help, list, version and lint interfaces, runtime provider variables,
and strict nested schemas for batch item packets. Compare real worker commands
and Host children with synthetic environment sentinels; never include credential
values in model inputs. A renderer source diff requires a matching executable
diff and explicit evidence; a restored original bundle is the parity baseline.

Before another paid cohort, check whether the already incurred startup and
initial branch requests alone exceed the fixed whole-task cost. If that lower
bound fails, identify the required context/cache/dispatch change first rather
than repeat the cohort hoping for different cache luck. Neutral fixture speed,
structural valid/launch-ready, quality acceptance and business cost/time gates
are distinct results; report each honestly.

Engineering qualification and business comparisons are separate. Published
task-specific comparisons are maintained in the [Workflow Package gallery](https://tohman233.github.io/workflow-package/).
This document contains no local runtime paths or machine-specific workflow resources.
