# 质量检查与返工

## 结构与内容

- 源文件 SHA256 前后一致；输出能打开，页面数量符合选页和单双语设置。左右双语一般为原页宽度之和；交替双语一般页数加倍，但选页保留行为应实测。
- 检查翻译覆盖、标题、跨栏/跨页段落、图注、表格、参考文献。不要将 PDF 字体的 Unicode 映射异常直接认定为视觉缺字；结合实际渲染。
- 数字、负号、上下标、单位、引用编号、变量、根号与积分上下限逐项抽查。术语命中不是术语正确的充分条件。
- 图像数量/哈希可用于提示丢失，但矢量图、资源复用和重新编码会改变统计；不能仅凭图片计数宣布所有图形保留。

## 视觉核验

按需用已有 PDF 渲染器（例如 Poppler 或 PyMuPDF）渲染第一页、公式密集页、表格页、图片页以及所有修改页。短文可全页检查；长文标明抽查范围。文本提取不能替代版式判断。没有渲染/视觉能力的平台应报告未验证版式，不假装完成检查。

特别留意首字下沉、装饰性文字、多栏、行内公式、脚注和跨页表格。扫描/OCR 结果另标识，检查容易混淆的 0/O、1/l、负号、小数点和希腊字母。

## 有界修复

先区分翻译错误、分段错误、公式识别错误、排版溢出和 OCR 错误。一次调整一个相关条件，保留旧结果，对同一代表页重试。优先修正术语/提示/适用参数；不要用整页白底覆盖来掩盖丢失。确需手工修复时保留原公式或矢量内容，不自行改写数学含义。

两次针对性修复仍无改善，就保留最好版本并列出未解决页码；不要不停全量重译。引擎不能满足用户质量要求时明确标为草稿或待人工复核。

## QA 记录模板

输入/哈希；引擎版本；模型和接口提供方（不含密钥）；源/目标语言；物理页码范围；输出布局；术语来源；OCR 状态；检查方法与页码；修改记录；未解决问题；最终输出路径。
脚本的 `needs-review` 仅表示引擎成功产出文件，最终审核由 agent 完成。不得自动改为 reviewed 而未进行实际检查。
