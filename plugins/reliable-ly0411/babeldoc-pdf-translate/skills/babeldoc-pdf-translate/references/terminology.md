# 术语与专业领域

## 优先级与上下文

用户指定译法 > 用户批准的项目术语表 > 本文已定义的含义 > 有来源的领域术语 > 模型建议。同一个缩写在不同领域可能不同，先看标题、摘要、上下文、单位和图注。不要将航空例表自动用于所有文档。

自动提取不等于自动验证。启用 auto_terms/save_terms 可以得到候选；术语要求严格时，agent 先基于可提取正文整理候选 CSV，再执行最终翻译。不要假定 BabelDOC 自动提取结果一定遵守人工术语的全部优先级；合并冲突并抽查最终输出。

遇到多义词时只就影响大的歧义向用户简洁提问，其余继续准备。不知道的扩写保留英文，不编造。用户要求联网核实时查标准发布者、专业词典或原始论文，并保存来源；不把模型建议标成行业标准。

## 数据格式

引擎 CSV：`source,target,tgt_lng`，UTF-8。tgt_lng 可省略；一个任务最好使用单一目标语言。包含逗号或引号的值遵循 CSV 引号规则。脚本检查空值和冲突，不判断专业正确性。

单独保留可选的术语审核表，列为：原文、译文、领域、本文证据/页码、外部来源、状态（用户批准/上下文推断/待确认）。不要把审核备注塞入引擎 target 单元格。

例如用户明确要求英文保留：

```csv
source,target,tgt_lng
phase margin,phase margin（相位裕度）,zh-CN
landing gear,landing gear（起落架）,zh-CN
```

若用户希望纯中文，就将 target 改为中文。固有名词、型号、代码、单位、引用和公式不能为了词汇一致性被随意重写。

## 更新后的重译

更改术语或提示后先检查缓存行为；必要时开启 ignore_cache 并使用新的输出目录。对于同形异义、大小写、复数或词形变化，匹配可能不完全；先用代表页试译，再检查词表中最关键的词是否按上下文出现。
