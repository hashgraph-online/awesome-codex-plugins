# Picking words

## Candidates

Take 3-5 words or short phrases a person would type. Start from the target prompts, then competitors' names, subtitles and keywords. Keep only words the plugin can honor.

## Check each word

The test is the store's own search, which only the user's browser reaches here. Ask the user to type each word into the store's directory search and paste the top 10 names.

With no paste, use `listings_search query="<word>" store=<store> limit=10`. It searches OpenApps' catalogue, so it's a proxy: add `Degraded: word checks used OpenApps' search, not the store's`.

For each word, note how many of the top 10 hold it in their name, and whether they do the plugin's job.

## Choose

A word every top result holds in its name is crowded. Target the least crowded word that people with this job would type, and take a narrow phrase the plugin can lead over a broad word it can't. Going after narrow words first is a search-engine habit, unproven in app stores, so say that if you recommend it.

Give each target word a field, using the store file's Search section where it has one.

Report the table: word, top 10 holding it in the name, who they are, and the field it went to.

## More than one listing

If the plugin does separate jobs for separate people, put one listing per job to the user as a question. Results vary: one publisher's listings can rank far apart, and ChatGPT's guidelines bar spam.
