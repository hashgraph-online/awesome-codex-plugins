# 가설을 관측으로 구분한다

원인이 여러 개인 실패에서만 읽는다. 단순한 오타에 가설표를 만들지 않는다.

1. 실패하는 최소 명령과 정상 대조군을 먼저 기록한다. 버전·설정·cwd·입력 등 달라진 조건을 남긴다.
2. 서로 다른 원인 가설을 적고, 각 가설이 참이면 관측될 결과와 반증 조건을 붙인다.
3. 한 실험에서는 구분에 필요한 변수를 바꾼다. 결과를 보기 전에 예상 결과를 써서 사후 설명을 줄인다.
4. 원인 후보를 켜고 끌 때 실패도 따라 바뀌는지 확인한다. 코드가 그럴듯해 보이는 것만으로 확정하지 않는다.
5. 기존 테스트가 이미 실패를 잡으면 재사용한다. 회귀가 빠져나갈 때만 그 경계의 테스트를 추가한다.
   수정 전 실패/수정 후 성공을 같은 판정기로 남긴다. 테스트를 약화해서 통과시키지 않는다.

| 가설 | 구분할 실험 | 예상 | 관측/명령·rc | 판정 |
| --- | --- | --- | --- | --- |
| 환경/설정 차이 | 같은 입력, 조건 한 개 변경 | 실패가 이동 | 실제 출력 | 지지/반증/미확인 |

무진전이면 같은 실험을 반복하지 않고 계측 위치나 가설을 바꾼다. 재시도 상한은 debug 본문의
기존 가드를 따른다. 역할을 늘리는 것 자체를 새 증거로 세지 않는다.

임시 파일·프로세스·설정 변경을 기록하고 자기 소유 자원만 정리한다. 재현 로그/핵심 증거는
보존한 뒤 불필요한 자원을 정리한다. 타세션 자원이나 사용자가 만든 파일은 지우지 않는다.
서드파티 실행은 가능한 OS 쓰기 제한으로 격리한다. HOME 변경만으로 쓰기가 차단되지는 않는다.
