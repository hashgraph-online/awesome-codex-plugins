# 요구사항 정련 (Elicitation)

> `plan-task` Step 1(T1 요구사항 명확화)의 상세 절차. 규범
> `rules/planning-protocol.md` 가 **무엇을 지켜야 하는지**를 정하고, 이 문서가
> **어떻게 찾는지**를 소유한다. 여기서 규범을 재정의하지 않는다.

---

## 이 문서가 푸는 문제

등급 체계(P0~P3)만 있으면 실전에서 *"딱히 모호한 게 없었다"* 로 끝난다. 모호함은
**감지되기를 기다리는 것이 아니라 찾아 나서는 것**이고, 어디를 봐야 하는지 모르면
찾아지지 않는다. 못 찾은 모호함은 사라지지 않고 **구현 중에 추측으로 메워진다** —
그리고 그 추측은 아무 데도 기록되지 않는다.

---

## 0. 자격 인벤토리 — 요구사항 수집보다 먼저

**지금 확보된 접근 권한을 세고, 그 경계선을 이번 범위선으로 삼는다.**

```markdown
## 확보됨
- 레포 쓰기 권한 · 로컬 실행 환경 · 공개 문서

## 미확보 (이 경계 밖은 mock/adapter 로 처리)
- 운영 DB 인스턴스   → in-memory adapter, 스키마만 검증
- 외부 결제 API 키   → mock adapter
- 사내 정책 문서     → 정책값은 초안, 승인 대기
```

미확보를 **기다리지 않는 것**이 핵심이다. 경계 안쪽을 전부 검증 가능하게 만들어 두면
권한이 생기는 순간 adapter 만 갈아끼우면 된다.

이 인벤토리는 그대로 **위임 브리프의 금지사항**이 된다
(`rules/delegation-contract.md` 4블록 중 3번). 금지사항을 사람이 따로 불러주게 하지
말고 **여기서 도출한다.**

### 권한과 무관한 절대 금지선

권한이 있어도 단독으로 하지 않는다 — 되돌릴 수 없거나 외부에 실제 효과를 내는 행위.

실서비스 배포 · 운영 데이터 마이그레이션 · 실제 결제/환불 · 실제 알림 발송 ·
공개 API 의 파괴적 변경 · 과금 발생 · 권한 범위 확대 · 개인정보 보존 기준 변경.

이 목록은 프로젝트 성격에 따라 **늘어날 수는 있어도 줄어들지 않는다.**

---

## 1. 물을 것을 고르는 규칙

**구현 결과를 바꾸는 결정만 묻는다.** 답을 받아도 코드가 같으면 그 질문은 사람의 시간만 쓴다.

| 묻지 않는다 | 왜 |
| --- | --- |
| "관리자 화면이 필요한가요?" | 스펙에 이미 답이 있거나, 답이 코드를 안 바꾼다 |
| "이 기능 필요하죠?" | 확인 질문. 새 정보가 없다 |
| 조사로 채울 수 있는 값 | 묻지 말고 `[researched: 출처, n]` 로 채운 뒤 **검토만** 요청한다 |

| 묻는다 | 왜 |
| --- | --- |
| "10:00~11:00 예약이 있을 때 10:30 시작을 허용합니까?" | 경계값. 답이 없으면 구현자가 추측한다 |
| "홀드 만료와 결제 완료가 겹치면 어느 쪽이 우선입니까?" | 충돌. 두 규칙이 동시에 참 |
| "정확히 24시간 전은 무료 취소에 포함됩니까?" | 부등호의 등호 |
| "차감 후 확정이 실패하면 즉시 복구합니까, 운영자 검토 상태로 둡니까?" | 롤백 범위 |

**한 번에 5개 이하로 묶어서** 묻고, 답을 못 받으면 `[unresolved]` 로 남기고 **진행한다.**
답을 기다리며 멈추지 않는다 — 단, P0 는 예외다(규범 §모호함 등급).

## 2. 찾는 자리 — 네 군데를 훑는다

요구사항 문장을 받으면 아래 넷을 **의도적으로** 훑는다. 하나도 안 나왔다면 훑지 않은 것이다.

### ① 상태 전이가 갈라지는 지점

상태를 나열하고 **전이표**를 그린다. 빈 칸이 질문이다.

```
        │ 대기   결제중  확정   취소
 만료   │  ?      ★      –      –      ← ★ 가 질문: 결제중 만료는 어디로?
```

### ② 두 규칙이 동시에 적용되는 지점

규칙을 쌍으로 교차시킨다. *"A 와 B 가 같은 입력에 동시에 참일 수 있는가"* 가 참이면
**우선순위 또는 합성 규칙**이 필요하다. 없으면 구현자가 정한다.

### ③ 부등호의 등호 포함 여부

스펙의 모든 `이상/이하/초과/미만/전/후` 에 대해 **경계값 자체**를 물어본다.
*"24시간 전"* 은 `<` 인가 `<=` 인가. 이 한 글자가 환불 분쟁이 된다.

### ④ 실패 후 롤백 범위

다단계 연산마다 *"k 단계에서 실패하면 1..k-1 을 되돌리는가"* 를 묻는다.
되돌린다면 **되돌리기도 실패하면** 어떻게 되는가.

## 3. 값에는 출처를 붙인다

규범이 정한 3분류(`[confirmed]` / `[researched: 출처, n=표본]` / `[unresolved]`)를
**모든 값에** 적용한다. 실전 주의점 셋:

1. **`n` 을 생략하지 마라.** 표본 하나로 만든 규칙은 대개 틀리고, `n=1` 은 그 사실이
   문서에 남게 한다.
2. **라벨은 «관측»에 붙지 «추론»에 붙지 않는다.** 관측이 두 번 재현됐다고 그 위에
   얹은 결론까지 검증된 것이 아니다 — `[관측 n=2 / 추론 미검증]` 처럼 대상을 적는다.
3. **상충은 해소하지 말고 기록한다.** 하나를 고르는 순간 그 선택의 근거가 사라진다.

```json
"_unresolved": {
  "sessionTimeoutMin": "문서 30 / 코드 15 상충. 운영 확인 필요. 설정값으로 위임."
}
```

## 4. 정책값은 산문에서 빼낸다

**산문에 숫자가 남아 있으면 그 계획은 미완성이다.** 숫자가 문장 안에 있으면 구현자가
그것을 하드코딩하고, 바뀔 때 어디를 고쳐야 하는지 아무도 모른다.

계획 산출물에서 모든 정책값(임계값·상한·기간·비율·재시도 횟수)을 뽑아 **한 곳**에 모은다.
어디에 모을지는 프로젝트가 정한다 — 설정 파일, 계획 파일(`plan.md`)의 표, 상수 모듈.
중요한 것은 **위치가 하나**라는 것이다 — 복사된 값은 한쪽만 고쳐져 갈라진다.

---

## 5. 완료 조건은 실행 가능한 명령이다

*"잘 동작함"* · *"안정적으로 처리됨"* 은 완료 조건이 아니다. 판정하는 사람에 따라 답이
달라지기 때문이다. **종료코드로 판정되는 명령**을 쓴다.

```
✗ 로그인이 정상 동작한다
✓ pytest tests/test_auth.py -q     (exit 0)
✓ curl -sf localhost:8000/health   (exit 0)
```

**출력이 비결정적인 부분이 있으면 조건을 둘로 나눈다.** 통과/실패 게이트는 결정적인
부분(스키마·권한·상한·상태 전이)에만 걸고, 비결정적인 부분은 고정 평가셋과 임계값으로
점수를 낸다. 섞으면 게이트가 노이즈가 되어 아무도 보지 않는다.

단, **금지 행위 위반은 임계값이 아니라 0** 이고 결정적 게이트로 다룬다.

## 6. 작업 규모와 Planning 완료 조건

**규모 판정과 규모별 완료 조건은 이 문서가 소유한다** (규범은 얇게 유지한다 — 상시 주입
예산이 유한하고, 이 내용은 기획을 수행할 때만 필요하다).

| 규모 | 범위 | Planning 완료에 필요한 것 |
| --- | --- | --- |
| **Small** | 1개 모듈 · 1-3파일 | 요구사항 |
| **Medium** | 2-3개 모듈 · 4-10파일 | + 사용자 여정 · 상태 전이 · 에러 전략 |
| **Large** | 4개+ 모듈 · 10파일+ | + 비즈니스 규칙 · 규칙 간 관계 · 예외 처리 |

**공통(모든 규모)**: P0 모호함 = 0 · 영향 범위와 리스크 분석 완료 · **완료 조건이 실행
가능한 명령**(§5). 셋이 다 차야 Dev 로 넘긴다.

### 이 문서의 절차를 규모에 맞춘다

| 규모 | 적용 |
| --- | --- |
| **Small** | §1(물을 것 고르기) + §5(실행 가능한 완료 조건). §0·§2 는 생략 가능 |
| **Medium** | + §2 의 ①②(상태 전이·규칙 충돌), §3(출처 태그) |
| **Large** | 전부. §0 자격 인벤토리와 §4 정책값 분리는 Large 에서 **생략 금지** |

---

## 흔한 실패

- **질문을 다 모아두고 답을 기다리며 멈춘다** — P0 가 아니면 `[unresolved]` 로 진행한다.
- **모호함이 없다고 결론낸다** — §2 의 네 자리를 훑은 근거를 남기지 않았다면 그것은
  "없다"가 아니라 "안 찾았다"다. 음성 결과에는 **어디를 봤는지**를 같이 적는다.
- **조사로 채울 수 있는 것을 사람에게 묻는다** — 사람의 시간은 경계값 판정에 쓴다.
- **값을 조용히 채운다** — 나중에 확인된 값인지 지어낸 값인지 구별할 수 없게 된다.
- **완료 조건을 사람이 읽고 판정하게 둔다** — 판정자가 바뀌면 결론이 바뀐다.
