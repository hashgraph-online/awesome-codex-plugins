# cross-engine-review

서로 다른 엔진에서 도는 세션들이 **증거로** 합의에 도달하게 하는 진행 절차.

## 왜 있나

한 세션 안의 다관점 리뷰(`multi-perspective-review`)는 관점을 늘리지만 **모델·컨텍스트·
툴이 같아 사각지대를 공유한다.** 서로 다른 엔진의 세션은 도구 접근이 달라 **증거 자체가
다르다** — 한쪽은 공고문만 읽고 다른 쪽은 실물을 보러 갈 수 있다.

## 무엇이 어려운가

운송이 아니다. 셸이 있는 에이전트면 참여자가 될 수 있고, 파일 우편함만으로 프로토콜이
성립한다. 어려운 것은 **토론 규율**이고, 그중 가장 위험한 실패는 **가짜 합의** —
두 에이전트가 수렴하는 가장 쉬운 길은 합의 기준을 조용히 낮추는 것이다. 그건 검사를
지워서 초록을 만드는 false-green 과 같은 형태다.

그래서 이 스킬은 합의 기준을 **토론 전에** 못박게 하고, 합의문에 **미충족 기준**과
**기준 변경 이력**을 반드시 적게 한다. 미충족이 남은 채 끝나는 것은 실패가 아니다.
미충족을 숨기고 합의했다고 쓰는 것이 실패다.

## 쓰는 법

`/cross-engine-review` — 절차는 `SKILL.md` 가 SSOT. 우편함 경로·참여자·운송 수단은
소비자가 정한다. 이 스킬은 특정 CLI·MCP·플러그인을 전제하지 않는다.
