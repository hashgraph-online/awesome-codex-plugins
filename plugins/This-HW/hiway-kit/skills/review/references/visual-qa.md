# 실제 화면 검증

UI·브라우저·TUI·출력 문서의 보이는 동작을 바꾼 경우에만 읽는다.

1. 소비자가 사용하는 실제 표면을 연다. 웹은 호스트의 브라우저 도구, TUI는 실제 터미널,
   문서는 생성된 PDF/페이지를 사용한다. 정적 코드 검사로 화면 검증을 대신하지 않는다.
2. 변경한 여정의 정상·오류·빈 데이터·로딩 상태 중 해당하는 것을 실행한다.
3. 지원 대상인 화면 폭·테마·입력 방식을 고른다. 프로젝트가 지원하지 않는 조합을 의무화하지 않는다.
4. 잘림/넘침, 텍스트 가독성, 포커스 이동, 키보드 조작, 레이블/대비, 상태 피드백을 확인한다.
5. 디자인 변경은 프로젝트의 기존 간격·색·타입·컴포넌트 규칙과 대조한다. 별도 브랜드 스타일을 강요하지 않는다.
6. 재현 경로, 실제 관측, PASS/FAIL/미검증과 필요한 캡처를 남긴다. 관련 오류 로그도 확인한다.

실제 브라우저/화면에 접근할 수 없으면 한계를 보고한다. 보지 않은 화면을 정상이라고 판정하지 않는다.
로그인·MFA·사용자 승인 단계는 호스트의 사람 인계 경로를 사용한다. 캡처에서 비밀/개인정보를 가린다.
