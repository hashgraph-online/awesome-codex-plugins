# Project profile

Before running checks on a new project, fill these in. Look first at the project's `AGENTS.md`, `CLAUDE.md`, `Makefile`, CI config, and the user's global instructions. Ask the user only when none of those answer it.

| Item | What to record | Example |
|---|---|---|
| Build permission | Can you build at all, or only when the user asks? | "Build only on explicit request" |
| Regenerate | Command to run after every branch switch | `make project`, `tuist generate`, `xcodegen`, `npm ci`, codegen |
| Generated drift | Files local tooling rewrites that must not be committed | lockfiles, vendored frameworks |
| Lint / CI gate | Cheap check that matches CI | `make verify`, `npm run lint`, `ruff check` |
| Scoped tests | How to run only the suites a change touches | `xcodebuild test -only-testing:<Target>/<Suite>`, `pytest path::test`, `npm test -- <pattern>` |
| Pass evidence | How to read the real result | a result bundle, a JUnit file, a pass line, the exit code with `pipefail` |
| Full suite | Command for the integration branch, if one is run | test plan, `make test` |
| Disk needs | Rough free space a build needs | "~10 GB for build caches" |
| PR host tooling | How PRs are read and replied to | `gh`, `glab`, Bitbucket API or MCP |
| Merge settings | Merge strategy, and whether branches are deleted on merge | "merge commit; auto-delete off" |
| Pushing | Always `safe-push.sh`: a dry run, the user's explicit approval, then the printed command | — |

## Example: iOS app generated by Tuist

- Run `make project` after every checkout. If the build later reports `Build input files cannot be found`, the generated project is stale. Run `tuist generate --no-open` directly, then confirm the missing file no longer appears in `*.xcodeproj/project.pbxproj`.
- Before every commit, run `git status`. Restore only generated drift proven to come from this operation; preserve pre-existing user edits. Review the diff before any `git checkout HEAD -- <path>`.
- Scope tests with `-only-testing:` and pipe through a formatter that keeps the failing exit status (for example `xcsift -E`). Read the real counts from the newest `.xcresult`. A result of `totalTestCount: 0` or `result: unknown` means the run didn't execute anything.
- Reuse the existing DerivedData. Don't pass `-derivedDataPath`, because a fresh cache means a full rebuild for every branch.
