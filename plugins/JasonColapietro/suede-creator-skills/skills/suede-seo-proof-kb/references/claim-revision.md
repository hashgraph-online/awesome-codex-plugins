# Worked correction and verification

This is a synthetic example. Do not export its numbers to a real page.

**Input.** A public guide says an export took 12 seconds in a pilot. A new release benefits a different cohort. The team measured 8 seconds in 20 runs with matching file size on the new tier, but has not measured the change on the original tier. Two published URLs and one comparison FAQ reuse the old sentence. The comparison uses a customer name whose permission is being withdrawn.

**Expected result.**

1. Keep the original observation as a historical record if retention is permitted. The observed 8 seconds gets a new or explicitly revised record with its own tier, sample, date and measurement method. Do not state that all exports got faster or claim a direct improvement across incomparable cohorts.
2. Mark the named case as revoked for public use. It does not become anonymized proof by default. For the FAQ, queue removal of the name and result unless independent approval supports a replacement.
3. Locate uses by ID first, search for old wording plus its context, then inspect matches. A count of 12 support integrations on another page is not a hit. Record direct URLs and anchors and whether copy, preview metadata or structured data carries the claim.
4. Propose exact scoped replacements only for eligible surfaces. For a page serving the original cohort, retain a dated, supported observation if permitted or return a neutral description. For the new tier, specify that the 8-second figure was observed in the stated test and is not a loading-time promise.
5. If implementation was authorized, compare the approved copy against the rendered guide, FAQ and any structured data. Record which routes remain inaccessible. The correction is not marked live because a file changed or a build passed.

**Recovery.** If the team has neither a publishable source nor access to the raw results, list the named owner and evidence request. Draft a version without the metric. Do not infer a new value from a chart thumbnail or summarize a customer's removal request in public copy.

**Validation.** A reviewer should find one current record per claim, no public excerpt beyond its clearance, exact page-to-claim mappings, and an explicit treatment for historical claims, unchecked pages and revocation. Each proposed replacement should make sense even if lifted out of the rest of the page.
