# Worked contracts: Suede AI Design Skills

Illustrative applications, not claims of measured customer results.

## Read-only review

**Input:** Review an invoice dashboard change. The request names a branch and
its target; the user wants reviewers to find issues caused by the change. The
primary task is finding and opening overdue invoices. Existing density, copy
and logo are approved.

**Expected output:** Resolve exact base/head and any included working changes.
Trace the full diff and affected shared consumers. Inspect the primary path,
representative desktop/mobile views and applicable states. Return one ranked
report with source/render evidence and introduced, regression or pre-existing
classification. Keep application source and approved content unchanged.

**Failure checks:** An unchanged consumer of a changed shared shell is not
automatically pre-existing. A removed line is not automatically a regression
if another part of the diff supplies the behavior. A clean tree does not imply
permission to select the last commit. Missing browser access does not become a
visual pass or a product defect. Record each exact coverage gap.

## Authorized scoped repair

**Input:** Fix the confirmed invoice-filter clipping issue from that report.
Keep unrelated layout, wording and assets intact.

**Expected output:** Reproduce the clipping with representative local data,
trace the shared sizing cause and make the smallest authorized correction.
Recapture the same viewport/state and inspect again, including another affected
consumer. Repeat until the scoped result is established or a concrete blocker
remains. Return changed files, relevant check results and actual render evidence.

**Failure checks:** Do not expand the fix into a palette or font replacement,
rewrite the offer, rebuild the component as a lookalike or claim success from
source alone. Preserve WIP. If the runtime fails, report the exact command/error
and distinguish completed source work from unverified rendered behavior.

## Reference-driven build

**Input:** Restyle the existing invoice dashboard with supplied target tokens
and an authorized reference. Preserve the user's approved claims and logo.

**Expected output:** Inspect reference pixels and target render at matching
viewports, map visual roles into the existing system and implement only the
requested surface. Keep accessible focus/contrast when the reference conflicts.
Verify desktop/mobile and relevant states after each correction; report scoped
fidelity and any missing evidence. A user-selected marketing kit is conditional,
not a reason to impose a poster treatment on this dashboard.
