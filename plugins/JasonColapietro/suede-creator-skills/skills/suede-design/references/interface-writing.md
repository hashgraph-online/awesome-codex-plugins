# Interface writing: preserve meaning and enable action

This reference covers labels, hints, errors, confirmations and state messages.
Substantial sales copy belongs to suede-copy; funnel architecture belongs to
suede-site-alchemy when those skills are available. Without them, follow the
approved copy brief and report the routing limit. Do not install a plugin.

## Establish the vocabulary and authorization

Find the current string source: component, translation catalog, API or CMS.
Read nearby labels and the approved offer, price, terms and factual claims.
Inventory the object nouns and action verbs through the whole flow. Distinguish
unseen server/CMS strings from inspected strings.

An audit reports ambiguity; it does not edit text. An authorized layout fix
preserves approved sales copy and factual claims unless the user approved a
specific conversion case and rewrite scope. Do not shorten an offer to make a
fixture fit or replace a measurable claim with invented proof. Adjust layout
first when the approved wording is simply under content pressure.

## Review against actual behavior

| Surface | Evidence question |
| --- | --- |
| Action label | Does it describe the action that actually occurs and its object when needed? |
| Link | Can a reader identify the destination in the supplied context? |
| Field | Are the label, format and requirement available before an error? |
| Error | Does it identify what failed and offer the real recovery path? |
| Pending | Is the operation's state clear without promising success too early? |
| Confirmation | Does it reflect the observed result, with the next useful action? |
| Permission | Is the available path accurate without revealing private resources? |
| Destructive/payment action | Are consequence, amount and recovery/confirmation truthful? |

A brand's sentence case, punctuation, humor or first-person voice is not a
failure by itself. Report inconsistent terminology, misleading consequences or
unusable recovery, not a preferred tone. For high-stakes actions, clarity of the
actual consequence matters more than cleverness.

Keep accessible names aligned with visible labels. Name the action, not the
icon glyph. Keep error messages associated with the affected input and verify
announcements with the appropriate accessibility evidence. An error sentence
alone does not prove correct error behavior.

## New copy within scope

Use the product's established vocabulary and complete localized messages.
Avoid assembling translated sentences from fragments; use the existing locale
system and locale-aware date/number/plural formatting. Match supported input
methods without assuming every interaction is a click.

Prefer specific recovery and orientation: a filtered empty state can name the
filter and offer its existing clear action; an unavailable booking can explain
that no times remain without pretending a booking succeeded. Never invent a
backend capability or promise because it would improve the words.

For reversible frequent actions, an existing undo path may reduce friction;
for irreversible or financial actions, use the product's approved confirmation
and error-prevention model. Do not transact during review. Test these states
through local synthetic seams and preserve production behavior.

Report each wording issue against the actual source and invoked action. Keep
copy changes separate from layout changes in the handoff, with the approved
reason and rendered fit evidence when a rewrite is authorized.
