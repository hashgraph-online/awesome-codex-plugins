# Sprint evidence ledger

This example is fictional. Take week labels from actual release timing, not
from expected timing when the sprint was planned.

| Checkpoint | Evidence | Decision example | Owner |
|---|---|---|---|
| Start | URL, query group, market, device, complete lookback and prior window, lead-event definition | Continue only if the demand and task fit are supported | SEO analyst |
| First change | Pull request, high-value path smoke test, exact revised text, published URL readback | Revert if metadata/template changes reach unrelated URLs | Site owner |
| Midpoint | Direct URL and search readbacks, unchanged conversion routing, any competing internal URL | Keep measuring if sample is sparse; fix real regressions | SEO analyst |
| Outcome | Same-cohort impressions, clicks, position and conversion denominator | Record improved, inconclusive or regressed with supporting data | Lead |

When logging results, distinguish a search click from an actual conversion.
A changed SERP layout, seasonality, or a major release introduces competing
explanations. Report these limitations without assigning percentages of
causation the observation cannot establish.
