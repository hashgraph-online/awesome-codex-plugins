# Suede AI Workflow Skills: Worked Handoff

## Inputs

Request: “Which Suede skill should I use to improve this landing page's search
traffic and signup path?” Supply the current page/repository and desired done
signal if available. Synthetic case: a technical audit exists, conversion
evidence is missing, and the user is asking for routing rather than authorizing
a new implementation.

## Expected output

Apply the precedence table before choosing specialists. A recommendation can
name `suede-seo-audit` for an unresolved scored search audit and
`suede-site-alchemy` for the conversion path, with dependency order and the
verbatim request preserved. If the target is one multi-file implementation that
must be searched, built, and gated as one graph, route to `suede-graph-flo-xr`
instead of casually launching multiple editors. For “what next,” inspect current
state read-only and return one action, why now, and a runnable quick prompt.

## Failure case

Only the umbrella is installed. Read `condensed-workflows.md` and return the
relevant fallback rather than claiming a specialist or MCP tool was invoked.
If subagents are unavailable, describe the dispatch limitation and perform only
the supported authorized work. A recommendation request alone does not authorize
editing, committing, deploying, or messaging.

## Validation

Match the request to the narrowest owner and check the source of every state
claim. Ensure the next-action prompt names the target, action, output, and done
signal. Preserve the user's words at handoff, cap dispatch numerically when used,
and verify a selected specialist actually exists before describing it as loaded.
