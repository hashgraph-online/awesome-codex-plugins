# 规划与阶段复盘（kaoyan-plan）

规划由主会话从骨架写到定稿；外援最多在定稿前审一次，只交问题清单。**问用户怎么排，不替用户定**：涉及时间分配的地方写成选项。

开工先读工作区的 `kaoyan.yaml`：考试日期、`exam.checkpoints`（复盘日）、`records.status`（状态卡）、`records.decisions`（决定）、`roles.audit`。没有配置就转 `kaoyan-setup`。

## 先分大小

| 情况 | 例子 | 怎么做 |
|---|---|---|
| 小问题 | 明天学什么、今天怎么排、某科落后了怎么办 | 读状态卡和每日进度最后几行，直接答，给 2–3 个选项 |
| 大规划 | 阶段复盘、周计划、调各科比重 | 照下面的流程，最好开一个新会话做 |

用户想“重新写一份长计划”时，先指向最近的复盘日：**考前最后一两个月只在复盘日对表、调整，不再写新的总计划。**规划和排版类的产出最容易挤掉独立做题的时间。

## 阶段复盘流程

| 步 | 谁 | 做什么 | 交什么 |
|---|---|---|---|
| 0 | 用户 / 主会话 | 前一天：收件夹里有新学习记录先用 `kaoyan-archive` 归档；按 `references/status-card.md` 更新状态卡 | 状态卡 |
| 1 | 主会话 | 新会话里只读状态卡和“决定”，不通读各科原文件。缺某一科的细节，派一个只读子代理（如插件的 `finder`）读那一科的学习日志，只要结论和出处 | 心里有数 |
| 2 | 主会话 | 写**两套方向不同的骨架**（如“保专业课”和“补短板”），挑一套或拼两套，改成 `plan_adjust.md`，一次写成 | `plan_adjust.md` |
| 3 | 审稿者（可选） | `roles.audit` 不是 `none` 时审一次（见下） | 问题清单 ≤8 条，主会话逐条决定改不改 |
| 4 | 主会话 | 和用户确认选项后定稿；结论写进“决定” | 一行决定 |
| 5 | 主会话 | 用户要 PDF 时照 `kaoyan-report` 出；版式见下 | PDF |

### 两套骨架写什么

只依据状态卡和“决定”。每套不超过 600 字：目标拆分、各科时间比重、这阶段砍掉什么、取舍（换来什么、牺牲什么）、最大的风险。不排到小时，不替用户定作息。另外写清四件事：

1. 每套到下一个复盘日怎样算达标（要量得出来）；
2. 落后 3 天先砍什么；
3. 状态卡里互相矛盾或缺的数据；
4. 要问用户的 2–3 个问题，整理成选项。

两套骨架是给用户选方向用的，放在 `plan_adjust.md` 的最后一节，写成“推荐（已按这个排）/ 另一种”。

### 审稿（一次）

任务书写：下面是定稿前的调整方案，对照状态卡和“决定”查四类问题：漏掉的科目、和已有决定冲突、时间排不下、达标标准量不出来。交问题清单不超过 8 条（位置、错在哪、依据、改法），没问题写“未发现”，不要重写方案。附件只给 `plan_adjust.md`、状态卡、“决定”。

只审这一次，改完不再送审。审稿者不可用时跳过，直接和用户确认。

### 写进“决定”

在 `records.decisions` 的表里追加一行：日期、结论、依据（“状态卡 某日”）。替代旧决定时把旧的那行用删除线划掉，不删。

### 规划 PDF 的写法

总规矩在 `kaoyan-report`，规划专用的补充：

- 结构：封面块 → 四格数字 → 时间轴图（`segments()`）→“一页看完”3–4 条结论加“这周要做的”提示框；每节先结论后细节，告诉用户怎么做。
- 时间安排一律做成表：按日期的排程表、每周节奏表、周历（`<table class="cal">`）、复盘日表、落后时的砍单表。
- 状态用色块标签（`<span class="st ok|mid|bad">`），“别再犯”用 `::: warn`，“怎么做”用 `::: tip`，流程用 `.flow` 步骤条。
- 不写来源和过程：不写“依据某报告第几节”“审稿指出”“两套骨架对比”。
- 要用户选的事放最后一节，写成“推荐（已按这个排）/ 另一种”的表。

## 不做

- 骨架草稿不进“决定”；只有定稿结论进。
- 外援不替用户排时间，也不写方案正文。
- 计划没完成只照实记，不催；要不要顺延由用户定。
- 计划执行失效、被用户纠错时，转 `kaoyan-retro`，不在这里改规则。
