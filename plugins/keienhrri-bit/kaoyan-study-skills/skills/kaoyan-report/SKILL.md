# 报告和讲义排版（kaoyan-report）

排版固定下来，不每次重新设计。贵的不是排版本身，是成稿阶段来回零碎改：每改一轮，主会话都要把整个上下文重读一遍。

## 生成器

本 skill 目录下的 `scripts/build_report.py`。需要 pandoc、Chrome（或 Edge、Chromium）、Python 3.10+；Python 依赖写在脚本头里，用 uv 时自动装：

```bash
uv run <本 skill 目录>/scripts/build_report.py <正文.md> <输出.pdf> "<页眉标题>" "<日期>" [图模块.py] [--json] [--strict]
```

没有 uv：`pip install pypdf pypdfium2 pillow` 后用 `python` 跑。浏览器找不到时用 `--chrome <路径>` 或环境变量 `KAOYAN_CHROME`。

跑完打印一行机检结果：

| 字段 | 意思 | 合格 |
|---|---|---|
| `pages` | 页数 | |
| `unrendered_math` | PDF 文字里残留的 `$` 或 `\命令`，公式没渲染出来 | 空 |
| `blank_pages` | 空白页 | 空 |
| `overflow` | 宽过版心被裁掉的公式、表格、图（前 40 字） | 空 |
| `missing_images` | 没加载出来的图片（相对路径按 Markdown 源文件所在目录解析） | 空 |
| `sparse_pages` | 最后一页以外不到三成满的页 | 可以不管 |
| `sheet` | 全部页拼成的一张缩略图 | 要看就只看这一张 |

正文里不要用半角美元符号：它会被当成公式定界符，机检也会把它报成没渲染的公式。要写金额就写“美元”或用全角 ＄。

## 正文能用的写法

- 封面块：`<div class="cover"><div class="kicker">科目 · 卷名</div>`，空一行写 `# 两行标题<br>第二行`，再 `<div class="meta">日期、用了哪些材料、谁转录谁复判</div></div>`。**材料和过程只在 meta 里交代一次。**
- 四格数字：`<div class="tiles"><div class="tile"><div class="big">8<small> / 15</small></div><div class="lab">正常尺度</div></div>…</div>`
- 提示框：`::: key`（蓝，结论）、`::: warn`（红，别再犯）、`::: tip`（绿，怎么做）。
- 题卡（解析集、订正册）：题头 `<div class="ch"><span class="no">3</span><span class="tt">题干简述</span><span class="sc"><b>1</b> / 6</span></div>`，下面接 `::: q`（题面）、`::: you`（学生原话，楷体）、`::: err`（错在哪一步）、`::: sol`（标准解答）、`::: pts`（评分点）、`::: mem`（要记住的）、`::: pit`（易错点）、`::: chk`（自查）。
- 状态标签 `<span class="st ok|mid|bad|info">稳</span>`；判定 `<span class="ok">对</span>`、`<span class="no">错</span>`、`<span class="part">部分</span>`；行内学生原话 `<span class="you">…</span>`。
- 步骤条 `<div class="flow"><div><b>①</b><h4>标题</h4><p>说明</p></div>…</div>`；周历 `<table class="cal">`。
- 图：图模块里 `from charts import *`，用 `bars()`（横条图）、`segments()`（分段条），最后写 `FIGS = {"名字": 函数}`；正文放 `<!--FIG:名字-->`。不用 matplotlib 默认样式。
- 公式 `$…$` 和 `$$…$$`；表格里公式中的 `|` 会自动换成 `\vert`。

## 结构

封面块 → 四格数字 → “〇 先说结论”3–5 条，每条加粗开头一句 → 正文 `## 一　…` 起编号，每节先结论后细节 → 要学生选的事放最后一节，写成“推荐 / 另一种”的表。

## 写法

1. **正文不放出处**：不写文件名、行号、“见某某.md”“（出处：…）”“依据某报告第几节”，不放脚注式依据清单。外援交回材料里的出处只供主会话核对事实，核完就删。
2. **不写过程和模型口吻**：不写“某模型转录显示”“某模型指出”“两套方案对比”，不写套话，不滥用星号和加粗。
3. **少用括号**：一句话最多一处括号补充，能拆成两句就拆；题号、分值这类短括号除外。
4. **告诉学生怎么做**：每节第一句就是结论；时间安排一律做成表；评分点用一行紧凑短句写完，不每题画大表。
5. **数字一致**：tiles、结论、表格里的同一个数必须相同，写之前核对。
6. 学生的话用楷体原样引用；符号、术语全篇统一。
7. 下一步写成 2–3 个选项，由学生选，不替学生排时间。

## 流程

1. **主会话直接写成稿**：先把事实底稿备齐（判分表、转录稿、状态卡、核过的数字），再整份一次写成。有推导的每题末尾留一行 `**答**：…`，用 SymPy 核。约 5000 字以上、不需要新推导的讲义、手册交 `writer` 子代理写（任务书给大纲、底稿、核过的数字和输出路径），主会话只核数字、Grep `〔待核〕`、看机检。外援交回的文字不搬进正文。
2. **改动集中做**：小处最多改五六处；要改的多就整份重写一次，不连续零碎改。
3. **构建后看机检那一行**：`unrendered_math`、`blank_pages`、`overflow`、`missing_images` 都为空就算版面合格。有问题只改报出来的那几处，再构建一次。要肉眼确认时只看一次 `sheet` 缩略图。标题孤行、窄列折行这类小毛病不修。
4. **有推导的成稿交付前审一次**（`roles.audit` 不是 `none` 时）：只收问题清单不超过 10 条（位置、错在哪、依据、改法），主会话逐条决定采不采，改完不再送审。一两页、没有推导的不审。
5. 自查：Grep 正文里的 `\.md|:\d+|出处|GPT|Gemini|Claude`，封面 meta 以外应为 0。
6. 对话里不复述成稿全文，只给 PDF 路径和 3 行要点。

完整例子：仓库 `examples/synthetic-mechanics/report.md`，构建出的 PDF 在同一目录。
