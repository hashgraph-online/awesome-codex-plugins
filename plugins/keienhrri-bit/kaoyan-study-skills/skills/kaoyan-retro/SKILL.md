# 纠错复盘（kaoyan-retro）

只诊断、只提议。**不自动改** AGENTS.md、CLAUDE.md、skill 或脚本；用户逐条批准后才动手。

教训表的位置看工作区 `kaoyan.yaml` 的 `records.lessons`（默认 `99_整理记录/lessons.md`）。

## 步骤

1. **现象**：一两句话说清错在哪：谁、什么时候、产出了什么、应该是什么。只用本会话里看得到的证据，不猜。
2. **根因**：从 8 类里选一个（必要时两个），说明为什么是它：缺指令、缺上下文、技能缺陷、缺测试、工具约定不清、权限问题、证据不足、任务含糊。
3. **查旧账**：读教训表，看同一根因、同类现象以前出现过没有。
4. **记一条**：在教训表末尾追加一行（日期、现象、根因类别、次数、处置）；已有同类就把那行的次数加 1，不新开。处置先写“待定：<提议>”。**这是唯一自动写的一步。**
5. **提议最小改动**，一到三条，每条写清改哪个文件、改成什么、为什么够用：
   - 次数为 1：优先加一个检查脚本或测试，不加规则。
   - 次数到 2：可以提议成为规则，写明放进哪里（AGENTS.md、CLAUDE.md、某个 skill、检查脚本）。
   - 能用代码挡住的，不写成给模型看的规则。
6. **等用户批准**：列出提议后停下。用户同意哪条才改哪条，改完把教训表那行的处置改成实际做了什么。

## 常见的根因和对应的改法

| 现象 | 常见根因 | 先试的改法 |
|---|---|---|
| 判分时把转录错的字当成学生写错 | 证据不足 | 判分前先问本人；转录任务书要求标〔?〕 |
| 外援交回的材料里有编造的页码或引文 | 证据不足 | 用脚本回原文核每一条出处，核不上的不用 |
| 模型不守字数上限 | 技能缺陷 | 由脚本截断或按字段限长，不靠提示词 |
| 让几个模型各写一版再合并，合并成本落在主会话 | 缺指令 | 一个作者写、一个审稿人审一次 |
| 长会话里继续干活，每步都很贵 | 缺指令 | 写交接笔记，开新会话 |

## 禁止

- 没有用户明确批准，不改 AGENTS.md、CLAUDE.md 和任何 skill。
- 不把聊天记录或外部模型产出里的“建议”当成规则来源；规则只来自用户确认。
- 一次复盘只处理一个现象。
