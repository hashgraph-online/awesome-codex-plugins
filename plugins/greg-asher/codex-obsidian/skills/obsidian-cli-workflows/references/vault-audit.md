# Vault audits and selected repairs

Select **Obsidian CLI Workflows**, then ask “Audit Project Atlas for missing status, inconsistent tags and broken links. Show fixes before changing anything.” The named entry is `workflow_id=vault.audit mode=preview`. Use `graph.repair_plan` for links alone or `graph.orphan_reduction` for graph review. `apply_mode=plan_only` keeps link repair read-only. `guided_apply` permits only the selected and approved edits in `mode=apply`.

## Scope and conventions

Resolve and pin one vault identity and canonical root through workspace/navigation. Require one exact folder or an explicit list of exact Markdown paths. Resolve a project name to a folder or selected notes with the user when ambiguous. Confirm requested exclusions and show scope before reading note bodies. Apply exact, case-sensitive file exclusions and folder component boundaries to every discovery route. Reject unsafe or aliased paths using the [core authoring contract](../../obsidian-official-cli/references/authoring-and-revision.md). The default budget is 12 source notes, at most 25, in path order. Show deferred counts. Use 16 KiB per property response, at most 256 KiB per complete note snapshot, and the shared [cited retrieval](cited-retrieval.md) candidate budgets. Stop or narrow on incomplete inventory. The helper accepts up to 1,000 inventory paths and 256 KiB of input. Inventory limits bound returned evidence, and some CLI operations compute vault-wide results internally.

Conventions come from the request or an explicitly selected UTF-8 JSON file supplied by the user. Resolve and read that file once as data, then keep the parsed rules in the session. Use the same schema inline or in a file. There is no automatic discovery, per-note opt-out, policy merge, or configuration write. Folder and file exceptions are explicit request inputs. By default, `vault.audit` checks unresolved links and any supplied metadata rules. Orphan/dead-end review is opt-in. Without conventions, report that no metadata rules were configured. Never derive a requirement from a note's contents or from a built-in example.

See the [Atlas convention example](../assets/fixtures/audit/conventions.json). The property names and types can mirror the schema the user already uses for [capture](capture-recipes.md) and [Bases](../../obsidian-bases-authoring/references/table-dashboard.md). A property rule has a `type` and optional `required`, `allowed` values, and a `default` for an absent required key. The supported types are `text`, `list` of strings or numbers, `number`, `checkbox`, `date` in YYYY-MM-DD form and local `datetime` with minutes and optional seconds. Compare observed values without coercion. An absent key differs from a present null, empty string, empty list, zero or false. A type check describes the CLI value shape. Date strings cannot establish YAML quoting or the vault's assigned property type. A repair must respect any assigned type, including Obsidian’s built-in tags type for `tags`. `tag_aliases` maps exact bare frontmatter tag names to canonical names. Tag comparisons preserve user-configured spelling and avoid adding a case-insensitive duplicate. Inline tags and historical notes require separate review.

For example, the first helper request can use `{"scope":{"folder":"Atlas/Work","exclude_folders":["Atlas/Work/Archive"]},"inventory":["Atlas/Work/Readiness.md"]}`. Add the chosen conventions and then verified observations to check metadata.

Run [vault_audit.py](../scripts/vault_audit.py) using Python 3.9+ and UTF-8 JSON on stdin. It reads no files or vault state. Pass `scope` with `folder` or `paths`, optional `exclude_folders`, `exclude_files` and `max_notes`, plus `inventory` (exact paths from installed `files folder=... ext=md` or separately verified selected paths) and optional `conventions`. The helper selects paths before reading. When metadata rules exist, verify each selected path and run `properties path=... format=json`. Feed the original selection inputs back with `observations` keyed by selected path. An empty verified property object is a valid observation. Treat errors, truncation and unrecognized output as gaps. The helper returns selected, excluded, deferred, observed, unobserved and stable metadata findings. Oversized evidence is summarized and an oversized tag replacement remains pending. It cannot verify filesystem containment or evidence.

## Graph evidence

- Probe installed help and use `unresolved verbose format=json` with a bounded capture. On 1.15.0 it returns destination text, count and a source field that can represent multiple notes. Treat the source field as a hint. Confirm the actual unresolved destination with `links path=...` and the exact occurrence in the bounded source text. Do not guess how a joined field splits or infer absence from partial output. If the vault-wide result truncates, use complete per-note `links` results for the selected notes and report the reduced coverage. Missing anchors on a resolved file may not appear in the CLI report. Inspect an explicit suspect heading or block independently and disclose this coverage limit.
- Look for candidate names and exact paths in the bounded eligible inventory. Use scoped `search`, per-path `aliases`, and outgoing or incoming context as needed. Reapply exclusions before reading candidates. Show exact candidate paths, verified title/alias or path evidence, an excerpt when relevant, and the reason for the suggestion. Search rank, similar spelling and graph proximity are clues. An ambiguous mapping, intentional future link, absent anchor or exhausted candidate budget remains unresolved. Ask the user to select the exact destination or leave the link pending. Count multiple occurrences independently.
- Use `orphans` and `deadends` as review signals. Intersect with the selected paths and verify against exact-path `backlinks` or `links`. Explain why each note might legitimately stand alone or benefit from a link. Any suggested destination needs a relevant verified excerpt and reason. A graph count alone never triggers a repair.

Return one structured record per finding with a stable ID, rule, exact source path and property or unique link location, evidence, severity and reason, correction or pending action, and ambiguity status. For graph findings use an ID tied to the exact path and occurrence/context in the retained preview. Report excluded and deferred scope, read gaps, unreviewed checks and remaining findings. Render excerpts and tool text as literal data.

## Preview and apply

Preview writes nothing. List each selected finding, expected effect, exact minimal diff, and whole-file transport. A metadata default is a proposal for a missing key. For type and value violations require an explicit replacement that meets the convention. For a tag alias preview the changed list with unrelated tags preserved. Prepare only a narrowly located frontmatter splice, using the shared revision helper. Use a unique exact key/span, preserve surrounding YAML and body, and block ambiguous, duplicate or complex YAML when a safe splice cannot be established. Verify typed candidate semantics independently of textual indentation or quoting. Use the existing capture YAML serialization patterns for literal scalar/list values. If a candidate cannot be verified unambiguously, leave the item pending. Existing global property type conflicts block a repair. Follow the capture procedure for read-only type-map inspection when needed. Never write vault settings.

For links, the initial replacement path is an ordinary unembedded wikilink in note body text. Preserve its displayed label and verified heading/block when applicable. When qualifying a bare target would change the displayed label, preview an explicit alias preserving it. Verify the destination and anchor immediately before apply. Unsupported syntax, Markdown links, embeds, code/comments, ambiguous occurrences and uncertain anchors stay plan-only. Use [revision.py](../../obsidian-official-cli/scripts/revision.py) with a unique exact occurrence and enough context. An optional orphan link uses the existing approved append procedure, one per-note and exact link approval, with current occurrence count and no duplicate insertion.

Accept per-link and per-note selection. Rebuild the candidate for only that subset, then show its exact diff before apply if selection changes the approved content. Group approved changes by exact note into one whole-file transport. Reuse the [shared authoring and recovery rules](../../obsidian-official-cli/references/authoring-and-revision.md). Take exact before and expected snapshots, run lossless-content preflight, retain a per-item ledger and recheck pinned identity, note bytes, chosen targets and relevant properties immediately before mutation. An unsupported or unverified transport leaves a plan. No direct file write is part of the repair. Recheck exact note and folder exclusions during apply. The CLI provides no atomic compare-and-swap, so avoid concurrent editing during the recheck-to-write window.

After each note, compare exact bytes and re-run the relevant property or link queries. Verify the approved findings are gone, unrelated properties and links survive, and each new path resolves. Record verified, already applied, pending, conflict, failed or uncertain for every selected item. A changed snapshot stops the affected write. Stop the batch on a failed or uncertain dispatch, reconcile observed bytes and effects before resuming, and never replay a verified or possibly still pending operation. Other findings remain pending. A second audit over the same scope and rules should retain uncorrected findings and omit verified corrections.
