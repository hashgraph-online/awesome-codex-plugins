# 即梦分镜审核技能

> **工作区根**：Codex 项目根（AGENTS.md 所在目录；下文所有 `scripts/…`、`tools/…`、`config/…` 相对该根，可用环境变量 `JIMENG_ROOT` 显式指定）。
> **技能目录 `${SKILL_DIR}`**：本 SKILL.md 所在目录（`.agents/skills/<技能名>/`）；Codex 加载技能时会给出技能路径。

[技能说明]
    审核分镜师产出的即梦格式分镜提示词（母镜头+子镜头结构）。
    导演以批判性视角审视产出，通过逐条比对、脑内预演、逐条评分确保质量。

[审核对象]
    outputs/<集数>/02-jimeng-prompts.md

[审核流程]

    第一步：建立整体理解
        - 读取导演讲戏本（01-director-analysis.md）
        - 读取人物提示词和场景道具提示词
        - 读取待审核的即梦分镜产出
        - 审核立场：找出问题，而非确认通过

    第二步：结构检查（母镜头+子镜头）
        - 每个母镜头是否对应一个剧情点？
        - 每个母镜头总时长是否 ≤ 15秒？
        - **母镜头编号是否连续（1、2、3、4……）？是否出现 3A、4B 等字母后缀编号？出现即 FAIL**
        - 子镜头编号是否在每个母镜头内独立从1开始？
        - 子镜头时长之和是否等于母镜头总时长？
        - 每个母镜头是否在分镜过渡后声明了全局风格设定？
        - 每个母镜头是否有分镜过渡（定调 + 连接）？

    第三步：分镜过渡质量检查
        - 分镜过渡是否为本段定调（情绪基调/叙事目的）？
        - 分镜过渡是否确保了前后视频的连接（衔接/转场）？
        - 首段是否有开场基调描述？
        - 末段是否有收束方式描述？

    第四步：逐条比对
        - 对每个子镜头，逐句对照导演讲戏本中对应剧情点的导演阐述
        - 找出导演阐述中有但子镜头中被弱化、遗漏或偏离的地方
        - 找出分镜师自行添加的、导演阐述中没有的内容

    第五步：脑内预演
        - 对每个子镜头，想象它被送进即梦平台后生成的视频画面
        - 判断：生成的视频是否与导演讲戏本描述的画面一致？

    第六步：逐条软质量检查
        对每个子镜头，按「验收清单」逐条确认，产出问题清单（分级：必须修复 / 建议改进）
        不再使用 1-10 分制评分；「必须修复」级问题决定 PASS/FAIL

    第七步：输出结果
        - 汇总问题清单，标注每项为「必须修复」或「建议改进」
        - 无「必须修复」级问题 → PASS
        - 存在任一「必须修复」级问题 → FAIL + 问题清单

[验收清单]

    母镜头结构（整体检查，不评分）
        □ 母镜头是否对应剧情点？
        □ 母镜头总时长是否 ≤ 15秒？
        □ **母镜头编号是否连续（1、2、3、4……）？是否出现 3A、4B 等字母后缀编号？出现即 FAIL**
        □ 子镜头编号是否每个母镜头内独立从1开始？
        □ 子镜头时长之和是否 = 母镜头总时长？

    分镜过渡（整体检查，不评分）
        □ 每个母镜头是否有分镜过渡？
        □ 分镜过渡是否定调（情绪基调/叙事目的）？
        □ 分镜过渡是否连接前后视频（衔接/转场）？

    全局风格设定（整体检查，不评分）
        □ 每个母镜头是否在分镜过渡后、子镜头前声明了全局风格设定？
        □ 设定内容是否完整？

    素材对应表（整体检查，不评分）
        □ 完整性、准确性、无孤立引用、素材边界正确

    台词对照（整体检查，不评分，任一不符即 FAIL）
        □ **运行台词对照校验脚本，对照剧本原文逐字核对分镜【台词】字段**：
           ```
           python tools/run_all_checks.py scripts/[剧本名]/outputs/epXX/02-jimeng-prompts.md --script-dir ${SKILL_DIR}/scripts  #（有 bash 时等价：bash tools/run_all_checks.sh <剧名> epXX）
           ```
        □ 剧本原文中每一句台词在分镜中都有对应（无缺失）
        □ 分镜中每一句台词与剧本原文逐字一致（无改写、无凭记忆复述）
        □ 台词清单（epXX-dialogue-list.md）与剧本原文逐字一致

    单条子镜头软质量（逐条检查，产出问题清单，不评分）
        检查维度：
        □ 七字段完整性：【景别】【运镜】【机位】【画面】【微表情】【台词】【音效】
        □ 忠实度：核心动作、台词、镜头运动是否被完整保留？
        □ 画面还原度：脑内预演，即梦生成效果是否符合导演意图？
        □ 摄影机合理性：焦段与景别是否匹配？有无越轴风险？
        □ 微表情质量：是否有具体的面部肌肉描写？情绪百分比是否合理？
        □ 台词质量：台词是否对照剧本原文逐字复制（而非凭记忆复述）？拆句后各句是否仍逐字保留原文？四要素是否完整？
        □ 情绪一致性：微表情的百分比和台词的情绪强度是否一致？
        □ 动作可执行性：动作描写是否具体？是否在时长内可完成？
        □ 夜晚光线：若为夜戏母镜头，画面是否禁写「暖黄」？是否用昏黄灯光/油灯昏光/冷暗局部照明？

        问题分级：
        - 必须修复：导致生成错误、偏离导演意图、违反脚本/格式铁律、台词失真、合规风险
        - 建议改进：不影响正确性，但可提升生成质量或一致性的优化点

    整体连贯性（整体评估）
        □ 正反打：对话场景是否包含正反打镜头？
        □ 衔接自然：相邻子镜头之间的画面、情绪是否能自然过渡？
        □ 节奏合理：整体节奏是否有起伏变化？
        □ 情绪弧线：全部子镜头串联起来，情绪弧线是否与导演叙事设计一致？

[输出规范]

    问题清单格式：
        母镜头 | 子镜头 | 分级 | 问题描述 | 位置 | 修改方向
        1 | 1 | 建议改进 | 微表情细节不够具体 | 微表情 | 补充眉眼肌肉描写
        1 | 2 | 必须修复 | 【画面】缺人物姿态，仅写动作 | 画面 | 补明"坐着/站着"等姿态

        整体连贯性评估：[简述]

    PASS 格式（无「必须修复」级问题）：
        业务审核：PASS
        [问题清单（可含建议改进项）]
        整体评价：[1-2句总结]

    FAIL 格式（存在「必须修复」级问题）：
        业务审核：FAIL
        [问题清单]
        需要修改的问题（必须修复级）：
        问题1：[具体问题描述]
        - 位置：[如 母镜头1 / 子镜头3]
        - 当前问题：[具体描述]
        - 预演效果：[即梦生成效果会出什么问题]
        - 修改方向：[具体建议]

[全量模式（合并常规审核与终审，一集完成的唯一审核，即阶段八）]

    触发时机：阶段七 四道校验全绿 + 衍生文件（clean.txt / view.html / 素材清单表）生成后。
    执行方式：派一个审核子代理，同时加载 jimeng-review（全量模式）+ compliance-review-skill。
    本模式为唯一审核模式，取代原先「常规审核 + 终审」两套审核（现并为阶段八），避免重复执行。

    PASS 判定（单一客观口径）：
        四道脚本校验全绿 AND 无「必须修复」级问题。

    【时长分工口径（2026-08-20 强化）——终审判定时必须遵守】
    - 台词时长是唯一硬判据：每条【台词】文本逐字=剧本原文、分配时长≥台词本参考、有效语速≤11字/秒；缺失/改写/冗余=必须修复。
    - 非台词时长（反应/动作/母镜头总时长）不做硬判据：**不因「母镜头总时长 ≠ 导演 P 预算」判 FAIL**（导演非台词时长不精准，由分镜师自控）。
    - 只核：每母镜头 ≤15s、子镜头和=母镜头声明、反应镜头一般 ≥1s（0.5s 可作建议改进；若大量出现且情绪读不清则必修）。

    整体检查表（任一硬伤即 FAIL）：
        □ 四道校验复核（check_mother_id / calc_duration / check_picture_field / check_dialogue）全绿
        □ 台词对照：剧本原文每句在分镜有对应且逐字一致
        □ 声明行：只列本母镜头实际 @点名出现的人物
        □ 合规审核（compliance-review-skill）PASS

    输出文件：scripts/[剧本名]/outputs/epXX/03-final-review.md
        结构：终审结论 → 整体检查表 → 问题清单（必须修复/建议改进）→ 连贯性评估。
        PASS 结论为「终审：PASS」，等于一集完成；FAIL 则脚本问题回主会话走 corrections.json 修正，
        其余问题回传 storyboard-artist 子代理重跑阶段六。
