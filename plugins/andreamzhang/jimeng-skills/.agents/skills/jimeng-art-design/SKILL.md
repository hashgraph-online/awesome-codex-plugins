# 服化道设计技能

> **工作区根**：Codex 项目根（AGENTS.md 所在目录；下文所有 `scripts/…`、`tools/…`、`config/…` 相对该根，可用环境变量 `JIMENG_ROOT` 显式指定）。
> **技能目录 `${SKILL_DIR}`**：本 SKILL.md 所在目录（`.agents/skills/<技能名>/`）；Codex 加载技能时会给出技能路径。

[技能说明]
    美术设计技能，将导演提供的人物清单、关键道具清单和场景清单，以及导演阐述中的补充视觉信息，转化为可直接用于文生图工具生成参考图的详细提示词。

    人物提示词出图格式：竖屏9:16白底，四格排版，分割构图。顶部面板：参考角色的特写肖像（保持面部特征和发型完全一致）。底部面板：三个无头的全身人体模特视图并排排列（在颈部截断，没有头部，仅展示服装），包括正面、侧面和背面视图。
    场景提示词出图格式：**一个场景 = 一条独立提示词（单图出图）**，不拼宫格、不做多场景合图。
        - 每条提示词只描述一个场景的完整空间（2026-09-30 用户指令：取消宫格场景设计）
        - 同一场景的日/夜/光线差异写在同一「光线区分」条目内，不另建资产、不另出图

[执行流程]

    第一步：读取上游产物
        - 读取导演分析产出中的人物清单、关键道具清单和场景清单
        - 读取剧本原文（scripts/[剧本名]/script/第X集.md），提取人物小传信息：
          - 剧本开头的人物介绍段落（如"十年前，大夏国师项东流选择隐退于市井"）
          - 剧本中对角色外貌、身份、气质的直接描写
          - 人物小传是角色造型的第一信息来源，优先级高于导演讲戏本中的人物清单
          - 导演讲戏本的人物清单用于补充小传中没有的视觉细节（如具体服装款式）
        - 将人物小传与导演清单合并，形成完整的角色信息后，再设计提示词
        - 读取 `${SKILL_DIR}/references/gemini-image-prompt-guide.md` 了解提示词写法规范
        - 读取 `${SKILL_DIR}/examples/` 下的示例文件，了解高质量提示词的写法标准
        - 读取已有的 assets/character-prompts.md、assets/prop-prompts.md 和 assets/scene-prompts.md（如存在），了解已设计的人物、道具和场景
        - 若 `assets/资产/人物`、`assets/资产/道具`、`assets/资产/场景` 中存在现成图片，先将其视为已建立的视觉资产，匹配项优先复用，不重复设计
        - 对于已有图片但尚未沉淀到文字资产库中的条目，可根据图片里真实可见的五官、服装、材质、结构、光线和布局信息，反推为提示词并写入对应资产文件
        - 反推提示词时只能写图片里能确认的内容；图片未显示的细节宁缺毋滥，不得臆造
        - 根据人物清单和场景清单中的"素材状态"列，只为标注为"新增"或"变体"的项设计提示词
        - 关键道具清单是道具设计的第一依据：凡标注为"新增"或"变体"的关键道具，必须设计并写入道具提示词
        - 如果导演阐述中还有同等级关键道具被清单遗漏，可补充，但不得与导演稿冲突
        - "复用"项跳过，不需要设计

    第二步：设计人物造型提示词
        为每个人物编写设定提示词（2026-10-09 起统一格式，用户案例为唯一口径）：

        人物条目固定六段结构（一段正文，逐行书写，不得用表格/项目符号）：
        出图要求：竖屏9:16，纯白背景，上1下3四格排版，分割构图。顶部面板：该角色特写肖像，保持面部特征和发型完全一致。底部面板：三个无头全身人体模特视图并排排列，在颈部截断，没有头部，仅展示服装，从左到右依次为正面、侧面、背面。顶部肖像与底部服装必须是同一角色、同一套服装。
        角色信息：<角色名，身份定位，年龄/性别，气质，情节背景>
        面部特征：<脸型，眼型/眉毛/鼻/唇，肤色，发型发色，佩戴物，表情>
        服装细节：<上衣，下装，鞋，配饰，标志性元素，色彩，材质，图案>
        画质要求：真人实拍质感，高清真人摄影画质，8K超高清，专业影棚柔和无影柔光，均匀漫射光，无强烈硬阴影。画面不能出现3D建模感、CG渲染感、二次元动漫感、手绘插画感、油画感、雕塑感、塑料假肤感；真人实拍必须有真实皮肤次表面散射纹理，可看清毛孔、细小绒毛、轻微肤色不均，但不磨皮不加磨皮滤镜，也不能有肿胀填充面部的网红整容脸。干净商业角色设定图，纯白背景，无文字，无水印，无logo，无杂乱背景。
        避免：多余头部、错误人体结构、多手多脚、服装不一致。

        写作要求：
        - 每个角色一段，独立可复制，禁止多人合并到同一段。
        - 服装按“款式 + 颜色 + 材质 + 细节”逐件写全；配饰写明位置与左右侧。
        - 背面视图必须写清背景专属元素（如背上斜挎物、箭袋、披风等）。
        - 剧本没写到的细节按“身份 + 整体风格”合理补设计，写不清的宁缺毋滥。
        - 禁止出现临时状态或动作描述（如“此刻瞪大眼”“正在看报纸”“膝盖微曲”）。

    第三步：设计人物音色描述
        在人物造型提示词完成后，**单独**为每个人物设计音色描述，写入同一条目下。
        这是独立于视觉形象的第二步产出，不得与造型提示词混在一起。

        音色描述必须包含：
        - 声线类型：性别 + 年龄段 + 音色类型（如"中年男声·低沉宽厚型"）
        - 基础质感：音高、音色、厚度、年龄感
        - 说话习惯：语速、节奏、咬字
        - 地域口音：所属方言区/口音特征
        - 声音辨识度：整体听感、在人群中的识别特征

        音色描述禁止包含：
        - 口头禅、语气词（如"嗨""啧啧""得了吧"等具体口头语）
        - 具体台词内容
        - 与声音无关的视觉描写

        设计依据（按优先级）：
        1. 人物的年龄、性别、身份职业
        2. 人物的性格气质（沉稳/张扬/刻薄/憨厚等）
        3. 人物的地域背景（北方/南方/农村/城市等）
        4. 导演阐述中对该角色说话方式的描述

    第四步：设计道具提示词
        为关键道具/界面资产编写设定提示词：

        出图布局：
        - 一张图，白色背景
        - 同画面展示正视图、45度视角图、关键细节放大图或激活状态图
        - 重点体现材质、结构和在镜头中的可见方式

        提示词必须包含：
        - 道具整体形态与比例
        - 材质、颜色、表面纹理、结构分层
        - 发光/特效/悬浮状态（如有）
        - 手持、佩戴、悬浮、嵌入空间等使用状态
        - 与当前世界观兼容的视觉逻辑
        - 整体气质与功能暗示

    第五步：设计场景环境提示词
        将导演分析出的所有场景，**一个场景一条独立提示词（单图出图）**逐一编写；
        不拼宫格、不做多场景合图、不写「宫格 / 格子 / 3×3 / 4×4 / 留空」这类表述。

        核心规则：
        - 场景内不得出现任何人物，所有场景必须描述无人状态下的初始面貌
        - 场景应呈现"事件发生前"的空场景状态——家具整洁、物件归位、无使用痕迹
        - 同一场景的日/夜/光线差异写在同一条目的「光线区分」里

        每条场景提示词必须包含：
        - 场景名与 @引用名（分镜引用的唯一权威）
        - 地点类型与空间布局
        - 视角统一为全景高机位俯拍——从屋顶/天花板/高空等高于场景主体的位置向下拍摄，约45度俯角，展现房间整体布局
        - 门的位置（室内场景必须明确标注门在画面中的位置，如"门位于画面右下角"，并描述门的材质、颜色和状态）
        - 时间（影响光照）
        - 光源类型与光线方向
        - 整体色调/色彩倾向
        - 关键道具/家具/物件（描述其静态摆放状态）
        - 空间纵深与层次
        - 氛围/情绪
        - 风格（写实/电影感等）

        全剧所有场景必须保持视觉风格统一，光影逻辑自洽。
        每条提示词后附该场景的负面提示词（通用基线对齐 config/global-style.md）。

    第六步：输出
        按照 `${SKILL_DIR}/templates/art-design-template.md` 定义的格式，分别写入三个文件：
        - 人物提示词（含音色描述） → 追加到 assets/character-prompts.md
        - 道具提示词 → 追加到 assets/prop-prompts.md
        - 场景提示词 → 追加到 assets/scene-prompts.md
        首集时创建文件，后续集数追加新增/变体条目到文件末尾。

[提示词写法原则]
    参考 `${SKILL_DIR}/references/gemini-image-prompt-guide.md`，核心要点：

    - 叙事描述式：用完整段落描述，不要关键词堆叠
    - 具体化：所有描述必须具体到可视化的程度
        - "穿红色衣服" ✗ → "穿深红色修身棉袄外套，内搭碎花棉布衫" ✓
        - "室内场景" ✗ → "现代都市写字楼的开放式办公区，大部分工位已空" ✓
    - 摄影术语融入自然语言
    - 情绪通过视觉细节传达，不要抽象描述

[注意事项]
    - gemini-image-prompt-guide.md 是提示词写法的核心参考
    - 人物提示词为竖屏9:16白底四格分割构图：顶部特写肖像，底部颈部截断的无头全身人体模特正/侧/背三视图，不得包含临时状态、站姿或动作描述
    - 音色描述为人物造型之后的独立步骤，先完成视觉形象，再单独设计音色，不得混为一谈
    - 音色描述不得包含口头禅、语气词等具体口头语
    - 导演稿关键道具清单中的"新增"/"变体"项目必须逐项落入 `assets/prop-prompts.md`
    - 场景提示词为无人空场景的初始状态，不得出现任何人物、人员活动痕迹
    - **场景提示词一个场景一条独立提示词（单图出图）**，禁止宫格/拼图/多场景合图、禁止出现「格N」「宫格」等表述（2026-09-30 用户指令）
    - 如果是为变体设计（如同一人物的冬装版），需在提示词中注明与原版的关联和差异
    - 服装状态变体铁律：角色脱衣/换装/衣物破损后仍需出镜，必须建立独立状态变体资产（如「@陈峰没外套」），
      在与原资产同条目下注明关联与差异（改了哪件衣、状态如何变），且变体名必须能一眼看出与基础态的差异
    - 变体资产命名规则：`@基础名 + 状态词`（如 @陈峰、@陈峰没外套），禁止无规律命名
    - 分镜师只允许引用资产库中已登记的 @引用名，不得自造
