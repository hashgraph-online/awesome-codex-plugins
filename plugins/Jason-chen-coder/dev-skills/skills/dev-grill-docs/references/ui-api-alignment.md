# UI 与接口对接澄清

适用于已有 UI、原型或页面代码，也有接口文档/服务端实现，需要判断能否对接、缺什么，以及整理前后端同步材料的场景。

目标是形成可确认的对接契约。以 UI 表达的用户行为为线索，核对现有能力；不要把页面草稿当成已经确认的产品要求，也不要把接口存在等同于整个交互已支持。

## 自然语言入口

最短入口：**“帮我对一下接口”**。结合当前页面、项目或功能上下文，也识别“看看接口缺什么”“这个页面能对接了吗”“接口有了，看看怎么对接”“整理给后端确认”等同义表达，不要求用户记 skill 名或复述产物格式。

直接复用当前会话已明确的项目、页面和接口来源；只有来源缺失或存在影响结论的歧义时，才问最少的必要信息。来源不是必须在同一句话中重新提供的参数。

按语义而非单独关键词路由：只问一个接口字段时直接查文档；“帮我把接口接进去”这样的明确实现请求保留实施范围，不将其改成仅交报告。仅询问 skill 如何触发也不是要求执行项目对接分析。

## 先查证，再列缺口

- 确认目标页面、接口来源、交付范围和验收行为。先读项目相关 HANDOFF、既有说明与代码；保护已有工作区改动。
- 从 UI 的展示字段、输入校验、按钮动作和状态变化拆解所需能力。检查数据来源、请求参数、完成条件、失败反馈，以及必要的生命周期行为。
- 对照实际 HTTP 方法、路径、参数、响应和业务错误。按任务需要检查状态查询、计时归属、取消/停止、重进恢复、能力范围等，避免把它们机械地套到每个接口。
- Swagger/OpenAPI 取证优先使用可用的 `swagger-doc-skill`；没有该 skill 时直接读取用户提供的规范或文档，不把它作为依赖阻塞。单个接口查询无需启动此澄清流程。
- 区分在线文档、本地源码、模拟回执和实机证据。记录来源与核对日期；本地实现不证明已部署，文档示例值不证明真实配置或范围。
- 将结果归为“可直接对接”“部分支持/语义待确认”“文档未覆盖”。找不到公开接口时这样表述，不断言后端绝无实现。建议字段和接口必须明确标为建议。
- 只问会改变行为、范围或验收的关键问题。每项待确认事项说明受影响的 UI 和需要谁确认；能从代码确定的事实不再交给用户回答。

## 默认产物：UI 对照 → 红框截图 → 接口缺口与待确认事项

用户请求 UI/接口对接缺口分析时，默认输出简洁的单文件 HTML，不需要额外说“带截图”“红框”或“生成 HTML”。沿用项目产物目录；没有约定时使用 `.claude/artifacts/designs/<feature>-integration.html`。明确要求仅聊天、不要文件、Markdown 或其他格式时服从用户选择；简单事实问答不生成报告。

只保留简短背景/核对日期和以下三个主体部分，按受众语言书写：

### 01 · 现有 UI 对照

用表格展示：**UI 能力｜现有接口/支持程度｜缺口或待确认事项**。

方法、路径和关键字段要准确，但不堆完整响应 schema、源码片段或实施步骤。多个接口共用前缀时可以集中说明。每行对应一个明确的页面能力，避免重复描述同一缺口。

### 主要缺口 · 对应 UI 截图

- 优先使用当前页面的真实渲染、现有组件预览/截图测试，或用户提供且版本适用的设计图。标明来源；不要为了截图调用设备运动、修改业务逻辑或制造“已接通”的状态。
- 在对应控件上加红色矩形框，配简短编号；编号与旁边的缺口说明一一对应。可在 HTML 中用 CSS/SVG 叠加红框，保留截图原貌。不要用生成式重绘替代 UI 证据。
- 保留必要的页面上下文，确保控件文案可读、红框不遮挡字段。只截与缺口有关的画面；同一页能清楚标注多项时避免重复整页。
- 测试注入的角度、金额、时间、运行状态等必须在图旁标明“测试数据/非设备实时状态”。将输入草稿、禁用按钮与真实可操作状态区分。
- 无法运行页面时，可使用已有可信截图并说明版本；完全没有截图来源时标记“待补截图”，继续交付已验证的对照，不伪造图片。涉及敏感信息时使用测试数据或遮盖后再交付。

### 02 · 接口缺口与待确认事项

用简短表格展示：**待补充/确认的能力｜最少需要约定的字段或行为｜确认方/结论（已知时）**。

区分“需要新增能力”和“已有能力但语义不明确”；不要把每个缺口都变成新 URL。优先列阻碍当前 UI 的事项，省略与此次交付无关的扩展需求。末尾给出明确同步动作，例如“请后端确认已有实现、字段与行为约定，并反馈未支持项的安排”。

## 可转发与验证

- 截图以内嵌 data URI 或等效方式打包，CSS 和必要脚本内联；不依赖本地图片目录、localhost、外部字体或 CDN。证据来源链接可以保留，但打开报告不应依赖它们。
- 清除无关本机路径、凭证及调试信息。原图入口如需保留，也必须离线可用；不把测试工具和内部环境说明塞进产品 UI。
- 在浏览器查看最终 HTML：核对图片加载、红框位置、编号匹配、文字可读性及窄窗口布局；检查输出文件没有本地资源依赖。不能完成渲染验证时明确说明限制。
- 交付时给出 HTML 文件路径，说明是否可直接离线转发，以及重要的证据限制。生成报告不等于已向同事发送；实际发送需要用户授权。

## 完成与交接

报告可在契约尚未确认时交付；清楚保留待确认项，不把“整理完成”标成需求已对齐。只有关键数据来源、动作语义、状态/失败处理及不支持能力的处理决定已明确，才符合主 skill 的 `ALIGNED` 含义。

契约确认后，按用户请求进入 `dev-plan` 拆实现与验证步骤，或在既有授权范围内继续工作。仅请求澄清时止于报告；不修改客户端、服务端或擅自补上高影响的产品决策。
